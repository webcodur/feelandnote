# 인물 읽어보기

> 현재 사용자 화면의 읽어보기는 `인물 안내` 하나만 노출한다. 이 문서는 안내의 한국어
> `plain_text`와 영어 `plain_text_en`을 작성·검수·게시하는 규칙 SSoT다.

## 현재 범위

`FigureReadingTabs.tsx`는 안내만 렌더하고 `celebServiceItems.ts`의 `person-explore` 항목은 닫혀
있다. DB의 `interpretive_title*`·`interpretive_text*`는 삭제하지 않고 보존하지만, 사용자가
인물 탐구를 되살리라고 명시하기 전에는 생성·재작성·게시 기준에 포함하지 않는다.

한 인물의 작업 단위는 한국어와 영어 안내 두 필드다. 한쪽만 고치거나 게시하지 않는다.

## 조사와 작성

먼저 이름·소속·직군·생몰로 동명이인을 막는다. 원전·본인 저작·직접 인터뷰·공식 기록·학술·
권위 자료를 우선하고, 위키백과와 위키데이터는 신원과 생애 개관에 쓴다. 현대 인물은 본인의
모국어 자료와 본인 매체도 확인한다. 검색 결과의 잘린 문장이나 기자의 요약을 본인 발언으로
바꾸지 않는다. 프로필 이름이 영문 이름과 여러 출처의 통용명에 명백히 어긋날 때는 안내문에만
검증된 통용명을 쓰고 프로필 결함을 보고한다. 이름을 추측해 고치거나 프로필 필드를 함께 바꾸지
않는다. 시작 동기와 `세웠다`·`이끌었다`·`성장시켰다` 같은 인과·주도성은 자료가 개인의 행동을
직접 확인할 때만 쓴다.

안내는 처음 보는 독자가 누구이며 무엇을 했고 왜 알려졌는지 이해하게 쓴다. 생애를 전부
나열하지 않고 정체를 설명하는 중심 행동이나 생각 하나를 고른다. 중심에는 그 사람이 직접 한
행동이 있어야 하며, 대표 업적을 지운 뒤 왜 유명한지 알 수 없게 만들지 않는다. 전문용어는
지우지 말고 같은 문장에서 일상어로 푼다.

첫 문장에서 명사로 정체를 설명할 때는 `[인물명]은/는 …이다.`인 완결문이나, 이름과 서술격
조사를 함께 생략한 `…명사.`형 bio 명사구 중 하나를 쓴다. `하데스는 그리스 신화에서 망자들을
다스리는 신이다.`와 `그리스 신화에서 망자들을 다스리는 신.`은 모두 허용한다. `…신다.`처럼
`이다`만 `다`로 줄이거나 `…신입니다.` 존댓말로 쓰지 않는다. bio형을 완결문으로 바꿀 때는
끝에 `이다`만 붙이지 말고 이름을 주어로 넣는다. bio형도 인물의 정체를 알려야 하며,
`본명 이혜빈.`처럼 인적사항 한 조각만 쓰지 않는다.

짧은 이야기는 극적인 일화를 뜻하지 않는다. 한 행동·질문·생각이 다음 문장을 불러오고 결과나
의미에 닿으면 된다. 자료가 받치면 `문제나 질문 → 직접 한 행동 → 달라진 결과`를 잇되, 모든
인물에게 위기와 반전을 만들지 않는다. 마지막 문장은 이 흐름을 닫고, 별개의 수상·판매량·죽음·
최신 이력을 새로 붙이지 않는다.

각 문장은 같은 중심을 밀어야 한다. 인과 없이 서로 다른 업적을 붙이지 않고, 사건을 시작했으면
자료가 허용하는 범위에서 결과까지 닫는다. 별명·성격·역할·관장 영역은 구체적 행동을 대신하지
못한다. 판본·편찬 연도·장 번호·발굴자·긴 존호는 인물을 이해하는 데 필수일 때만 남긴다.

날짜·나이·수량·직함·고유명사는 그것을 지우면 행동의 원인이나 결과를 이해할 수 없을 때만
남긴다. 중심과 무관한 최초·유일·최장 수식은 정체 설명에 붙이지 않고, 같은 사실을 수치나 다른
표현으로 되풀이하지 않는다. 작품·전투·정책을 여러 개 쓰려면 같은 선택이나 변화로 이어져야 한다. 이어지지 않으면
대표 하나만 고른다. 아직 실행되지 않은 계획·목표·예고는 결과를 대신하지 못한다. 팀 소속
인물은 팀의 작품·차트·수상을 개인의 행동처럼 쓰지 않는다. 확인된 개인 행동이 적으면 팀
이력을 대신 채우지 말고 짧게 끝낸다. 널리 통용되는 한국어 작품명·단체명이 확실하면 한국어
본문에 영문 이름만 남기지 않는다.

평범한 동사를 우선하고 장식용 은유, 영웅화, 설교형 결말을 쓰지 않는다. 결정적 행동에서는
사람을 주어로 세우고 수식어가 누구의 판단이나 행동을 가리키는지 분명히 하되, 첫 문장의 정체
설명이나 문맥상 자연스러운 사물 주어까지 기계적으로 바꾸지 않는다.

한국어는 `docs/project/production/writing-rules.md`를 따른다. 한국어를 확정한 뒤 같은 사실과
확신의 정도를 보존해 영어를 쓴다. 보통 한국어 180~420자지만 재료가 단순하면 짧게 끝낸다.

## 검수

1. 처음 보는 독자가 이 사람이 누구이고 무엇으로 알려졌는지 알아볼 수 있는가.
2. 한국인이 처음부터 한국어로 쓴 글처럼 자연스럽게 읽히는가.

둘을 만족하면 통과한다. 다만 명백한 사실 오류, 팀·조직의 일을 개인에게 돌린 표현, 한영 의미
차이는 함께 고친다. 이력·작품·수치만 늘어놓아 인물을 알아보기 어렵거나 번역투·인명사전 말투가
남아 있으면 실패다. 특정 문장 수나 이야기 공식에 맞지 않는다는 이유만으로 실패시키지 않는다.

기존 글이 이 기준을 통과하면 본문을 보존하고 검수 상태만 기록할 수 있다. 실패한 글만 조사부터
다시 한다.

## 상태와 저장

| 값 | 의미 |
|---|---|
| `review_status IS NULL` | 현행 안내 기준 미검수 |
| `ai_reviewed` | AI 검수 완료 |
| `human_reviewed` | 인간 검수 완료. 자동화가 덮어쓰지 않는다 |

- 검수 상태는 처리 이력이지 영구적인 품질 보증이 아니다. 사용자가 전수 재감사를 명시하면
  `ai_reviewed`도 다시 읽는다. `human_reviewed`는 품질 의견을 낼 수 있지만 자동으로 고치지 않는다.
- 한국어와 영어 안내를 한 행 갱신으로 함께 저장한다.
- `interpretive_*`는 기존 값을 그대로 보존한다.
- 설명 행이 없는 신규 인물은 한영 안내만 작성한다. DB의 닫힌 필드가 `NOT NULL`이므로 기존
  안내 전용 반영 관례와 같은 `미작성` 표식만 넣고 인물 탐구 내용은 생성하지 않는다.
- 검수를 통과한 active 인물만 `published_at`을 기록한다. `published_at IS NULL`이면 공개 조회에서
  빠진다.
- 선검수 결과·초안·조사 캐시·실패 사유는 실행 중 임시 폴더에만 두고 DB 반영과 실패 인계가
  끝나면 삭제한다.
- 실패한 인물은 `review_status IS NULL`로 남겨 다음 회차에 다시 들어오게 한다.
- 신규 행이 반영 뒤 검증에 실패하면 그 행의 `review_status`와 `published_at`을 조건부로 비워
  다음 회차에서 다시 처리한다.
- 반영 뒤 DB 재조회와 한국어·영어 실화면을 확인한다.

`sw/web-bo/scripts/celeb/readings.ts`의 생성·반영 경로는 안내 두 필드만 갱신하고, 닫힌 인물
탐구 네 필드는 반영 전후 값을 대조해 보존한다. 평소 잔여 검수는 미검수만 대상으로 삼고,
사용자가 전수 재감사를 명시한 경우에만 `--recheck-reviewed`로 `ai_reviewed`까지 다시 읽는다.
`--stats`는 읽기 전용 현황 확인에만 사용한다.
