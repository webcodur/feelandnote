# 합성 음성 정리 — 들숨 제거와 쉼 정리

TTS가 만든 음성은 경로·엔진과 상관없이 **처음 생긴 자리에서** 들숨을 지우고 앞·중간·뒤 쉼을 정리한다. 구현은 [`sw/audio-bo/scripts/voice_cleanup.py`](../../../sw/audio-bo/scripts/voice_cleanup.py) 하나다. 파이썬 경로는 `clean_file`을 import하고, Node 경로는 [`@feelandnote/shared/bo/voice-cleanup`](../../../packages/shared/src/bo/voice-cleanup.ts)으로 부른다. 문턱과 쉼 상한 값은 스크립트 상수가 쥐고, 이 문서는 판단 근거와 적용 규칙을 둔다.

## 적용 규칙

- 합성 결과가 처음 생긴 자리에서만 건다. 사람이 편집기(트림·들숨 편집·간격 넓히기·연령 변형)에서 손본 음원을 저장하는 창구에는 걸지 않는다 — 일부러 넓힌 간격까지 다시 줄인다.
- 새 합성 경로를 만들면 같은 모듈을 부르고 아래 표에 한 줄 더한다. 경로마다 정리 코드를 따로 두지 않는다.
- 정리가 실패하면 합성도 실패로 처리한다. 정리 안 된 음원이 조용히 나가지 않게 한다. 파이썬(numpy)·ffmpeg·ffprobe가 필요하다.
- 길이를 기록하는 경로는 정리 뒤 길이(요약의 `seconds`)를 쓴다.
- wav 단계가 있으면 거기서 정리한다. 손실 압축 음원을 풀어 다시 압축하면 2세대 손실이 된다. ElevenLabs 미리듣기처럼 mp3로만 받는 경로는 원본 샘플레이트·128k로 한 번 더 인코딩된다.
- 프로필은 `reading`(내레이션·안내, 문장 사이 쉼 기준)과 `dialogue`(인물 대사, 쉼표 자리 쉼 기준) 둘이다.

| 경로 | 거는 자리 | 프로필 |
|---|---|---|
| 인물 안내 음성 배치 `sw/web-bo/scripts/celeb/reading-voice.mjs` | attempt wav 채택 직후, 인코딩·검수 전 | reading |

| web-bo 대사 작업대·음원 만들기 창구 `generateVoicePreview`(`sw/web-bo/src/actions/admin/voice-gen.ts`) | 미리듣기 응답 전 | dialogue |

## 들숨 제거

TTS 보이스는 문장 사이마다 숨을 들이쉰다(Gemini Charon이 대표적이다). **대사를 침범하지 않아도 감상을 방해하므로 결함으로 본다.** 위치가 문장 경계든 쉼표든 가리지 않는다. 재생성은 해법이 아니다 — 보이스의 기본 동작이라 다시 뽑아도 같은 자리에서 또 난다.

### 탐지 — 발화를 먼저 배제하고 남은 곳만 본다

순서가 핵심이다. 「소리가 있는 곳에서 들숨을 골라내는」 방향은 실패한다 — **들숨은 발화보다 100배 작아서**(진폭 0.0015~0.0057 대 0.1~0.8) 가청 문턱을 0.010에 두면 들숨은 문턱 아래로 빠지고 발화만 걸린다. 그 상태로 구간을 지우면 대사가 사라진다(26.09.13 실측: 매칭율 0.9882 → 0.9622, 단어 85 → 83).

```
1. 짧은 창·홉(WINDOW·HOP)으로 RMS 엔벨로프를 만든다
2. SPEECH_RMS 이상은 발화로 확정하고 좌우 SPEECH_GUARD까지 보호구역으로 묶는다
3. 보호구역 밖에서 BREATH_FLOOR_RMS보다 큰 연속 구간을 찾는다
4. 길이가 BREATH_MIN~BREATH_MAX이고 구간 최대 RMS가 BREATH_PEAK_MAX 미만인 것만 채택한다
5. 그 구간을 파일 자신의 잡음 바닥(룸톤)으로 FADE만큼 교차 페이드해 채운다 — 디지털 0으로 비우지 않고, 구간을 삭제하지 않는다
```

발화를 물리적으로 건드릴 수 없는 구조다. 리산드로 마르티네스 ko에서 15곳을 지우고 받아쓰기로 대조하니 **매칭율·단어수·전사 글자수가 원본과 완전히 같았다**(0.9882 / 85 / 255자).

들숨 구간은 잘라내지 않고 소리만 룸톤으로 바꾼다. 길이를 줄이는 것은 아래 쉼 정리 단계뿐이다.

**세기 상한이 없으면 말끝 여운을 들숨으로 채운다.** 단어 끝이 발화 문턱 아래로 잦아드는 여운은 보호구역 밖까지 이어져 길이 조건을 통과한다. 상한 없이 채운 구간 중 바로 앞에 발화가 붙은 것이 읽어보기 28%, 대사 54%였고, 끝 음절이 뭉개져 받아쓰기가 「승리입니다」를 「승림」으로 적었다(26.09.13). 실측 들숨은 최대 0.0057이라 `BREATH_PEAK_MAX`로 들숨은 그대로 잡고 여운만 뺀다. 상한을 넣자 점수가 떨어졌던 대사 6슬롯 중 5슬롯이 원본 점수로 돌아왔다.

**디지털 0으로 비우면 받아쓰기가 없는 끝인사를 지어낸다.** 원래 음원의 쉼에는 16bit RMS 13~30의 잡음 바닥이 있는데, 들숨 자리를 0으로 비운 정리본은 정확히 0인 샘플이 파일에 따라 4.6~12.6%까지 늘었다. 검수가 그 자리에서 「다음 영상에서 만나요」「We'll be right back」「감사합니다」를 받아써 `unexpected-spoken-content/tail`로 떨어뜨렸다(26.09.13, 등록분 964건 중 26건). 검수의 `vad_filter`로는 막지 못했다. 룸톤으로 채우자 0 비율이 1.6%로 내려갔고 떨어진 26건 중 20건이 통과했다.

주기성·자기상관·문장 경계 판정·Whisper는 쓰지 않는다. RMS 하나로 끝난다.

### 폐기한 접근 — 다시 시도하지 않는다

| 방법 | 결과 |
|---|---|
| 전대역 스펙트럼 평탄도(SFM) | 실패. 들숨 에너지는 3kHz 이하에 몰리는데 0~12kHz로 계산해 고음역 0값이 기하평균을 끌어내린다 |
| 대역제한 SFM·ZCR | 자음 전이구간과 구별 못 한다 |
| Whisper 단어 타임스탬프 | 위치 파악용으로도 못 쓴다. Whisper가 들숨을 앞 단어 안으로 뭉갠다 — 기준 사례에서 들숨 4곳 중 공백으로 보이는 건 1곳뿐이었다 |
| Silero VAD 단독 | 자음·발화 개시를 non-speech로 잘라 후보가 파일당 10개 넘게 남발된다 |
| 주기성 기반 프레임 게이팅 | 대사가 일부 사라진다(0.9804). 발화와 들숨이 한 구간에 섞여 있을 때 경계를 못 가른다 |
| 들숨 구간을 디지털 0으로 채우기 | 받아쓰기가 무음에서 끝인사를 지어내 멀쩡한 등록분이 검수에서 떨어진다. 파일 자신의 잡음 바닥으로 채운다 |
| 후보를 길이·평균 세기로만 채택 | 발화 문턱 아래로 잦아드는 말끝 여운까지 채워 끝 음절이 뭉개진다. 구간 최대 RMS가 `BREATH_PEAK_MAX` 미만인 것만 채택한다 |
| 직전 발화와 조용한 틈 없이 이어진 구간 제외 | 상한 아래로 남는 작은 말끝 꼬리(최대 0.006 수준, 미야모토 무사시 대사 공격1)를 거르려 했으나 확인된 들숨까지 빠진다. 이어짐 비율이 대사 77%·읽어보기 51%이고 클레이토스 ko는 20곳 중 7곳, 리산드로 마르티네스 en은 16곳 중 14곳이 이어져 있다. 작은 꼬리는 남는 한계로 두고 검수에서 걸린 것만 개별 판단한다 |

파형 그림은 **진단에만 쓴다.** 숫자만 보면 「0.5도 소리, 0.008도 소리」로 같아 보이지만, 파형을 그리면 탐지 구간 안에 규칙적 진동(발화)이 들어 있는 게 한눈에 보인다. 규칙이 확정된 뒤로는 상시 경로에서 뺀다 — 이미지 판독을 전량에 반복하지 않는다.

## 쉼 정리 — 앞·중간·뒤

들숨을 지우면 그 자리가 침묵으로 남아 쉼이 드러난다. 쉼은 **자리에 따라 자연스러운 길이가 다르므로** 하나의 값으로 재지 않는다. 상한과 목표는 사용자 청취로 정했고 값은 `PROFILES`가 쥔다. 상한을 넘는 쉼만 목표값으로 줄이고, 상한 이하는 건드리지 않는다.

| 자리 | 프로필 | 청취 근거 |
|---|---|---|
| 쉼표 | dialogue | 제갈량 인사3의 0.58초는 자연스럽고, 인사2의 1.16초는 길다 |
| 문장 사이 | reading | 읽어보기에서 0.82~0.96초가 자연스럽다. 0.55초로 당기면 빠르다 |
| 문단 사이 | 미구현 | 상한 1.8초·목표 1.5초로 정했다(문장의 1.5배, 2초를 넘으면 음원이 끊긴 것처럼 들린다). 문단 경계를 판정하는 코드가 없어 규칙만 둔다 |

### 앞뒤 여백

- 앞은 발화 시작 전 `HEAD_KEEP`, 뒤는 발화 끝 뒤 `TAIL_KEEP`까지만 남긴다. 대사 음원에서 뒤 여백이 1.2초를 넘는 경우가 있었다(손자 명언 1.21초, 제갈량 명언 1.19초).
- 여백이 이미 짧으면 건드리지 않는다(칭기즈 칸 명언은 앞뒤 모두 0.00초).

### 발화를 자르지 않는 장치

발화 판정 문턱(`VOICE_RMS`)을 들숨 탐지의 발화 문턱보다 **훨씬 낮게** 잡아 어두운 자음까지 발화로 보고, 그 양옆 `TRIM_GUARD`를 무조건 보존한다. 자를 수 있는 것은 그 바깥의 순수 무음뿐이다. 쉼을 줄일 때도 구간 중앙만 덜어내 양끝 여유를 남긴다.

실측(26.09.13): 대사 3건은 받아쓰기 글자가 완전히 같았고, 읽어보기 2건은 매칭율이 유지되거나 올랐다(리산드로 0.9882 → 0.9922).

## 정리 전후를 비교할 때

받아쓰기 점수는 앞뒤 무음 길이만 달라져도 흔들린다. 채운 곳 없이 앞 무음만 줄었는데 「테오」가 「태호」로, 「리프트 오프」가 「liftoff」로 적힌 사례가 있다(26.09.13). 점수가 떨어지면 먼저 들숨 채움 여부와 소리 구간 길이가 원본과 같은지 보고, 둘 다 같으면 받아쓰기 흔들림으로 판정한다.
