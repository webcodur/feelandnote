# UI Scroll — 동적 콘텐츠 펼침 시 스크롤 튐 방지

## 증상

스크롤을 내린 상태에서 콘텐츠가 세로로 늘어날 때(아코디언 펼침, 목록 append, 지연 로드 이미지 삽입) 펼침 지점 **위쪽** 콘텐츠가 위로 밀려 사라지고, 클릭한 요소가 제자리에 있지 않고 튄다. 유저는 흔히 "아래가 고정되고 위로 나간다", "헤더가 오르락내리락한다"고 표현한다.

## 원인

브라우저의 **스크롤 앵커링**(`overflow-anchor: auto`가 기본). 스크롤 컨테이너는 뷰포트에 보이는 앵커 노드의 화면상 위치를 유지하려 한다. 앵커보다 위에서 콘텐츠가 늘어나면, 앵커를 제자리에 두려고 스크롤 오프셋을 키워 위쪽 콘텐츠(및 클릭한 헤더)를 밀어 올린다.

## 해결

스크롤을 **실제로 담당하는 컨테이너**에 `overflow-anchor: none`을 준다.

- Tailwind: `[overflow-anchor:none]`
- CSS: `overflow-anchor: none;`

개별 아이템(펼쳐지는 요소)에만 주는 것은 대개 부족하다 — 앵커는 스크롤 컨테이너 기준으로 선택되므로, 아이템에 none을 줘도 목록 바깥 요소가 앵커로 잡히면 그대로 튄다. **컨테이너 레벨에서 꺼야 확실하다.**

## 스크롤 컨테이너 찾기 (핵심 함정)

`overflow-y-auto`가 붙은 요소가 스크롤 주체가 **아닐 수 있다.** 그 요소에 `min-h-screen`(또는 콘텐츠보다 큰 min-height)이 있으면, 요소가 콘텐츠만큼 늘어나 내부 스크롤이 생기지 않고 실제 스크롤은 **문서 전체(`html`/`body`)** 에서 일어난다.

진단 순서:
1. 먼저 문서 최상위 `html`(전역 CSS)에 `overflow-anchor: none`을 준다 — 문서 스크롤에는 이게 확실히 먹는다.
2. 고정 높이 + `overflow-auto`인 **내부 스크롤 영역**이 따로 있다면 그 요소에도 준다.

## 검증

동적으로 펼칠 때 클릭한 요소가 제자리를 유지하고 콘텐츠가 **아래로만** 늘어나면 성공.

## 주의

`overflow-anchor: none`은 부작용이 거의 없다 — 스크롤 위치 자동 보정만 끈다. 채팅창처럼 새 메시지가 아래에 쌓일 때 하단을 유지해야 하는 특수 화면에서만 앵커링이 유용하므로, 그런 경우엔 전역 대신 국소 적용을 검토한다.
