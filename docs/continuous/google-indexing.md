# 검색엔진 색인·수집 신청

**현재 도달점:** 공개 인물 6,649명의 한영 13,298주소와 주요 페이지 986주소, 총 14,284주소가 운영 사이트맵에 있다. 10월 19일 active 명단 전체와 대조해 누락·잔여 0명을 확인했다. 신규 공개 7명(anne-bronte·moon-geun-young·alan-ritchson·im-soo-jung·kim-ok-vin·kim-tae-hee·shin-min-a)의 한영 14주소는 운영 200·자기 canonical·index, follow를 검증한 뒤 네이버·Bing에 접수하고 IndexNow 공용 접수 HTTP 200을 확인했다. Google은 기존 대기 11주소를 접수했으며 최종 API 재검사에서 8주소 색인 완료, 3주소 크롤링 완료·미색인이다. 태프트 한국어 주소에서 일일 할당량 초과를 확인해 개별 신청을 끝냈다. 전체·인물 사이트맵을 재제출했고 Google의 인물 13,298주소 재읽기와 오류·경고 0을 확인했다. Daum은 사용자가 지정한 PIN 파일로 인증한 뒤 신규 7명의 한국어 상세 7주소를 개별 수집으로 접수했고, 건별 「수집요청이 완료되었습니다」를 확인했다.

**엔진별 마지막 작업:** 아래 일시는 콘솔의 접수·재읽기 시각 또는 마지막 검수 시각이며 모두 한국시간(KST, UTC+9)이다. 재개 시 먼저 이 표의 일시·한도 결과를 확인한다. 기록 교체 규칙은 [지속 과제](README.md)가 쥔다.

접수는 실제 재크롤·색인·대표사진 반영 완료를 뜻하지 않는다.

마지막 실제 검색 확인(10-19)에서 Google은 `site:feelandnote.com`의 빌 게이츠·다리오 아모데이·젠슨 황 상세를 현재 제목 그대로 1순위로 보여 줬다. 검색 설명은 현재 meta description 대신 인물 안내 본문을 골랐다. 저장 HTML은 세 인물 모두 현재 제목을 담았지만, 설명에는 이전의 「감상 기록을 모았습니다」와 건수가 남아 있고 og:image 버전도 운영과 달랐다. 마지막 크롤은 빌 게이츠 10-10 00:37:50, 다리오 아모데이 10-12 18:22:55, 젠슨 황 10-12 18:16:40(KST)이다. 운영 대표이미지 3장은 200·JPEG와 실제 사진을 확인했고, 젠슨 황 일반 검색 결과에는 인물 썸네일 없이 26px 파비콘만 보였다. 네이버 「필앤노트 + 인물」은 세 인물 모두 상세를 보여 주지 않았고, 다리오 검색에는 `/content/` 작품 결과가 잔존한다. Daum 브랜드 통합·사이트 검색에는 서비스 도메인 결과가 없다.

**다음 착수는 Google 할당량 회복 뒤 미접수 주소의 개별 신청 재개다.** 대상과 순서는 위 표의 Google 행이 쥔다. 사이트맵·브랜드·설명문 규칙은 [SEO](../project/operations/ops-02-seo.md)가 쥔다.

다음 일일 작업은 아래 순서로 진행한다.

1. 빌 게이츠·다리오 아모데이·젠슨 황의 실제 검색 결과에서 상세 주소·최신 제목·설명·대표사진을 확인한다. 아바타를 쓰는 경우 승인된 원래 황갈색 배경도 확인한다. 현재 운영 응답, 검색엔진 저장 문서, 실제 검색 결과를 대조해 메타를 이미 읽은 경우와 아직 재수집되지 않은 경우를 구분한다.
2. 네이버는 요청 내역을 먼저 보고 미접수 주소가 남아 있으면 그것부터, 없으면 신규 공개 인물·새 페이지를 실제 일일 한도까지 신청한다. 기존 접수 주소는 반복하지 않는다.
3. Google은 위 표의 미접수 순서대로 이어간다. 이미 최신 변경이 반영된 주소를 반복 신청하지 않는다.
4. 셀럽 상세를 우선 처리한 뒤 세력 상세를 이어간다. 해리스 프리커와 의도적 noindex 작품은 후속 신청에서 제외한다.
5. 다음(Daum)은 신규 공개 인물의 미접수 주소가 생기면 개별 수집을 신청한다. 실제 검색 제목·설명·대표사진 반영을 확인한다. 사이트 검색의 `Feel&Note`·HTTP 등록 변경은 최초 신청자 확인이 남았다.

Daum 리스트 Seed는 메인·탐색·인물 명부, 직군 명부 16개 전체, `/explore/faction`·`/explore/myth`·`/explore/works/curated`까지 접수한 상태다. 10-17에 남은 `athlete`·`other`와 세력·신화·기관 선정 허브 5건을 추가 접수해 목록 Seed 큐를 비웠다. 기존 접수 주소는 반복하지 않는다.

네이버는 신규 7명의 한영 14주소까지 접수했다. 다음 신청은 신규 공개 인물·미접수 페이지가 생길 때다.

신청 전에 현재 active 명단 전체를 운영 사이트맵과 대조한다. 예전에 생성하고 오늘 공개한 인물이 있으므로 `created_at`만으로 신규 공개 여부를 판단하지 않는다. 운영 응답·자기 canonical·검색 허용과 기존 접수 내역도 확인한다. 대표 디렉토리만 신청하고 상세 주소가 모두 처리됐다고 간주하지 않는다. 같은 날 이미 접수한 주소, 영구 이동하는 옛 주소, 비공개·의도적 noindex 주소는 신청 대상에서 뺀다. 인물 주소는 현재 공개 사이트맵에서 확인하며 이름으로 slug를 추측하지 않는다.

## 신청과 반영 확인

- 사용자의 지시에 따라 로그인된 **Chrome 확장**으로 Google Search Console과 네이버 Search Advisor를 조작한다. 기존 로그인 계정을 유지한다.
- Aside 브라우저로는 `u0`(webcodur@gmail.com)가 Google Search Console·Bing Webmaster·네이버 Search Advisor에 접근된다(`aside repl --account u0`, 호출마다 새 세션이며 호출당 한 주소씩 처리). 네이버는 u0에 로그인을 올렸고 Search Advisor 계정은 `booster`다. Daum 웹마스터는 사이트 URL+PIN 인증으로 진입한다 — PIN 파일 위치는 [비밀 파일 규약](../project/platform/platform-04-env-vars.md)이 쥔다. 값은 Git 추적 파일에 기록하지 않는다. 콘솔 접근이 막힐 때는 IndexNow(`sw/web-bo/src/lib/indexnow.ts`와 같은 키로 `api.indexnow.org`에 POST)로 네이버·Bing 대상을 통지한다.
- Google은 URL 검사 화면의 대상 주소가 신청하려는 주소와 일치한 뒤 「색인 생성 요청」을 누르고 결과를 확인한다. 이전 URL의 결과 대화상자를 닫은 뒤 다음 주소로 넘어간다. 접수 후에는 마지막 크롤 시점·색인 상태·저장된 페이지가 최신인지 확인한다.
- 네이버는 「요청 → 웹 페이지 수집」에서 정식 주소를 입력하고, 요청 내역의 실제 링크·등록일로 접수를 확인한다. 목록 갱신이 늦거나 이전 행의 접근성 이름이 남으면 실제 링크와 행 본문을 다시 읽고, 접수 여부를 확인하기 전에 재신청하지 않는다. 신청 뒤 실제 검색 결과의 인물 사진·제목·설명도 확인한다.
- Google의 「할당량 초과」 또는 네이버의 「사이트별 일간 최대 요청 수를 초과하였습니다.」가 뜨면 해당 엔진의 당일 신청을 끝낸다. 다른 주소로 우회해 계속 누르지 않는다. Google 접수 건수는 날마다 달랐으므로 고정 건수를 가정하지 않는다. 네이버는 이번에 50주소 접수 뒤 한도를 확인했다.
- Google 접수 확정은 결과 대화상자의 「check_circle 색인 생성 요청됨 - URL이 우선순위 크롤링 대기열에 추가되었습니다」 문구로만 판정한다. 「색인 생성 요청됨 / 다시 요청」 칩이나 직전 주소의 대화상자 잔여 텍스트가 본문에 남아 오탐을 만든다. 접수 직후 같은 주소를 다시 검사하면 칩 상태(요청됨·등록됨)로 실제 반영을 확인할 수 있다.
- Google의 「색인 생성 요청을 제출하는 중에 문제가 발생했습니다」는 할당량 초과와 구분한다. 해당 주소를 반복 요청하지 않고 다음 주소로 넘어간다. 결과 미확인·조작 실패가 이어지면 원인을 확인한 뒤 재개한다.

이 문서에는 현재 도달점·마지막 접수·한도 문구·다음 신청 대상만 갱신한다. 날짜별 이력이나 URL별 조사 파일을 따로 쌓지 않는다. 사이트맵·IndexNow·메타데이터 운영 규칙은 [SEO](../project/operations/ops-02-seo.md)가 쥔다.
