# 그록 인물 연표 릴레이

그록으로 인물 연표를 채울 때만 이 문서를 따른다. GPT용
[`RESEARCH_RELAY_ALGORITHM.md`](../../../RESEARCH_RELAY_ALGORITHM.md)는 그대로 둔다.
사건 필드·허용 `kind`·화면 규칙은 [`celeb-timeline.md`](celeb-timeline.md)가 쥔다.

같은 세션의 자기 검수로는 부족하다. 조사자와 **다른 새 세션**이 각 행을 틀린 값으로 두고
독립 검색으로 깨뜨린다. 이 원칙이 릴레이 전체를 지탱한다.

## 역할

| 역할 | 하는 일 | DB 쓰기 |
|---|---|---|
| 스크립트(오케스트레이터) | 대상 배정, 세 그록과 한국어 편집자 발주, 구조 검사, 대기열 관리, 승인분 반영 | 있음 |
| 조사자 (그록) | 검색으로 사실을 교차 확인해 사건 배열(JSON)을 쓴다 | 없음 |
| 의심자 (그록, 새 세션) | 각 행을 유죄로 두고 독립 검색으로 결함 목록을 낸다 | 없음 |
| 수정자 (그록) | 결함 목록을 반영해 사건 배열을 다시 쓴다 | 없음 |
| 한국어 편집자 (Codex GPT, 새 세션) | 국문과 영문을 대조하고 전체 연표를 통독해 뜻이 무너진 국문만 고친다. 사건 선택으로 생애가 읽히지 않으면 재조사로 돌린다 | 없음 |

**그록은 DB에 쓰지 않는다.** 배열을 출력하면 스크립트가 검사·대기열·반영을 맡는다.
큐·원장·조사 테이블을 만들지 않는다.

## 조사자

배정받은 인물 하나만 처리한다. 신원(이름·직군·국적·생몰)을 먼저 확신하고 동명이인을 섞지 않는다.
검색으로 사실을 교차 확인한 사건을 보통 8~14개(출생 포함, 사망일이 있을 때만 사망 포함)로
연도순 JSON 배열에 담는다. 6개보다 적으면 연표로 내지 않는다. 사건 수를 맞추려고 중요하지 않은
일을 부풀리거나 확인되지 않은 일을 만들지는 않는다. DB에 넣지 않는다.
몰년이 있는 실존 인물은 출생과 사망을 빼면 안 된다. 범위는
[`celeb-timeline.md`](celeb-timeline.md) 「생부터 몰까지」가 쥔다.

서술 규칙과 견본은 [`celeb-timeline.md`](celeb-timeline.md)의 「서술 쓰기」가 쥔다. 여기에 옮겨 적지
않는다. 조사자도 의심자도 그 견본을 읽고 같은 수준으로 쓴다. 검색으로 재확인되는 사실만 쓴다.

초연·창작·공연은 `work`다. 책이나 악보를 인쇄해 낸 경우만 `publish`다.
좌표는 그 장소의 Wikidata `P625`만 쓴다. 확인되지 않으면 장소명만 남긴다.
한 사건이 두 도시이면 좌표를 비운다. 특정 건물 사건에 도시 중심 좌표를 넣지 않는다.
장소명이 그 도시이면 그 도시 `P625`는 맞다. 다른 인물이 같은 도시 좌표를 쓰는 것은 재사용이 아니다.

## 의심자

출발점은 검토가 아니다. **이 행은 틀렸다.** 검색이 같은 연도·장소·종류를 독립적으로 내놓지 못하면 그 필드는 결함이다. 그럴듯함, 조사자 보고, 위키 한 페이지의 분위기, 「대체로 맞음」은 무죄가 아니다.

조사 세션을 이어받지 않는다. 발주 프롬프트의 인물 id·slug와 live DB만 본다. DB에 insert·update·delete 하지 않는다.

각 행을 유죄로 두고 다음을 전건 의심한다. 한 항목이라도 무죄를 못 밝히면 그 행을 결함에 넣는다.

- 다른 사람·동명이인의 사건이다
- 연도·사실이 검색 두 곳에서 같은 숫자로 나오지 않는다
- 종류가 아래 표와 다르다. 초연을 `publish`로 둔 행은 무조건 결함이다
- 좌표가 그 장소 Wikidata `P625`가 아니다
- **이 인물 안에서** 같은 숫자 쌍이 서로 다른 장소명에 쓰였다
- 장소명이 건물·극장·스튜디오인데 좌표가 그 도시 중심이다
- 장소명이 그 도시인데 좌표가 그 도시 `P625`가 아니다. 다른 인물의 같은 도시 좌표는 보지 않는다
- 국문과 영문이 같은 사실을 말하지 않는다
- 깨진 문자, 필수값 누락, 실존 인물의 서사 단계, 중복 사건

출처가 갈리거나 검색이 안 되면 조사자 손을 들어 주지 않는다. 그 필드를 결함으로 적고 올바른 값은 `비움`이다.

결함 한 줄은 `index / 필드 / 지금 값 / 올바른 값 또는 비움 / 검색으로 확인한 근거`다.
모든 행의 모든 필드가 위 의심을 통과했을 때만 `결함 0`을 쓴다.

### 종류

| 일어난 일 | kind |
|---|---|
| 출생 | birth |
| 사망 | death |
| 수학·사사 | education |
| 초연·창작·공연·업적 | work |
| 책·악보를 인쇄해 냄 | publish |
| 전투 | battle |
| 이동·여행 | travel |
| 임명·취임 | office |
| 특정인과의 만남 | meeting |
| 결혼 등 나머지 | other |

## 발주

세 그록의 발주 프롬프트는 스크립트가 만든다. 조사자·의심자 프롬프트에 이 파일과
`celeb-timeline.md` 경로가 박히고, 의심자 프롬프트 첫 줄에는 `이 행들은 틀렸다. DB에 쓰지 마라`가
들어간다. 이 문서를 고치면 다음 발주부터 그대로 반영된다 — 프롬프트에 규칙을 복제하지 않는다.

## 자동 실행

위 순서를 `sw/web-bo/scripts/celeb/timeline/apply-grok.ts`가 수행한다. 여섯 단계다.

| 단계 | 주체 | 하는 일 |
|---|---|---|
| 1 조사 | 그록 (새 세션) | 검색해서 사건 배열을 쓴다 |
| 2 의심 | 그록 (별도 새 세션) | 전건을 유죄로 두고 독립 검색으로 **사실만** 판정해 결함 목록을 낸다 |
| 3 수정 | 그록 (조사자 역할) | 결함 목록을 받아 사실을 반영하고 문장을 견본 수준으로 다시 쓴다 |
| 4 한국어 편집 | Codex GPT (별도 새 세션) | 모든 국문 제목·서술을 영문과 대조하고, 전체 생애를 통독해 뜻이 무너진 문장만 고친다 |
| 5 구조 검사 | 스크립트 | 필수값·좌표 짝과 편집 중 비국문 필드가 바뀌지 않았는지만 본다 |
| 6 승인 | 사람 | 대기열의 최종 문장을 읽고 쓸만하면 넣는다 |

```bash
# 1~5단계. 결과는 DB가 아니라 대기열로 간다
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts run --auto --deceased --total 35 --lanes 12 --stage

# 6단계. 제목과 본문을 나란히 세워 대조한다. 행을 하나씩 읽으면 겹침이 안 보인다
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts review
# 반려는 .tmp-celeb-timeline-grok/staged/<slug>.json 을 지우면 된다.

# 6단계. 남아 있는 파일만 DB에 넣고 왕복 검증한다
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts commit --dry
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts commit
```

`run`은 반드시 `--stage`로 실행한다. 한국어 편집과 사람 승인을 건너뛴 즉시 DB 반영 경로는 쓰지 않는다.
`commit --dry`는 사실·한국어 기록, 현재 DB 지문, 구조와 선별기를 실제 commit과 같은 순서로 검사하되
파일을 옮기거나 DB를 바꾸지 않는다. 실제 `commit` 전에 먼저 실행한다.
최종 편집자가 사건별 감사 근거까지 대조한 현행 버전 stage만 commit할 수 있다. 그 이전에 만든 stage는
형식이 같아 보여도 보류한다.
그록 크레딧·사용량 한도로 `Couldn't start`가 나오면 새 인물 배정을 중단한다. 이미 만든 stage는
보존되므로 한도가 회복된 뒤 같은 명령으로 남은 대상만 이어간다.

기존 연표를 개편할 때는 `--replace-existing`을 쓴다. 조사 시작 시 라이브 사건 전체와 지문을
stage에 보존하며, 승인 시점의 라이브 값이 지문과 다르면 교체하지 않는다. 교체 직전 원본은
stage 옆 `backups/`에 남기고, 새 배열 삽입이나 왕복 검증이 실패하면 원본을 복구한다.

사실 재조사보다 먼저 기존 연표의 번역투를 줄이는 중간 개선을 명시적으로 선택한 경우에는
`apply-korean-diagnostic.ts`를 쓴다. `revised` 결과만 받고 `fact_check`·`research_needed`는 보류한다.
진단 시작 때의 원본과 현재 DB가 사건별로 같고, 국문 제목·서술 외 필드가 진단 전후에 같아야 쓸 수
있다. 실제 반영 전 `--dry`를 실행하며, 반영기는 원본 백업을 만든 뒤 국문 두 필드만 저장하고 전체
대상을 다시 읽어 검증한다. 이 반영은 사실 관문 통과가 아니므로 이후 재생성·사실 감사 대상에서 빼지
않는다.

```bash
pnpm exec tsx scripts/celeb/timeline/apply-korean-diagnostic.ts --dry
pnpm exec tsx scripts/celeb/timeline/apply-korean-diagnostic.ts --apply
```

```bash
# 최근 개편 473명은 기존 배열을 보지 않고 처음부터 다시 조사한다
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts run --include-file data/celeb/timeline-life-rewrite/recent-473-slugs.json --replace-existing --lanes 4 --stage --dir .tmp-celeb-timeline-grok/rewrite-recent-473/staged

# 기존 1~16건 가운데 위 명단을 제외한 인물도 처음부터 다시 조사한다
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts run --auto-existing --min-events 1 --max-events 16 --exclude-file data/celeb/timeline-life-rewrite/recent-473-slugs.json --lanes 4 --stage --dir .tmp-celeb-timeline-grok/rewrite-1-16/staged

# 기존 17건 이상은 먼저 현재 배열을 감사하고, 부실 판정만 재생성한다. 빈 연표는 신규 조사한다
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts run --auto-existing --audit-existing --min-events 17 --lanes 4 --stage --dir .tmp-celeb-timeline-grok/audit-17-plus/staged
pnpm exec tsx scripts/celeb/timeline/apply-grok.ts run --auto --lanes 4 --stage --dir .tmp-celeb-timeline-grok/fill-empty/staged
```

역할을 이렇게 가르는 이유는 각자 할 수 있는 일이 다르기 때문이다. **사실 검증은 사람이 못 한다.**
읽어서 잡히는 것은 자기가 이미 아는 사실과 충돌하는 오류뿐이고 무명 인물에서는 0건이다. 반대로
**문장이 쓸만한지는 검색 없이 읽으면 알 수 있다.** 그래서 사실은 2단계가, 국문 의미 대조는 4단계가,
최종 판단은 6단계가 쥔다.

- 기본 실행에서는 사건이 이미 있는 인물을 건너뛴다. `--replace-existing`은 처음부터 재조사하고,
  `--audit-existing`은 현재 배열을 독립 의심자에게 전건 검증시킨다. `fiction` 티어는 받지 않는다.
  허구는 `apply-fiction-grok.ts`가 원전 순서·서사 단계로 채운다.
- 의심자는 실제로 연 출처를 `sources`에 2곳 이상 적어야 한다. 미달이면 검색을 안 한 것으로 보고
  최대 5회까지 다시 시킨다. `http(s)` URL의 도메인이 서로 다른 출처만 세며, 모든 사건 index가 결함 또는
  무결함으로 판정되지 않아도 재시도한다. 각 사건도 서로 다른 URL 두 곳과 대조 근거를 별도로 내야 한다.
  출처·사건별 대조·결함 목록은 최종 stage에 함께 남고, 이 기록이 없는 파일은 commit할 수 없다.
  이 게이트가 없으면 `evidence: "placeholder"` 같은 시늉이 `결함 0`으로 통과한다.
- **의심자에게 최종 문장을 쓰게 하지 않는다.** 사실 판정자에게 서비스 문장을 맡기면
  「2018년 Birthday Honours에서 Knight Bachelor가 되었다」가 그대로 저장된다. 3단계가 있는 이유다.
  의심자가 사건 자체를 다른 사람의 일·일어나지 않은 일로 판정하면 수정자에게 넘기지 않고
  `needs-research`로 보낸다. 수정자는 사건 수·순서와 결함이 없던 행을 바꿀 수 없다.
- **한국어 편집자는 새 사실을 만들지 않는다.** 국문 제목·서술만 고칠 수 있고, 영문 서술과
  연도·종류·장소·좌표는 그대로 둔다. 영문만으로 뜻을 확정할 수 없으면 고쳐 쓰지 않고 사실 확인
  보류로 돌린다. 사건 선택의 큰 공백 때문에 생애가 읽히지 않으면 연결 문장을 만들지 않고
  `research_needed`로 돌린다. 의심자의 사건별 근거와 결함도 함께 받아, 수정자가 연도를 고친 뒤
  「그해」가 옛 연도를 가리키는 식으로 최종 문장이 감사 근거와 다시 충돌하면 `fact_check`로 막는다.
  `started acting again`을 「연기 폭을 넓혔다」로 확장하는 식의 해석은 금지한다.
- 장소를 비울 때는 국문·영문·좌표를 한 묶음으로 비운다. 한쪽만 지우면 지구본에 검증되지 않은
  마커가 남는다.
- 서술이 사라질 사건은 배열에서 뺀다. 서술 없는 카드는 화면에서 빈칸이 된다.

정규식으로 문장의 좋고 나쁨을 판정하지 않는다. 뜻이 무너진 한국어는 전체 국·영문 연표를 읽는
독립 편집자가 판정한다. 스크립트는 필수 필드·연도 순서·종류·좌표 모양과 편집 중 비국문 필드가
바뀌지 않았는지를 막는다. 단어 하나를 금지하는 정규식 관문을 세우면 규칙이 데이터를 이겨 멀쩡한
산출물까지 반려된다. 정규식은 무엇을 룰북에 남길지 측정할 때만 꺼내 쓴다.

grok CLI 자체를 다루는 법은 `grok-cli` 스킬이 쥔다. 호출 형태, Windows spawn 함정, 프로세스 자원
고갈과 회차 분할, effort와 묶음 크기의 짝, 출처 기반 성실성 게이트가 거기 있다. 여기에 옮겨 적지
않는다. **수백 명을 한 프로세스로 연속 처리하면 죽는다는 것만 기억하고 그 문서를 읽는다.**

성공·사실 보류·재조사 보류·사람 보류·반영 파일이 있는 인물은 같은 명령에서 건너뛴다. 호출 실패로
아무 산출물도 없는 인물만 다음 회차에 다시 들어오므로 별도 재실행 목록은 만들지 않는다.

## 좌표 채우기

장소명이 이미 적힌 행에 좌표만 없는 경우는 조사가 아니라 조회다. 다음 두 스크립트가 맡는다.

- `sw/web-bo/scripts/celeb/timeline/backfill-coords.ts` — 테이블 안에서 같은 지명의 검증된 좌표를
  옮기고, 국가명 접두어와 행정단위 접미사 차이를 흡수한다. 외부 호출이 없다.
- `sw/web-bo/scripts/celeb/timeline/geocode-places.ts` — 테이블에 답이 없는 이름만 Wikidata에 묻는다.
  조회와 반영이 분리돼 있어 검수 후 넣는다.

- `sw/web-bo/scripts/celeb/timeline/resolve-places-grok.ts` — 규칙으로 안 풀리는 이름을 그록에게 묻는다.
  고대 지명·동음이의어처럼 의미를 알아야 풀리는 것들이다. `high` 신뢰도만 채택한다.
  `infer` 모드는 장소명이 아예 없는 사건의 본문에서 장소를 유추한다.

순서를 지킨다. **기계로 풀리는 것을 먼저 끝내고 남은 것만 그록에 넘긴다.** 문자열 매칭으로
붙는 좌표까지 모델에 물으면 호출만 늘어난다.

**장소명 없는 사건은 대부분 채우면 안 되는 것이다.** 표본 227건에서 장소가 나온 건 7건(3%)이고
나머지는 영화 출연·작곡·집필처럼 원래 지점이 없는 일이었다. 억지로 촬영지나 본사를 붙이면
그 인물의 이동 경로가 오히려 왜곡된다. 유추는 본문에 지명이 명시된 것만 건진다.

국가·주·도에는 좌표를 붙이지 않는다. 「미국」에 워싱턴 D.C. 좌표가, 「캘리포니아」에 주 중심
좌표가 붙으면 지도에 뜻 없는 점이 찍힌다. 그리고 한자 지명의 한국어 독음은 현대 지명과 충돌한다.
실제로 「개봉」이 카이펑 대신 서울 지하철 **개봉역**으로 매칭됐다. Wikidata 결과는 설명문으로
정착지 여부를 확인한 뒤에만 쓴다.
