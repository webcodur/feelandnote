# 영향력 평가

이 문서는 실존 인물이 각 분야의 변화를 얼마나 인과적으로 만들었는지 평가해 `celeb_influence`에 저장하는 규칙을 쥔다. `celeb_reality`가 `REAL`·`BOTH`인 인물에 적용하고 `FICTION`에는 `celeb_influence` 행을 만들지 않는다. 축 경계는 [`celeb-00-01-pipeline.md`](celeb-00-01-pipeline.md)를 따른다.

## BOTH 인물의 근거 층

`celeb_reality='BOTH'`는 사료가 뒷받침하는 층과 전승층을 가려 채점한다. 스펙트럼의 `BOTH_REALITY_EVIDENCE_RULE`과 같은 규칙이되, 영향력은 인물의 자질이 아니라 세상에 생긴 변화를 재므로 한 가지가 다르다.

- 정치·전략·기술·사회·경제 축은 **사료가 뒷받침하는 행적에서만** 센다. 확인되지 않은 치적을 인물의 기여로 세지 않는다.
- 문화 축과 시대초월성은 **전승 자체가 후대에 남긴 자취**를 셀 수 있다. 다만 그것이 인물이 한 일이 아니라 그 인물을 둘러싼 서사가 퍼진 결과임을 근거 문장에 명시한다. 단군왕검을 예로 들면 고조선 통치의 실적이 아니라 개천절과 민족 시조 관념이 근거다.
- 사료층이 얇으면 앞의 다섯 축을 낮게 두고 그 얇음을 근거에 적는다. 전승의 크기로 앞 축을 채우지 않는다.

## 정본

평가 전에 다음 세 정본을 현재 코드에서 직접 읽는다.

- `packages/influence-constants/src/core.ts`: 축 키·라벨·상한·총점 만점·랭크 임계값과 계산 함수
- `packages/ai-services/src/prompts/influence-rulebook.ts`: 인과적 기여 단계·점수 기준·시대초월성·출력 규칙
- [`../data/03-celeb.md`](../data/03-celeb.md): `celeb_influence` 컬럼·제약·총점 트리거

축·점수 구간·랭크 표를 이 문서에 다시 고정하지 않는다. 코드 값이 바뀌면 그 값을 사용한다.

## 평가 원칙

- 명성이나 동시대의 상관관계가 아니라 본인이 직접 만들거나 구조적으로 가능하게 한 변화를 평가한다.
- 직접 기여, 구조적 기여, 촉매적 기여와 인과 연결 거리는 프롬프트 정본의 기준으로 판정한다.
- 각 점수와 설명은 확인 가능한 행적과 결과를 근거로 삼는다. 전문 분야 밖의 축을 인지도만으로 올리지 않는다.
- 시대초월성은 이미 제도·원리·문화 체계로 정착해 장기 지속하는 영향만 인정한다. 아직 일어나지 않은 미래 가능성은 점수 근거가 아니다.
- 다른 인물의 점수나 설명을 복사하지 않는다. 같은 사건을 여러 축에 쓰더라도 각 축에 미친 인과를 따로 설명한다.

## 저장 구조와 언어

`celeb_influence`는 JSON이 아니라 평면 컬럼이다. 일곱 축 각각 다음 세 값을 저장한다.

- 점수: 축 키와 같은 컬럼
- 한국어 설명: `{축}_exp`
- 영문 설명: `{축}_exp_en`

신규·전체 평가에서는 한국어와 영어 설명을 함께 작성한다. 영어는 한국어를 낱문장 단위로 옮기지 않고 같은 근거와 인과 범위를 간결하게 다시 쓴다. 사용자가 한국어만 평가·교정하라고 제한했다면 기존 영문 설명을 만들거나 고치지 않는다. 공통 영문 경계는 [`celeb-09-01-i18n.md`](celeb-09-01-i18n.md)를 따른다.

`celeb_id`는 기존 `celebs.id`를 사용한다. `total_score`는 일곱 점수의 합을 DB 트리거 `trg_calc_influence_total`이 계산하므로 입력값으로 관리하지 않는다. 랭크도 DB에 저장하지 않고 코드의 `calculateInfluenceRank`로 계산한다.

## 실행

1. 이름과 식별 정보를 대조해 한 명의 `celebs.id`와 현재 `celeb_reality`를 고정한다. `FICTION`이면 영향력 행을 만들지 않고 종료한다.
2. 정본 코드와 현재 `celeb_influence` 값을 모두 읽는다.
3. 각 축에 실제 변화를 만든 행적과 결과를 조사하고, 프롬프트 기준으로 점수와 한국어·영문 설명을 작성한다.
4. 축 키·점수 범위·설명 누락을 코드 상수와 대조한다. 추측·희망적 미래·과도한 간접 연결은 제거한다.
5. 사용자가 반영을 지시한 범위에서 해당 `celeb_id` 행만 INSERT 또는 UPDATE한다. 기존 평가의 일부만 고치는 요청이면 나머지 축을 덮어쓰지 않는다.
6. 같은 ID를 재조회해 일곱 점수와 요청 언어의 설명이 저장됐는지, `total_score`가 트리거 합계와 일치하는지 확인한다.

일곱 축이 모두 코드 범위 안에 있고 각 점수의 근거가 설명에 드러나며, 반영한 값과 재조회 결과가 일치해야 완료다.
