# 기관 선정 (`(main)/library/curated/*`)

> **최종 실측 체크: 26.08.01** — 실 DB 전량 집계(기관 25·목록 25·항목 2,529·표지 85%), 화면 응답·렌더 내용 대조, 실서비스 반영 확인
>
> 사용자 노출 명칭은 **「기관 선정」**(26.08.01 확정). 코드 식별자는 `curator`/`curated_list`다.

## 0. 왜 만드는가

이 서비스의 작품은 전부 **"어떤 인물이 골랐다"** 한 축으로만 붙어 있다. `celeb_contents`가 인물↔콘텐츠를 잇고, 서가의 시대별·직군별 화면도 전부 그 축의 변주다.

**"어떤 기관·매체가 선정했다"** 축이 없다. 세인트존스 고전 100선, 뉴욕타임스 21세기 최고의 책 100, 부커상, BBC 빅 리드 — 대중이 작품을 고를 때 실제로 참조하는 권위가 통째로 빠져 있다.

개인 컬렉션(`flows`)은 사용자 각자의 묶음이라 성격이 다르다. 세력도감(`celeb_tags`)은 인물 묶음이다. 콘텐츠를 묶는 공적 목록은 착수 시점에 어디에도 없었다(전역 검색 실측, 관련 테이블·액션·컴포넌트 0건).

**도서가 1차 대상이지만 영화·게임·음악까지 같은 구조로 담는다.** 목록마다 대상 매체를 지정하고, 장르·주제 특집(SF 50선, 공포영화 100선)도 표식으로 구분한다.

## 1. 선례 — 세력도감을 본떴다

세력도감은 **여러 인물을 하나의 묶음으로 진열**하는 완성된 기능이다. 인물→콘텐츠로 대상만 바꾸면 구조가 그대로 맞는다.

| 세력도감이 이미 푼 문제 | 그대로 쓴 답 |
|---|---|
| 묶음의 다국어 | 콘텐츠는 DB 이중 컬럼(`_en`), UI 라벨은 messages 파일. 폴백은 `en ?? ko` |
| 묶음 안에서만 감추기 | 연결 행에 `hidden`. **대상의 전역 status로 진열을 결정하지 않는다** — 그 실수로 인물 42명이 13개 테마에서 사라진 사고가 `getFeaturedTags.ts:226-235` 주석에 남아 있다 |
| 묶음별 개별 설명 | 연결 행에 `note`·`sort_order` |
| 캐시 무효화 | 쓰기 액션마다 BO 화면 + web 캐시 태그를 함께 무효화. 변경 범위에 맞춰 태그를 고른다 |

**한 가지는 따르지 않았다.** 세력도감은 그룹과 개별 테마를 `parent_id` 자기참조로 같은 테이블에 뭉쳤다. 둘의 성격이 같아 유효했던 선택이다. 여기서는 **기관과 목록의 성격이 다르므로**(기관: 국가·설립연도·성격 / 목록: 발표연도·선정 방식·근거) 테이블을 갈랐다.

**`content_id`를 NULL 허용으로 둔 것이 이 설계의 핵심이다.** 100선을 수집하면 상당수가 아직 우리 DB에 없다. 매칭된 것만 담으면 목록이 조각나 "100선"이라는 말 자체가 거짓이 된다. 원문 제목을 먼저 전량 적재하고 연결은 나중에 채운다. 실측으로 1차 수집 360항목 중 연결된 것은 149건(41%)이고, 나머지 211건은 원문 표기만으로 목록에 남아 있다.

🔴 **`UNIQUE(list_id, raw_title)`은 걸지 않는다.** 처음에 걸었다가 제거했다 — 서울대 100선에 오비디우스 『변신』과 카프카 『변신』이 **둘 다** 있다. 제목만으로 막으면 한 권이 통째로 사라진다. 중복 방지는 적재 도구가 제목+저자로 맡는다.

인덱스: `(curator_id, sort_order)` · `(list_id, sort_order)` · `(content_id) WHERE NOT NULL` · `(series_key, published_year desc) WHERE NOT NULL` · GIN `topics`

### 2.4 해마다 나오는 목록 — 두 종류를 구분한다

성격이 다르므로 담는 방식도 다르다. 실제 수집에서 둘 다 나왔다.

**해마다 통째로 갈리는 것** (대학 100선 개정판). 2024년판과 2025년판은 내용이 100권씩 다른 별개 목록이다.
→ 목록 행을 해마다 따로 만들고 `series_key`를 같은 값으로 두어 묶는다. `edition`에 판 표기. 화면에서 연도 전환.

**해마다 한두 편씩 쌓이는 것** (부커상). 1969~2025년 57년치가 목록 하나에 60항목으로 들어간다.
→ 목록 1행 + `is_annual=true` + 각 항목의 `year`. 연도별로 쪼개면 목록 57개가 각 1항목씩 갖는 꼴이 된다.

### 2.5 RLS

세 테이블 모두 SELECT `USING (true)`, 쓰기는 `admin`·`super_admin`만. `celeb_tags`와 동일 패턴. 실측 확인: 테이블별 정책 4개(select 1 + admin 3).

- 컴포넌트는 `sw/web/src/components/features/library/curated/`. 목록 카드(`CuratedListCard`)는 허브·기관 화면이 공유한다.
- 조회는 `sw/web/src/actions/library/curated.ts` 하나가 전담한다(허브·기관·목록·작품 역조회 4종). 캐시 태그는 `CACHE_TAGS.CURATED`.
- 서가 허브(`LIBRARY_SECTIONS`)의 4번째 구획으로 들어갔다. 네비게이션 하위 링크(`navigation.tsx`)에도 등록.
- 🔴 **주소 짝 검증** — 목록 화면은 주소의 기관과 목록이 실제로 맺어진 짝인지 확인하고 어긋나면 `notFound()`로 보낸다. 확인하지 않으면 아무 기관 이름으로나 남의 목록이 열린다.
- 미연결 작품은 링크로 감싸지 않고 흐리게 두며 "아직 등록되지 않은 작품"을 붙인다. **목록에서 빼지 않는다.**
- 사이트맵에 기관·목록 주소를 개별 등재한다(`sitemap.ts`의 `fetchCuratedPaths`). "서울대 권장도서 100선" 같은 검색어와 정면으로 맞는 자리다.

**작품 상세 연결** — `ContentDetailPage.tsx`에 「선정 이력」 구획을 넣었다(`CuratedEntriesSection`). `getContentDetail`의 `Promise.all`에 조회를 더하고 `ContentDetailData.curatedEntries`를 늘린 구조로, 등장인물 구획과 같은 모양이다. 순위가 있는 선정을 앞에 놓아 훈장처럼 읽히게 정렬한다.

> 아코디언 제목은 `DecorativeLabel`이 **글자 사이를 벌려** 그린다(「선 정 이 력」). HTML에서 제목을 문자열로 찾을 때 연속 검색이 실패하므로 없는 것으로 오판하지 마라.

### 3.2 백오피스 — 만들지 않는다

**전용 편집 화면은 예정에 없다(26.08.01 유저 결정).** 운영은 아래 세 도구로 한다.

1. 조사 결과를 §4.2 형식의 JSON으로 `docs/curated-lists/`에 둔다
2. `import-curated-list.ts`로 적재한다(멱등이라 몇 번을 돌려도 같다)
3. `match-curated-items.ts` → `register-curated-books.ts`로 작품을 잇는다
4. `/api/revalidate`에 `curated`·`contents` 태그를 던져 캐시를 비운다

목록 자체가 외부 발표물이라 화면에서 손으로 고칠 일이 거의 없다 — 원문이 바뀌면 JSON을 갈아 끼우고 다시 적재하는 편이 정확하다. 화면이 필요해지면 `factions/themes/[tagId]/ThemeEditor.tsx`가 본이 된다(검색·드래그 정렬·인라인 저장·이미지 업로드가 한 화면에 있다).

## 4. 데이터 수집

### 4.1 원칙

- **`source_url` 없는 목록은 만들지 않는다.** 발행처 원문을 우선한다. 적재 도구가 빈 값을 거부한다.
- 목록 원문의 제목·저자를 **그대로 적재**한다. 번역하거나 다듬지 않는다.
- 작품 매칭은 별도 단계다. 네이버(ko)·OpenLibrary(en)만 쓴다(Google Books 금지 — 일일 한도).
- 매칭 실패는 실패로 남긴다. **비슷한 작품을 갖다 붙이지 않는다.**
- 공식 출처로 확인할 수 없으면 가장 그럴듯한 2차 출처를 쓰되 어디였는지 기록한다(26.08.01 유저 방침).

### 4.2 도구

| 파일 | 역할 |
|---|---|
| `sw/web-bo/scripts/import-curated-list.ts` | 수집 JSON → DB 적재. 기관·목록은 slug 기준 갱신, 항목은 목록 단위 전량 교체(멱등). 이미 맺은 작품 연결은 제목+저자로 회수해 되붙인다. `_`로 시작하는 파일은 부속 자료로 보고 건너뛴다. `--dry` |
| `sw/web-bo/scripts/match-curated-items.ts` | 항목 ↔ **기존** 콘텐츠 연결. 제목 정규화 + 저자 대조. 도서·영상 모두 다루며 목록의 대상 매체와 같은 것만 후보로 삼는다. `--dry` `--list <slug>` `--relink` |
| `sw/web-bo/scripts/register-curated-books.ts` | 우리에게 **없는** 작품을 외부에서 찾아 등록하고 잇는다. 도서는 카카오·Open Library, 영상은 TMDB. `--dry` `--limit N` `--list <slug>` |
| `docs/curated-lists/_author-aliases.json` | 저자 표기 대응표. 음역 차이(맥루한↔맥루언)는 규칙으로 안 잡혀 사람이 확인한 것만 등록 |
| `docs/curated-lists/_match-report.json` · `_register-report.json` | 실행 보고(보류·미보유·미발견 명단). 실행마다 덮어쓴다 |

**작품을 새로 등록할 때의 판정**

- 🔴 **네이버 책 검색 API는 종료됐다.** 호출하면 `404 SE05 존재하지 않는 검색 api`가 온다(26.08.01 실측). 한국어 책 메타의 창구는 **카카오**(`KAKAO_REST_API_KEY`)다. `contents.external_source` CHECK에 `kakao_book`이 이미 들어 있다.
- **한글 제목은 국내 창구에서만 찾는다.** Open Library에 던지면 한국 고전이 로마자 표기로 잡혀 엉뚱한 저자가 붙는다(『춘향전』 → "In-jun Paek" 실측).
- **영문 제목은 원서를 먼저 본다.** 저자 표기가 로마자 그대로라 오연결 위험이 가장 낮다.
- 🔴 **저자 이름이 서로 다른 문자로 적혀 있으면 글자 대조가 불가능하다**(「Marguerite Duras」↔「마르그리트 뒤라스」). 이때만 예외를 두되 조건이 셋이다.
  1. **검색어에 저자를 함께 넣어** 검색처가 먼저 걸러주게 한다
  2. 제목이 정규화 후 **완전히 같을** 때만 채택한다(비슷한 정도로는 안 된다)
  3. 저자 없이 제목만으로 찾은 결과에는 **이 예외를 쓰지 않는다** — 『One-Way』가 같은 제목의 영어교재에 붙은 사고가 있었다(26.08.01)
- **검색어에 넣는 저자명은 다듬는다.** 괄호 안 본명·필명(「Émile Ajar (Romain Gary)」)이나 악센트(「Éric Vuillard」)를 그대로 넣으면 검색처가 한 건도 돌려주지 않는다. 첫 저자만 남기고 악센트를 푼다.
  > 실측 효과는 제한적이다(26.08.01 전량 재실행 기준 12건 추가, 전체 84%→85%). 남은 미연결의 대부분은 저자 표기가 아니라 **로마자로만 적힌 국내 미출간작**과 **논문·발췌**라 이 규칙의 사정거리 밖이다.
- 🔴 **TMDB는 영문으로 검색해야 한다.** `language=ko-KR`로 부르면 제목이 한국어로만 오고(『My Neighbour Totoro』→「이웃집 토토로」) 원제 자리에는 현지어(「となりのトトロ」)가 들어와, **영문 목록과 대조할 문자열이 응답 어디에도 없다.** 이것 하나로 고전 영화 17편이 통째로 안 잡혔다. 영문으로 대상을 확정한 뒤 한국어 제목·포스터는 상세 조회로 따로 받는다.
- **영상은 제목과 개봉 연도가 함께 맞아야 채택한다.** 같은 제목의 리메이크가 흔해 연도 대조가 감독 대조보다 확실하다.
- **제목이 크게 갈리면 감독으로 확정한다.** 『Sunset Blvd.』↔『Sunset Boulevard』, 『Fear Eats the Soul』↔『Ali: Fear Eats the Soul』은 제목 대조가 듣지 않는다. 감독명은 양쪽 다 로마자라 정확히 맞는다.
  ⚠️ **제목만 비슷하면 채택하는 방식은 쓰지 마라** — 키아로스타미의 『Close-up』이 동명의 다른 감독 작품에 붙은 사고가 있었다(26.08.01). 느슨한 제목 대조 대신 감독 확인을 넣어 해소했다.
- **적재·연결 후 캐시를 비워야 화면에 뜬다.** `/api/revalidate`에 `curated`(콘텐츠도 손댔으면 `contents`까지) 태그를 던진다. 개별 목록 화면은 slug별 캐시 키라 새로 뜨지만 **허브는 옛 캐시가 남아 새 기관이 보이지 않는다.**
- ⚠️ **캐시를 비운 직후 첫 요청이 500을 낸 적이 두 번 있다**(26.08.01, `/library/curated`와 `/library`). 재요청부터는 계속 200이고 재현되지 않았다. **원인 미확정** — 캐시가 빈 상태에서 여러 조회가 한꺼번에 되살아나는 경합으로 보이나 확인하지 못했다. 개발 서버에서만 본 증상이므로 배포 후 같은 자리를 다시 봐야 한다.

**매칭 판정 규칙** (오연결을 막는 순서)

1. 제목 정규화 — 부제(`: A Novel`) 제거, 괄호주석 제거, 관사 제거, 문장부호·공백 제거
2. 원문에 저자가 있으면 **저자까지 맞아야 연결한다.** 같은 제목 다른 작품을 막는 유일한 방어선이다
3. 저자 대조는 완전일치 → 부분포함 → 편집거리 유사도 → 대응표 순
4. 저자가 맞는 후보가 여럿이면(같은 책이 중복 등록된 경우) 감상 기록이 많은 쪽을 정본으로 고른다
5. 원문에 저자가 없으면(작자 미상 고전) 제목만으로 고르되 보고서에 남긴다

🔴 **전수 조회는 반드시 페이징한다.** PostgREST는 1,000행에서 조용히 끊는다. `content_locales`는 14,640행이다. 매칭 스크립트의 `selectAll`이 정렬키를 고정해 페이지로 나눠 받는다.

> 반면 **공쿠르상은 70%에서 92%로 올랐다**(26.08.02). 프랑스어 원제로 남아 있던 항목을 우리 쪽에 새 작품으로 등록해 이어 붙인 결과다. 원제가 프랑스어처럼 라틴 문자로 적히는 언어는 서지 자료에서 찾을 길이 있고, 일본어를 로마자로 옮긴 표기는 그렇지 않다 — 이것이 두 목록의 갈림길이다.

> **비영어권 목록을 새로 담을 때** — `raw_title`에 원어를 그대로 넣으면 표지가 통째로 빈다. **국내 출간명 > 영문 표기 > 원어** 순으로 고르고 원어는 `note`에 남기도록 조사 단계에서 지시한다.

**남은 불확실**

서울대 목록 6건이 출처마다 다르다. 50번 자리는 학내 기사가 「금강삼매경론(원효)」, 공식 보존본이 「보조법어(지눌)」로 아예 다른 책이다. 학내 기사 표기로 담고 항목마다 충돌을 적어 뒀다(26.08.01 유저 방침 — 공식 확인이 불가능한 건은 가장 그럴듯한 출처로 두고 진행).

**이어지지 않은 427건은 대부분 결손이 아니다.** 절반이 아쿠타가와상(132)과 세인트존스(85) 둘에 몰려 있다.

- **논문·발췌**가 가장 많다(세인트존스 85건). 하이젠베르크·아보가드로·아인슈타인의 논문, "Excerpt from…" 항목은 단행본이 아니라 서점 자료에 없는 게 정상이다.
- **여러 작품 묶음** — 「To the Lighthouse, A Room of One's Own」, 「홉스봄 4부작」처럼 원문이 한 줄에 여러 권을 적은 항목.
- **중·단편** — 이상문학상 수상작은 중단편이라 단독 서지가 없는 경우가 있다.
- **제목만 같은 다른 작품** — 케루악 『On the Road』와 매카시 『The Road』, 벤 존슨의 희곡 『The Alchemist』와 코엘료의 소설. 일부러 잇지 않았다.

억지로 이으면 목록이 거짓말을 한다. 못 찾은 항목은 원문 표기 그대로 화면에 남는다.

## 5-1. 작품은 서비스 공통 작품 카드로 그린다

목록 상세의 작품은 `ContentCard`(`components/ui/cards/ContentCard`)로 그린다. 처음에는 이 화면 전용 카드를 따로 만들었는데, 그 결과 **한국어판·영문판 전환이 이 화면에만 없었다**(26.08.02 유저 지적). 판 전환·감상한 사람 수·별점은 공통 카드가 이미 갖고 있고, 언어별 자료(`title_ko`/`title_en`/`thumbnail_en`/`has_en_edition`)도 `flattenLocales`가 이미 돌려주고 있었다 — 조회는 멀쩡했고 그 값을 화면으로 넘기지 않았을 뿐이다.

- 순위·발표 연도는 공통 카드에 새로 낸 `overlayTopLeft` / `overlayTopRight` 자리에 얹는다. 표지 위 양쪽 위 모서리다.
- **아직 우리에게 없는 작품만 예외다.** 공통 카드는 작품 식별자가 있어야 동작하는데 그런 작품은 식별자가 없다. 대신 공통 카드와 같은 테두리·모서리·글자 자리를 따라 그려 격자에서 줄이 어긋나지 않게 한다.

> 이 저장소에서 **공통 부품을 못 찾고 자체 구현한 두 번째 사례**다(앞은 허브 뒤로가기). 화면을 새로 만들 때는 같은 일을 하는 부품이 `components/ui`·`components/shared`에 있는지 먼저 뒤진다.

## 5-2. 기관 로고 확보 (26.08.02 완료 — 38/38)

로고는 `curators.logo_url`에 담고, 화면에서는 흰 타일 위에 정사각으로 얹는다(대부분 흰 종이를 전제로 만들어져 어두운 화면에 그대로 두면 묻힌다). **타일에도 이미지에도 여백을 주지 않는다** — 로고 파일 자체에 여백이 들어 있어 한 번 더 주면 44픽셀 자리에 그림이 절반만 찬다.

**확보 경로는 아래 순서로 시도한다.**

1. **위키미디어** — `action=query&prop=images`로 로고 파일명을 찾고 `prop=imageinfo&iiurlwidth=512`로 내려받는다. 정사각인지 반드시 확인한다(왕립학회는 1417×1417로 그대로 쓸 수 있었다).
2. **사이트의 `apple-touch-icon`** — 위키에 없을 때 가장 잘 듣는다. 다만 `/apple-touch-icon.png`를 그냥 찔러 보면 404가 흔하므로, **첫 화면 HTML을 받아 `<link rel="...icon">`의 실제 경로를 뽑아 쓴다**. 실제로 곧장 찔러서는 6곳 중 1곳만 나왔지만, HTML을 열어 보니 4곳이 더 나왔다(경로가 `/wp-content/uploads/fbrfg/`, `/profiles/cambridge/themes/…` 등으로 제각각이었다).
3. **가로형 로고 잘라내기** — 정사각 자료가 없으면 글자 부분의 색 픽셀 범위를 재서 머리글자만 잘라낸다(미국로맨스작가협회 500×56 → RWA 부분만). 눈대중으로 자르면 글자 끝이 잘린다.
4. **기관의 이미지 서비스** — 파이낸셜타임스는 사이트가 크롤러를 막지만(403) 자체 이미지 서비스(`__origami/service/image/v2/…brand-ft-logo-square-coloured`)는 512×512 정사각을 내준다.

> **받은 아이콘이 그 기관 것이 맞는지 확인한다.** 영국심리학회 아이콘은 주황 바탕의 여성 얼굴이라 학회 로고로 보이지 않았는데, 사이트 스스로 "학회 로고에서 따온 프시케"라 적어 둔 것을 보고 정품임을 확인했다. 겉모습만으로 버리지 않는다.

내려받은 파일은 `sw/web/public/images/curated/<slug>.png`에 두고 `logo_url`은 `/images/curated/<slug>.png`로 적는다. 위키미디어 원본 링크를 그대로 쓴 기관도 있는데(`next.config.ts`에 호스트가 등록돼 있다), 새로 담는 것은 저장소에 두는 쪽을 택한다 — 외부 링크는 어느 날 사라진다.
