### 직군 분류 주의사항: leader / commander / politician 구분

**leader(지도자)**: 종교 지도자, 사회운동 지도자만 해당한다.
- 예: 예수, 석가모니, 무함마드, 간디, 마틴 루터 킹

**commander(지휘관)**: 군사적 활동이 높거나 직접 전투에 참여한 인물. 왕·황제라도 칼을 잡았으면 지휘관이다.
- 예: 알렉산더 대왕, 칭기즈 칸, 나폴레옹, 이순신, 광개토대왕, 이성계

**politician(정치인)**: 정치 권력을 행사했으나 군사적 활동이 없는 인물. 군주·황제·왕비라도 전투 참여가 없으면 정치인이다.
- 예: 예카테리나 2세, 엘리자베스 2세, 메이지 천황, 제임스 매디슨

**판단 순서**: 군사활동 여부를 먼저 확인 → 있으면 commander, 없으면 politician. 종교·사회운동이면 leader.

## 수식어(title) 작성 가이드

- **용도**: 인물 이름 앞에 붙는 짧은 수식어
  - 예: "군주론의 마키아벨리", "철의 여인 마거릿 대처"
- **길이 제한**: 2~8자 이내로 최대한 짧게

### 우선순위 (위에서부터 적용)

1. **대표작**: 작품명 하나
   - 예: '군주론', '자본론', '코스모스'
2. **실제 호칭/별명**: 역사적 통용 호칭
   - 예: '철의 여인', '가왕', '독안룡'
3. **핵심 업적**: 가장 상징적인 것 하나
   - 예: '테슬라 창립자', '지동설'

### 금지

- 긴 설명형 문장
- 나열식 표현
- "~의 아버지/어머니" 같은 뻔한 표현

## 성별(gender) 필드 규칙

`gender` 필드는 **boolean** 타입이다.

| 값 | 의미 |
|-----|------|
| `true` | 남성 |
| `false` | 여성 |
| `null` | 알 수 없음 / 해당 없음 (논바이너리, 그룹, 불명) |

### 판단 기준

- **역사적 인물**: 문헌/기록 기반으로 명확히 판단
- **현대 인물**: 공식 프로필 또는 본인 발언 기반
- **불명확한 경우**: null로 설정

### 전 티어 공통 — 채울 수 있으면 채운다 (2026-08-06)

성별은 실존·픽션 **전 티어에서 결손으로 본다.** 원전·기록에 근거가 있으면 비우지 않는다.

- **픽션(fiction) 인물**: 서사(대표 원전)에서 성별이 명확하면 판정한다. 신·영웅·왕·요정처럼 문법·서사에서 남성/여성이 분명한 존재는 `true`/`false`를 채운다.
- **괴물·동물·집단도 원전 기준으로 판정한다** (2026-08-06 변경). 예: 케르베로스(티폰·에키드나의 아들 → true), 레르나 히드라(여성 괴물 → false). 문법적 성(gender of noun)과 서사상 역할을 근거로 쓴다.
- **성별이 정말 판정 불가한 존재만 null**로 둔다 (예: 성별 묘사가 전혀 없는 원초적 혼돈, 논바이너리로 명시된 존재).

## 작성 규칙

1. **nickname**: 정확한 풀네임을 한국어로 작성
   - 예: 슬라보예 지젝, 알베르트 아인슈타인
   - **한국에서 가장 많이 통용되는 표기를 우선한다.** 외래어 표기법(표준 음역)보다 한국 매체·검색에서 실제로 많이 확인되는 표기를 따른다. 둘이 갈리면 웹 검색으로 더 많이 쓰이는 쪽을 확인한 뒤 결정한다.
     - 예: Thomas Wolf → 표준 음역 "토마 울프"가 아니라 통용 표기 "토마스 울프"

2. **bio**: 100자 이내
   - 주어 없이 출신/직업을 짧게 서술
   - 마침표로 끊은 뒤 주요 업적 이어감

3. **nationality**: ISO 3166-1 alpha-2 국가 코드
   - 현대인이 아닌 경우 현재 해당 지역의 국가 코드로 재구성
   - 예: 알렉산더 대왕 → GR, 공자 → CN
   - 고대 국가로 특정 불가능한 경우 빈 문자열

### 국적 결손 — 전 티어에서 채운다 (2026-08-06)

국적은 실존·픽션 **전 티어에서 결손으로 본다.** 특정 불가로 쉽게 비우지 않는다.

- **실존 인물**: 출신·성장·활동 기반 국가를 ISO 코드로. 고대 인물은 현재 해당 지역 코드로 재구성(위 3번).
- **픽션(fiction) 인물**: 작품·신화 세계의 **문화적 배경 지역**을 현재 ISO 코드로 재구성한다.
  - 그리스 신화·서사 인물 → GR (제우스·헥토르·아프로디테·파리스·포세이돈·키르케 등)
  - 중국 고전(삼국지·서유기·봉신연의 등) → CN
  - 북유럽 신화 → NO (토르), 인도 서사(라마야나·마하바라타) → IN, 아서왕 전설 → GB, 길가메시 → IQ, 이집트 신화 → EG, 일본 신화(고사기·삼국유사 등은 배경에 따라) → JP/KR
  - 배경 지역을 특정할 수 없거나 신화가 초지역적(원초적 우주·혼돈 존재)이면 빈 문자열
- **집단·비인격 존재**는 원전에서 특정 배경이 있을 때만 채운다(없으면 빈 문자열).

4. **birth_date / death_date**
   - 정확한 날짜를 알 수 없으면 연도만 작성
   - 기원전은 음수로 표기 (예: -356)

### 생년 결손 조사·추정 규칙

`birth_date`는 인물 정렬·동시대 인물·연대기에서 직접 쓴다. 정확한 생년이 공개되지
않았더라도 아래 절차로 인물을 먼저 확정하고, 서비스에서 사용할 대표 추정 연도를
넣는다. 별도 추정 플래그나 테이블은 두지 않으며, 화면에서 생년값에 추정치가 포함될
수 있음을 일괄 안내한다.

1. **동명이인부터 잠근다.** 이름만으로 검색 결과를 채택하지 않는다. 프로필의 영문명,
   직군, 수식어, 소개, 국적과 기존 `wikidata_qid`를 먼저 맞춘다. 팩션 출연자는
   `faction_people → faction_clusters → faction_groups → faction_episodes`의 편·세력·직함·대사를,
   fiction은 `fiction_source_characters`의 대표 원전 연결을 신원 문맥으로 함께 본다.
2. **실존 인물은 공개값을 우선한다.** 공식 프로필·기관 기록·기업 공시·본인 발언처럼
   날짜가 명시된 출처를 우선하고, Wikidata는 QID의 인물 유형·직업·국적·활동 시기를
   프로필과 대조한 뒤 사용한다. 생년만 확인되면 연도만 저장하고 월·일을 만들지 않는다.
3. **공개 생년이 없으면 활동 연대에서 역산한다.** 특정 연도의 공개 나이, 졸업·학위,
   첫 경력, 임원 취임 같은 시간 단서를 순서대로 사용한다. 가능하면 서로 독립적인 단서
   둘 이상을 맞추고, 결과는 날짜가 아닌 대표 연도 하나로 저장한다.
4. **fiction은 실제 생일이 아니라 창작 배경 연도다.** 먼저 작품·신화 세계의 기준 사건
   하나를 잡는다. 예를 들어 일리아스 인물은 트로이 함락 추정 연도를 기준으로 삼고,
   당시 같은 세대의 전사들은 한 묶음으로 배치한다. 이후 부모·자녀, 쌍둥이, 노왕,
   젊은 영웅, 선대 신과 후대 신처럼 서사상 나이 관계가 분명한 기준 인물 몇 명을 잡아
   상대 연도를 보정한다. 여러 팩션에 나온 같은 프로필은 하나의 연도를 공유한다.
5. **적용 전후를 검증한다.** 기존 비결손 값은 별도 근거 없이 덮어쓰지 않는다. 부모가
   자녀보다 늦게 태어나거나, 쌍둥이 연도가 다르거나, 기준 사건 당시 역할과 나이가
   맞지 않는 값을 막고, 반영 뒤 서비스 대상의 `birth_date` 결손을 다시 전수 조회한다.

5. **명언**: basic 단계에서 다루지 않는다. `profiles`에는 명언 컬럼이 없다 — `quotes`·`quotes_en`은 2026-03-23 `drop_profiles_quotes_and_recreate_compat_view`로 DROP됐고, 위 JSON에 이 키를 넣으면 INSERT가 즉시 실패한다. 명언 정본은 `celeb_dialogues.lines.quote`·`lines_en.quote`이며 Speech 트랙이 작성한다 → `celeb-speech.md` §6.2

6. **문자열 처리**
   - 큰따옴표는 작은따옴표로 대체

7. **is_verified**
   - **항상 false** (공식 인증은 수동 처리)

8. **status**
   - **항상 `'inactive'`** — 신규 셀럽은 비활성 상태로 생성
   - 검수 완료 후 수동으로 `'active'`로 전환
