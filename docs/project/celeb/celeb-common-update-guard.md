# 셀럽 데이터 업데이트 가드 (공통 규칙)

모든 셀럽 데이터 수정 에이전트가 반드시 따르는 규칙.

---

## 원칙: 백지 재작성

기존 데이터를 참조하지 않는다. 매번 새로 리서치하고 새로 작성한다.

- ❌ 기존 텍스트를 읽고 "수정"하지 않는다
- ❌ 기존 텍스트를 "개선"하지 않는다
- ✅ 기존 텍스트를 무시하고 처음부터 새로 쓴다

---

## UPDATE 전 변경 검증

UPDATE SQL 실행 **직전에** 반드시 기존 데이터를 SELECT하여 비교한다.

### 절차

1. 새 텍스트 작성 완료
2. DB에서 기존 텍스트 SELECT
3. 기존 텍스트와 새 텍스트 비교
4. **완전히 동일하면 UPDATE하지 않고 SKIPPED 처리**
5. **한 글자라도 다르면 UPDATE 실행**

### 배치 처리 시

배치(CASE문 등)로 여러 건을 한번에 UPDATE할 때도 동일하게 적용한다.

```sql
-- 1단계: 기존 데이터 조회
SELECT id, nickname, consumption_philosophy
FROM profiles
WHERE id IN ('id1', 'id2', ...);

-- 2단계: 기존과 동일한 건은 CASE문에서 제외
-- 3단계: 변경된 건만 UPDATE
```

---

## 완료 보고 형식

배치 작업 완료 시 반드시 아래 형식으로 보고한다.

```
## 배치 결과 (OFFSET X ~ Y)
- UPDATED: N건 (실제 변경)
- SKIPPED: N건 (기존과 동일하여 스킵)
- FAILED: N건 (에러 발생)

### SKIPPED 목록
| nickname | 사유 |
|----------|------|
| 홍길동 | 새로 작성한 텍스트가 기존과 동일 |
```

- SKIPPED가 배치의 30% 이상이면 **경고** 표시
- SKIPPED된 건은 다음 배치에서 재시도하지 않는다 (같은 결과가 나올 가능성이 높다)
