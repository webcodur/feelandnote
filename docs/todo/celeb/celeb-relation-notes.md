# 인물 관계 설명 채우기

탐색 허브의 관계망 구획을 운영에 열려면 `celeb_relations.note`의 빈자리를 메워야 한다.
관계 자체는 충분히 쌓였고 설명만 모자란다.

관계 테이블 규격은 [`docs/project/data/db-celeb.md`](../../project/data/db-celeb.md),
화면은 [`docs/project/service/explore.md`](../../project/service/explore.md)의 「관계망」이 쥔다.

## 남은 몫

2026-08-27 실측. 양끝이 모두 노출 가능한(공개·`full`/`light`·slug·얼굴) 간선만 셌다.

| 묶음 | 설명 있음 / 전체 | 남은 건수 |
|---|---:|---:|
| 맞선 (rival) | 842 / 842 (100%) | 0 |
| 함께한 (colleague·cofounder) | 2,866 / 2,932 (98%) | 66 |
| 영향·사제 (influence·teacher) | 1,622 / 1,810 (90%) | 188 |
| **가족 (family)** | **0 / 240 (0%)** | **240** |

관계를 가진 인물 2,201명 중 이웃 설명이 전부 있는 인물이 82%, 하나도 없는 인물이 3%다.
전체 비율은 나쁘지 않으나 **어느 인물을 여느냐에 따라 빈칸만 보이는 판이 나온다** —
첫 화면에 서던 아리스토텔레스가 받은 관계 넷 중 셋이 빈칸이었다.

## 채우는 규칙

- 방향 규약은 원장과 같다: `rel_type`은 "to_id가 from_id에게 무엇인가"다.
- 설명은 **받은 사람 시점**으로 쓴다. 사슬과 탐색기가 물려받은 자취를 따라가므로
  그 시점이 다음 인물로 넘어가는 문장이 된다. 원장에 양방향 두 행이 있으면
  화면은 받은 사람 시점 행을 골라 쓴다(`influenceChains.ts`의 `RECEIVER_VOICE`).
- `note`(한국어)와 `note_en`(영문)을 짝으로 넣는다. 한쪽만 넣지 않는다.
- 수동 보강은 반드시 `source='manual'`로 저장한다. `celeb/relations.ts` 재수집은
  `source='wikidata'` 행만 갈아끼우므로 manual 행은 보존된다.
- 웹에서 독립적으로 팩트체크한다. 대본이나 3자 큐레이션 해석만으로 채우지 않는다.

## 가족을 먼저 볼 것

가족 240건은 한 건도 없다. 위키데이터 속성 수집으로 관계만 받아 왔고 근거 문장을 만든 적이
없기 때문이다. 다만 가족은 관계 유형(아버지·배우자·형제) 자체가 정보라 화면에서
배지만으로도 읽힌다 — 설명이 없어도 다른 묶음만큼 허전하지는 않다.
그래서 채우는 값이 가장 큰 쪽은 **영향·사제 188건**이다. 여기가 비면 사슬의 고리가 말을 잃는다.

## 다 채운 뒤

`sw/web/src/app/[locale]/(main)/explore/page.tsx`의 `RELATION_MAP_ENABLED` 한 줄을 지우면
운영에 공개된다. 그때 퍼지 분류도 함께 옮겨야 한다 — 관계망 파일들이 지금은
`cloudflare-purge-impact.mjs`의 `NON_HTML_RUNTIME_FILES`에 있는데, 탐색 허브가
Cloudflare 보관 대상이 되거나 관계망이 인물 상세로 옮겨 가면 `celeb`으로 올려야 한다.
