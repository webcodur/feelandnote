# 셀럽 아바타 규격 SSoT

인물 얼굴 이미지(`celebs.avatar_url` → R2 `celebs/{id}/avatar.webp`)의 **프레임 기하·안전 영역·발주 프롬프트·판정 기준**을 정한다.
파일 크기·포맷·업로드 경로는 `docs/project/db-celeb.md` 「셀럽 이미지 규격」, 등록 자동화는 `.agents/skills/celeb-avatar-register/SKILL.md`가 각각 SSoT다. 여기는 **한 장의 그림이 어떻게 생겨야 하는가**만 다룬다.

최초 작성 2026-08-01. **지금 등록된 이미지를 소급 교체하지 않는다** — 신규 생성·재생성·재크롭분부터 적용한다.

---

## 0. 왜 규격이 필요한가 (2026-08-01 실측)

현재 얼굴 크기와 위치가 제각각인 것은 사람의 실수가 아니라 **구조가 그렇게 돼 있어서**다.

| 갈래 | 실측 |
|------|------|
| 크롭 구현 벌 수 | 6벌 (`upload-celeb-avatar.ts` · `batch-celeb-avatars.ts` · `crop-faces.ts` · `src/utils/faceDetection.ts` · 폐기 2벌) |
| 얼굴 비율 상수 | 3종 — `0.45` / `2.2배(=0.4545)` / `0.55` |
| 세로 기준점 | 3종 — 얼굴 상자 중심을 정중앙 / 정수리 여백 기준 상단 고정 / 콧대 지점을 정중앙 |
| 얼굴 검출 모델 | 2종 — 서버 SSD MobileNet v1, 관리자 화면 TinyFaceDetector (상자 규약이 달라 같은 비율값이 같은 결과를 내지 않는다) |
| 생성 프롬프트의 축 | 크롭과 다른 축 — "머리 높이가 화면 높이의 55~65%" (크롭은 "눈썹~턱 상자 큰 변이 화면의 45%") |
| 최근 교체분 | 검출을 끄고(`--face-detect false`) 사람이 눈으로 좌표를 찍은 건이 다수 |
| 검출 실패 시 | 중앙 크롭이 아니라 entropy 크롭 — 얼굴 위치가 사실상 무작위 |
| 잔존 레거시 | 2026-03-24 이전 등록분 300×300, 상단 정사각(`left:0, top:0`)으로 잘렸다 |

**측정 대상과 세로 기준점을 통일하지 않으면 어느 상수를 고쳐도 통일되지 않는다.** 아래 §1이 그 통일된 기준이다.

### 0.1 등록분 표본 실측 (2026-08-01, 36명)

활성 인물 중 무작위 36명을 내려받아 §1 기준선을 겹쳐 눈으로 판정했다. **어긋남이 한쪽으로 쏠려 있다.**

| 항목 | 실측 |
|------|------|
| 턱 아래가 비어 인물이 떠 보이는 것 | 36명 중 **1명** — 대부분 옷깃·머리카락·어깨가 아래를 채우고 있다 |
| 얼굴이 규격보다 크고 아래로 내려앉은 것 | **대다수** |

> 이때 머리 꼭대기·머리 장식이 화면 위에 닿거나 잘린 것을 11명(31%)으로 세었으나, **이후 규격에서 머리 위는 자유로 바꿨다**(§1). 지금 기준으로는 결함이 아니다.

이어서 다른 60명을 판정 도구로 쟀다.

```
npx tsx scripts/measure-avatar-geometry.ts <이미지폴더>
```

| | 규격 | p10 | 중앙 | p90 |
|---|:---:|:---:|:---:|:---:|
| 눈높이 | 46 | 39.2 | **44.0** | 48.7 |
| 턱끝 | 81 | 70.4 | **78.0** | 85.0 |

**규격 합격 32명 / 60명 (53.3%).** 어긋난 쪽은 대체로 얼굴이 규격보다 **작은** 경우다.

> ⚠️ **처음에는 이 표를 정반대로 읽었다.** 당시 규격이 턱끝 70이어서 합격은 5명(8.3%)뿐이었고, "얼굴이 규격보다 크게 잘렸다"고 판정했다. 그러나 규격 쪽이 틀렸다 — 실물에서 뽑지 않은 숫자였다(§1 「이 숫자는 어디서 왔나」). 지금 기준으로는 절반이 합격이고, 문제는 큰 얼굴이 아니라 작은 얼굴이다.

> 머리 높이는 이 도구가 재지 않는다. 랜드마크에 정수리가 없어서인데, 규격에서도 머리 위를 자유로 뒀으므로 잴 필요가 없다(§1).

### 새 규칙으로 자르면 어떻게 되는가

**기하가 규격대로 나오는지만** 검증했다. 원본으로는 대표 사진 12장을 썼다 — 얼굴 주변 여백이 넉넉한 원본이 필요했기 때문이다. 눈높이가 43.0~44.9로 좁게 모였다(등록분은 39.2~48.7). **자르는 규칙이 값을 정확히 재현한다는 것**이 여기서 확인된 것이고, 그 값 자체는 이후 실물 기준으로 다시 잡았다(§1).

이탈 3장의 사유가 규칙의 한계를 보여준다.
- 1장(마크 베니오프) — 원본에서 얼굴이 위쪽 가장자리에 붙어 좌표가 밀렸다. **경고가 정확히 예고했다.**
- 2장(엥겔스·주희) — 인물이 고개를 크게 숙여 눈-턱 거리가 실제보다 길게 잡혔다.

즉 **고개를 숙이거나 든 자세에서는 눈-턱 기준이 흔들린다.** §3이 정면 응시를 고정하는 또 하나의 이유다.

> 이 표본으로 시선·소품·복식 같은 **연출을 평가하지 않았다.** 대표 사진은 인물이 활동하는 모습을 담는 별개 자산이라(`hero-photo-status.md`) 아바타 연출 규격의 대상이 아니다. 여기서 확인한 것은 자르는 규칙이 기하를 맞추는가 하나뿐이다.

### 머리 장식은 기계가 모른다 — 그래서 규격에서 뺐다

갓·관·왕관·티아라를 쓴 인물은 얼굴 위로 장식이 크게 올라가는데, 얼굴 검출과 랜드마크는 그것을 전혀 보지 못한다. **자동으로 자르는 한 보장할 수 없다.** 보장할 수 없는 것을 규격으로 두면 계속 불합격만 쌓인다. 그래서 머리 위는 자유로 뒀다(§1).

### 기존 이미지는 대개 다시 자를 수 없다

등록된 아바타는 이미 잘린 결과물이라 원본이 없다. 더 당길 수는 있어도 **빼는 것은 불가능하다** — 없는 화면을 만들 수 없기 때문이다.

시험 실측(2026-08-01, 좌우 치우침 7명): 재크롭이 통한 것은 **2명뿐**이고 5명은 얼굴이 이미 화면 가장자리에 붙어 옮길 여백이 없었다. **고치는 절차는 §5.5**에 있다.

원인이 코드와 맞아떨어진다. 옛 크롭 코드가 얼굴 상자 중심을 화면 정중앙에 놓고 상자의 2.2배로 잘랐으므로, 얼굴 위치가 사람마다 흔들리고 가장자리에 붙는 일이 잦았다. 사람이 눈으로 좌표를 찍은 건도 같은 감각으로 잘렸다.

> 위 36명·60명은 표본이다. 활성 1,550명 중 누가 어디에 해당하는지는 **미확인**. 전수 판정 방법은 §5.1.

### 0.2 등록 경로 지도 — 지금 살아 있는 길과 막힌 길

한 장의 얼굴이 서비스에 오르는 길이 **11갈래**였고 그중 7갈래가 아직 살아 있다. 길마다 자르는 방식이 다르다.

**2026-08-01 정비 후** — 살아 있는 길은 전부 §6의 같은 규칙을 쓴다.

| 경로 | 자르는 방식 | 상태 |
|------|------|------|
| 위키미디어 일괄 | 눈·턱 기준(공용 구현), 품질 95 | 살아 있음. 검증된 QID가 있을 때만 |
| 단건 등록 (Commons·임의 URL·로컬 파일) | 눈·턱 기준(공용 구현), 품질 95 | 살아 있음. **정본**. 신원 근거 필수 |
| 세력도감 개인샷 승격 | 위와 같음 | 살아 있음. 신화·허구 인물만, 사람이 한 명씩 |
| 관리자 화면 업로드 | 눈·턱 기준(같은 구현)으로 자동 제안 → 사람이 손으로 조정 | 살아 있음. **유일하게 사람이 직접 맞추는 길** |
| 생성 후 등록 | 자르지 않음. 발주 프롬프트가 기하를 정함 → 배경 지우기 → 단건 등록 | 살아 있음 |
| 얼굴 정사각 전처리 도구 | 눈·턱 기준(공용 구현), PNG 출력 | 살아 있음. 위 경로의 재료 준비용 |
| 자동 웹 검색 등록 / 세력도감 일괄 승격 | — | **막힘**(실행 시 거부) |
| 옛 저장소 이전 | 상단 정사각 → 300×300 | 과거 1회성. 결과물이 아직 섞여 있다 |

### 정비 전에 괴상했던 것 넷 — 셋은 해결

1. ~~얼굴을 못 찾으면 아무 데나 자르고 성공으로 쳤다~~ → **해결.** 엔트로피 폴백을 없앴다. 단건은 업로드 전에 실패하고, 일괄은 그 인물만 실패로 집계한다. `--allow-no-face true`를 명시해야만 중앙 크롭으로 진행하며 그때도 경고를 남긴다.
2. ~~관리자 화면이 같은 그림을 두 번 재인코딩했다~~ (0.9 → 0.85) → **해결.** 중간을 무손실로 넘기고 마지막 한 번만 0.95로 인코딩한다.
3. ~~길마다 화질이 달랐다~~ (85 / 88 / 95 / 100) → **해결.** 아바타는 전부 95다.
4. **관리자 화면과 서버가 서로 다른 얼굴 검출 모델을 쓴다** — 이건 그대로다. 다만 §6이 눈·턱을 직접 재는 방식이라 **모델이 달라도 같은 결과가 나온다.** 상자 배율을 쓰던 시절에만 문제였다.

## 1. 프레임 기하 — 100 단위 정규화

정사각 화면의 **왼쪽 위 모서리를 원점**으로, 가로·세로를 각각 100단위로 본다. 800×800 파일이면 1단위 = 8px다.

```
   0                    50                   100  (가로)
 0 ┌─────────────────────┬─────────────────────┐
   │   머리카락·모자·투구는 여기 닿거나 넘어도 된다  │
   │           /                    \           │
   │          |                      |          │
46 │ ─────── ●───────────┼───────────● ──────── │ 눈높이 (양 눈동자)
   │          |                      |          │
   │           \                    /           │
81 │            ▔▔▔▔ 턱끝 ▔▔▔▔                  │
   │      목 · 옷깃 · 갑옷 · 머리카락 — 무엇이든    │
100└─────────────────────┴─────────────────────┘
```

**새로 만들 때 겨냥하는 자리 — 이 셋이 목표다.**

| 항목 | 목표 |
|------|:---:|
| **눈높이** (양 눈동자 연결선) | **46** |
| **턱끝** | **81** |
| 얼굴 세로 중심축 (콧대) 가로 위치 | **50** |

**이미 있는 것을 재작업할지 가르는 선은 이것 하나뿐이다.**

| 항목 | 불합격 |
|------|:---:|
| 얼굴 중심축이 좌우로 밀림 | 45 미만 또는 55 초과 |

세로 위치에도 값이 있지만 **극단만 거르는 안전망**이고 얼굴 크기를 판정하지 않는다 — 눈높이 20~65, 턱끝 50~98. 얼굴이 점이 되거나 턱이 화면 밖으로 나가는 수준만 걸린다.

> **얼굴 크기는 판정하지 않는다.** 목표에서 벗어나도 그 자체로는 흠이 아니라는 것을 두 번 실측으로 확인했다(§5.1). 세로 위치는 극단만 거르는 안전망으로 남겨 뒀고, 얼굴이 크거나 작은 것·잘린 것·상반신이 들어온 것은 **전부 눈으로 본다.**

**눈에서 턱까지 35** — 이것이 얼굴 크기를 정한다. 위 둘의 차이일 뿐 별도 항목이 아니다.

### 숫자 말고 말로 하면

- **눈이 화면 딱 중간 높이에 온다.**
- **턱이 위에서 5분의 4 지점에 온다.**
- **턱 아래로 남는 5분의 1**을 목이든 옷깃이든 갑옷이든 수염이든 무엇이 채운다.
- 얼굴은 좌우 정중앙.

한마디로 **얼굴이 화면을 꽉 채우고 아래 5분의 1만 목 자리로 남는다.** 머리 위가 넘치는 것은 신경 쓰지 않는다.

### 머리 위는 자유다

**머리카락·모자·투구·왕관·갓이 화면 위 모서리에 닿거나 넘어가도 무방하다.** 이유는 셋이다.

- 원형으로 잘리면 위쪽 모서리는 어차피 사라진다. 머리끝이 화면에 닿아도 원형 안에서는 자연스럽다.
- 머리 장식을 다 담으려면 카메라를 빼야 하고, 그러면 얼굴이 작아진다. 20~40px에서는 얼굴 식별이 우선이다.
- 얼굴 검출은 머리 장식을 보지 못한다. 자동으로 자르는 한 어차피 보장할 수 없다.

**다만 얼굴 자체가 잘리면 안 된다.** 이마·눈썹·귀가 화면 밖으로 나가면 불합격이다. 잘려도 되는 것은 머리카락과 머리에 쓴 물건뿐이다.

### 목 아래도 자유다

**턱 아래를 무엇이 채우든 무방하다.** 맨 목이 조금 보이든, 옷깃·러프·관복 깃이 목을 덮든, 투구의 목가리개나 갑옷 어깨보호구가 가리든, 긴 머리카락이 덮든 상관없다. 목 아래가 거의 안 보여도 된다.

> 근거: 소개 화면(`/about`)에 세운 8명 중 **목 아래 어깨가 드러난 사람이 하나도 없다.** 이순신·광개토대왕은 투구 어깨보호구, 셰익스피어는 러프 칼라, 세종·정약용은 관복 깃, 뉴턴·제퍼슨은 어깨를 덮은 긴 머리다. 그런데 여덟이 나란히 놓여도 어색하지 않고, 오히려 목 주변의 장비가 인물의 시대와 신분을 말해 준다.

애초에 얼굴이 이 규격만큼 크면 목 아래가 거의 남지 않는다. **어깨선을 확보하려고 카메라를 빼지 마라.** 그러면 얼굴이 작아져 손해다.

**막는 것은 하나뿐이다** — 쇄골과 가슴이 드러나 상반신이 길어지는 것. 그렇게 되면 인물이 작아지고 목록에서 혼자 튄다.

### 얼굴이 없는 인물 — 규격 밖이다

신원이 공개되지 않아 얼굴 자료가 아예 없는 실존 인물이 있다. **사토시 나카모토**, **클로윈디** 같은 경우다. 이들의 아바타는 얼굴 대신 익명성 자체를 형상화한다 — 후드 속 어둠, 복면과 고글 같은 식이다.

여기에는 §1의 눈높이·턱끝·콧대를 적용할 수 없다. 잴 얼굴이 없다.

| | 얼굴 없는 인물에게 |
|---|---|
| 눈높이 46 · 턱끝 81 · 콧대 50 | **면제** |
| 정면, 한 명, 소품·글자 없음, 쇄골·가슴 안 보이기 | **그대로 지킨다** |
| 머리 윤곽 | 프레임 안에 들어오되, 후드·복면이 위로 잘리는 것은 머리 장식과 같이 본다 |

**얼굴 크기는 다른 아바타와 나란히 놓았을 때 튀지 않는 정도로 사람이 맞춘다.** 목록에서 이 인물만 머리가 크거나 작으면 그것이 결함이다.

**등록 경로가 다르다.** 자동 크롭은 얼굴을 못 찾아 실패한다(§0.2). 관리자 화면에서 사람이 직접 맞춰 올리거나, 단건 등록에 `--allow-no-face true`를 명시해야 한다. 실측(2026-08-01)으로 두 인물 모두 얼굴 미검출을 확인했다.

**판정 도구가 "얼굴 미검출"을 뱉어도 결함이 아니다.** 이 인물들은 애초에 기계 판정 대상이 아니다. 미검출 목록을 훑을 때 이들을 재작업 대상으로 올리지 마라.

### 이 숫자는 어디서 왔나

> **계산에 쓰이는 값의 원천은 코드다** — `sw/web-bo/src/lib/avatar-geometry.ts`의
> `AVATAR_SPEC`. 크롭·판정·업로드가 그 값을 읽는다. 아래는 그 숫자가 **어느 표본에서
> 나왔는지**를 남긴 근거이며, 값을 바꿀 때는 코드를 고치고 이 절의 설명을 함께 갱신한다.

**이상적인 아바타 규격이 아니라, 이 서비스에서 좋다고 판정된 실물에서 뽑았다.**

기준 표본은 소개 화면(`/about`)에 세운 8명이다 — 세종·셰익스피어·이순신·뉴턴·광개토대왕·프랭클린·정약용·제퍼슨. 서비스 얼굴로 골라 놓은 인물들이고 나란히 놓았을 때 통일감이 좋다.

| | 8명 실측 | 채택한 목표값 |
|---|:---:|:---:|
| 눈높이 | 41.4 ~ 49.6 (중앙 46.3) | **46** |
| 턱끝 | 75.0 ~ 85.4 (중앙 81.3) | **81** |
| 콧대 가로 | 45.9 ~ 50.6 | **50** |

> 이 표는 **목표값의 출처**다. 판정 허용 범위가 아니다 — 실측 폭을 그대로 허용선으로 삼았다가 폐기했다(§5.1).

> ⚠️ **처음에는 눈 44 / 턱 70으로 잡았다가 뒤집었다.** 여권 사진류의 이상적 수치에서 온 값이었고, 그 기준으로는 위 8명이 **전원 불합격**이었다. 등록분 60명의 턱끝 중앙값이 78로 나왔을 때도 "규격보다 크게 잘린 결함"으로 판정했으나, 실은 그쪽이 이 서비스의 표준이었다. **실물을 재기 전에 정한 숫자로 실물을 판정하면 안 된다.**

- **눈높이 46 — 정중앙보다 살짝 위.** 원형으로 잘려도 시선이 안정적으로 앉는 자리다.
- **눈에서 턱까지 35 — 이것이 얼굴 크기를 정한다.** 머리끝이나 어깨를 기준으로 삼지 않는 이유는 위 두 절에 있다. 눈과 턱은 기계가 직접 잴 수 있고 옷·장비에 가려지지 않는다.

## 2. 안전 영역 — 실제로 잘려나가는 부분

아바타는 **정사각 그대로 보이는 일이 거의 없다.** 화면 조사 실측 기준으로 세 겹의 잠식이 있다.

### 2.1 원형 마스크 (거의 모든 화면)

공용 얼굴 컴포넌트가 원형을 강제한다. **정사각 네 모서리, 곧 넓이의 21.5%가 상시 잘린다.**

- 안전 반지름은 47단위(중심 50,50 기준)로 본다 — 테두리·링이 겹치는 몫을 뺀 값이다.
- §1 배치는 이 안에 들어온다: 눈은 원 중심에서 4, 턱은 31 떨어져 있다.
- **위쪽 모서리는 신경 쓰지 않는다.** 모자 챙·왕관 뿔·머리카락이 잘려도 무방하다(§1). 어차피 원형에서 사라지는 자리다.
- **아래쪽은 무엇으로든 채워져야 한다.** 옷깃이든 갑옷이든 머리카락이든 어깨든, 턱 아래가 비면 원형 안에 머리만 떠 보인다.

### 2.2 세로 직사각 잘림 (게임 화면 일부)

초상 맞히기 4:5, 새벽 게임판 3:4, 유랑 인물 카드 220×290 — 정사각을 넣으면 **좌우가 각각 10~12.5% 잘린다.**

- 가로 12 ~ 88 구간이 어디서든 살아남는 영역이다.
- §4.1이 발주 프롬프트에서 **양쪽 귀를 가로 28~72 안에 두라**고 하는 근거가 이것이다. 귀와 머리카락 실루엣이 그 안에 있으면 어느 화면에서도 얼굴이 온전하다.
- 가로로 긴 직사각으로 잘라 쓰는 곳은 확인되지 않았다(썸네일은 여백을 채우는 방식이라 잘리지 않는다).

### 2.3 테두리·링

거의 모든 표시처가 2~3px 테두리를 덧대고, 인물 상세의 아바타 레일은 안쪽 여백 6px + 테두리 3겹으로 **반지름의 약 12%를 더 먹는다.** 안쪽으로 파고드는 링을 쓰는 곳도 두 군데 있다. §2.1의 안전 반지름 47은 이 몫을 반영한 값이다.

### 2.4 크기 범위

가장 작게는 20px(공유 서재 목록), 가장 크게는 영상 원형 440px과 썸네일·카드뉴스 전면(1080~1280px)이다.

- **20~40px에서 읽혀야 한다** — 얼굴이 작게 박히면 아무것도 보이지 않는다. §1이 머리끝이 아니라 눈-턱으로 얼굴 크기를 정하는 것도, 머리 위를 자유로 둔 것도 이 요구에서 나왔다.
- **800px 원본이 1280px로 늘어나는 경로가 있다.** 잔존 300×300 레거시는 이 경로에서 뭉갠다. 재작업 우선순위의 근거다.

## 3. 고정할 것과 인물마다 다르게 할 것

`docs/project/image-generation.md` §5.2가 "아바타 발주서 골격을 고정하지 마라"고 금지한 것은 **연출을 찍어내는 것**이다. 프레임 안의 기하는 규격이므로 고정한다. 둘을 갈라 쓴다.

| | 항목 |
|---|---|
| **전원 고정** | §1의 모든 기하 · 정면~3/4 15도 이내 · 카메라 응시 · 한 명만 · 소품 없음 · 글자 없음 · 목을 덮는 옷깃 · 21세기 카메라로 찍은 컬러 사진 질감 |
| **권장** | 인물의 **전성기** 얼굴(§4.3.1) — 불합격 사유는 아니다 |
| **인물마다 다르게** | 조명 방향과 색온도(측광·반역광·창가 자연광·부드러운 정면광 등) · 표정(차분~미소 사이) · 복식 · 얼굴 크기(§4.3의 세 값 중 택일) · 3/4 회전 방향과 각도(0~15도) · 배경 색조(누끼를 뜨면 사라지지만 머리카락 경계 품질에 영향) |

정면 응시를 고정하는 이유는 취향이 아니라 기능이다 — 20~40px 원형에서 옆모습은 얼굴이 읽히지 않고, 세로 직사각 잘림에서 옆얼굴은 화면 밖으로 밀린다. **"증명사진 떼샷" 느낌은 조명·복식·표정으로 깬다.**

## 4. 발주 프롬프트 확정본

생성 도구에 그대로 넣는 블록이다. 인물 묘사는 넣지 않는다(얼굴 참조 이미지가 신원을 정한다 — `image-generation.md` §6).

### 4.1 프레이밍 블록 (전원 동일, 수정 금지)

```
FRAMING — TIGHT HEAD-AND-SHOULDERS PORTRAIT, FIXED GEOMETRY
Do NOT copy the reference image's crop, framing, camera angle, gaze direction or
background. Take only the person's identity from the reference. Everything below
overrides the reference.

Square 1:1 frame. Read the frame as 100 units wide and 100 units tall, measured
from the top-left corner.
- The eye line, an imaginary line through both pupils, sits 46 units below the
  top edge, slightly above the middle of the frame.
- The chin sits 81 units below the top edge. The distance from the eye line to
  the chin is therefore 35 units. This is what sets the size of the face, and it
  makes the face fill most of the frame. This is deliberate.
- The vertical centre line of the face, the bridge of the nose, sits at 50 units
  across, dead centre. The head is never pushed to one side.
- Hair, a hat, a helmet, a crown or any headdress MAY touch or run past the top
  edge. Do not pull the camera back to fit them in, and do not shrink the face
  to leave room above the head. Losing the top of the hair is fine.
- The face itself is never cut. The forehead, both eyebrows and both ears stay
  inside the frame.
- Below the chin, whatever is there is fine: a little bare neck, a high collar, a
  ruff, a robe, the neck guard of a helmet, pauldrons, or long hair falling over
  the shoulders. The shoulders do not need to be visible at all. Do NOT pull the
  camera back to fit the shoulders in.
- The collarbone and the chest are NOT visible, and the torso is never long. The
  garment closes high around the neck.

This image is displayed inside a circular mask that removes the four corners, and
is sometimes cropped to a narrow vertical rectangle that removes the outer 12
percent of each side. Keep the face and both ears well inside those limits. The
top corners are cut away, so anything above the head is expendable.

Head-on frontal view, or at most a fifteen degree three-quarter turn. The person
looks directly into the camera. Not a profile, not a high angle, not a low angle.
Exactly one person. No hands, no microphone, no headset, no book, no ball, no
weapon, no props of any kind. No legible text, lettering or signage anywhere.
```

### 4.2 질감 블록 (전원 동일)

```
RENDERING — THIS IS A PHOTOGRAPH, NOT A PAINTING, NOT A DRAWING, NOT A SCULPTURE
Ultra-photorealistic photograph shot on a modern 21st century full-frame camera.
Even if the reference is a painting, an ink drawing, a statue, a coin or an old
low-resolution photo, the result is a real photograph of a living person.
No painterly brushwork, no ink lines, no illustration, no digital painting, no
CGI render, no wax-figure look.
Full color photograph. Rich, natural, lifelike color — never black and white,
never sepia, never monochrome or desaturated.
```

배경은 이 블록에서 다루지 않는다. 아래 연출 변주에 딸린 스타일 지시(`Clean background, slightly blurred`)가 맡는다.

밀랍 인형이 되는 것을 막으려면 `Photorealistic`·`Bold cinematic`·`f/1.4`·`lens flare`를 겹쳐 쓰지 않는다(`image-generation.md` §1-9).

> ⚠️ **회화·도상 REF는 그대로 넣으면 캐리커처가 된다**(2026-08-02 실측). 전통 초상화를 REF로 재생성한 중국 고전 인물 7명이 전부 움푹 꺼진 뺨·처진 가는 수염·험악한 눈매·밀랍 질감으로 **서로 닮은 과장 얼굴**이 됐다 — 모델이 회화의 양식화를 실존 인물의 생김새로 읽고 증폭한다. 여성은 성별까지 뒤집힌 예가 있다(서태후). 대응 두 가지를 발주서에 함께 넣는다. ① 양식 복제 차단 — "회화의 양식화를 복제하지 말고 평범하고 자연스러운 실제 사람으로" 명시. ② **인물 기록에 맞는 나이·체형·수염·인상을 개별 지정** — 회화 REF는 신원 고정력이 약해 이 정도 묘사가 허용되며, 없으면 배치 전체가 같은 틀로 수렴한다. 실물 사진이 남은 인물은 그쪽을 REF로 쓰는 것이 우선이다.

### 4.3 연출 변주 블록 (인물마다 하나씩 골라 기입)

배치 발주 시 **인물별로 미리 정해 발주서에 개별 기입한다.** 돌려막지 않는다.

조명 — 부드러운 정면 키라이트 / 측광(한쪽 뺨에 그림자) / 반역광(머리카락 테두리에 빛) / 창가 자연광 / 낮은 색온도 실내광 / 높은 색온도 흐린 날 빛
얼굴 크기 — 턱끝 77 / 81 / 85 중 택일 (눈높이 46은 고정)
회전 — 정면 0도 / 왼쪽 8도 / 오른쪽 8도 / 왼쪽 15도 / 오른쪽 15도
복식 — 인물의 시대·직군에 맞되 반드시 목 아래를 덮는 옷깃

**표정은 새로 만들 때 차분함과 미소 사이에서 고른다.**

```
차분·평온 ────── 옅은 미소 ────── 미소
        ↑ 이 구간 안에서 인물마다 다르게
```

- **미소를 금지하지 마라.** 발주서에 `no smile` 같은 문구를 임의로 넣지 않는다. 온화한 얼굴은 이 범위 안이다.
- 인물의 성격에 맞는 지점을 고르되, 배치 발주에서 한 지점으로 통일하지 않는다.

> ⚠️ **표정은 판정 항목이 아니다.** 위는 새로 만들 때 겨냥하는 범위일 뿐이고, **이미 등록된 이미지를 표정 때문에 교체하지 않는다.** 크게 웃어 이가 드러나거나 입이 벌어진 것도 결함으로 세지 않는다.
>
> 2026-08-01 테스트에서 발주서에 `no smile`을 임의로 넣어 무표정을 강제한 일이 있다. 규격에 없는 제약이었다.

### 4.3.1 어느 시기의 얼굴인가 — 전성기를 권장한다

**그 인물이 알려진 이유가 된 시기의 얼굴**을 기본으로 삼는다. 업적을 남긴 무렵, 활동이 절정이던 때다.

- 말년의 노쇠한 모습이나 무명 시절의 얼굴은 피한다. 목록에서 그 사람을 알아보기 어렵다.
- 인물마다 그 시기가 다르다 — 창작자는 대표작을 낸 무렵, 지휘관은 주요 전역을 치른 무렵, 학자는 대표 연구를 낸 무렵.
- **자료가 그 시기 것밖에 없으면 그것을 쓴다.** 없는 얼굴을 지어내는 것보다 낫다.

**권장이지 불합격 사유가 아니다.** 남은 자료가 말년 사진뿐인 인물이 많고, 그것 때문에 재작업하지는 않는다. 새로 만들거나 원본을 고를 때 이 쪽을 택하라는 뜻이다.

### 4.4 출력 지정

```
Output size: exactly 1024 x 1024 pixels, square 1:1.
```

1024로 뽑아 800으로 줄인다(1.28배 여유). 더 키워도 얻는 게 없다.

## 5. 검수와 재작업

검수는 **두 단계**다. 수치로 한 번 거르고, 그다음 이미지를 직접 본다. 두 번째가 본체다.

| | 무엇을 잡나 | 수단 |
|---|---|---|
| 1단계 | 얼굴이 좌우로 밀린 것 | `measure-avatar-geometry.ts` |
| 2단계 | **그 밖의 전부** — 상반신 유입·시선·잘림·배경·질감 | `build-avatar-contact-sheet.ts`로 격자를 만들어 직접 본다 |

### 5.1 1단계 — 수치로 거른다

```
npx tsx scripts/measure-avatar-geometry.ts <이미지폴더>
npx tsx scripts/measure-avatar-geometry.ts --from-db --offset 0 --limit 200
```

이미지마다 눈높이·턱끝·얼굴 중심축을 재고 §1 허용 범위와 대조해 합격·이탈을 찍는다. 판정 수치는 `src/lib/avatar-geometry.ts` 하나에서만 온다.

`--from-db`는 등록된 아바타를 직접 받아 판정한다. 전수 검수용이며 1,500명 규모라 200명씩 나눠 돈다.

**"얼굴 미검출"이 곧 결함은 아니다.** 사토시 나카모토·클로윈디처럼 얼굴이 없는 것이 정상인 인물이 있다(§1). 미검출 목록을 재작업 대상으로 옮기기 전에 그 인물이 여기 해당하는지 먼저 본다.

**이 도구가 실제로 잡는 것은 좌우 치우침 하나뿐이다.** 얼굴 크기 판정은 두 번 시도했다가 둘 다 폐기했다.

**① 턱끝 하한 — 상반신 유입과 구분되지 않았다**

| 인물 | 턱끝 | 실제 |
|---|:---:|---|
| 소 아이아스 | 68.4 | 정상 — 목까지만 나온다 |
| 모리타 아키오 | 67.4 | **불량** — 양복 깃과 넥타이가 넓게 |
| 알키비아데스 | 71.3 | 정상 — 목까지만 나온다 |
| 히치콕 | 73.1 | **불량** — 양복과 어깨 |

얼굴이 작은 것 자체는 흠이 아니다. 턱 아래에 **무엇이** 보이는가가 가르는데 수치는 그걸 모른다.

**② 턱끝 상한 — 오탐만 만들었다**

86을 넘겨 걸린 7명(링컨 88.3 · 알렉스 카프 89.4 · 쿠로사와 88.2 · 알 파라비 87.5 · 아인슈타인 86.2 · 에이다 러브레이스 86.5 · 앨런 튜링)을 눈으로 보니 **전원 멀쩡했다.** 소개 화면 8인과 같은 느낌이고 흠이 없다. 86이라는 선은 그 8인의 최대치(85.4)에서 억지로 뽑은 값이었을 뿐이다.

**진짜 얼굴 잘림은 랜드마크가 알려주지 못한다** — 잘린 얼굴에서도 좌표를 추정해 뱉기 때문이다. 이마가 화면 밖으로 나가도 수치는 멀쩡하게 나온다.

**그 밖에 못 보는 것**

| 못 보는 것 | 왜 |
|---|---|
| 이마·눈썹·귀가 화면 밖으로 잘렸는지 | 얼굴 윤곽이 프레임을 넘는지 판단하지 않는다 (머리카락·머리 장식 잘림은 규격상 무방) |
| **고개 숙임·들기, 눈 감김, 시선 이탈** | 얼굴이 어디를 향하는지 판단하지 않는다 |
| 턱 아래가 비어 인물이 떠 보이는지, 쇄골·가슴 노출 | 목 아래를 보지 않는다 |
| 소품, 손, 두 명 이상, 글자 | 얼굴 밖을 보지 않는다 |
| 배경, 질감, 회화 티, 흑백 | 색과 재질을 보지 않는다 |

**연출과 기하는 따로 어긋난다.** 실측 예 — 등록된 에블린 글레니 아바타는 연출이 규격대로(정면 응시·눈 뜸·단정한 목선)인데 기하가 눈높이 50.0 / 턱끝 87.3으로 크게 벗어났다. 얼굴이 규격보다 훨씬 크게 잘려 목 아래가 전혀 없다(머리카락이 위에 닿은 것은 무방하다). 반대로 기하만 맞고 시선·소품이 어긋난 경우도 얼마든지 통과한다. **둘 중 하나만 보면 나머지 절반을 놓친다.**

그러므로 기계는 1차 체일 뿐이고, 합격분도 반드시 2단계를 거친다.

### 5.2 2단계 — 격자로 직접 본다

```
npx tsx scripts/build-avatar-contact-sheet.ts --out <출력폴더> --limit 36
npx tsx scripts/build-avatar-contact-sheet.ts --out <출력폴더> --slugs a,b,c
```

등록된 아바타를 내려받아 §1 기준선(눈 46 · 턱 81 · 중심축 50)을 겹친 격자로 묶고, 칸 번호와 인물의 대응표를 함께 낸다. 30~40명을 한 번에 판정할 수 있다.

**이 그림을 AI나 사람이 직접 보는 것이 검수의 본체다.**

- 한 장을 자세히 볼 때는 **240px과 32px 두 크기로 줄여 놓고** 본다. 32px에서 얼굴이 안 읽히면 나머지는 볼 필요가 없다.
- **판정은 실사용 크기로 한다.** 아바타는 20~240px로 표시된다. 그 크기에서 안 보이는 것은 결함이 아니다.

> ⚠️ **양쪽으로 다 틀렸다 — 2026-08-01 실측 3건.**
> - **작게 보고 단정** — 220px 격자에서 "어깨·가슴이 넓다"고 판정한 인물이 실제로는 목까지만 나왔다(알키비아데스).
> - **크게 확대해 없는 결함을 만듦** — 생성물을 1100~1400px로 확대해 "안경테가 끊겼다"고 보고했으나, 더 크게 열어 보니 테두리·브릿지·코받침 전부 정상이었다. 코 그림자와 겹친 부분을 잘못 읽은 것이다. 같은 건에서 "피부 질감이 인공적"이라 한 것도 1400px에서만 보이고 800px에서는 사라진다.
>
> 확대는 **의심을 확인하는 수단**이지 결함을 찾는 수단이 아니다. 확대해서 처음 보이는 것은 대개 결함이 아니다.

### 5.3 불합격 — 다시 뽑는다

| 유형 | 증상 |
|------|------|
| **치우침** | 콧대가 가로 45~55 밖. 세로 직사각 잘림에서 얼굴이 밀린다. **수치로 잡히는 유일한 항목** |
| 원경 | 32px에서 얼굴이 점이 된다. 수치가 아니라 눈으로 판정한다 — 얼굴이 작아도 목까지만 나오면 정상이다 |
| 처짐 | 원형에서 이마 위 빈 공간이 크게 뜬다 |
| **얼굴 잘림** | 이마·눈썹·귀가 화면 밖으로 나감. **머리카락·모자·투구가 잘리는 것은 무방하다** |
| 흉상 | 쇄골·가슴이 보이거나 상반신이 길어져 인물이 작아짐 |
| 부유 | 턱 아래가 비어 원형 안에 머리만 떠 보임 |

| 이물 | 두 명 이상, 손·마이크·소품, 읽히는 글자 |

### 5.4 합격이되 급하지 않은 어긋남

- **얼굴 크기가 목표(눈 46 / 턱 81)에서 벗어난 것은 그 자체로 손대지 않는다.** 목까지만 나오면 작아도 되고, 목이 거의 안 보일 만큼 커도 된다.
- **표정도 판정하지 않는다.** 크게 웃든 입이 벌어졌든 그것 때문에 교체하지 않는다(§4.3).
- **머리 위는 얼마든 상관없다.** 여백이 넓든, 머리끝이 화면에 닿든, 모자가 잘리든 판정하지 않는다.
- **턱 아래도 무엇으로 채워지든 상관없다.** 맨 목이든 옷깃이든 갑옷이든 머리카락이든, 어깨가 아예 안 보여도 판정하지 않는다.

### 5.4.1 신원부터 본다 — 기하보다 앞선다

**얼굴이 그 사람이 맞는가.** 이것이 틀리면 나머지 판정은 의미가 없다.

수치도 격자도 신원을 보지 못한다. 사람이 인물을 알아보거나, 자료와 대조해야 한다.

- **아바타와 대표 사진을 나란히 놓고 본다.** 둘이 다른 사람이면 최소 하나는 틀렸다. 대표 사진 생성기가 아바타를 REF로 받으므로 보통은 같은 얼굴이어야 하는데, 대표 사진이 다른 경로로 들어온 경우가 있다.
- 성별·시대·민족이 프로필과 어긋나는지 본다. 소개글에 적힌 생몰년·출신과 그림이 맞물리는지 확인한다.
- 신원 오류가 확인되면 **기하를 손보지 말고 이미지를 내린다** — DB의 `avatar_url`·`portrait_url` 을 비우고 R2 파일을 지운다.
- **백업하지 않는다.** 다른 사람 얼굴이 붙은 이미지는 자산이 아니라 오염물이다. 남겨 두면 나중에 REF로 재사용되거나 되살아날 위험만 남는다. 기하·품질 결함으로 교체하는 경우와는 다르게 다룬다.

**얼굴이 틀렸으면 `wikidata_qid` 부터 의심한다.** 자동 등록이 그 식별자의 대표 사진을 그대로 가져오므로, 식별자가 다른 사람을 가리키면 얼굴도 그 사람이 된다. **이미지만 지우고 식별자를 두면 다음 등록에서 같은 얼굴이 또 들어온다.**

> 실측(2026-08-01, 표본 10명): 2명이 신원 오류였다. 라오서는 남성 작가인데 아바타가 서양 여성이었고, 오승은은 명대 소설가인데 선글라스 낀 현대 남성이었다. **둘 다 아바타와 화보가 서로 다른 사람이기까지 했다.**
>
> 원인은 식별자였다 — 라오서의 `wikidata_qid` 가 `Q204168`(Lorrie Moore, 미국 여성 소설가)로 잘못 붙어 있었다. **생몰년이 우연히 비슷해 이름·설명을 봐야 잡혔다.** 명단과 교정 내역은 `docs/todo/celeb/celeb-avatar-defects.md`.

### 5.5 불합격이 확인된 뒤 — 고치는 순서

**등록된 아바타는 이미 잘린 결과물이라 대개 다시 자를 수 없다.** 그러므로 먼저 재크롭이 되는지부터 확인하고, 안 되면 새 그림이 필요하다.

**1) 재크롭이 되는지 본다**

```
npx tsx scripts/crop-faces.ts <내려받은폴더> <출력폴더> --size 800
```

- **경고가 없고 결과가 규격에 들면** 그것으로 교체한다. 다만 원본 일부를 잘라 800으로 늘리는 것이라 확대가 들어간다(실측 약 1.2배). 원형 100px 표시에서는 티가 안 나지만 손실은 손실이다.
- **"얼굴이 원본 가장자리에 붙어 위치가 밀렸다"는 경고가 뜨면 그 그림으로는 못 고친다.** 옮길 여백이 없다는 뜻이다.

> 시험 실측(2026-08-01, 좌우 치우침 7명): 재크롭이 통한 것은 **2명뿐**이고 5명은 여백이 없어 실패했다. 이 비율을 기준선으로 삼는다 — 대부분은 아래 2)로 간다.

**2) 재크롭이 안 되면 — 새 그림이 필요하다**

두 갈래이고, 둘 다 이 문서의 규격을 따른다.

| 길 | 언제 | 절차 |
|---|---|---|
| **신규 이미지 탐색** | 더 나은 원본 사진이 있을 법한 인물(현대 인물, 공식 자료가 있는 경우) | 웹·Commons에서 얼굴이 크고 정면인 사진을 찾아 단건 등록. 신원 근거 필수 |
| **재생성** | 쓸 만한 원본이 없거나 옛 인물·회화만 남은 경우 | §4의 발주 프롬프트로 다시 뽑는다 |

**⚠️ 재생성은 유료다. 사전 승인 없이 실행하지 않는다**(`CLAUDE.md` 20번). 대상 명단과 규모를 먼저 확정해 보고한 뒤 승인을 받는다.

**3) 기하가 아닌 원인은 따로 본다**

수치로 이탈이 잡혔어도 원인이 크롭이 아닐 수 있다. 배경 지우기가 실패해 한쪽이 비면 중심축이 밀린 것처럼 나온다(2026-08-01 아돌프 히틀러). 이런 건 다시 잘라도 그대로이므로 원인을 먼저 확인한다.

**명단은 여기 적지 않는다** — `docs/todo/celeb/celeb-avatar-defects.md`가 교체 대상 명단의 SSoT다. 이 문서는 절차만 쥔다.

### 5.6 자가 검토 의무

`image-generation.md` §1.6에 따라 **생성 직후 직접 열어보고 결함부터 보고한다.** 도구의 "저장했다"는 검토가 아니다. AI 눈에 99점이면 사람 눈에는 50점이라는 보정을 걸고 본다.

## 6. 자르는 규칙 — 눈과 턱을 기준으로 한다 (2026-08-01 실측 확정)

**얼굴 검출 상자에 배율을 곱하는 방식을 버린다.** 상자는 모델·인물마다 잡는 범위가 달라, 같은 값을 넣어도 결과가 흔들린다.

> 실측(표본 60명): 상자 큰 변 대비 눈-턱 거리가 **0.542 ~ 0.714로 32% 요동친다.** 어떤 배율을 써도 얼굴 크기가 ±14% 흔들린다는 뜻이다. 지금까지 상수를 아무리 맞춰도 통일이 안 된 근본 원인이 이것이다.

눈과 턱은 랜드마크로 직접 잰다. 그러면 **검출 모델이 무엇이든 같은 결과**가 나오고, 관리자 화면과 서버에 다른 값을 넣을 필요도 없어진다.

```
정사각 한 변  S    = (턱끝Y − 눈Y) ÷ 0.35
위쪽 좌표    top  = 눈Y − 0.46 × S
왼쪽 좌표    left = 눈X − 0.50 × S
```

구현은 `sw/web-bo/src/lib/avatar-geometry.ts` 하나다. 노드 스크립트와 관리자 화면이 같이 쓴다. **수치를 바꾸려면 이 문서를 먼저 고치고 그 파일로 옮긴다.**

### 랜드마크를 못 얻었을 때만 쓰는 폴백

| 항목 | 값 | 근거 |
|------|:---:|---|
| 상자 큰 변 ÷ 정사각 변 | **0.557** | 표본 60명 중앙값 0.628 ÷ 0.35 = 1.794배의 역수 |
| 상자 세로 중심이 놓이는 높이 | **0.532** | 같은 표본 실측 |

**폴백은 신뢰도가 낮다**(±14%). 결과에 그 사실을 표시해 넘긴다.

### 그 밖의 값

| 항목 | 현재 | 확정 |
|------|:---:|:---:|
| 출력 크기 | 800 (일부 가변) | 800 |
| 품질 | 85 / 88 / 95 / 100 / 0.85+0.9 이중 | **95 하나로** |

### 조용히 어긋나던 것을 드러낸다

원본이 규격보다 작거나 얼굴이 원본 가장자리에 붙어 있으면, 계산한 좌표를 이미지 안으로 밀어 넣을 수밖에 없다. 지금까지는 이것이 **아무 신호 없이** 일어나 얼굴이 규격을 벗어난 채 저장됐다. 새 구현은 이럴 때 경고를 함께 돌려주며, 호출부는 이를 기록하거나 실패로 처리한다.
