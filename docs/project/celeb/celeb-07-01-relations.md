# 인물 관계

이 문서는 full·light·fiction 인물의 관계를 선정하고 `celeb_relations` 또는 `celeb_relations_external`에 기록하는 규칙을 쥔다. 테이블 구조는 [`../data/03-celeb.md`](../data/03-celeb.md), 관계 유형과 방향 정규화의 코드 SSoT는 [`../../../packages/shared/src/constants/celeb-relations.ts`](../../../packages/shared/src/constants/celeb-relations.ts)다.

## 관계로 인정하는 범위

- 두 인물이 같은 시대·직군·단체에 속했다는 이유만으로 관계를 만들지 않는다. 가족, 사제, 직접적인 사상 영향, 공동 창업, 동료 활동, 우정, 경쟁처럼 두 사람 사이의 구체적 사실이 확인되어야 한다.
- 실존 인물은 신뢰할 수 있는 전기·공식 기록·당사자 발언·Wikidata의 명시 속성으로 확인한다. fiction 인물은 원전이나 대표적인 정본에 실제로 드러나는 관계만 쓴다.
- `counterpart`는 제우스와 유피테르처럼 서로 다른 문화권에서 독립된 프로필로 다루는 대응 신격·인물을 잇는다. 단순히 역할이 비슷하다는 해석에는 쓰지 않는다.
- 확인할 관계가 없으면 행을 만들지 않는다. 관계 데이터의 부재는 프로필 미완성을 뜻하지 않는다.
- 관계 사실은 `publication_status`와 독립적이다. 상대가 비공개여도 사실을 지우지 않으며, 화면에서 이동만 막는다.

## 내부 관계와 명단 밖 관계

| 경우 | 저장 위치 | 처리 |
|---|---|---|
| 양쪽 모두 `celebs`에 있음 | `celeb_relations` | 두 실제 셀럽 ID를 연결 |
| 상대가 서비스 명단 밖이지만 신원이 확인됨 | `celeb_relations_external` | `from_id`와 상대의 정확한 QID·이름·사진을 기록 |
| 상대의 신원을 확정하지 못함 | 저장하지 않음 | 동명이인이나 추정 인물을 넣지 않음 |

명단 밖의 실제 상대를 대신해 서비스에 등록된 다른 인물을 끼워 넣지 않는다. 자동 수집은 가족 관계만 외부 노드로 확장한다. 검증된 맞수·지기는 수동으로 보강할 수 있지만, 명단 밖 스승·영향 인물·공동 창업자까지 자동 확장하지 않는다.

## 방향과 중복

관계 사실 하나는 한 행만 저장한다. `rel_type`은 **`to_id`가 `from_id`에게 무엇인지**를 뜻한다.

- 자녀 → 부모는 `from_id=자녀`, `to_id=부모`다. 성별이 확인되면 `father`·`mother`, 아니면 `parent`를 쓴다.
- 제자 → 스승은 `from_id=제자`, `to_id=스승`과 `teacher`로 저장한다.
- 영향을 받은 인물 → 영향을 준 인물은 `from_id=수용자`, `to_id=영향원`과 `influence`로 저장한다.
- 배우자·형제·친구·라이벌·공동 창업자·동료·대응 인물처럼 대칭인 관계는 두 ID를 정렬해 한 행만 둔다.
- 반대 방향 표현인 `child`·`student`·`influenced`가 입력되면 코드 정규화를 거쳐 위 방향으로 바꾼다.

저장 전 `canonicalizeCelebRelation`으로 방향을 맞추고 `celebRelationFactKey`로 중복을 검사한다. 같은 부모 관계에서는 `father`·`mother`를 중립형 `parent`보다 우선하고, 같은 두 사람의 사제 관계와 영향 관계가 겹치면 더 구체적인 `teacher`를 남긴다. 가족 관계가 확인된 두 사람에게 부차적인 사회 관계를 겹쳐 넣지 않는다.

## 설명과 출처

- `source='wikidata'`는 수집 스크립트가 관리한다. 수동으로 확인해 넣은 관계는 `source='manual'`로 저장한다.
- `note`와 `note_en`은 어느 인물 화면에서 보아도 성립하도록 두 사람의 행동과 결과를 함께 설명한다. 한쪽만 주어로 삼아 반대편에서 뜻이 뒤집히는 문장을 쓰지 않는다.
- 공동 창업·동료·우정·경쟁처럼 유형만으로 맥락이 부족한 관계에는 무엇을 함께 했는지 짧게 적는다.
- `label_ko`·`label_en`은 현재 소비처가 없는 레거시 열이므로 새 값을 만들지 않는다.
- 외부 인물의 QID는 이름만 맞춰 넣지 말고 설명·생몰·직업을 함께 대조한다. 공식 영문 라벨이 있으면 `name_en`에 그 값을 쓴다.

## 수집과 검증

Wikidata 관계 수집기는 기본적으로 DB를 바꾸지 않는 dry-run이다.

```bash
pnpm --dir sw/web-bo celeb:relations
pnpm --dir sw/web-bo celeb:relations -- --apply
```

`--apply`는 사용자가 DB 반영을 명시한 경우에만 실행한다. 재수집은 `source='wikidata'` 행만 교체하고 `manual` 행은 보존한다. 기본 실행에서는 노이즈가 큰 단체 공동 소속 관계를 수집하지 않는다.

반영 전후에는 다음을 확인한다.

- 중복 `wikidata_qid`가 보고되면 해당 인물의 QID를 먼저 교정한다.
- 정규화한 사실 키가 중복되지 않는지, 대칭 관계가 양방향 두 행으로 남지 않았는지 확인한다.
- 외부 노드가 실제 상대와 일치하는지 QID 설명과 생몰 정보로 다시 확인한다.
- 수동 관계가 재수집 뒤에도 남아 있는지 확인한다.
- fiction 관계와 대응 관계는 해당 원전에서 근거를 다시 확인한다.

DB를 갱신할 때는 [`celeb-00-01-pipeline.md`](celeb-00-01-pipeline.md#업데이트-가드)의 업데이트 가드를 함께 따른다.
