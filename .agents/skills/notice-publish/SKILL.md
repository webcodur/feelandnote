# 공지사항 작성·영문화

공지는 **한국어와 영어가 한 벌이다.** 둘 중 하나만 쓰고 끝내지 않는다.

## 데이터 계약

`notices` 테이블의 여섯 필드가 전부다. 새 컬럼을 만들지 않는다.

| 필드 | 규칙 |
|---|---|
| `title` / `title_en` | 각각 100자 이내 |
| `content` / `content_en` | 빈 값 금지 |
| `is_pinned` | 상단 고정. 기본 `false` |
| `author_id` | 관리자 회원 UUID |

영문 두 필드는 **필수다.** `localizeNotice`가 영어 화면에서 `title_en`·`content_en`을
그대로 내보내므로, 비면 영어 방문자에게 빈 공지가 뜬다. 한국어를 복사해 넣지도 않는다.

## 문체

기존 공지와 같은 결을 지킨다. 새 문체를 발명하지 않는다.

- 제목은 짧은 명사구다. "서가 페이지 신설", "알람 기능 생성"처럼 무엇이 달라졌는지만 적는다.
  "~했습니다" 같은 서술형 제목을 쓰지 않는다.
- 본문은 정중한 존댓말로 사실만 적는다. 무엇이 바뀌는지, 언제 반영되는지, 사용자가 무엇을
  할 수 있는지 순으로 쓴다.
- 항목이 둘 이상이면 `■ 소제목` 뒤에 설명 한 단락을 붙인다.
- 사용자가 초안에 `~~`나 빈칸을 남겼으면 **기능을 코드·문서로 직접 확인하고 채운다.**
  화면에 없는 기능을 지어내지 않는다.
- 과장·감탄·홍보 문구를 넣지 않는다. `no-trash-prose`를 함께 적용한다.

영문은 번역투로 옮기지 않고 영어 공지로 다시 쓴다. 한국어의 `■` 구조와 문단 수는 맞춘다.

## 등록 경로

정상 경로는 **웹의 공지 작성 화면**(`/agora/board/notice/write`)이다. 관리자 세션으로
`createNotice`가 실행되며 `revalidateTag('notices')`까지 함께 처리한다.

과거 날짜로 넣어야 하거나 여러 건을 한 번에 넣을 때만 `sw/web-bo`에서 1회성 스크립트를 쓴다.

```powershell
# sw/web-bo 에서
pnpm exec tsx scripts/<이름>.ts --dry
pnpm exec tsx scripts/<이름>.ts --apply
```

스크립트는 DB 연결 환경변수 `NEXT_PUBLIC_DB_API_URL` + `DB_SECRET_KEY`를
사용하고, 등록 뒤 재조회로 확인한 다음 **파일을 지운다.** 1회성 스크립트를 저장소에 남기지 않는다.

## 밟으면 터지는 곳

### 스크립트로 직접 넣으면 최대 1시간 늦게 보인다

`getNotices`는 `revalidate: 3600`, 태그 `['notices','board-comments']`로 캐시된다. 이 태그는
`/api/revalidate`의 허용 목록(`CACHE_TAGS`)에 없어서 외부에서 비울 수 없다. 서버 액션
`createNotice`만 `revalidateTag`를 호출한다. 급히 노출해야 하면 작성 화면으로 등록한다.
DB에 값이 들어갔는데 화면에 없다고 해서 등록 실패로 판단하지 않는다.

### 같은 제목을 두 번 넣는다

스크립트에는 `title`로 기존 행을 조회해 건너뛰는 중복 방지를 반드시 넣는다.

### top-level await가 죽는다

`tsx`가 CJS로 변환해 최상위 `await`에서 `Top-level await is currently not supported`로 멈춘다.
`async function main()`으로 감싸고 `main().catch(...)`로 호출한다.

### 날짜를 문자열로 넘길 때

`created_at`을 지정하지 않으면 현재 시각이 들어간다. 과거 날짜로 올리려면
`'2026-08-19T09:00:00+00:00'` 형태로 명시한다.

## 확인

등록 뒤 DB를 재조회해 여섯 필드를 눈으로 확인하고, `/agora/board/notice`와 홈 공지 구획
(최근 5건 티저)에서 한국어·영어 두 화면을 모두 연다. 영어 화면에서 제목·본문이 비어 있지
않은지가 마지막 관문이다.
