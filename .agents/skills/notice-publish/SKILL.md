# 공지사항 작성·영문화

공지는 **한국어와 영어가 한 벌이다.** 둘 중 하나만 쓰고 끝내지 않는다.

## 데이터 계약

`notices` 테이블의 여섯 필드가 전부다. 새 컬럼을 만들지 않는다.

| 필드 | 규칙 |
|---|---|
| `title` / `title_en` | 각각 100자 이내 |
| `content` / `content_en` | 빈 값 금지 |
| `is_pinned` | 상단 고정. 기본 `false` |
| `author_id` | 관리자 회원 UUID |
| `created_at` | **발행 시각.** 미래면 예약 공지다. 비우면 지금 |

영문 두 필드는 **필수다.** `localizeNotice`가 영어 화면에서 `title_en`·`content_en`을
그대로 내보내므로, 비면 영어 방문자에게 빈 공지가 뜬다. 한국어를 복사해 넣지도 않는다.

## 문체

기존 공지와 같은 결을 지킨다. 새 문체를 발명하지 않는다.

- 운영자 소개 호칭은 [루트 AGENTS.md의 프로젝트 개요](../../../AGENTS.md#프로젝트-개요)를 따른다.
- 제목은 짧은 명사구다. "서가 페이지 신설", "알람 기능 생성"처럼 무엇이 달라졌는지만 적는다.
  "~했습니다" 같은 서술형 제목을 쓰지 않는다.
- 본문은 정중한 존댓말로 사실만 적는다. 무엇이 바뀌는지, 언제 반영되는지, 사용자가 무엇을
  할 수 있는지 순으로 쓴다.
- 항목이 둘 이상이면 `■ 소제목` 뒤에 설명 한 단락을 붙인다.
- 사용자가 초안에 `~~`나 빈칸을 남겼으면 **기능을 코드·문서로 직접 확인하고 채운다.**
  화면에 없는 기능을 지어내지 않는다.
- 과장·감탄·홍보 문구를 넣지 않는다. 한국어는 「한국인이 한국어로 쓴 글 답게」 쓴다.

영문은 번역투로 옮기지 않고 영어 공지로 다시 쓴다. 한국어의 `■` 구조와 문단 수는 맞춘다.

## 등록 경로

기본 경로는 **DB 직접 등록**이다. 사용자가 게시를 지시하면 `sw/web-bo`의 로컬 `.env`에 있는
`NEXT_PUBLIC_DB_API_URL` + `DB_SECRET_KEY`로 `notices`에 바로 INSERT한다.
브라우저 관리자 로그인이나 추가 게시 승인을 요청하지 않는다. 브라우저는 공개 노출 확인에 쓴다.

`author_id`는 기존 공지에서 확인하고 `user_accounts.role`이 `admin` 또는 `super_admin`인지 검증한다.
DB 클라이언트는 `auth: { autoRefreshToken: false, persistSession: false }`로 만든다.
1회성 코드를 표준입력으로 실행하거나 임시 스크립트를 쓴다. 파일로 실행할 때는 다음과 같다.

```powershell
# sw/web-bo 에서
pnpm exec tsx scripts/<이름>.ts --dry
pnpm exec tsx scripts/<이름>.ts --apply
```

등록 뒤 재조회로 확인하고, 임시 스크립트를 만들었다면 **파일을 지운다.**
비밀값은 출력하거나 스크립트에 적지 않는다.

## 예약 발행

`created_at`이 곧 발행 시각이다. 미래로 두면 그때까지 방문자에게 보이지 않는다.
예약 전용 컬럼은 없고 앞으로도 만들지 않는다.

- DB 등록 시 `created_at: '2026-09-05T00:00:00+00:00'`처럼 발행 시각을 명시한다. 생략하면 지금 올라간다.
- 관리자는 목록·상세에서 예약분을 그대로 보며 제목 옆에 「예약」 딱지가 붙는다.
  방문자에게는 목록·홈 티저에서 빠지고, 주소를 알고 들어가도 404다.
- 시각이 지나면 저절로 올라간다. 배포도 수동 조작도 필요 없다.

노출 경계와 딱지 판정은 `sw/web/src/lib/board/noticeSchedule.ts` 하나가 쥔다.
경계를 버킷 단위로 올림하므로 예약 공지가 제 시각보다 조금 일찍 뜰 수 있다.
분 단위로 정확해야 하는 공지는 이 방식으로 내보내지 않는다.

## 밟으면 터지는 곳

### DB 등록과 목록 노출 사이에 캐시 지연이 있다

`getNotices`는 캐시 키에 `currentPublishBoundary()`를 포함하므로 노출 경계가 바뀌면 새로 조회한다.
경계 간격은 `sw/web/src/lib/board/noticeSchedule.ts`의 `NOTICE_PUBLISH_BUCKET_MS`가 쥔다.
DB 저장과 상세 본문을 먼저 확인하고, 목록·홈은 다음 경계 이후 다시 확인한다.
`notices` 태그는 `/api/revalidate`의 허용 목록에 없으므로 이를 호출하거나 전체 캐시를 비우지 않는다.
노출이 늦다는 이유로 재등록하거나 로그인 경로로 전환하지 않는다.

### 같은 제목을 두 번 넣는다

스크립트에는 `title`로 기존 행을 조회해 건너뛰는 중복 방지를 반드시 넣는다.

### top-level await가 죽는다

`tsx`가 CJS로 변환해 최상위 `await`에서 `Top-level await is currently not supported`로 멈춘다.
`async function main()`으로 감싸고 `main().catch(...)`로 호출한다.

### 날짜를 문자열로 넘길 때

`created_at`을 지정하지 않으면 현재 시각이 들어간다. 과거 날짜로 올리려면
`'2026-08-19T09:00:00+00:00'` 형태로 명시한다.

## 확인

등록 뒤 DB를 재조회해 필드를 눈으로 확인하고, `/agora/board/notice`와 홈 공지 구획
(최근 5건 티저)에서 한국어·영어 두 화면을 모두 연다. 영어 화면에서 제목·본문이 비어 있지
않은지가 마지막 관문이다.

예약으로 넣었다면 **로그인하지 않은 상태에서** 목록·홈 티저에 없고 상세 주소가 404인지
함께 확인한다. 관리자로 보면 예약분도 보이므로, 관리자 화면만 보고 넘어가면 검증이 아니다.
