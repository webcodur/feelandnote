# LIGHT·FICTION 인물 한 줄 정의 필드

## 목적

인물 이름만 봐서는 누구인지 모르는 사용자가 검색 결과와 상세 상단에서 곧바로 정체를
파악할 수 있도록, 이름 뒤에 붙는 구체적인 한 줄 정의를 마련한다. 기존 `title`은 대표작·
호칭·업적 가운데 하나를 2~8자로 적는 수식어이므로 이 역할을 대신하지 않는다. `bio`의 첫
문장을 잘라 쓰거나 모델이 요청 시점에 즉석 생성하는 방식도 사용하지 않는다.

원하는 결과는 다음과 같다. 오른쪽 문구만 새 필드의 값이며, 이름과 구분 부호는 화면과 SEO
조립기가 붙인다.

| 인물 | 한 줄 정의 예시 |
|---|---|
| 아킬레우스 | 그리스군 최강의 전사 |
| 오디세우스 | 뛰어난 지략을 지닌 이타카의 왕 |
| 헬레네 | 트로이 전쟁의 발단이 된 스파르타 왕비 |
| 아가멤논 | 그리스 연합군을 이끄는 미케네의 왕 |

## 현재 임시 처리

- `full`은 실제 감상 기록을 중심으로 한 기존 제목을 유지한다.
- `light`는 수식어의 원래 용도에 맞춰 `title — 이름`으로 표시한다.
- `fiction`은 연결 원전이 있으면 `이름, 《원전》의 등장인물`로 표시한다.
- 원전 연결이 없는 `fiction`은 `title — 이름`, `title`도 없으면 이름만 사용한다.
- 페이지 기능을 나열한 `인물 안내·영향력·스펙트럼`이나 `삶과 영향` 같은 제목은 쓰지 않는다.

이 방식은 현재 데이터만 사용하므로 사실을 새로 만들지는 않지만, 인물마다 다른 매력을
설명하는 최종 제목은 아니다.

## 다음 미션

1. 새 필드의 이름과 저장 위치를 정한다. `headline`·`identity_line` 등은 후보일 뿐이며,
   이 문서만으로 DB 테이블이나 컬럼을 만들지 않는다.
2. 한국어와 영어를 독립된 편집 원고로 관리한다. 영문은 한국어 어순을 그대로 옮기지 않는다.
3. 우선 활성 `light`·`fiction` 전원을 조사한다. `full` 적용 여부는 실제 화면 효용을 본 뒤
   별도로 결정한다.
4. 한 줄에는 그 인물을 다른 인물과 가르는 역할·지위·대표 사건 하나만 넣는다. 작품 목록,
   페이지 기능, 추상적인 성격 평가는 넣지 않는다.
5. 최상급과 인과관계는 대표 원전이나 신뢰할 수 있는 사료로 확인한다. 근거가 약하면 더
   좁고 객관적인 표현으로 낮춘다.
6. 이름과 구분 부호는 값에 저장하지 않는다. 문구는 이름 뒤에 바로 붙여 읽을 수 있는
   명사구로 작성한다.
7. 관리자 입력·한영 누락 감사·길이 검증·상세 상단·SEO·Open Graph·공유 제목의 사용처를
   한 번에 연결한다.
8. 원전이 여러 개인 픽션 인물은 대표 원전을 편집 판단으로 지정한다. 현재 연결 목록의
   가나다순 첫 작품을 대표 원전으로 간주하지 않는다. 소실된 직접 원전도 원전명은 보존한다.

## 완료 기준

- 활성 대상의 한국어·영어 한 줄 정의가 모두 채워져 있다.
- 네 인물 이상을 한꺼번에 비교해도 같은 말이 반복되지 않고 각 인물을 구별할 수 있다.
- 원전·사료 대조에서 틀린 최상급, 지위, 혈연, 사건 인과가 없다.
- 새 값이 있으면 상세 상단과 메타데이터가 사용하고, 없으면 현재 임시 제목으로 안전하게
  돌아간다.
- 한국어·영어 제목, Open Graph, 공유 제목, 구조화 데이터의 이름이 서로 어긋나지 않는다.
- 단위 테스트와 KO/EN 실제 경로 검수를 통과한다.

작업을 마치면 현행 필드 규격은 `docs/project/celeb/celeb-1-basic-profile.md`에 흡수하고,
SEO 사용 규칙은 `docs/project/operations/seo.md`에 남긴다. 이 문서는 TODO에서 제거한다.
