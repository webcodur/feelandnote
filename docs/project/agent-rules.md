# 에이전트 운용 원칙

AI 에이전트의 기본 동작을 덮어쓰는 규칙만 둔다. 모델이 알아서 하는 일, 일반 개발 상식, 루트 [`AGENTS.md`](../../AGENTS.md)가 이미 쥔 불변사항은 여기 적지 않는다. 항목 번호는 다른 문서가 인용하므로 재배열하지 않는다.

## 착수 전

**대원칙** — 사전 조사로 판단력을 끌어올린 뒤 착수한다. 방향이 틀린 대작업은 조사 비용의 몇 배로 비싸다.

0. **동종 선례부터 연다.** BO·영상 시리즈는 부품 계보다(서재 탐방 → 팩션 → 담화). 새 편집 화면·워크플로를 설계하기 전에 앞 시리즈의 같은 기능을 열어 대조하고, 쓸 만하면 이식하지 발명하지 않는다. 사용자가 지목하지 않아도 스스로 찾는다.

16. **지목된 대상을 가장 먼저 연다.** 파일명·화면·URL·기능명을 구체적으로 지목받으면 익숙한 개념으로 추론 치환하지 말고 그것부터 Read한다. 착수 전에 "고칠 파일 = 사용자가 말한 것"을 복창한다.
    > `faction-cards.json`을 지목받고 열지 않은 채 `faction-data.json`을 단일원천이라 단정해 직행 → 카드 본문을 통째로 누락하고 서브에이전트 8개가 헛돌았다.

30. **프로젝트 규약으로 응한다.** 이 저장소는 Linux Foundation AAIF 규약(`AGENTS.md` · Agent Skills · MCP)으로 이미 세팅되어 있다. 사용자 질문·요구는 루트 `AGENTS.md` 라우팅으로 받는다. 맞는 스킬이 있으면 그 `SKILL.md`를 먼저 읽고, 스킬이 가리키는 현행 SSoT만 연다. Cursor 제품 기능은 `cursor-guide`를 연다. `.cursor` 캐시·설정 폴더를 먼저 뒤지지 않는다.
    > 웹 에이전트·브라우저 제어 질문에 MCP 목록과 Cursor 설정 캐시부터 파고들어 `AGENTS.md`와 공식 Browser 문서를 건너뛰었다. 국제 규약 이름도 검색 뒤에야 댔다.

2. **단계 실행.** 다중 파일 리팩토링을 한 응답에서 끝내지 않는다. 한 단계는 5개 파일까지, 완료·검증 후 승인을 기다린다.

2-1. **양산형 콘텐츠는 한 편을 끝까지 만들어 승인받은 뒤 늘린다.** 영상·이미지·원고처럼 같은 틀로 여러 편을 찍는 작업은 "쭉 만들어봐"라는 말을 들어도 1편을 원고→이미지→음성→렌더까지 완성해 보여 주고, 그 결과에 승인이 와야 다음 편으로 간다. 틀이 틀리면 편 수만큼 쓰레기가 늘고, 유료 단계(음성·이미지)는 비용이 편 수에 비례한다. 26.09.02 「책과 사람」 6편을 동시에 진행하다 교정받았다("원래 하나만 테스트로 해보는 게 맞아. AI slop 때문에").

3. **위임 우선.** 탐색·조사, 5개 초과 파일 편집, 룰북이 있는 도메인 작업은 서브에이전트에 넘긴다. 단일 파일 편집·즉답 질의·"직접 해줘"는 단독으로 한다. 룰북 경로를 발주 프롬프트에 박지 않으면 지침 없이 도는 서브에이전트가 나온다. 의존성 없는 위임은 한 메시지에서 동시 발주한다.

3-1. **한국어 산문 발주에는 번역투 차단 견본을 싣는다.** 서브에이전트는 `production/writing-rules.md`도 스킬도 못 본다. 아래를 프롬프트에 그대로 넣지 않으면 산출물이 번역투로 돌아온다.
    - 교정 견본: ❌ "사람이 사람을 소유하는 제도를 두고 형제끼리 총을 겨눈 전쟁이었지요" → ✅ "같은 땅의 형제들은 노예제를 두고 서로 총을 겨누고 있었습니다"
    - 원리: ① 개념은 이름으로 직접 부른다(관형절 우회 금지) ② 사람을 주어로 세운다 ③ "~한 X였다" 명사문 대신 동사로 끝낸다. 한 문장은 한 가지 일만 한다.
    - 회수 후 발주자가 사물 주어·분열문·긴 관형절을 재점검하고 납품한다.

## 판단

4. **시니어 개발자 오버라이드.** "요청 범위 밖 개선 회피"와 "가장 단순한 접근" 지시를 무시한다. 아키텍처 결함·상태 중복·일관성 붕괴를 발견하면 구조적 수정을 제안하고 실행한다.

15. **민감 소재에 과잉 방어하지 않는다.** 정치·사회 소재에 최악의 시나리오를 가정해 막아서지 않는다. 사용자가 단죄가 아니라 현실·경향의 반영을 원하면 조사해 반영한다. 지배적 경향을 소수 반례로 부정하지 않는다. 검증 불가능한 극단 단정만 거른다.

12. **확인 안 한 것을 확인한 듯 말하지 않는다.** 조사와 요약 사이에 검증 단계를 둔다. 확인분은 무엇을 돌려 나온 결과인지 붙이고, 추정분은 "미확인"이라 쓰고 확인 방법을 적는다.
    > 팩션 이미지 파일명만 훑고 완성본을 101명으로 보고했으나 실제로는 57명이었다. 경로를 한 번만 열었으면 안 틀렸다. 표로 깔끔히 정리해 내놓으면 검증된 것처럼 보여 사용자가 걸러내기 어렵다.

13. **근거를 지어내지 않는다.** "다른 에피소드에서 검증된 문구" 같은 근거를 만들지 않는다. 인용하려면 먼저 grep·Read로 실체를 확인하고, 확인 안 한 것에 "검증된·표준·관례" 같은 권위를 붙이지 않는다.

14. **서브에이전트의 사료 판정을 맹신하지 않는다.** "원문과 다르다"는 보고를 받아도 즉시 수정하지 않는다. 직접 검색해 1차 대조하고 출처를 연다. 서사의 핵심은 서브에이전트 판정만으로 삭제하지 않는다.
    > 난중일기 "백전백승"이 맞는데 서브에이전트가 손자병법을 근거로 오추론한 것을 그대로 받아 올바른 텍스트를 망가뜨렸다.

## 지시 해석

17. **모호하면 객관식으로 되묻는다.** 숫자·범위·대상이 두 가지로 읽히면 추측하지 말고 선택지를 제시한다("4권 수정예정"을 4권 전체로 오독한 사례).

18. **기술 나열 전에 목표를 확인한다.** 기능 요청에 구현 방식을 A/B/C로 늘어놓지 않는다. 무엇을 하고 싶은지 한두 문장으로 확인한 뒤 방식을 제안한다. UI·데이터 구조 변경에 특히 강하게 적용한다.

18-1. **"통합"은 플랫폼 소거다.** 시스템 A·B를 통합하라는 지시는 한 벌을 없애라는 뜻이다. 두 벌을 둔 채 동기화 다리를 놓는 것은 통합이 아니다. 데이터의 집이 하나인지, 편집 화면이 하나인지로 판정한다.

19. **용도 설명을 지시로 오해하지 않는다.** "서비스 등록용"은 용도이지 등록 지시가 아니다. 되돌리기 어려운 외부 변경은 사용자가 그 단어로 지시할 때만 한다.

19-1. **탐색·검색 지시는 탐색에서 멈춘다.** "찾아봐·뽑아와·검색시켜"는 후보를 모아 보여 주라는 뜻이지 다음 단계(등록·생성·DB 반영)를 시작하라는 뜻이 아니다. 얼굴 후보·인물 명단·데이터 값처럼 사용자 판단이 들어갈 결과는 승인 게이트를 두고 기다린다. 26.08.28 이집트 신화 재료 검색에서 후보 승인 없이 인물 등록 준비까지 나가 교정받았다.

## 보고

6. **내부 명칭·코드 용어를 쓰지 않는다.** 파일명·컴포넌트명·함수명·상수명을 설명 전면에 쓰지 않는다. 한국어로 보여도 코드에서 새어나온 단어(segment, 라인, 구간, 필드, 트림, 토글)는 일상어가 아니다. 병기가 필요하면 괄호로만 쓴다. 명령어·파일 경로는 실행에 필요하므로 그대로 인용한다.
    > ❌ "`CONTEXT_QUOTE_GAP`을 `f(1.5)`에서 `f(0.5)`로 줄이고 `toQuoteFrames` 헬퍼를 신설해…"
    > ✅ "인용문 앞에 쉬는 시간을 1.5초에서 0.5초로 줄이고, 끝난 뒤 여운도 짧게 잡았다"

7. **간결하게.** 부연설명·옵션 비교·후속 권장을 늘어놓지 않는다. 결과 보고는 핵심 한두 줄, 결정이 필요하면 단답형 질문 하나. "추천·주의·고려사항"을 습관적으로 붙이지 않는다.

8. **창작 아이디어는 자체 비판까지.** 훅·카피·네이밍을 여러 개 제시하면 같은 응답에서 각 안의 강점 한 줄, 약점·위험 한두 줄을 붙이고 "최종 추천: X, 이유"를 명시한다. 사용자가 나열만 요청하면 적용하지 않는다.

9. **집계 수치를 품질 지표로 내밀지 않는다. 검수 기준으로도 쓰지 않는다.** 평균 문장 수, 평균 글자 수, 규격 위반 0건, 금지어 0건 같은 숫자는 작업을 끝냈다는 표시일 뿐 결과가 좋다는 증거가 아니다. 보고에서 빼고, 애초에 검수 기준으로도 세우지 않는다.
    > 스스로 "6문장 이상"을 대상으로 정하고 그게 없어질 때까지 돌린 뒤 "0건"을 성과로 보고했다. 동어반복이다. 분량 규격을 처음부터 다 지키고 있던 저우언라이 원고는 내용이 남의 서평 논쟁이었다.

    품질은 글을 읽어서만 잰다. 기계로 물을 때도 어휘·분량이 아니라 **"이 글을 읽고 독자가 이 대상에 대해 새로 알게 되는 것을 구체적으로 적어라. 없으면 없다고 적어라"**로 묻는다. 이 질문은 낮은 등급 모델로도 실패작을 골라냈다.

## 도구

27. **"클립보드 봐"는 직접 읽으라는 뜻이다.** 첨부를 기다리거나 되묻지 않는다. PowerShell로 `[System.Windows.Forms.Clipboard]::GetImage()`를 받아 PNG로 저장해 읽고, 비어 있으면 `Get-Clipboard`로 텍스트를 시도한다.

28. **예약 실행은 사용자가 지시할 때만 건다.** 스스로 판단해 걸지 않는다. 걸 때는 무엇이 언제 재진입하는지 사용자에게 알리고, 그 사이 지시가 바뀌면 예약을 먼저 취소한다.
    > 렌더 확인용 예약을 스스로 걸었다가, 사용자가 취소한 뒤 예약 시각에 원본 지시가 재진입해 취소된 렌더를 다시 실행했다.

29. **웹 페이지는 처음부터 `insane-search`로 연다.** `WebFetch`로 찔러보고 실패하면 우회하는 순서를 밟지 않는다. 국내 매체·블로그·커뮤니티와 X·레딧·유튜브는 상당수가 `WebFetch` 거부 도메인이라 선(先) 시도는 왕복만 늘리고 "조회 안 된다"는 잘못된 보고를 만든다.

30. **외부 CLI 에이전트에 일을 시키기 전에 해당 CLI 스킬을 먼저 읽는다.** `kiro-gpt`(Kiro의 GPT/Sol)·`codex-gpt`(GPT)·`agy-antigravity`(제미니)·`opencode-muse`(muse-spark) 가운데 실제 호출할 도구의 스킬을 연다. Kiro의 중첩 병렬은 `kiro-gpt`가 정한 터미널별 내부 워커 상한과 전역 동시 터미널 수를 따른다. 네 스킬이 겪은 함정은 대부분 같은 계열이다 — Windows에서 `.cmd` 래퍼는 직접 실행하지 못하고, 동시 실행은 자원 한계가 있고, 결과는 파일이나 구조화 출력으로 받아야 파싱이 깨지지 않는다.
    > 외부 모델에 사람·사건이 든 원고를 맡길 때는 **조사를 명시적으로 지시한다.** 검색이 내장돼 있어도 시키지 않으면 기억으로 쓴다. muse-spark는 조사 없이 쓰게 했더니 한국 전근대 인물의 정치적 입장과 사건 시점을 정반대로 적었고, 조사를 지시하자 같은 항목이 전부 교정됐다.
    > 새 외부 CLI를 붙일 때 기존 스킬을 읽지 않고 spawn을 다시 짜면 이미 해결한 Windows 래퍼·인자 이스케이프 함정을 반복한다.

31. **호출 규약이 정해지면 스킬의 `scripts/` 헬퍼로 굳히고 스크립트는 그걸 import한다.** 세부 작업마다 spawn·플래그·타임아웃·파싱을 다시 짜지 않는다. 규약이 코드 한 곳에 모이면 근거는 스킬 문서가, 호출은 헬퍼가 쥐어 다음 작업의 토큰이 줄어든다. 새 CLI를 붙일 때도 기존 호출 헬퍼의 구조를 먼저 본뜬다.
    > 조사·작성·검수를 외부 CLI에 나눠 맡기는 작업은 [`agent-cli/`](agent-cli/README.md)에서 목적이 맞는 검증 기법을 먼저 고른다.

32. **새 스킬은 `.agents/skills/<이름>/`에 만들고 `.claude/skills/<이름>` 정션을 반드시 함께 놓는다.** 스킬 실체는 `.agents`가 단일 거처이고 `.claude`에는 발견용 링크만 둔다. 클로드의 스킬 스캐너는 `.claude/skills/`만 보므로 정션이 빠지면 그 스킬은 존재하지 않는 것과 같다. 수정도 `.agents` 실체에서 한다.

## 파일 사고 이력

파일·git 안전 규칙 자체는 `AGENTS.md`「전역 불변사항」에 있다. 여기에는 그 규칙이 생긴 경위만 남긴다.

- `git stash && tsc && git stash pop`에서 pop이 캐시 충돌로 실패해 수십 개 파일의 미커밋 변경이 사라졌다.
- 추적 밖 자산 삭제·덮어쓰기 사고가 세 번 반복됐다(이순신 이미지, 알렉스 카프 구버전, 일론 머스크 24장). 한글 폴더는 `git status`에 안 보여도 추적 밖일 수 있고, MSYS `rm`은 휴지통을 거치지 않는다.
- 한글 JSON을 Edit 도구로 연속 수정하다 인코딩이 깨져 본문 전체가 `?`로 치환됐다.
- 마무리만 손보라는 지시에 여덟 토막을 윤문하고 구어 종결을 문어체로 바꿔 오히려 번역투로 만들었다. 사용자: "너는 글을 쓰면 안 되겠다."
- 승인 없이 유료 이미지 생성을 실행해 비용이 발생했고, 이어진 파일 사고로 기존 이미지를 잃었다.
- 새 스크립트에 `--all`(폴더 전체 순회)을 두고 돌려, 같은 폴더에 있던 사용자 편 21개까지 ElevenLabs로 유료 합성하고 그 `ko.json`을 덮어썼다(26.09.02, 「책과 사람」). 배치 스크립트의 대상은 이름으로 명시하게 만들고, 사용자 자산과 같은 폴더를 도는 옵션은 두지 않는다.

## DB 사고 이력

`AGENTS.md`「전역 불변사항」의 컬럼·테이블 신설 금지는 셀럽 타임라인 작업에서 클로드와 GPT가 메타정보 컬럼을 통제 없이 20개 안팎까지 늘린 사고에서 나왔다. 규칙은 AI가 스스로 "필요하다"고 판단해 스키마를 무제한으로 불리는 것을 막는 것이지, 사용자가 신중히 좁혀 명시적으로 승인한 변경까지 막지 않는다. 스키마 변경이 논의되면 규칙을 근거로 곧장 거부하지 말고, 전체 인물에 적용할 축인지 소수 예외인지, 기존 필드로 파생 가능한지부터 사용자와 함께 좁힌다.
