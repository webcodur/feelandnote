# [작업 목표] 서가(Scriptures) 역사 타임라인 누락 이미지 기획 및 선별 생성

이전 세션에서 총 38개의 누락 이미지를 식별했습니다. 다음 세션에서는 기계적인 이미지 생성을 멈추고, 아래 지침에 따라 **'생성 가능한 항목과 스킵할 항목의 선별'** 및 **'데이터 구조 분석'**을 선행해 주십시오.

## 1. 현재 파악된 작업 대상 (총 38개 항목)
*   **Book (17개)**: 독서(묵독, 하이퍼텍스트), 서체(세리프, 산세리프 등 8개), 독서법(음독, 묵독 등 7개)
*   **Video (2개)**: 기법(편집과 몽타주, 버추얼 프로덕션)
*   **Music (16개)**: 악기(원시 악기 등 7개), 경험(제의와 광장 등 8개), 매체(생음악 1개)
*   **Game (3개)**: 플랫폼(가정용 콘솔, 휴대용/모바일, 온라인/VR/클라우드)

## 2. 🚨 작업 방향: '이미지화 적합성' 판단 및 스킵 (가장 중요)
모든 항목을 억지로 이미지로 만들려고 하지 마십시오.
1.  **이미지화 부적절 항목 스킵**: "묵독", "음독", "정독" 등과 같이 눈에 보이지 않는 행동 양식이나, 억지로 시각화했을 때 오히려 본질을 흐리거나 부자연스러워지는 추상적 개념은 **과감하게 스킵(이미지 생성 생략)** 하십시오. (해당 부분은 UI에서 이미지가 없는 텍스트 노드로 남겨두는 방향으로 처리)
2.  **명확한 시각적 대상만 생성**: "세리프(Serif)", "가정용 콘솔", "초기 활판 인쇄기" 등과 같이 시각적 형태가 명확하고 이미지로 보여주었을 때 정보 전달력이 높아지는(백과사전 도해처럼) 항목들만 선별하여 이미지를 생성하십시오.
3.  **선별 리스트 작성**: 38개의 항목 중 어떤 것을 생성하고 어떤 것을 스킵할 것인지 분류한 리스트를 사용자에게 먼저 컴펌받으십시오.

## 3. 🚨 데이터 연동 구조 파악 방안
이미지가 없는(스킵된) 노드들이 에러 없이 자연스럽게 렌더링되도록 처리하는 것이 중요합니다.
1.  `sw/web/src/constants/scriptures/*.json` 파일 분석
2.  현재 타임라인 컴포넌트 코드 분석 및 `imageUrl` 값이 비어있을 경우의 처리 로직 확인
3.  선별된 이미지만 생성 후 JSON 데이터 업데이트 계획 수립

## 4. 잘못된 편견 및 설정 제거
*   '나노바나나(Nano Banana)'는 이용할 이미지 생성 AI 모델이지 삽입할 캐릭터 마스코트가 아닙니다.
*   이미지에 앱 전체 UI 테마인 'Neo-Pantheon 다크 테마'를 강제로 부여하지 마십시오. 오직 콘텐츠 정보를 온전히 전달하는 **객관적, 사실적, 역사적 스타일**로 생성하세요.
