# 팩션 ELE 보이스 캐스팅

팩션 인물 대사의 ElevenLabs 보이스를 매번 처음부터 듣지 않기 위한 운영 문서다. 목표는 자동 확정이 아니라 **추천 후보를 좁히고, 최종 판단은 사람이 듣고 승인**하는 흐름이다.

## 지금 쓰는 방법

1. `pnpm dev:remotion-bo` 실행 후 팩션 에피소드 편집 화면을 연다.
2. 인물 행의 `음성` 버튼을 누르고, 엔진을 `ELE`로 바꾼다.
3. `추천 후보`에서 1~3순위 보이스를 먼저 듣는다.
4. 후보가 맞으면 보이스를 선택하고, 아래 `새 음원 생성`에서 실제 대사 미리듣기를 만든다.
5. 마음에 들면 미리듣기를 저장하고, 필요하면 배속·음량·감정 태그를 조정한다.
6. 한 번 들어본 보이스는 목록에서 `좋음`, `보류`, `제외`, `메모`를 남긴다. 다음 인물부터는 이 기록이 추천과 필터에 바로 반영된다.

추천은 인물의 직함, 소속, 이력, 대사, 발화 스타일, 감정 태그와 ElevenLabs 보이스의 이름·설명·라벨을 비교해 만든다. `좋음`으로 표시한 보이스는 다음 추천에서 점수가 올라가고, `제외`한 보이스는 추천과 기본 목록에서 빠진다.

또한 기존 팩션 편의 `faction-data.json`을 읽어 같은 보이스가 과거에 어떤 인물에게 쓰였는지도 함께 보여준다. 이미 `AI-Supremacy`, `PayPal-Mafia`, `Digital-Resistance` 같은 완료작에 들어간 `quoteElevenlabsVoiceId`는 별도 이관 없이 추천 근거가 된다.

## 보이스 메모

ELE 보이스 목록에서 각 보이스마다 다음 값을 남길 수 있다.

| 값 | 용도 |
|----|------|
| `좋음` | 다시 쓸 만한 후보. 추천 점수를 올린다. |
| `보류` | 상황에 따라 쓸 수 있음. 추천 점수를 약하게 올린다. |
| `제외` | 앞으로 안 쓸 보이스. 추천과 기본 목록에서 숨긴다. |
| `해제` | 잘못 누른 판정을 지운다. 메모는 유지할 수 있다. |
| 메모 | "젊은 해커형", "낮지만 답답함", "대표급에는 좋음" 같은 청취 판단. |

선택창 위쪽의 빠른 필터:

- `좋음`: 좋다고 남긴 보이스만 본다.
- `보류`: 보류로 남긴 보이스만 본다.
- `메모 있음`: 청음 메모가 있는 보이스만 본다.
- `기존 사용`: 다른 팩션 인물에 이미 쓴 보이스만 본다.
- `미사용`: 아직 팩션에 쓰지 않은 보이스만 본다.
- `제외 표시/숨김`: 제외한 보이스를 다시 확인하거나 기본 목록에서 감춘다.

저장 위치:

```txt
sw/remotion/public/factions/_voice-casting/ele-voice-notes.json
```

이 파일은 에피소드 데이터와 분리된 전역 보이스 도감이다. 한 번 판단한 보이스는 다른 팩션 편에서도 그대로 참고된다.

## 기존 매칭 이력

BO는 다음 API로 현재 팩션 데이터의 ELE 보이스 사용 이력을 읽는다.

```txt
GET /api/elevenlabs/voice-history
```

수집 대상은 `sw/remotion/public/factions/*/faction-data.json` 중 활성 편이다. `_`로 시작하는 폴더와 `not-using`은 제외한다.

화면에서는 보이스마다 다음 정보가 붙는다.

- `사용 N회`: 기존 편에서 이 보이스가 쓰인 횟수
- 사용 인물 예시: 최근/대표 인물 이름 1~3명
- 기존 감정 태그와 직함 정보: 추천 점수 계산에 사용

즉, “이미 어느 인물에게 잘 맞았는지”가 다음 캐스팅 후보 선정에 들어간다.

## 운영 원칙

- 인물마다 전체 보이스를 다시 듣지 않는다. 추천 후보부터 듣는다.
- 같은 편 안에서 주요 인물은 목소리가 구분돼야 한다. 너무 비슷하면 다른 후보로 바꾼다.
- `제외`는 과감하게 쓴다. 후보 풀이 깨끗해야 추천이 빨라진다.
- `좋음` 메모는 구체적으로 남긴다. 예: `낮은 권력자형`, `빠른 창업자형`, `조용한 연구자형`.
- 최종 확정 전에는 실제 대사로 미리듣기를 만든다. ElevenLabs 기본 샘플만으로는 문장 길이와 감정이 다를 수 있다.

## 강화 파이프라인

다음 단계는 기존 완료작을 정답 데이터로 흡수하는 것이다.

1. **기존 매칭 수집**
   `AI-Supremacy`, `PayPal-Mafia`, `Digital-Resistance`의 `quoteElevenlabsVoiceId`, 인물 정보, 감정 태그, 배속을 자동으로 읽어 보이스별 사용 이력을 만든다. 현재 BO의 `voice-history` API가 이 역할을 한다.

2. **보이스 도감 확장**
   사용 이력과 메모를 합쳐 보이스마다 잘 맞는 역할군을 붙인다. 예: 권력자, 연구자, 해커, 반체제, 창업자, 군사 브리핑. 지금은 추천 점수에 바로 반영하고, 다음 단계에서는 별도 도감 파일로 정제할 수 있다.

3. **인물별 Top 3 자동 추천**
   새 에피소드에서 인물 정보와 진영 성격을 읽고, 같은 편 안의 중복·유사 목소리까지 고려해 후보 3개를 낸다.

4. **청취용 오디션 묶음**
   후보 3개를 같은 짧은 대사로 한 번에 생성해 비교한다. 기본 샘플이 아니라 실제 톤 테스트로 판단한다.

5. **피드백 반영**
   사용자가 `좋음`, `보류`, `제외`, 메모를 남기면 다음 추천 점수에 반영한다. 충분히 쌓이면 인물군별 기본 후보가 자동으로 안정된다.

완성형은 “AI가 보이스를 확정”하는 시스템이 아니라, **AI가 후보를 줄이고 사용자가 귀로 승인하는 캐스팅 보조 시스템**이다.
