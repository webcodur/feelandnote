# ElevenLabs v3 오디오 태그 삽입

한국어 대본에 v3용 오디오 태그를 배치한다. 대상은 역사·신화 인물의 1인칭 독백이나 서술형 내레이션.

## 절대 원칙

1. **원문 어휘를 바꾸지 않는다.** 태그와 문장부호만 추가. 표현 수정이 필요하면 별도 제안.
2. **바꾼 문장부호는 전부 명시한다.** v3는 문장부호 반응이 태그보다 크게 작용한다.
3. **개행·빈 줄을 유지한다.** 줄바꿈은 호흡과 정적으로 읽힌다.
4. **사용자 화면에 보이는 DB 원문에는 새 태그를 저장하지 않는다.** 셀럽 22종 음성은 합성 전용 오버라이드로 분리한다.

## 태그 두 종류 — 이 구분이 전부다

**이벤트 태그** `[laughs]` `[sighs]` `[gasps]` `[gulps]` `[clears throat]` `[breathes]`
지점에서 1회 발생 후 즉시 복귀. 레퍼런스 이탈 시간이 짧아 설정에 관계없이 잘 먹힌다.

**상태 태그** `[intense]` `[excited]` `[happily]` `[cheerfully]` `[sorrowful]` `[whispers]` `[shouts]` `[deliberate]` `[snarling]` `[mockingly]` `[deadpan]` `[rushed]` `[slows down]` `[strained]`
다음 태그까지 지속. 레퍼런스 보이스와 같은 축에서 경쟁하므로 설정에 민감하고 잘 눌린다.

## 배치 규칙

- 어절 경계에만. 조사 사이 삽입 금지 (`나를 [laughs] 부른다` ✗)
- 문장 중간 이벤트 태그 앞에는 `...`를 둬 소리가 들어갈 공간을 확보한다.
- 짧은 독립 대사에서 반응이 먼저 일어나야 하면 이벤트 태그를 첫 줄에 단독 배치한다. 이때 앞에 `...`를 억지로 붙이지 않는다. 헤라클레스 `g1` 실청취에서는 중간 웃음보다 선두 `[laughs]`가 매끄러웠다.
- 한 문장에 이벤트 + 상태 동시 금지. 하나가 씹힌다
- 문장당 1개, 전환점만 2개. 3개 이상은 상쇄돼 평평해짐
- 중요한 이벤트 태그는 독립된 줄로 분리 (전환점 정적 + 제거 용이)
- 감정 전환은 단계적으로. 웃음 → 슬픔 직행 금지

## 문장부호 = 지시

한국어에 대문자가 없으므로 CAPS 강조를 대체한다.

- `!` `!!` — 강도 단계
- `—` — 끊어치기, 단절
- `...` — 호흡, 여운, 이벤트 태그 앞 공간
- 어절 분리 — `영원히! 불타오르리라!!`

`<break>` 태그는 v3 미지원. `...`로 대체.

## 감정 아크 (태그보다 먼저 설계)

- **도입부는 바닥에서.** 첫 줄부터 최대치면 올라갈 데가 없다. `[deadpan]` / `[deliberate]`로 하한 확보
- **최고 출력은 1회만.** `[shouts]` 두 번이면 클라이맥스 소멸. 명령부는 `[snarling]`으로 누르고 최종 선언에만 폭발
- **볼륨 대신 속도.** `[rushed]` → `[slows down]`은 음량 없이 무게를 만들고 정점과 겹치지 않는다

## 한국어 주의

- 상태 태그 반응이 영어보다 약함 (태그 튜닝이 영어 기준)
- 안 먹히면 동의어 교체: `[mockingly]` → `[sarcastic]` → `[contemptuous]`
- 그래도 안 되면 태그를 빼고 문장부호 + 어미로 처리
- **accent 계열 태그 금지** — 종성·이중모음 발음이 오염된다

## 출력 형식

1. **태그 삽입 대본** — 코드블록, 복사 가능한 형태
2. **배치 근거** — 설계 판단이 들어간 지점만. 태그마다 나열하지 않는다
3. **변경한 문장부호** — 목록. 안 바꿨으면 "원문 그대로" 명시
4. **생성 설정** — 아래 블록

## 생성 설정 (항상 첨부)

```
model            eleven_v3
stability        0.0 (Creative)  ← 다이내믹 큰 대본
                 0.5 (Natural)   ← 차분한 내레이션
style            0.0             ← 필수
similarity_boost 0.5 ~ 0.6
```

**`style`은 반드시 0.** style은 원본 화자 스타일을 증폭 → 레퍼런스 평균으로 끌어당김. 오디오 태그는 평균에서 벗어나라는 지시 → 정면 충돌. 0.3만 줘도 상태 태그에 브레이크가 걸린다.

`similarity_boost`가 높으면 원본 음색 밀착 압력으로 다이내믹이 제한됨. 단 0.5 미만은 캐릭터 동일성이 흔들린다.

- v3는 생성당 **200자 이상** 권장. 줄 단위로 쪼개지 말고 통으로 생성
- Creative는 편차가 크다. **3~5회 뽑아 선택**하는 것을 전제로
- **노멀라이즈(-14 LUFS) 이전 원본**으로 판단. `loudnorm`은 다이내믹 압축을 걸어 폭발 구간을 누른다

## 셀럽 22종 대사의 합성 전용 태그

`celeb_dialogue_voice_generate.py`에 `--tts-overrides <json>`을 넘긴다. DB에는 화면용 순수 대사를 두고 JSON의 `slots`에만 태그·합성용 문장부호를 넣는다. 생성기는 태그·공백·문장부호를 제외한 발화 글자가 DB 원문과 다르면 유료 호출 전에 중단한다.

```json
{
  "slug": "heracles",
  "locale": "ko",
  "slots": {
    "g1": "[laughs]\n악수 좀 나누었을 뿐인데, 표정이 왜 그런가?",
    "bd1": "[laughs]\n힘이 세면 머리가 나쁠 줄 알았나?"
  }
}
```

합성 뒤 오버라이드 파일은 임시 작업물이면 삭제한다. 실제로 보낸 `ttsText`는 run의 `manifest.json`에 남으므로 검수와 재현 근거는 보존된다.

## 진단

"안 먹힌다"는 보고를 받으면 증상부터 분기한다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 이벤트는 되는데 상태만 안 됨 | 설정 (거의 확정) | `style` → 0.0, `stability` → 0.0 |
| 전부 무시됨 | 모델이 v2 계열 / stability Robust(1.0) | `eleven_v3` 확인, Robust 해제 |
| 태그가 그대로 발음됨 | 형식 또는 한국어 케이스 | 소문자·대괄호 확인, 태그 교체 |
| 설정 맞췄는데도 눌림 | 보이스 헤드룸 부족 | 아래 참조 |

**이벤트 태그만 살아남는 패턴은 설정 문제의 전형이다.** 문법이나 보이스 문제였다면 이벤트 태그도 같이 죽었을 것이므로, 대본·보이스를 다시 만들 필요가 없다는 신호다.

**보이스 헤드룸 부족**
Voice Design 프롬프트에 `restless`, `bursts of sudden volume`, `barely holding back` 같은 **강도·페이싱 지시**가 있으면 베이스 보이스가 이미 최대치라 태그가 더 올릴 수 없다.

- 성격은 **음색 질감어**로: `bronze scraping bronze`, `gravelly`, `dark and heavy`
- 강도는 **태그**로
- 프롬프트에 `wide dynamic range`, `measured, even baseline`을 넣어 진폭 여지 명시

## 작업 순서

1. 화자의 성격과 감정 구조 파악
2. 진폭 아크 설계 (바닥 / 상승 / 정점 / 마무리)
3. **정점 위치를 먼저 확정**하고 나머지를 그 아래로 배치
4. 상태 태그로 구간 분할
5. 이벤트 태그를 전환점에 배치
6. 문장부호 조정
7. 출력 형식대로 제출
