# 인물 관계

full·light·fiction 인물의 관계 선정과 기록 규칙이다. 공개 전환에 필요한 조사 기준은 [`active 요건`](celeb-00-02-active-requirements.md)을 따른다. 테이블 구조는 [`data-03-celeb.md`](../data/data-03-celeb.md), 축·방향·정규화의 코드 SSoT는 [`celeb-relations.ts`](../../../packages/shared/src/constants/celeb-relations.ts)다.

## 네 축과 근거

사회 관계는 **영향을 줌·영향을 받음·협력·대립** 네 축만 사용한다. 가족 관계가 아닌 쌍에서 각 축은 독립적이다. 같은 두 사람이 서로 영향을 주면서 협력하고 대립할 수 있다. 행의 존재가 해당 축의 참 값이며 별도 boolean 열을 만들지 않는다.

- 영향은 직접 가르침, 당사자가 인정한 배움, 사상·기법·활동에 미친 구체적 영향으로 확인한다.
- 협력은 공동 창업·공동 제작·공동 활동처럼 두 사람이 실제로 함께한 일을 확인한다. 같은 직군·시대·조직의 명부에 함께 있다는 사실만으로 만들지 않는다.
- 대립은 직접적인 경쟁·논쟁·정치적 충돌 등 확인된 사건을 쓴다.
- **가족 관계가 확인된 두 사람에게 부차적인 사회 관계를 겹쳐 넣지 않는다.** 가족 간 영향은 가족 관계에 포함되므로 별도 영향 행을 추가하지 않는다. 직접적인 가르침·협력·대립 근거를 찾았더라도 가족 쌍에는 사회 관계를 중복 등록하지 않는다. 가족 판정은 공통 상수의 `isCelebFamilyRelation`을 따른다.
- 친구라는 사실만으로 협력 축을 켜지 않는다. 기존 사제는 영향 방향으로, 공동 창업은 협력으로 읽는다. 다른 과거 유형은 네 축 화면에서 제외하되 기존 기록을 지우지 않는다.
- 실존 인물은 공식 기록·당사자 발언·신뢰할 수 있는 전기·Wikidata 명시 속성으로 확인한다. fiction은 원전이나 대표 정본에 드러나는 사실만 쓴다.
- 근거가 없으면 빈칸을 유지한다. 미수록은 영향이 없다는 판정이 아니다. 관계 사실은 상대의 공개 여부와 독립적이며 비공개 상대는 화면에서 이동만 막는다.

## 저장과 방향

양쪽이 등록 인물이면 `celeb_relations`의 실제 ID를 연결한다. 명단 밖 상대는 `celeb_relations_external`에 정확한 QID·이름·사진으로 기록한다. 다른 등록 인물을 대신 끼워 넣지 않는다. 자동 수집은 명시적인 가족 속성의 명단 밖 상대만 확장한다. 사회 관계는 명단 밖으로 자동 확장하지 않는다.

`rel_type`은 **상대가 현재 인물에게 무엇인지**다. 내부의 영향 사실은 수용자 `from_id` → 영향원 `to_id`, `influence`로 한 행만 저장한다. 영향원 화면은 이를 `influenced`로 읽는다. 반대 방향의 실제 영향도 확인되면 별도 한 행이다. `colleague`는 협력, `rival`은 대립이며 두 ID를 정렬해 저장한다. 외부 상대는 방향을 뒤집을 수 없으므로 `influence`·`influenced`를 그대로 쓴다.

새 가족 관계는 `CELEB_FAMILY_RELATION_TYPES`, 새 사회 관계는 `CELEB_RELATION_AXES`를 허용한다. 전체 신규 입력은 `CELEB_RELATION_INPUT_TYPES`를 따른다. 가족 입력을 사회 축 제한으로 거부하지 않는다. 자녀 → 부모는 상대의 성별에 따라 `father`·`mother`, 성별을 특정하지 않으면 `parent`로 저장하고 내부 `child` 입력은 방향을 뒤집어 `parent`로 정규화한다. 대칭 가족 관계는 두 ID를 정렬한다. 가족 쌍은 먼저 제외하고, 나머지 기존 행은 `canonicalizeCelebRelationAxis`로 읽고 `celebRelationFactKey`로 같은 축의 사실만 중복 제거한다. DB 트리거도 새 관계의 유형·방향·그룹과 가족 중복을 검사한다.

## 설명과 신원

수동 사실은 `source='manual'`, 자동 수집은 `source='wikidata'`다. `note`·`note_en`은 두 인물의 행동과 결과를 함께 설명하여 어느 쪽 화면에서도 성립하게 쓴다. 사제·공동창업 같은 세부 맥락은 설명에 남기고 유형을 늘리지 않는다. 소비처가 없는 `label_ko`·`label_en`은 새로 쓰지 않는다.

반영 전 양쪽의 직업·생몰·직함과 QID 설명을 대조한다. 이름만 맞는 동명이인이나 잘못 배정된 QID를 연결하지 않는다. 외부 인물은 공식 영문 라벨이 있으면 `name_en`에 쓴다. 영향 외의 축에서 시대가 어긋나면 신원을 다시 확인한다.

셀럽 본인의 `wikidata_qid`도 관계 작업 전에 설명·직업·생몰을 조회해 확인한다. 다른 사람의 QID이면 관계 작업 전에 교정하거나 비운다. 중복 QID가 보고되면 먼저 교정하며, 중복이 남은 상태에서 자동 수집을 DB에 반영하지 않는다.

한국어 이름을 일괄 치환할 때는 이름 뒤에 조사가 붙은 자리만 바꾸어 다른 단어 안의 문자열을 건드리지 않는다. 받침이 바뀌면 뒤따르는 조사도 맞춘다. 예를 들어 「넵투누스가」를 「넵튠이」로 바꾼다.

## 수집과 조사

`pnpm --dir sw/web-bo celeb:relations`는 dry-run이고 `-- --apply`를 붙이면 반영한다. 자동 수집은 가족의 명시 속성을 가족 유형으로 보존하고, 영향·사제·대립의 명시 속성과 공동 창업은 네 사회 축으로 옮긴다. 가족·외부 가족은 신규 사실만 추가하고 기존 기록을 지우지 않는다. 수동·과거 세부 유형은 보존하며 현재 네 축의 자동 행만 갱신한다. 전체 조회와 신규 삽입이 성공한 뒤 이전 자동 행의 잔여분을 제거한다.

`--apply`는 사용자가 DB 반영을 명시한 경우에만 실행한다. 반영 전후에 정규화한 사실 키와 대칭 관계의 중복, 외부 상대의 QID 신원, 수동 기록의 보존을 확인한다. fiction 관계는 원전 근거를 확인한다.

Wikidata 속성이 비어 있으면 본문을 직접 조사한다. `-- --supplement <조사.json>`은 전체 재수집 없이 확인한 사실을 보강하며 기본 dry-run이다. 파일은 `schemaVersion: 1`, `pairs` 배열을 사용한다. 각 항목은 두 slug(`a`·`b`), 신원 QID(`a_qid`·`b_qid`), 가족 유형 또는 현행 사회 축(`kind`), 한영 설명(`note_ko`·`note_en`), 직접 확인한 출처 URL 배열(`sources`)을 가진다. 수집기는 URL만 보고 사실을 검증하지 않는다.

보강은 신원·설명·출처와 같은 축의 중복을 검사한다. `--apply`는 신규 관계만 DB에 넣은 뒤 재조회한다. 출처를 별도 R2 객체로 보관하지 않는다. 기존 설명을 덮어쓰지 않으며 같은 입력 재반영은 새 행을 만들지 않는다. 반영·검수한 임시 조사 파일은 폐기한다.

우선 조사 인물은 `node --env-file=.env --import tsx scripts/celeb/relations-influence-targets.mjs`로 조회한다(`sw/web-bo`에서 실행). 조회수·영향력의 순위, 네 축으로 읽은 내부·외부 영향 관계의 양쪽 수를 사용하며 DB나 후보 파일을 쓰지 않는다. 조사 대상 수와 상위 비율은 이 스크립트의 옵션으로 고른다. 인물별 조사·반영은 [`RESEARCH_RELAY_ALGORITHM.md`](../../../RESEARCH_RELAY_ALGORITHM.md), DB 수정은 [`업데이트 가드`](celeb-00-01-pipeline.md#업데이트-가드)를 따른다.
