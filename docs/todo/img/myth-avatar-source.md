# 신화 인물 아바타 확대본 재생성

신화 명단 919명 중 아바타가 있는 913명의 현재 등록본을 백업·실측했다. 등록본은 모두 이미 잘린 800×800 파일이다. 눈~턱 비율이 현행 정규화 상한 44%를 넘는 검토 후보는 54명이고, 48%를 넘는 심한 확대는 아래 14명이다. 현재본을 다시 REFRAME해도 잘린 머리·뺨·목은 복원되지 않는다.

`amata` `charybdis` `gawain` `gudrun` `haemosu` `hogni` `iarbas` `jiang-ziya` `peleus` `pelles` `sahadeva` `tiresias` `vali` `vidar`

[현재본·넓은 후보 비교 HTML](../../../_backup/faction-avatars/myth-20260924-source/review.html)에 54명을 모았다. 같은 폴더의 `_tight-audit.json`과 `_manifest.json`은 대상·현재 URL·로컬 후보를 대조하는 자료다. 이름이 맞는 큰 파일도 현 등록 얼굴과 다른 사례가 있어 원본으로 확정하지 않았다. R2의 넓은 화보 22명분을 누끼·REFRAME해 보았지만 대부분 얼굴을 1.3배 이상 확대해야 했고 일부는 얼굴·시선이 달랐다. 해모수 재생성 시안도 머리띠·수염·갑옷이 바뀌어 반려했다. 이번 시안은 R2·DB에 등록하지 않았다.

확대본은 원본 탐색이나 현재 800px 파일의 재크롭으로 처리하지 않는다. 위 비교 HTML의 54명을 실제 크기로 확인해 확대된 인물을 모두 재생성한다. 48% 초과 14명부터 시작하되 나머지 40명도 육안 판정에서 확대본이면 같은 경로로 처리한다.

1. **계정·입력 준비** — Aside Vault에 보관한 계정으로 브라우저에 로그인하고 `aside account list`로 사용 가능한 Aside 프로필을 확인한다. 각 프로필의 Gemini 멀티로그인 `/u/N`은 번호가 바뀔 수 있으므로 페이지의 `Google 계정:` 표시로 실제 계정을 확인한 뒤, 한도가 남은 계정을 순회한다. 현재 등록 얼굴을 신원 참조 이미지로, 인물별 복식 자료를 별도 참조로 준비한다. 씨앗과 프롬프트는 매번 `aside repl`의 현재 `pwd/artifacts/`에 복사한다. 옛 `gen-u2.js`·`gen-u2.sh`는 계정·세션 경로가 고정되어 있으므로 그대로 실행하지 않는다. 발주·회수 동작은 `D:\image\_avatar-work\tools\gemini-lane.js`를 참조한다.
2. **바스트샷 생성** — 스튜디오 사진처럼 정수리 위, 양옆, 어깨 아래에 충분한 여백이 있는 바스트샷을 요청한다. 얼굴만 꽉 찬 헤드샷은 금지한다. 현재 얼굴의 눈·코·입·얼굴형과 인물 고유의 머리·복식을 대조해 다른 사람으로 바뀐 결과를 버린다. 생성 원본은 slug별로 보존한다. 우하단 다이아몬드가 인물 실루엣과 떨어진 배경에 있는지도 확인한다.
3. **최종 처리** — 합격 원본을 `C:\project\nobg`로 누끼 처리하고, `sw/web-bo/scripts/avatar/reframe.ts --sheet`로 얼굴 크기를 맞춘다. `_sheet-*.png`와 `_report.json`, 최종 800×800 이미지를 열어 정수리·턱·어깨의 잘림, 확대 흐림, 다이아몬드 잔여 여부를 확인한다. 다이아몬드는 **REFRAME 최종 프레임 바깥으로 빠져야 한다.** 남으면 더 여유 있는 바스트샷으로 다시 생성해 크롭한다.
4. **등록** — 얼굴 신원과 복식이 유지되고, 크기·누끼·다이아몬드 검수를 통과한 결과만 `celeb-avatar-register` 절차로 R2·DB에 교체한다. 등록 후 R2 재다운로드본과 서비스 표시를 확인한다. 생성 원본과 탈락본은 사용자 확인 전까지 보존한다.
