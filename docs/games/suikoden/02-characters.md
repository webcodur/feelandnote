# 02. 인물

`roster-data.ts`가 `publication_status='active'` 인물을 끝 페이지까지 읽는다. 고정 시나리오 명단이나 사망 연도 제한을 두지 않는다. 실존·실존과 전승의 중간·허구 구분은 DB의 `REAL/BOTH/FICTION`을 사용한다.

서버는 이름·직함·직군·국적·성별·생몰 연도·아바타 주소·평가 수치·현실성·음성 버전·조회수만 `RosterRow`로 보낸다. 이름과 직함은 요청 locale에 맞추며 영어가 없으면 한국어 원문을 사용한다.

`celeb_persona.persona`의 숫자는 공용 스펙트럼 파서로 읽는다. 평가가 없거나 불완전하면 `roster.ts`가 직군 원형과 지명도로 게임용 능력을 산출하고 화면에 산출값임을 표시한다. 등급과 병력 상한은 `gradeScore()`·`GRADE_THRESHOLDS`·`GRADE_INFO`·`maxTroopsOf()`가 쥔다.

병과 배정과 직군 원형은 `PROFESSION_CLASS`·`PROFESSION_ARCHETYPE`에서 관리한다. 고향 배정은 `map.ts`의 `homeTerritoryFor()`가 국적·직군·생년을 사용한다.

## 판 안의 인물

`Hero`는 명부의 읽기 전용 인물이며, `HeroState`는 소속·위치·병력·훈련·충성·부상·성장·명령 여부·성호를 보관한다. 명부에만 있고 판 안 기록이 없는 인물은 고향의 재야 인물로 읽는다.

방랑 동료, 탐색 후 등용, 방문 인재 수락, 포로 설득으로 인재를 맞이한다. 명성·매력·등급 저항·같은 시대와 국적 등이 확률에 관여하며, 화면의 예상 확률도 실행 함수와 같은 계산을 쓴다.

플레이어 세력에 들어온 인물에게 성호를 배정한다. 현재 소속을 떠난 인물은 집결 수에서 제외하고, 판을 넘어 남기는 성도 기록은 `codex.ts`가 관리한다.
