# 인물 세계 배너 — 발주서 (4판)

인물 상세 맨 위 배너에 까는 세계별 배경 사진의 규격과 세계 39종 발주 내역이다.
판정 규칙(어떤 인물이 어느 세계로 가는가)은 `sw/web/src/lib/celeb/world.ts`, 색·액자·구획 번호를 포함한 전체 상세 테마는 `docs/project/celeb/celeb-detail-themes.md`가 단일원천이며, 이 문서는 **배너 그림만** 다룬다.

> **현재 상태(26.08.03): 운영 적용 완료.** 39개 세계의 네이티브 3:1 원본 39장과 PC·모바일 운영본 78장이 모두 준비됐다. 코드 ID 대조에서 누락·여분·규격 오류·세계 간 동일 파일 중복이 없음을 확인했다.

1·2판 78쌍과 3판 안티그래비티 8쌍은 모두 운영에서 폐기했고, 4판 완료 뒤 중간본과 함께 정리했다. 저장소에는 승인된 4판 원본·운영본만 남긴다.

**4판 개정(26.08.03)**: 안티그래비티의 3:2 출력 제한을 서비스 규격으로 잘못 받아들였던 전제를 폐기했다. 이제 세계당 **네이티브 3:1 파노라마 한 장**을 생성하며, PC는 그 전체를 쓰고 모바일은 세로를 전혀 자르지 않은 채 좌우 초점만 사람이 고른다.

---

## 1. 이전 판이 실패한 이유 — 4판의 출발점

| 폐기한 접근 | 4판 원칙 |
|---|---|
| 고유명사 없는 처마·기둥·벽 조각 | **세계마다 실재하는 랜드마크를 지목한다** |
| 그림 자체를 어둡고 저채도로 구움 | **정상 노출·자연스러운 색으로 생성한다** |
| 글자 자리를 남기려고 가운데를 비움 | **배너 전체를 장면으로 채운다** |
| 삶의 흔적까지 없애 폐허처럼 보임 | **등불·연기·수레·널린 천은 두되 사람은 넣지 않는다** |
| 안티그래비티 3:2 원본에서 위아래를 잘라 3:1을 만듦 | **처음부터 최종 PC 비율 1536×512로 생성한다** |
| 모바일을 기계적으로 중앙 크롭 | **세로는 보존하고 세계별 `mobile-left`를 육안으로 고른다** |

> 생성 도구의 제한은 서비스 규격이 아니다. 최종 자산의 용도와 비율을 먼저 정하고 그 규격을 직접 지원하는 도구로 만든다.

## 2. 왜 사진인가

인물 화보 발주서(`sw/web-bo/scripts/generate-celeb-hero-photos.mjs`)가 "초사실 사진, 붓질·일러스트·CG 렌더 금지"로 못 박혀 있다. 배너 바로 아래에 그 화보가 붙으므로 배너가 회화풍이면 두 그림이 따로 논다. **배너도 사진이다. 다만 사람이 없는 공간 사진이다.**

## 3. 공통 규격 — 39장 전부 동일

| 항목 | 값 | 이유 |
|---|---|---|
| 노출 | **정상.** 어둡게 굽지 않는다. 밝은 낮이든 저녁이든 그 시간대의 제 밝기로 | 어둡게 구우면 디테일이 죽는다. 화면 톤은 덮개가 맡는다 |
| 채도 | **자연스럽게.** 억지로 빼지 않는다 | 같은 이유. 튀는 원색만 피한다 |
| 밀도 | 화면을 가득 채운다. 근경·중경·원경 세 겹 | 한 겹이면 조각으로 보이고 세 겹이어야 세상으로 읽힌다 |
| 랜드마크 | 그 세계를 아는 사람이 한눈에 알아보는 건축·구조물을 **화면의 주인공**으로 | 4절 표에 세계마다 지목해 둔다 |
| 삶의 흔적 | 등불·연기·수레·널린 천·발자국. 사람은 넣지 않는다 | 없으면 버려진 폐허로 보인다 |
| 최종 구도 | 1536×512 전체가 완결된 사진이어야 한다 | 생성 뒤 위아래를 자르지 않는다 |
| 금지 | 글자·로고·간판 문구·사람·얼굴 | |

**원본** — 정확한 3:1 가로형, 최소 1536×512 PNG. built-in `image_gen` 수당송 시험은 2172×724로 생성됐다. 원본은 `sw/web-bo/output/worlds-raw/`에 둔다.

**서비스 파일** — PC **1536×512**, 모바일 **928×512** WebP. 경로는 `sw/web/public/images/worlds/<세계>-pc.webp` · `<세계>-mb.webp`다.

PC와 모바일은 같은 3:1 원본을 쓴다.

- PC판: 원본 전체를 1536×512로 축소한다. 크롭하지 않는다.
- 모바일판: 정규화한 PC판에서 928×512를 가로로만 자른다. `mobile-left`는 자동 중앙값을 쓰지 않고 랜드마크·거리·소품이 온전히 남는 위치를 눈으로 고른다.
- 후처리: `node sw/web-bo/scripts/prepare-world-banner.mjs --id <world-id> --source <원본> --mobile-left <0~608>`.

### 코드 ID와 모바일 초점

파일명은 장면 설명용 영어가 아니라 `sw/web/src/lib/celeb/world.ts`의 ID를 그대로 쓴다. 특히 20세기 전쟁기는 `world-wars`, 신화는 `myth`, 중립은 `neutral`이다. `world-war-era`·`mythic`·`timeless`를 파일명으로 쓰지 않는다.

모바일 `mobile-left` 기본값은 304다. 아래 여덟 세계만 예외다.

| world id | `mobile-left` |
|---|---:|
| `tang-song` | 64 |
| `modern-china` | 240 |
| `ancient-japan` | 320 |
| `steppe` | 0 |
| `ancient-india` | 400 |
| `ancient-near-east` | 400 |
| `ottoman-persia` | 160 |
| `frontier-america` | 240 |

## 4. 화면 쪽 운영 표현

26.08.03 실물 조정에서 검은 덮개와 하단 페이드 계획은 채택하지 않았다. 뒤이어 전체 공간 구도를 다시 보면서 좌우 흐린 확대본과 경계 마스크도 피로를 만든다고 판정해 제거했다. 단색 좌우 여백 역시 실제 PC 화면에서 검은 박스처럼 읽혀 폐기했다. 그림 자체를 정상 노출로 유지하고 다음 방식으로 보여준다.

- 모바일 200px, PC 340px 높이의 배너를 쓴다.
- PC에서는 배너를 입장부와 같은 최대 1024px 면으로 한정한다. 1536×512 원본이 이 면을 `cover`로 직접 채우며, 배너 내부에 별도 좌우 채움 영역을 만들지 않는다.
- 모바일은 장별로 초점을 고른 928×512 파생본이 화면 폭을 `cover`한다. 기기 비율 차이로 생기는 소량의 좌우 잘림은 중앙 안전영역 안에서만 일어난다.
- 같은 그림의 흐린 확대본, 가로 마스크, 검은 덮개·하단 가라앉힘·장식선은 두지 않는다.
- 직군은 배너 색의 근거가 아니므로 직군색 덮개 API 자체를 제거했다.
- PC·모바일 파일 중 하나라도 없으면 `CelebWorldBannerView`의 임시 무늬로 폴백한다. 39세계 운영 파일은 모두 있으므로 정상 상세에서는 나타나지 않는다.

톤을 바꾸고 싶을 때 원본을 다시 생성하지 않고 화면 층으로 조절할 수 있다는 원칙은 유지한다. 다만 현재 승인된 화면에는 별도 톤 층이 없다.

## 5. 발주 문구 뼈대

```
Use case: historical-scene
Asset type: final production website hero banner background
Output canvas: exactly 1536 × 512 pixels, native 3:1 panoramic landscape.
Compose directly for this final canvas. Do not create a taller photograph and do not letterbox.

SUBJECT: <랜드마크>
SCENE: <랜드마크와 세계가 가로 전체에서 완결되는 장면>
SIGNS OF LIFE: <등불·연기·수레·널린 천 등>
LIGHT: <시간대와 방향>

The complete landmark stays inside the final 1536×512 canvas without touching an edge.
Foreground, middle ground and distance are all occupied — no empty stretches.
Normal exposure for the stated time of day. Natural colour. Do not darken or desaturate
the image.
Sharp, real material detail. No painterly brushwork, no illustration, no CGI render.
Absolutely no people or human figures anywhere, including tiny distant silhouettes.
No text, writing, logos, signage or watermark.
```

모바일판은 별도 생성하지 않는다. 같은 원본에서 좌우만 자르되 `mobile-left`를 장마다 육안으로 정한다.

**거리·시장류 장면 주의(26.08.03 시험에서 확인)**: "No people, no text"만으로는 사람과 간판 글자가 들어온다. 사람이 등장할 법한 세계는 첫 줄을 무인·무문자 강제로 세운다 — "Absolutely no people anywhere in the scene - the street is completely empty of figures. No text of any kind: every signboard, lantern and noren curtain is completely blank plain cloth or plain paper, with no characters, no calligraphy, no writing." (에도 시험 1차가 사람 1명·한자 간판 다수로 불합격, 이 문구로 재생성해 통과)

## 6. 세계 39종

## 7. 검수 기준

생성 직후 한 장씩 대조한다. 하나라도 걸리면 다시 뽑는다.

1. **지목한 랜드마크가 화면의 주인공인가** — 조각이 아니라 알아볼 수 있는 전체인가
2. 근경·중경·원경이 다 차 있는가 — 빈 하늘이 화면 절반을 넘지 않는가
3. 사람이 사는 흔적이 있는가
4. 사람·글자·로고가 없는가
5. 1536×512 전체가 그 자체로 완결된 사진인가 — 세로 크롭을 전제로 짠 구도가 아닌가
6. 노출이 정상인가 — 어둡게 구워 넣지 않았는가
7. 시대에 안 맞는 물건이 섞이지 않았는가
8. 928×512 모바일 가로 크롭에서 랜드마크와 핵심 장면이 온전히 남는가

## 8. 진행 상태

### 완료 과정에서 확인한 대표 실패

- 무굴의 미나렛이 여섯 개로 늘어나거나 통일신라 두 석탑이 서로 잘못 복제되는 등, 랜드마크 이름만으로는 구조가 보장되지 않았다. 구조적 특징을 프롬프트에 적고 원본을 확대 검사한다.
- 삼국 장면에 만리장성식 지붕 성루가 섞였고 신화 장면이 그리스 신전으로 기울었다. 시대·문화권 금지물도 함께 적는다.
- 조선·근현대 한국·라틴아메리카·에도 등에서 작은 현판·간판·유사문자가 반복됐다. 거리·시장·궁궐은 무인·무문자 지시를 첫 문장부터 강제한다.
- PC에서 맞는 구도도 모바일에 랜드마크가 함께 안 담길 수 있었다. 핵심 피사체를 중앙 43% 안에 모은 원본만 승인한다.

폐기된 2판 생성기는 정리했다. 새 원본은 built-in `image_gen`으로 네이티브 3:1 생성하고, 운영본 파생은 `prepare-world-banner.mjs` 하나만 쓴다.
