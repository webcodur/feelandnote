# 음성 합성·전사 파이프라인 (범용 구현 명세)

텍스트의 각 문장이 지금 읽히는 시각을 알아내, 영상 자막·글자 점등·웹 하이라이팅이 실제 발화에 붙게 하는 음성 스택을 **이 문서만으로 구현**할 수 있게 적은 명세다. 타 프로젝트에 그대로 이식할 수 있다 — 특정 저장소의 경로·데이터·엔진 배정은 후속 문서(이 저장소에서는 [`voice-pipeline.md`](voice-pipeline.md))가 쥔다.

## 0. 목표·산출물·전체 지도

**산출물 계약** — 단계별로 만들어야 할 것:

| 산출물 | 내용 | 만드는 단계 |
|---|---|---|
| `*.wav` | 정리·정규화 끝난 음성 (24kHz mono 16bit) | 3 합성·후처리 |
| 단어 타이밍 dump | 단어별 `{word, start, end}` 배열 | 5 전사 |
| 세그먼트 타이밍 | 문장별 `{start, end}` + 전체 `duration` | 6 정렬 |
| sub 타이밍 | 자막 한 줄 단위 경계 시각 | 7 청크 |
| 배속 메타 | 필드별 `*PlaybackRate` | 7 속도 조정 |
| 매니페스트 | 잡 해시 → 완료 상태 (재개용) | 3 합성 |

이 문서 전체가 파이프라인이다. 아래 구분은 파이프라인 안의 **단계(phase)**이며, 라벨은 데이터가 어디로 흐르는지를 말한다.

```text
─ 준비 (사람이 한다) ─
1. 환경 설정        무료 TTS 키 묶음, (선택) ElevenLabs, 로컬 도구

─ 생성 (텍스트 → 음성) ─   변경분만 생성, 매니페스트가 잠근다
2. 발화 사전       모호 표기 ↔ 읽기 규칙 결정·등록
3. 합성            키 순회 TTS → PCM → wav
4. 후처리          들숨·쉼 정리 → 라우드니스 정규화

─ 시각 추출 (음성 → 타이밍) ─   음성에서 시각을 뽑아 텍스트에 입힌다
5. 전사            단어 발화 시각 추출 + 원문 문자 매핑
6. 정렬            세그먼트 시각 매핑 + 자동 안전망

─ 조립 (타이밍 → 화면) ─   하이라이팅이 실제로 붙는 층
7. 청크·속도      sub 분할(트랜잭션) + 자/초 배속 산출

─ 품질 (산출물 → 공개) ─
8. 검증            정렬 경고·청크 불변식·길이·품질 QC
9. 대응 루프       기계 [승인|재합성|개선] / 인간 [승인|수동 편집]

─ 참조 ─
10. 수치의 출처    스펙트로그램·파형 측정으로 얻은 관측값 — 재측정 절차 포함
11. 후속 도구      들숨 처리·트리밍·정렬 편집기·Audacity
12. 이식 체크리스트 타 프로젝트 적용 시 필요 요소
```

작업 패턴 `prepare → run → contract → apply` 대응: **prepare** = 매니페스트 해시 비교로 변경분 선별, **run** = 합성·전사 배치(재개 가능), **contract** = 안전망·청크 불변식·preflight 검증, **apply** = 타이밍·배속·음원 등록(직전 백업 포함).

## 1. 사용자 환경 설정

파이프라인이 돌기 전에 사람이 확보한다. LLM은 2단계부터 개입한다.

### 무료 TTS 키 묶음 (주력 합성선)

- Google AI Studio에서 프로젝트별 API 키를 받는다. 계정당 프로젝트 10개까지 가능 — 계정 몇 개를 굴려 키 묶음을 확보한다.
- env 규약: `GOOGLE_GENAI_API_KEY_FREE<n>` 연번 나열(상한 없음, 변수 번호 오름차순 로테이션). 키 풀 열거는 코드 한 곳(`packages/shared/src/lib/gemini-keys.ts`)만 알고 나머지는 import한다.
- **결제 계정이 붙은 GCP 프로젝트 키는 두지 않는다.** 유료 Gemini·Vertex·Cloud TTS 경로를 만들지 않는다.
- 굳이 일레븐랩스에 돈 쓸 필요 없다 — 나레이터·일반 낭독은 무료 키로 충분하다.

### ElevenLabs (실존 인물 고유 목소리 전용, 유료 선택지)

- 유일하게 돈 쓸 이유는 인물 고유 목소리다.
- 계정별 env 키와 목소리 ID를 레지스트리 한 곳에 둔다. 언어가 다른 목소리 ID를 임의 재사용하지 않는다.
- 기본 합성 설정(정본 상수로 한 벌): model `eleven_v3`, stability 0.5, similarity_boost 0.75, style 0.3, speed 1.0.

### 로컬 도구

| 도구 | 쓰는 단계 | 비고 |
|---|---|---|
| ffmpeg / ffprobe | 정규화·정리·길이·PCM 변환 | PATH 필요 |
| Python + whisperx | 전사 | 격리 venv와 구분 — whisperx 설치 인터프리터 명시 지정 |
| numpy | 들숨·쉼 정리 | 경량 |
| Node/tsx | 오케스트레이션 | |
| Audacity(무료) | 수동 음원 수술 | §10 참조 |

## 2. 발화 사전 — 합성 전 텍스트 정리

TTS는 표기 그대로 읽으려 해서 모호 표기에서 틀린다. 합성 전에 "이 문자열을 이렇게 읽어라" 치환 사전을 만든다.

- **치환 대상**: 연도("1865년"→"천팔백육십오년"), 분수·비("13 대 133"), 로마숫자, 약어, 외래어, 고유어.
- **사전 형태**: 문서 JSON 안 `tts.replace` 맵 `{표기: 읽기}`. 합성 직전 본문에 일괄 적용한다 — 원문 텍스트는 건드리지 않는다.
- **등록 루프**: dry-run이 본문 토큰 중 미등록 모호 표기를 검출 → LLM이 읽기 판단 → `--apply`로 병합. 한자어 수사 혼합은 한 방향으로 통일한다(Gemini가 혼합 표기를 엉뚱하게 읽는다).
- 대사가 아닌 태그(`[whispering]` 등)가 음성으로 읽히는 사고(tag-spoken)를 QC에서 잡는다 — §8.

## 3. 합성

### 3.1 API 키 순회·재시도 (무료 키 한도 분산)

```text
keys = FREE<n> 중 설정된 것(변수 번호 오름차순). 로그의 keyIndex(1부터 셈)는 이 배열의 순번이라 변수 번호와 다를 수 있다
keyIndex = GEMINI_START_KEY(1-based) - 1, 클램프
keyRetries = keys.length - 1        # 키 교체 여유분
retries = 5                         # 같은 키에서의 재시도

loop:
  try 합성:
    빈 응답(오디오 데이터 없음) → retries-- >0 이면 2s 후 continue, 아니면 실패 보고
    성공 → PCM 반환
  catch e:
    status 429 | 403 | (400 이며 expired) → keyRetries-- >0 이면 다음 키로 순환
      (keyIndex = (keyIndex+1) % len, 클라이언트 재생성, retries = 5 리셋), 아니면 실패
    status 500 → retries-- >0 이면 3s 후 continue, 아니면 실패
    그 외 → 즉시 실패 보고
```

- SDK 클라이언트는 키를 박아 만들어지므로 **키 교체 = 클라이언트 재생성**이다.
- 미리듣기/단발 호출은 요청마다 이 루프를 새로 돌린다. 사용자-facing 스트리밍 용도면 모듈 레벨 keyIndex를 유지해 요청 간 키를 재사용해도 된다.
- 빈 응답을 조용히 통과시키지 않는다 — 파일을 쓰기 전에 데이터 유무를 본다.

### 3.2 모델·보이스·가이드

- 모델: `gemini-2.5-flash-preview-tts`(기본) / `gemini-3.1-flash-tts-preview`(200+ inline audio tag·70+ 언어, 단가 2배). 사전 보이스 목록: <https://ai.google.dev/gemini-api/docs/speech-generation?hl=ko>.
- 보이스 권장: 남자 `Charon`, 여자 `Aoede`(무난한 대안 `Kore`).
- 발화 가이드: 텍스트 앞 스타일 prefix `"편안하고 자연스럽게"` 권장. 3.1은 `[excited]`, `[pause: 0.5s]` 같은 inline tag도 인식.
- API 호출 형태: `generateContent({ model, contents:[{parts:[{text}]}], config:{ responseModalities:['AUDIO'], speechConfig:{voiceConfig:{prebuiltVoiceConfig:{voiceName}}} }})` → `candidates[0].content.parts[0].inlineData.data` (base64).

### 3.3 출력 포맷 — PCM에 WAV 헤더 씌우기

응답은 헤더 없는 **PCM 24kHz mono 16bit**다. 44바이트 헤더를 씌운다:

```text
RIFF | 36+dataLen | WAVE | fmt␣ | 16 | PCM(1) | ch=1 | sr=24000
| sr*ch*bits/8 | ch*bits/8 | bits=16 | data | dataLen | <pcm 본문>
```

필드는 전부 little-endian. 이 헤더 함수는 정본 하나만 둔다(모든 라우트·스크립트가 공유).

### 3.4 멱등성 — 매니페스트

- 잡 해시(텍스트+보이스+모델)를 매니페스트에 기록. 해시 같은 잡은 건너뛴다 → 중단 후 재개·증분 실행이 공짜.
- 수동 우회 생성(튜닝된 wav 직접 투입 등) 뒤에는 매니페스트를 재기록해 덮어쓰기를 막는다.
- 재합성은 해시를 바꿔 해당 잡만 다시 돌린다 — 전체 재생성 금지.

## 4. 후처리 — 들숨·쉼 정리 + 라우드니스 정규화

wav가 처음 생긴 자리에서 바로 돌린다. 후속 단계는 정리된 음원만 본다.

### 4.1 들숨·쉼 정리 (프로필제)

- **발화 구간을 먼저 제외하고** 조용한 나머지만 건드린다 — 대사가 잘리지 않게.
- 들숨 탐지: 에너지 창에서 흡기 패턴(검증된 들숨 RMS 대역 0.0015–0.0057)을 찾아 룸톤으로 메운다. 큰 실제 호흡은 남긴다 — 잘린 단어보다 낫다.
- 쉼 정리: 문장·쉼표 사이 과한 공백을 천장→목표로 줄인다. 프로필별 `(pause_max, pause_target)`: **낭독 (1.20, 1.05)초, 대사 (1.10, 0.95)초**.
- **소스 샘플레이트를 유지한다** — 44.1kHz MP3 대사를 24kHz로 리샘플했다가 대역폭이 반토막 난 사고가 있었다.
- 모든 합성 경로(배치·미리듣기·대사 생성)가 이 한 구현을 거치게 한다.
- 알고리즘 전체(엔벌로프·탐지 상수·룸톤 채우기·trim 규칙·실패 사례)는 §11.1이 쥔다.

### 4.2 라우드니스 정규화 (ffmpeg loudnorm 2-pass linear)

```text
1-pass 측정:
  ffmpeg -hide_banner -nostats -i IN -af "loudnorm=I=-17:TP=-1.5:LRA=11:print_format=json" -f null -
  → stderr의 JSON에서 input_i·input_tp·input_lra·input_thresh·target_offset 파싱

2-pass 적용:
  ffmpeg -y -i IN.raw -af "loudnorm=I=-17:TP=-1.5:LRA=11:linear=true
    :measured_I=..:measured_TP=..:measured_LRA=..:measured_thresh=..:offset=.."
    -ar 24000 -ac 1 OUT.wav
```

- 목표값 **I=-17 LUFS, TP=-1.5 dBTP, LRA=11**. -17 근거: ElevenLabs 네이티브 출력이 약 -17이라 엔진 혼용 구간의 음량 튐이 없다(과거 -19 기준에서 약 2dB 어긋남).
- **linear=true는 게인만 조정한다**(압축·톤 변경 없음) — 그래서 ElevenLabs 음원도 그대로 통과시켜도 안전하다.
- 원본은 `.raw/`에 백업한다.

## 5. 전사 — 단어 시각 추출 + 원문 매핑

1. whisperx로 전사 + 단어 timing을 뽑는다.
2. **diff-match-patch로 전사 문자를 원문 문자에 대조해 원문 단어에 시각을 이식한다.** whisperx가 발음을 다르게 인식해도("일리아스로"→"인리아스로") 원문 단어 위치에 정확한 시각이 붙는다 — 이 매핑이 하이라이팅 정확도의 핵심이다.
3. 출력은 파일 단위 단일 dump(`{파일키: [{word,start,end}...]}`) — 중단돼도 직전 상태 유지, 기존 키에 병합.

⚠ **음원을 크롭·재합성했으면 전사부터 다시 밟는다.** 시각은 음원 기준이라 크롭 전 결과를 재사용하면 경계가 밀린다.

## 6. 정렬 — 세그먼트 시각 + 자동 안전망

단어 시각을 세그먼트(문장)에 매핑한다. 신호처리 코어는 순수 함수로 분리해 모든 시리즈가 공유한다. 강제 정렬(forced-align)·ASR 단독 재구현 금지 — WhisperX 단어 타이밍 + 파형 보정만 쓴다.

### 6.1 신호처리 코어 (상수 포함)

아래 상수는 이론값이 아니라 실제 합성 음원을 스펙트로그램·파형으로 관측해 정한 측정값이다 — 출처와 재측정 방법은 §10.

| 함수 | 하는 일 | 상수 |
|---|---|---|
| `parseWav` | 헤더 파싱, data 청크 → Float32 samples | |
| `detectSilences` | 창별 RMS로 무음 구간 탐지 | 창 20ms, RMS<0.015, 최소 무음 0.2s |
| `trimWordLeadingSilence` | 단어 앞 무음 트림 | 창 10ms, 무음바닥 0.005, 발화온셋 0.02, 스캔 상한=구간의 70%, 무음 0.3s 미만·트림 0.05s 미만이면 패스, 10ms 여유 |
| `mergeIntoPhrases` | 단어를 구절로 병합 | 간격 0.5s+면 페이드아웃 경계 |
| `adjustPhraseBoundaries` | 구절 시작을 직전 무음 끝으로 당김 | 뒤로 최대 1.0s 탐색, 연속 무음 50ms(5창) 필요, 당김폭 0.1–1.5s |
| `fixNumericWordTimings` | 숫자·한글수사(`^\d`·`^[천백십만억]`) 단어의 비정상 단축 보정 | dur<0.4s 이며 예상(음절×0.18s, 0.5–2.0 클램프) 대비 비율<0.4 → 앞뒤 갭으로 확장(앞 90%·뒤 50%, 부족분은 앞 80%×0.7+뒤 80%×0.3) |
| `analyzeWithSilence` | 전사 없을 때 폴백: 문장 글자수 비례로 경계 추정 후 최근접 무음에 스냅 | 무음 중심과 추정 경계 거리 < duration×0.25, 가장자리 무음(0.5s 이내) 제외 |
| `computeSubTimings` | sub 경계 시각 산출 | 세그먼트 ±0.05s 안 단어만, 정규화 문자 누적 비율로 경계 배분, 다음 단어 시작 쪽 bias 0.75 |

### 6.2 자동 안전망 — 확신 있는 오류만 복구

저장 전 `voiceTimings`에 두 규칙만 적용한다:

| 증상 | 판정 | 복구 |
|---|---|---|
| 음수 duration | `end < start` — 정렬 실패의 가장 명확한 증상 | 다음 세그먼트 시작-0.05s까지 확장(없으면 start+max(0.5, 예상길이)) |
| 극단 찌부 | 실제 duration < 음절수×0.13s×0.5, 그리고 5자 이상 | 음절×0.13s로 확장 |
| 텍스트 앵커 | 화면 전환 시각이 문자열(예: `"imageChangeAt":"텍스트"`)로 남음 | 해당 텍스트의 발화 시각으로 해소, 매칭 실패 시 경고 |

**복구하지 않는 것**: ±0.5초 미세 어긋남 — 인간 편집기 영역(§9). 복구된 건 로그에 남겨 사람이 최종 확인한다.

## 7. 청크 분할 + 속도 조정 — 글자 점등이 붙는 층

### 7.1 sub 청크 (자막 한 줄 단위)

- sub 하나 = **자막 한 줄**. 요구사항이 없으면 임의 문자수로 자르지 않는다.
- 기준 상수: **30자 초과 세그먼트는 sub 분할 대상으로 보고, sub 하나의 상한은 35자**(초과 시 재분할 보고). 두 값은 정렬 경고와 청크 검증이 같은 상수를 import한다.
- 불변식: **`sub.join(' ') === text`**. 하나라도 깨지면 전체 abort, 디스크 미수정(트랜잭션).
- 분할 우선순위·금기: 쉼표+공백 경계 우선, 고유명사 파괴·보조용언 분리 금지.
- `subTimings`는 §6.1 `computeSubTimings`로 산출. 없으면 렌더가 글자수 비례로 폴백한다.

### 7.2 속도 조정 — 자/초 통일

- 필드별 목표 자/초(기본 6.5)를 정하고: `rate = 목표cps ÷ 실제cps` (실제cps = 글자수 ÷ duration).
- **클램프 0.5–2.0은 렌더 쪽 상수가 정본** — 산출 스크립트가 같은 상수를 import해 dry-run과 렌더가 갈라지지 않게 한다.
- 원본 wav·타이밍 파일은 건드리지 않는다. 스크립트 적재 시점에 duration·voiceTimings·화면전환 시각을 일괄 1/r 스케일한다.

## 8. 검증

| 검증 | 통과 기준 |
|---|---|
| 정렬 경고 | sub 미처리·과대 청크·비정상 duration 0건 |
| 청크 검증 | 깨진 sub·누락(30자 초과 미분할)·과대(35자 초과) 0건 — `--check` 모드 |
| 발화 품질 QC | 전사 재대조: `low-match`(원문 대조로 판단)·`unmatched-tail`(꼬리 잘림)·`tag-spoken`(태그 읽음) — 후 둘은 공개 전 해소 필수 |
| 화면 유지시간 | 음원 길이 ↔ 화면 표시 길이 일치 — 어긋나면 목소리가 잘림 |
| 발행 preflight | 파일 전량·메타데이터 확인 → `--apply`, 기존 음원은 `_backup` 보존 |

## 9. 대응 루프

실패 산출물의 분기. **기계는 규칙으로 설명 가능한 실패를, 인간은 취향·미세 타이밍·판단이 필요한 실패를** 담당한다.

### 9.1 기계 대응 — [승인 | 재합성 | 기계 개선]

- **승인**: 검증 통과분 → 다음 단계. 재실행 시 재생성 안 함(매니페스트).
- **재합성**: 빈 응답·꼬리 잘림·텍스트 레벨 발음 오류 → 발화 사전 갱신 + 해당 잡 해시 갱신 후 재큐. 키 한도는 자동 순회가 이미 처리.
- **기계 개선**: 같은 실패가 구조적으로 반복되면(특정 패턴 오독·특정 길이 잘림) 데이터가 아니라 **파이프라인 코드를 고친다** — 안전망 규칙 추가·분할 규칙 보강·엔진 옵션 조정. 건별 수동 패치로 메우지 않는다.

### 9.2 인간 대응 — [승인 | 인간 개선]

- **승인**: 검수 화면에서 구간을 들어보고 통과.
- **인간 개선**: ±0.5초 미세 어긋남 → 동기화 편집기 드래그. 발음이 구조적으로 틀림 → 발화 사전에 규칙 추가(기계가 다시 쓸 규칙이 된다). 음질 불량 → 보이스·스타일 prefix 조정 후 해당 잡만 재합성 승인.

## 10. 수치의 출처 — 스펙트로그램·파형 측정

이 문서의 임계값은 이론이 아니라 **실제 합성 음원을 스펙트로그램·파형으로 관측해 정한 측정값**이다. 어떤 값이 어떤 관측에서 나왔는지를 남겨 둔다 — 값의 근거를 모르면 다음 사람이 임의로 고친다.

| 값 | 관측 근거 |
|---|---|
| 들숨 RMS 대역 0.0015–0.0057 | 실제 합성물의 흡기 구간을 파형 에너지로 측정한 검증 대역. 대역 밖의 큰 호흡은 실제 호흡이라 남긴다 |
| 쉼 천장·목표 (낭독 1.20/1.05, 대사 1.10/0.95초) | 문장·쉼표 사이 공백 길이를 듣고 파형으로 재어 정한 값. 대사 끝 직전에 발화가 붙는 비율(대사 54%·낭독 28%)을 측정해 정리 강도를 프로필로 나눴다 |
| 무음 임계 0.005·0.015·0.02, 창 10–20ms | 실제 wav 에너지 분포에서 무음 바닥과 발화 온셋이 갈리는 지점을 관측한 값 |
| 음절당 0.13s(찌부 판정)·0.18s(숫자 보정) | 한국어 합성 발화의 관측 음절 길이. 정렬 실패 구간에서 실제 발화 길이를 재어 정함 |
| 당김폭 0.1–1.5s, 연속 무음 50ms, 다음 단어 bias 0.75 | 실제 정렬 오차 사례를 파형으로 확인하며 조정한 경계값 |
| 라우드니스 -17 LUFS | ElevenLabs 네이티브 출력을 측정해 맞춘 값(과거 -19 기준에서 약 2dB 튐이 관측됨) |
| 자/초 6.5 기본 | 한국어 낭독의 듣기 자연스러운 관측 발화속도 |

**시스템 자체가 무너지면 스펙트로그램으로 돌아간다.** 정렬이 엉키거나 들숨이 잘리거나 음량이 튀는 등 상수가 안 맞는 증상이 나오면 코드를 뜯기 전에 실제 wav를 스펙트로그램으로 열어 무음 바닥·발화 온셋·에너지 분포를 다시 측정한다. 이 상수들은 관측값이라 **엔진·보이스·언어·샘플레이트가 바뀌면 무효가 될 수 있다** — 새 환경에서는 추측으로 고치지 말고 재측정한 값으로 정본 상수를 갱신한다. 도구는 Audacity(무료) 스펙트로그램 뷰나 파형+RMS 스크립트면 충분하다.

## 11. 후속 대응 도구 구축

합성 파이프라인 밖에서 쓸 후처리 도구 셋. 각각 독립 실행 가능해야 한다 — 파이프라인 장애 시 손으로 굴리는 비상 도구이기도 하다.

### 11.1 들숨·쉼 정리기 (구현 명세)

§4.1 정책의 실제 알고리즘. numpy + ffmpeg로 구현한다. **모든 합성 경로(배치·미리듣기·대사 생성)가 이 한 구현을 호출하게 한다.**

**1) 디코드·엔벌로프**

- ffmpeg로 모노 s16le PCM 디코드, **소스 샘플레이트 유지**(리샘플하면 대역폭이 반토막 난다).
- RMS 엔벌로프: 창 25ms, 홉 10ms.

**2) 들숨 구간 탐지 → 룸톤 채우기**

```text
발화 보호:  env >= 0.030 인 프레임 ±0.040s 는 전부 보호(protected)
후보:       env > 0.0012(노이즈 바닥 위) 그리고 ~protected
들숨 판정:  후보 연속 구간 길이 0.06–0.80s, 그리고 구간 최대 env < 0.010
채우기:     파일 자체의 노이즈바닥(env < 0.0012) 프레임을 이어붙인 룸톤 풀에서
            무작위 오프셋으로 채운다 — 디지털 0 금지(아래 실패 사례)
경계:       8ms 크로스페이드 가중치로 섞는다
폴백:       조용한 구간이 0.2s 미만이면 RMS 0.0005 정규잡음으로 대체
```

**3) 쉼·앞뒤 정리(trim)**

- 발화 판정: env ≥ 0.005, 보호 마진 ±0.040s.
- 앞머리: 첫 발화 0.08s 앞까지만 남기고 절단. 꼬리: 마지막 발화 뒤 0.25s 남기고 절단.
- 중간 공백: gap > pause_max 이면 **중간을 깎는다**(양 끝 마진 보존) — `remove = gap - pause_target`, 최소 0.02s 이상만.
- 프로필 `(pause_max, pause_target)`: **낭독 (1.20, 1.05), 대사 (1.10, 0.95)초**.
- 인코딩은 출력 옆 staging 파일로 먼저 쓰고 `os.replace` — 실패한 인코딩이 반쯤 쓰인 원본을 남기지 않는다.

**실패 사례(측정으로 얻은 금기)**:

- **0으로 지우면 안 된다** — 조용한 구간을 디지털 0으로 만들면 전사기가 환각을 낸다("다음 영상에서 만나요" 같은 아웃트로를 지어냄). 공개 음원 964개 중 26개가 이 사유로 QC 실패. 반드시 파일 자체의 룸톤으로 채운다.
- **"들리는 이벤트" 탐지기로 들숨을 못 잡는다** — 들숨은 발화의 1/100 진폭이라 0.010 바닥으로 찾으면 발화를 집는다(전사 매칭이 0.9882→0.9622로 악화, 단어 85→83개 손실). 발화를 먼저 빼고 조용한 나머지에서 찾아야 한다.
- **들숨 피크 상한(0.010)을 넘는 구간은 단어 끝의 감쇠부다** — 채우면 단어 끝이 잘린다. 실제 사례에서 채움의 54%(대사)·28%(낭독)가 발화 직후를 덮고 있었다. 검증된 들숨은 0.0015–0.0057 — 더 큰 진짜 호흡을 남기는 게 잘린 단어보다 낫다.

### 11.2 트리밍

앞뒤 무음·여유 구간 크롭은 11.1의 trim 단계가 이미 한다(HEAD_KEEP 0.08s·TAIL_KEEP 0.25s). 별도 크롭 도구를 만들 필요는 없고, **크롭 뒤에는 전사·정렬을 다시 밟는다**(§5 경고 — 시각은 음원 기준이라 재사용하면 경계가 밀린다).

### 11.3 텍스트 정렬 세부조정 편집기

§9.2의 인간 개선 창구. 필요한 최소 기능:

- 세그먼트별 파형 표시 + start/end 경계 드래그(±0.5초대 미세 어긋남 수동 수정이 목적).
- 수정 결과는 타이밍 파일(`voiceTimings`/`subTimings`)에만 다시 쓴다 — wav는 절대 건드리지 않는다.
- 미리듣기로 확인 후 저장. 저장은 해당 세그먼트만 패치한다.

### 11.4 딥한 오디오 처리 — Audacity로 위임

EQ·노이즈 리덕션·컴프레서·클릭 제거 같은 일회성 음원 수술은 파이프라인에 넣지 말고 **Audacity(무료)**로 대응한다. 자동화 가치가 없는 일회성 작업이다. 수술한 음원을 파이프라인에 되넣으면 전사·정렬부터 다시 밟는다(§5 경고).
