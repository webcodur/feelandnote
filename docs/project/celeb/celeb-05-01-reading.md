# 인물 읽어보기

> 현재 사용자 화면의 읽어보기는 `인물 안내`와 두 번째 모드 `가상독백`을 노출한다. 이 문서는 안내의 한국어
> `plain_text`와 영어 `plain_text_en`을 작성·검수·게시하는 규칙 SSoT다.

## 현재 범위

`FigureReadingTabs.tsx`는 안내를 렌더하고, 가상독백이 있으면 `인물 안내 / 가상독백` 모드 탭을 세운다. 가상독백은 `getCelebBySlug`가 화면 언어로 골라 인물 상세 데이터에 함께 싣는다. 가상독백 원고 규칙은 `celeb-04-03-virtual-monologue.md`가 쥔다. `celebServiceItems.ts`의 `person-explore` 항목은 닫혀
있다. DB의 `interpretive_title*`·`interpretive_text*`는 삭제하지 않고 보존하지만, 사용자가
인물 탐구를 되살리라고 명시하기 전에는 생성·재작성·게시 기준에 포함하지 않는다.

한 인물의 작업 단위는 한국어와 영어 안내 두 필드다. 한쪽만 고치거나 게시하지 않는다.

## 조사와 작성

먼저 이름·소속·직군·생몰로 동명이인을 막는다. 원전·본인 저작·직접 인터뷰·공식 기록·학술·
권위 자료를 우선하고, 위키백과와 위키데이터는 신원과 생애 개관에 쓴다. 현대 인물은 본인의
모국어 자료와 본인 매체도 확인한다. 검색 결과의 잘린 문장이나 기자의 요약을 본인 발언으로
바꾸지 않는다. 프로필 이름이 영문 이름과 여러 출처의 통용명에 명백히 어긋나면 안내를 쓰기 전에
프로필 결함으로 보고한다. 이름을 추측해 고치지 않는다. 시작 동기와 `세웠다`·`이끌었다`·
`성장시켰다` 같은 인과·주도성은 자료가 개인의 행동을 직접 확인할 때만 쓴다.

안내는 처음 보는 독자가 누구이며 무엇을 했고 왜 알려졌는지 이해하게 쓴다. 생애를 전부
나열하지 않고 정체를 설명하는 중심 행동이나 생각 하나를 고른다. 중심에는 그 사람이 직접 한
행동이 있어야 하며, 대표 업적을 지운 뒤 왜 유명한지 알 수 없게 만들지 않는다. 전문용어는
지우지 말고 같은 문장에서 일상어로 푼다.

첫 문장은 `[인물명]은/는 …이다.` 완결문 하나로 쓴다. 인물명은 프로필 이름 그대로 쓰고, 조사는
이름 끝 받침에 맞춘다. `하데스는 그리스 신화에서 망자들을 다스리는 신이다.`처럼 이 한 문장만
읽어도 정체가 드러나야 한다. 이름을 뺀 `그리스 신화에서 망자들을 다스리는 신.` 같은 명사구,
`…신다.`처럼 `이다`를 줄인 꼴, `…신입니다.` 존댓말은 쓰지 않는다. `본명 이혜빈.`처럼 인적사항
한 조각이나 대명사·성만으로 시작하지 않는다. 음성으로 들을 때도 첫 문장이 문장으로 끝나야 한다.

짧은 이야기는 극적인 일화를 뜻하지 않는다. 한 행동·질문·생각이 다음 문장을 불러오고 결과나
의미에 닿으면 된다. 자료가 받치면 `문제나 질문 → 직접 한 행동 → 달라진 결과`를 잇되, 모든
인물에게 위기와 반전을 만들지 않는다. 마지막 문장은 이 흐름을 닫고, 별개의 수상·판매량·죽음·
최신 이력을 새로 붙이지 않는다.

각 문장은 같은 중심을 밀어야 한다. 인과 없이 서로 다른 업적을 붙이지 않고, 사건을 시작했으면
자료가 허용하는 범위에서 결과까지 닫는다. 별명·성격·역할·관장 영역은 구체적 행동을 대신하지
못한다. 판본·편찬 연도·장 번호·발굴자·긴 존호는 인물을 이해하는 데 필수일 때만 남긴다.

날짜·나이·수량·직함·고유명사는 그것을 지우면 행동의 원인이나 결과를 이해할 수 없을 때만
남긴다. 중심과 무관한 최초·유일·최장 수식은 정체 설명에 붙이지 않고, 같은 사실을 수치나 다른
표현으로 되풀이하지 않는다. 작품·전투·정책을 여러 개 쓰려면 같은 선택이나 변화로 이어져야 한다. 이어지지 않으면
대표 하나만 고른다. 아직 실행되지 않은 계획·목표·예고는 결과를 대신하지 못한다. 팀 소속
인물은 팀의 작품·차트·수상을 개인의 행동처럼 쓰지 않는다. 확인된 개인 행동이 적으면 팀
이력을 대신 채우지 말고 짧게 끝낸다. 널리 통용되는 한국어 작품명·단체명이 확실하면 한국어
본문에 영문 이름만 남기지 않는다.

평범한 동사를 우선하고 장식용 은유, 영웅화, 설교형 결말, `깊이 있는 연기를 선보였다`·`대중의
신뢰를 얻었다` 같은 인명사전식 찬사를 쓰지 않는다. 평가는 행동과 결과로 보여 준다. 결정적
행동에서는 사람을 주어로 세우고 수식어가 누구의 판단이나 행동을 가리키는지 분명히 하되, 첫
문장의 정체 설명이나 문맥상 자연스러운 사물 주어까지 기계적으로 바꾸지 않는다.

한국어는 한국인이 처음부터 한국어로 쓴 글처럼 쓴다. 개념은 이름으로 직접 부르고, 긴 관형절로
돌려 말하지 않으며, `~한 X였다` 명사문보다 동사로 끝낸다. 한국어를 확정한 뒤 같은 사실과
확신의 정도를 보존해 영어를 쓴다. 영어 첫 문장은 프로필 영문 이름으로 시작해 정체를 밝힌다.

### 형식

- 한 문단으로 쓴다. 줄바꿈을 넣지 않는다.
- 분량과 문장 수의 허용 범위는 `sw/web-bo/scripts/celeb/reading/format.ts`의 `READING_FORMAT`이 쥔다.
  범위는 인물마다 들쭉날쭉하지 않게 하는 틀이지 품질 기준이 아니다. 재료가 얇으면 하한 근처에서
  끝내고, 채우려고 사실을 늘어놓지 않는다.
- 한국어 본문에는 괄호를 쓰지 않는다. 원어 병기·생몰년·부연은 문장으로 풀거나 뺀다. 음성이
  괄호 속을 한 번 더 읽는다.
- 작품명은 책·영화·드라마·음반·게임처럼 한 편으로 선 작품에 《》, 노래·시·그림·단편·회차처럼
  작품의 일부나 작은 작품에 〈〉를 쓴다. 「」『』와 반각 <>, 따옴표를 작품명에 쓰지 않는다. 따옴표는 직접
  인용과 별칭에만 쓴다.
- 문장 강조는 `reading-voice-timing.mjs`의 `readingSentences`가 나눈다. 라틴 약자 뒤 마침표
  (`사무엘 L. 잭슨`, `J.K. 롤링`, `S.E.S.`)는 경계로 보지 않으므로 이름과 약칭은 표기 그대로 쓴다.
  제목 속 느낌표·물음표는 경계가 되므로 `《모차르트!》` 같은 제목은 `《모차르트》`로 쓴다.
- 영어 본문에는 한글과 한국어 문장부호를 넣지 않는다.

## 검수

1. 처음 보는 독자가 이 사람이 누구이고 무엇으로 알려졌는지 알아볼 수 있는가.
2. 한국인이 처음부터 한국어로 쓴 글처럼 자연스럽게 읽히는가.

둘을 만족하면 통과한다. 판정할 때는 「이 글을 읽고 독자가 이 인물에 대해 새로 알게 되는 것을
구체적으로 적어라. 없으면 없다고 적어라」로 묻는다. 다만 명백한 사실 오류, 팀·조직의 일을 개인에게
돌린 표현, 한영 의미 차이는 함께 고친다. 이력·작품·수치만 늘어놓아 인물을 알아보기 어렵거나
번역투·인명사전 말투가 남아 있으면 실패다. 「형식」을 어기면 글이 좋아도 실패다.

`readings.ts --stats`는 현재 DB 본문을 「형식」으로 검사해 위반 사유별 건수를 내고, `--screen-out`
경로를 주면 위반 목록을 쓴다. 반영 전 원고는 `reading/check-format.ts <원고 JSON> [<인물 이름 파일>]`로
같은 검사를 거친다. 형식을 통과한 글도 위 두 질문은 읽어서 판정한다.

기존 글이 기준을 통과하면 본문을 보존한다. 실패한 글만 조사부터 다시 한다.

## 게시와 저장

- 게시 여부는 `published_at` 하나로 나타낸다. 검수를 통과한 active 인물만 `published_at`을 기록하고,
  `published_at IS NULL`이면 공개 조회에서 빠진다. 인물을 active로 바꿔도 안내가 저절로 게시되지
  않는다.
- 한국어와 영어 안내를 한 행 갱신으로 함께 저장한다.
- `interpretive_*`는 기존 값을 그대로 보존한다.
- 설명 행이 없는 신규 인물은 한영 안내만 작성한다. DB의 닫힌 필드가 `NOT NULL`이므로 기존
  안내 전용 반영 관례와 같은 `미작성` 표식만 넣고 인물 탐구 내용은 생성하지 않는다.
- 선검수 결과·초안·조사 캐시·실패 사유는 실행 중 임시 폴더에만 두고 DB 반영과 실패 인계가
  끝나면 삭제한다.
- 반영 뒤 DB 재조회와 한국어·영어 실화면을 확인한다.

`sw/web-bo/scripts/celeb/readings.ts`의 생성·반영 경로는 안내 두 필드와 `published_at`만 갱신하고,
닫힌 인물 탐구 네 필드는 반영 전후 값을 대조해 보존한다. 직접 쓴 원고는 `slug`·`guide`·`guideEn`
배열 JSON으로 `--slugs … --rewrite-existing --generate --editorial-candidates=<파일> --apply --publish`에
넘긴다. 「형식」을 어긴 원고는 DB에 쓰지 않고 보류한다. 이 경로는 외부 모델을 부르지 않는다.
`--stats`는 읽기 전용 현황 확인에만 사용한다.

## 데이터

- 본문: `celeb_explanations.plain_text`, `plain_text_en`
- 공개 조건: `celeb_explanations.published_at IS NOT NULL`
- 닫힌 필드: `interpretive_title`, `interpretive_title_en`, `interpretive_text`, `interpretive_text_en`

## 읽어보기 음성

일일 생성·검수·등록의 현재 도달점은 [지속 작업 문서](../../continuous/celeb-tts-reading.md)가 쥔다.

전체 1회 생성 → 검수·등록 → 불량분 재시도는 `sw/web-bo/scripts/celeb/reading-voice-batch.mjs`가 자동으로 이어 실행한다.
기본 실행은 생성 API 한도에 도달하면 확보된 음성의 검수·통과분 등록을 한 차례 수행하고 기록을 저장한 뒤 종료한다. `--status`로 실제 실행 여부와 진척·중단 사유를 확인한다.
한영 안내 음성의 생성·속도 보정·MP3 변환·등록은 `sw/web-bo/scripts/celeb/reading-voice.mjs`,
본문 대조·음향·문장 사이 쉼 검수는 `sw/audio-bo/scripts/celeb-reading-voice-qc.py`가 담당한다.
실행 옵션은 생성 스크립트의 `--help`, 처리 기준과 임계값은 각 코드가 쥔다.

음성은 `voice-path.ts`의 `reading` 경로를 사용하고 기존 `voice_v`로 캐시를 갱신한다.
웹은 현재 본문 언어의 MP3가 재생 가능한 것으로 확인된 경우에만 중앙 조작부를 표시한다. 브라우저 기본 음성은 사용하지 않는다. 재생·일시정지·정지, 10초 앞뒤 이동, 재생 위치와 속도 조절을 제공한다.
생성 폴더의 원본과 `manifest.json`을 유지해 재개 시 합성을 반복하지 않는다.
문장 강조 시각은 최종 MP3 검수의 단어별 시각을 본문과 대조해 `reading.json`으로 함께 등록한다. 생성·등록은 `sw/web-bo/scripts/celeb/reading-voice-timing.mjs`, 기존 등록분 보완은 같은 폴더의 `reading-voice-timing-backfill.mjs`가 맡는다. 웹은 본문 해시·음원 ETag·길이가 일치할 때만 문장을 강조하며, 연결되지 않은 문장은 강조를 생략한다.

### 본문 교체와 음성

웹은 음원이 있으면 본문과 달라도 재생 버튼을 띄우고 문장 강조만 끈다. 본문만 바꾸면 옛 음성이 새
본문과 다른 내용을 읽는다. 기존 안내를 다시 쓸 때는 이 순서를 지킨다.

1. 본문을 폐기하기로 판정한 인물의 등록 음성을 먼저 내린다.
   `node --import tsx scripts/celeb/reading-voice-unpublish.mjs --slugs <slug,…> --run <run> --apply`가
   R2 음원과 문장 타이밍을 run 백업에 받은 뒤 지우고, `voice_v`를 올려 옛 주소 캐시를 끊고, 인물 캐시를
   비운다. 같은 run의 manifest 항목도 백업으로 옮긴다.
2. 새 한영 본문을 `readings.ts`로 반영하고 게시한다.
3. 같은 run에서 `reading-voice.mjs --slug <slug> --generate --publish`로 새 본문의 음성을 만든다.
4. 등록과 문장 강조를 확인한 뒤 run의 `_backup`을 지운다.
