# 독서 방식 이어하기

작성·수정·계정 운용과 단독 실행은 [독서 방식 룰북](../project/celeb/celeb-05-02-reading-way.md)이 쥔다. Gemini에 보내는 규칙은 그 문서의 `<!-- argon -->` 구간만 쓴다.

## 현재 재개 지점

26.11.12 원로 인물(26.11.11 신규 등록 19명)을 웹 Gemini Pro 계정의 Argon 높음으로 마쳤다. 14명을 저장했고, 장윤정·영탁·주현미·조용필·이미자는 원고와 책장이 모두 비어 조사 미달이다(아래 「다시 쓸 인물」). 인물 인자는 참조 링크 없이 DB의 이름·생몰·직업만 넣었다. Argon 한도가 찬 계정은 새 대화가 Flash-Lite로 떨어진다(26.11.12 u3). 보내기 전에 모드 표시가 Argon 높음인지 확인하고, 아니면 보내지 않는다. 다음은 오스틴 올레드(아래 「다시 쓸 인물」)·아만 생어·정유정이고, 그 뒤는 `buildRoster`로 다시 고른다. 같은 계정의 웹 한도는 옆 컴퓨터와 공유한다.

이건희·이어령·무스타파 술레이만은 26.11.07의 Argon 본문이 저장돼 있고 재작성이 남았다. 당시 작업 폴더의 미반영 원고는 한 컴퓨터의 임시 폴더에만 있으므로 재개 입력으로 쓰지 않는다. Carbon 새 대화에서 조사부터 다시 하고, 저장 때 착수 시점의 한영 값과 비교해 다른 세션 변경을 덮어쓰지 않는다.

과거에 맥락 수정을 지적해 다시 쓰게 한 인물은 이전 원고·지적을 보내지 않고 새 대화에서 조사부터 다시 한다. 국소 오류만 고친 건은 재작성에서 뺀다. 복구한 본문에 빠진 책이 있으면 감상 근거를 확인해 책장도 연결한다.

다음 대상은 현재 DB와 블로그 대장으로 선정한다. 과거 명단·계정 번호·한도 시각이나 삭제된 임시 작업 폴더를 재개 입력으로 쓰지 않는다. 블로그 쪽은 `D:/feelandnote/blog-assets/naver-blog/posts.json`의 `readingWay.sourceHash`와 현재 DB 본문의 UTF-8 SHA-256을 비교한다.

**자원 배분(26.11.15 사용자 지시):** 웹챗과 CLI는 별도 한도로 동시에 소진한다. CLI(agy)는 한 번에 한 계정만 붙으므로 Ultra 계정(Carbon)으로 독서 방식 신규 조사·출처 검증·영어본을 인물당 1프로세스로 동시에 돌린다. 웹챗은 Ultra 탭(u4)에서 Carbon, 프로 계정 탭에서 Argon만 열린다. 프로 계정은 판본 처리·감상 백필(`export-books2`, `RW_MODEL=argon`)에 쓰고, Argon 결과는 실행자가 출처 대조를 한 겹 더 한다. 계정 배정(26.11.15 사용자): `topstarpicks001~005`는 맥북이 쓰므로 이 컴퓨터에서는 웹·CLI 모두 쓰지 않는다(`AGY_EXCLUDE_ACCOUNTS`에 넣었다). 이 컴퓨터의 웹 Argon 계정은 webcodur·tlwns5598·bytebodybalance·famebookorg, Carbon은 Ultra다. **26.11.18 12:40 사용자 지시: `webcodur.us001`은 계정 오류가 있어 작업에서 뺀다(웹·CLI 모두, `AGY_EXCLUDE_ACCOUNTS`에 넣었다). 다시 쓰라는 말이 있을 때까지 아래 내용은 기록으로만 둔다.** 26.11.18 사용자가 Ultra 20x 계정 `webcodur.us001`을 더했다(자유롭게 쓴다). CLI는 계정 풀에 등록돼 `agm switch webcodur.us001@gmail.com --target agy`로 Carbon이 열리고, 웹은 Aside 프로필 `u2`에 로그인돼 있다. 자동화 브라우저(ego)에도 같은 날 사용자가 로그인해 두었다(웹 Gemini의 `u/N` 번호는 계정 목록으로 확인해 쓴다). 번호는 다시 로그인하면 바뀐다 — 26.11.18 11시에는 u/0 webcodur, u/1 tlwns5598, u/2 famebookorg, u/3 tk001, u/7 bytebodybalance, u/8 us001이었고, 그 전까지 u/4였던 tk001이 u/3으로 밀려 번호를 박아 둔 발송 스크립트가 계정 불일치로 멈췄다. us001의 웹 Carbon 높음은 첫 두 건에서 오류 없이 원고와 근거표를 냈다(같은 날 tk001은 두 건에 한 건꼴로 「An error occurred」). 새 대화의 모드 표시는 Flash-Lite로 뜨므로 발송 전에 Carbon 높음 선택을 확인한다. famebookorg는 Gemini 웹이 신형 메뉴(「사고 수준」 하위 메뉴)라 발송 함수가 아직 고르지 못하고, CLI는 26.11.15 agm 풀에 등록했고 Argon이 열린다(Ultra 한도가 차면 이어 쓴다). CLI 계정은 컴퓨터 전체에서 하나라, 원고 재료 생성(`prep-batch`)의 책 소개 요약이 쓰는 계정 순환(`agy-text`)이 호출 실패 한 번에 Ultra를 다른 계정으로 바꿔 Carbon 작업을 끊는다(26.11.15). 둘을 동시에 돌리지 않고, CLI 동시 호출은 4개 안팎으로 묶는다(13개를 몰았을 때 30분 시간 초과가 잇따랐다). 독서 방식을 새로 저장하면 본문에 나온 책을 같은 날 판본·감상까지 채운 뒤에만 블로그 원고 재료를 만든다(26.11.15 샬라메·오타니 등 18권을 빠뜨린 채 재료를 만든 일).

**Argon 책장 보완 결과의 검수(26.11.15):** Argon 높음의 책장 보완 JSON은 그대로 반영하지 않는다. 오타니 4권은 출처에 없는 합숙소 독서 장면을 지어냈고 2018년 출간 책을 닛폰햄 시절에 읽었다고 썼으며, 대표 출처로 댄 산케이스포츠 기사에는 네 권 모두 언급이 없었다. 에반스는 본문의 마이클 싱어 『될 일은 된다』를 발세카의 책으로 잘못 짝지었다. 그래서 (1) 책마다 본문 『』의 저자·작품과 같은지 실행자가 먼저 맞추고, (2) Ultra CLI Carbon이 출처를 다시 열어 감상배경을 고치고 확인한 `source_url`을 돌려주며, (3) 실행자가 그 기사 본문에 책 이름이 실제로 나오는지 확인한 뒤 결정 파일을 만든다.

**한도 판정은 모델별로 한다(26.11.16):** CLI의 「Individual quota reached」는 호출한 모델 계열에만 해당한다. Argon·Carbon이 막힌 Pro 계정에서도 Hydrogen은 돌았고, 블로그 책 선정·소개 요약 단계는 Hydrogen부터 쓴다. 한 모델이 막혔다고 「CLI 소진」으로 적고 CLI 작업을 통째로 보류하지 않는다. `agm list`의 잔량은 낡은 값일 수 있으니 `agm validate` 뒤 쓸 모델로 짧게 불러 확인하고, 구간마다 다시 잰다. 웹도 계정 하나로 몰지 않는다. Ultra 한 계정과 Pro 계정들에 한 건씩 걸고, 거절·빈 응답이 난 건은 계정과 모델을 바꿔 다시 채운다.

**목록형 출처로 책장 보완(26.11.16):** 웹 모델이 막혀도 돌릴 수 있는 길이다. 인물이 직접 고른 추천 목록(《더 위크》 여섯 권, 원그랜드북스 열 권, 파이브북스·버슬 인터뷰)이 출처인데 그 목록의 책이 책장에 다 없는 인물을 찾아, 원문을 직접 읽고 빠진 책을 감상과 함께 넣는다. 출처 주소별 관계 수만으로는 누락을 가릴 수 없다(같은 책이 다른 출처 주소로 이미 있는 경우가 절반을 넘었다). 원문 제목을 책장의 국문·영문 제목과 맞춰 본 뒤, 「&」·「and」나 연작 합본처럼 표기가 다른 중복을 반영 단계의 중복 검사로 한 번 더 거른다. 감상 첫 문단은 본인이 원문에 쓴 평만 옮기고, 서점이 쓴 소개문을 본인 발언처럼 쓰지 않는다. 본인 저서, 본인이 읽지 않았다고 밝힌 책, 논문·잡지는 넣지 않는다. 한국어판을 카카오에서 확인하지 못한 책은 OpenLibrary 판본 기록(제목·저자·ISBN·출판사)이 있을 때만 영문판으로 등록한다. 책장이 늘면 블로그 글의 제목·목록 표·하단 권수를 함께 맞추는데, 옛 양식 글은 표 갱신이 실패하므로 공개 화면의 표에 새 책이 들어갔는지 직접 확인한다(권수 점검은 표를 보지 않는다).

**책 나열형 재작성(26.11.14 소급 완료):** 「책을 늘어놓지 않는다」 규칙을 어긴 저장본은 기존 본문을 단서로 붙여 웹 Carbon 높음 새 대화로 다시 쓴다. 단서에는 「웹 검색·유튜브 도구를 쓰지 말고 기존 원고의 사실만으로」와 「8분 안에」를 넣는다. 기존 본문은 출처 대조를 거쳤으므로 새 원고는 기존 문장과만 맞추고, 영어본은 기존 영어 인용을 살려 실행자가 맞춘다. 기계 집계(가장 붐비는 문단의 『』《》 6개 이상, 500자당 6개 이상)는 후보만 뽑고 대상은 실행자가 읽어 정한다. 본인 작품·방송 낭독 책이 많거나, 책마다 일화가 붙었거나, 책이 독서 방법·학습 경로·창작 계기 안에서 움직이는 글은 나열형이 아니다. 26.11.14 예약·대기 글 인물 8명과 기계 후보 138명 중 36명을 다시 써 소급을 마쳤다. 조국·한동훈·이재명·윤석열·정청래는 짝 균형 때문에 보류했다. Carbon이 정치 인물에게 불리한 독서 사실(박정희 『나의 투쟁』)을 지우면 기존 원고 문장으로 되살린다. 평가어는 붙이지 않는다(룰북 「책을 늘어놓지 않는다」 다음 문단). 블로그 글이 있는 인물은 옛 인용형 목차 글을 `apply-reading-way`가 거부하므로 `prep-batch`로 선정·요약을 만들고 `prepare-unified-articles --reading-way --selections` → `run-unified-articles`로 다시 쓴다. 다른 세션이 먼저 고친 원고를 덮지 않도록 보내기 직전과 저장 직전에 DB 본문이 착수 시점과 같은지 확인한다. Carbon 생성 오류(「An error occurred」)는 탭 수와 무관하게 잦으므로 새 대화로 다시 보낸다.

조사·본문 저장·블로그 반영은 본 세션이 직접 수행하고, 새로 필요한 작품·판본은 '대기 - 판본 (수령)' 세션에 인계한다.

## 실행 진입점

현행 본문·감상배경 작성은 룰북 「단독 실행 도구」의 웹채팅 경로([`scripts/browser/reading-way-web/`](../../scripts/browser/reading-way-web/))로 한다. 아래 러너는 집계·다음 대상 확인과 export 함수 제공에 쓴다.

저장소 루트에서 실행한다. 아래 계정 표기는 구문 예시이므로 현재 로그인 계정과 High 선택 가능 여부를 확인해 바꾼다.

```powershell
# 모델 호출 없이 현재 DB 집계와 다음 대상 선정
node --import tsx scripts/browser/reading-way-argon.mjs --summary
node --import tsx scripts/browser/reading-way-argon.mjs --limit 10

# 한국어 원고만 회수
node --import tsx scripts/browser/reading-way-argon.mjs --apply --collect-only --limit 10 --pool u0:0,u0:2

# 본문을 바꾸지 않는 별도 책장 조사
node --import tsx scripts/browser/reading-way-argon.mjs --apply --books-only --only TARGET_SLUG --pool u0:0
```

회수 뒤의 무료 웹채팅 번역·본문 저장·도서 메타 확인·감상 관계 삽입·기존 블로그 수정은 룰북의 「단독 실행 도구」를 따른다. `draft_ready`·`books_pending`은 회수 상태이며 DB 반영 완료가 아니다. 회수 전용 러너는 정상 종료하므로 실행자는 회수 뒤 검수·무료 번역·저장·블로그 반영을 이어서 처리하고 다음 인물로 넘어간다. 러너를 띄우거나 원고를 회수했다는 보고만 남기고 턴을 끝내지 않는다. 진행 화면의 실행점은 [브라우저 도구 README](../../scripts/browser/README.md)에 있다.

저장 단계가 `query returned no rows` 등으로 실패해도 글이 이미 저장됐을 수 있다. 다시 생성하기 전에 DB 값과 원고를 대조하고, 일치하면 캐시만 갱신한다.

`--books-only` 재실행이 첨부 단계에서 `Current input attachment missing`으로 멈춘 사례가 있다(26.11.06, 원고 회수는 같은 날 정상). 일시 장애인지 Gemini 화면 변경인지 가리지 못했다. 재현되면 첨부 단계를 먼저 고치고, 이 문단을 지운다.

응답이 「웹 검색 중」에서 멈추는 사례가 있다(26.11.07). 중지 버튼이 없고 새로고침하면 대화가 비어 있어 기다려도 나오지 않는다. 정상 응답은 2~5분이므로 8분을 넘으면 끊고 새 대화로 보낸다. 원문을 첨부한 재검수는 「새 웹 검색이 필요 없다」고 적으면 1~2분에 끝났다. 무료 번역기는 입력을 한 줄로 보내므로 영어 문단 구분이 사라질 수 있다. 저장 전에 한국어 문단 수와 대조한다.

러너는 한 명이라도 High 확인이 보류(`model_verification_pending`)되면 배치 전체를 멈춘다. 남은 인물은 따로 다시 보낸다. 새 대화 전체 검수와 단서 재조사는 CLI 옵션이 없어 러너의 `submit`·`collect`를 import해 쓴다. 본문이 있는 인물은 `--feedback`으로만 대상이 되고, 단서 파일은 본문이 빈 인물에게만 첨부된다.

맥락을 짚지 않는 전체 검수는 문장을 다듬을 뿐 근거 없는 주장을 거르지 못했다(26.11.08, 4건 모두). 근거 없는 대목이 그대로 남거나 오히려 늘었다. 저장 전에 문장 단위로 원출처를 대조한다.

## 블로그 후보 인물 작성 (26.11.10 착수)

네이버 신규 글 후보(`sw/web-bo/scripts/naver-blog/lib/roster-data.mjs`의 `buildRoster` 후보) 가운데 독서 방식이 빈 실존 인물을 후보 순번대로 쓴다. 착수 시점 1,020명이었다. 대상은 매번 `buildRoster`를 다시 계산해 현재 DB로 고른다. 발송·회수·저장은 룰북 「단독 실행 도구」의 웹채팅 경로를 따른다.

`--books-only` 또는 웹채팅 책장 보완 경로로 감상경위를 받아 반영하고, 끝난 줄은 지운다. 현재 후보는 [body-gap.mjs](../../scripts/browser/reading-way-web/body-gap.mjs)로 다시 뽑는다(26.11.16 기준 전체 780명 1,813건, `--reading`은 읽기 동사 근처만 458명 761건이며 그중 제목 앞 저자가 책장 저자와 같아 이미 있을 가능성이 큰 `sameAuthor` 110건). 본문 책 제목은 『』와 《》 두 표기가 섞여 있어(본문 1,194개 중 《》 483개) 둘 다 잡는다. 「사진을 올렸다」처럼 읽기 동사가 없는 문맥은 `--reading`에서 빠지므로 전체 목록도 본다(장원영 『위대한 개츠비』). 본문 번역 제목이 책장 한국어판 제목과 다른 오탐도 있다(멍거 『타이탄』=『부의 제국 록펠러』). 책장 항목에 영문 제목만 있는 책도 같은 오탐을 낸다(26.11.16 스위셔·샌드버그·바치갈루피·시에나 길로리). 웹 책장 보완은 ego의 Pro 계정(u/2 tlwns5598·u/3 famebookorg·u/8 bytebodybalance, u/0 webcodur)에 나눠 보낸다. topstarpicks는 맥북 몫이라 쓰지 않고, u/1 feelandnote는 무료 등급이라 Argon이 잠겨 있다. 26.11.16 실측으로는 계정마다 Argon 높음 요청 7건 남짓에서 「코드 및 분석 한도」가 차고, 한 시간 남짓 뒤에 풀렸다. 웹 원고는 출처 원문을 다시 열어 확인한 문장만 남긴다. 기계 대조는 후보일 뿐이라, 인물 이름만 거론한 책(26.11.16 앤서니 홉킨스의 본회퍼·플라톤·아인슈타인은 기자가 붙인 책 제목이었다)과 남이 읽은 책은 빼고 원출처에서 본인의 독서를 확인한 책만 반영한다.

26.11.15 전수 대조: 본문이 있는 1,121명 가운데 510명의 『』 1,515권이 제목만으로는 책장에 없었다. CLI Argon으로 본문 문장과 책장 목록을 대조해 가르니 실제 누락 275권, 다른 제목·옛 번역명으로 이미 있음 410권, 감상 대상 아님(본인 저서·잡지·영화 등) 830권이었다. 제목 대조에서 괄호 부제·쉼표 차이(『타클라마칸(돌아올 수 없는 사막)』·『목수들아, 대들보를…』)와 옛 제목(『암굴왕』=『몬테크리스토 백작』)이 오탐을 만든다. 처리 순서는 블로그 대기열 인물 → 공개 글 인물 → 나머지다. 웹챗에는 그 인물 기존 감상의 서점 아닌 근거 주소를 참조로 넘긴다. 참조가 비면 Argon은 쓰지 않으므로 실행자가 먼저 원문을 찾는다. 웹이 원문을 열지 못한 책은 실행자가 원문을 읽고 직접 쓴다(26.11.15 나태주·샬라메). 반영기가 「이미 연결됨」으로 막으면 기존 감상을 원문과 대조하고 그대로 둔다.

## 글과 책장 전수 대조 결과 (26.11.08)

독서 방식이 있는 424명의 본문을 두 갈래로 검증했다. 다시 돌리면 [reading-way-shelf-scan.mts](../../scripts/browser/reading-way-shelf-scan.mts)가 책장에 없는 후보를 낸다. 기계 후보 수를 누락 수로 읽지 않는다.

- **책장에 없는 책.** 후보 1,003건을 LLM이 문맥·책장으로 거르고 원문을 확인해 153건을 책장에 넣었다. 근거를 못 찾은 책은 깊게 재조사해 찾으면 등록하고, 끝내 없으면 본문에서 뺐다.
- **책장에 있는 책.** 본문 문장 1,228건을 그 책의 감상 콘텐츠와 대조하고, 어긋난 258건만 소스 링크로 확인했다. 틀린 쪽이 감상이면 감상을 고쳤다. 감상 콘텐츠가 있으면 이 대조가 웹 검색보다 싸고 정확하다.
- 본문은 모두 175명을 고쳤고 블로그 독서 방식 구획도 같은 값으로 교체했다.

- 주제 문장의 근거까지 무너진 10명은 Argon High로 새로 썼다. 원문 대조를 거쳐 7명을 저장했다. 판빙빙·궁리·조이 웡은 Argon이 근거 부족으로 빈 원고를 냈고 책장에도 감상 책이 없어 조사 미달로 저장했다. 같은 상태였던 `hans-zimmer` `lee-kun-hee`는 다른 세션이 맡았다.
