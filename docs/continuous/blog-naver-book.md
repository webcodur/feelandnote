# 네이버 블로그

블로그 [`blog.naver.com/dmx777`](https://blog.naver.com/dmx777)는 책과 인물에 관심 있는 독자가 필앤노트의 기록을 보고 책의 구매·광고 링크까지 도달하게 하는 입구다. 사이트 링크를 넣는 데서 끝내지 않고, 글에서 소개한 책과 인물의 기록이 실제 광고 링크까지 이어지는지 확인한다. 독자가 원문으로 들어올 수 있도록 블로그·카페 링크 공유와 외부 공유를 허용하며, 본문 전체를 복제하는 공유는 허용하지 않는다.

사이트는 인물 페이지 `/celeb/{slug}`의 서재(`#library`)에서 실제 감상 기록과 책별 구매 단추를 보여 준다. 작품 상세 `/content/{contentId}?category=book`에서도 구매 링크로 이어진다. 서점 링크는 서점 선택창을 연 뒤에 나타나므로 첫 화면의 링크 목록만으로 구매 경로가 없다고 판정하지 않는다. 글마다 소개할 책의 작품 상세가 열리고 YES24 단추와 인물의 감상이 실려 있는지 확인한다. 인물 하단 「관련 상품」에는 독서 기록 외의 연관 상품도 섞이므로 그 목록 전체를 그 인물이 읽은 책으로 소개하지 않는다. 구매 버튼 규칙은 [ContentPurchaseAction.tsx](../../sw/web/src/components/features/commerce/ContentPurchaseAction.tsx)가 쥔다.

## 왜 운영하는가

- 사이트 유입의 9할이 네이버 검색이다. 한국에서 "OO 추천 책"을 치는 사람은 네이버에 있고, 네이버는 외부 사이트보다 자기 블로그 글을 위에 올린다.
- 2020년부터 쌓인 글과 방문이 있는 계정이다. 새 채널을 키우는 비용 없이 쓸 수 있다.
- 블로그 글이 사이트 링크를 늘리고 네이버 유입이 실사용 신호를 만든다. 구글 회복에도 보탬이 된다.

## 작업 환경과 원장

블로그 작업은 이 컴퓨터에서만 한다. 코드만 저장소에 있고 아래 셋은 저장소 밖에 있다.

| 리소스 | 위치 | 비고 |
|---|---|---|
| 원장·초안·사진·백업 | `D:/feelandnote/blog-assets/naver-blog/` | git 밖. 다른 컴퓨터는 `BLOG_ASSETS`로 경로를 덮는다. 외부 사본이 없으니 디스크 손상에 대비한다 |
| 네이버 로그인 Chrome 프로필 | `C:/project/_chrome-naver` | 모든 편집 도구가 이 프로필을 쓴다([`lib/browser.mjs`](../../sw/web-bo/scripts/naver-blog/lib/browser.mjs)) |
| DB 접속 키 | `sw/web-bo/.env` | 배치·이전은 [`platform-04-env-vars.md`](../project/platform/platform-04-env-vars.md) |

글 번호·대상·처리 상태는 `posts.json`이 쥔다. 초안은 `drafts.json`(기관)·`celeb-drafts.json`(인물)에 쌓고 발행하면 `posts.json`으로 옮긴다. 발행 여부는 초안의 `status`가 아니라 `posts.json`으로 판정한다. 개별 수정 원고는 `revisions/`·`remaining-institution-revisions/`(기관), `celeb-revisions/`(인물)에 있고, 기관 전체 목록 한국어 교정의 전후 자료는 `table-ko/`에 있다. 사이트 URL이 바뀌거나 인물이 비공개되면 이 원장으로 고칠 글을 찾는다.

### 완료 기록은 원장 필드로 본다

완료한 정비도 DB 감상·책장이 바뀌면 다시 고친다. 그래서 작업 이력을 문서에 쌓지 않고, 글마다 마지막으로 검증한 상태를 원장 필드에 남긴다. 다시 고칠지는 이 필드를 현재 서비스 값과 대조해 정한다.

| 필드 | 뜻 | 쓰는 도구 |
|---|---|---|
| `link` | `ok`·`check`가 활성 글. `deleted`·`private`·`replaced`·`to-delete`는 정비 대상에서 뺀다 | `link-existing`·`delete-posts` 등 |
| `scheduledAt` | 예약 시각. 실제 예약 목록과 대조해 쓴다 | 발행·예약 도구 |
| `bodyStyle` | 본문 서식 버전과 검증 단락 지문(`textsSha256`·`paragraphs`). `verify-body`의 대조 기준 | 전체 입력 도구·`restyle-body`·`apply-reading-way`·`replace-reviews` |
| `readingWay` | 독서 방식 구획의 원문 해시와 검증 시각 | `apply-reading-way(-batch)` |
| `fullList` | 인물 「전체 감상 목록」 표의 책장 해시·권수 | `apply-person-full-list` |
| `mobileLayout` | 모바일 판형 개편 완료 | `apply-mobile-layout` |
| `curatedTable` | 기관 선정 목록 표 서식 적용 | `restyle-curated-table` |
| `unified` | 통합 원고 해시. 독서 방식 도구가 저장하며 지우므로 입력 경로 판정에 쓰지 않는다 | `apply-unified-article`·`publish-unified-new` |
| `editorial`·`revisionSha256` | 개별 수정 원고 반영 표시. 현행 통합 양식 완료 표시가 아니다 | `apply-institution-revisions`·`apply-editorial-changes` |
| `curatedIntro` | 기관 글 도입문. 통합 생성기가 쓰고, 없으면 멈춘다 | 사람 검수 |

점검 명령은 모두 읽기 전용이다.

- 권수: `pnpm --dir sw/web-bo naver:audit-book-counts` — 공개 글과 예약 문서의 제목·본문 권수를 서비스 감상 도서 수와 대조한다. 소개 권수와 전체 권수를 구별한다.
- 예약: `pnpm naver:audit-reservations` — 실제 예약 목록을 원장과 대조한다.
- 본문: `pnpm naver:verify-body` — 검증 기준과 순서까지 대조한다.
- 후보: `pnpm naver:roster` → `_roster.md`. 후보 수는 원고 재료 수이며 검수를 마친 편수가 아니다. 선정 조건은 [`roster-data.mjs`](../../sw/web-bo/scripts/naver-blog/lib/roster-data.mjs)가 쥔다.
- 인물 사진: `sw/web-bo`에서 `node --env-file=.env scripts/naver-blog/portrait-board.mjs` → `naver-blog/portraits.html`. 인물 글의 대표 사진을 예약·전체로 나눠 보고, 카드를 누르면 본문 사본을 옆에 띄운다. `--bodies`를 붙이면 사본이 없거나 원장 기록이 사본보다 새 글만 다시 받는다(공개 글은 모바일 화면, 예약 글은 편집기에서 읽기만 한다). 예약 판정은 원장의 `scheduledAt`을 따르므로 원장이 실제 예약과 어긋나면 위 예약 점검을 먼저 돌린다.

독서 방식 구획의 반영 현황과 다음 대상 기준은 [독서 방식 작업 인계](celeb-reading-way.md), DB·블로그 감상 재편 진행은 [감상 재편 인계](../todo/celeb/db-blog-review-handoff.md)가 쥔다.

## 글 유형

글의 출발점은 인물, 기관의 선정 목록, 책 한 권이다.

1. **인물 안내글.** 한 사람의 책과 감상 기록을 소개한다. 기존 인물 글 재작성과 신규 인물 글에 같은 구성을 쓴다. 인물 소개·책 소개·DB 감상 원문에서 사이트의 독서 기록과 구매·광고 링크로 이어진다.
2. **기관 선정 안내글.** 선정 목록 전체와 대표 책의 감상 기록을 소개한다.
3. **책 안내글.** 책 한 권에서 시작해 그 책을 실제로 읽은 인물들의 감상을 모은다. [티스토리의 작품 편 구성](blog-tistory-cinema.md#글의-짜임)을 참고한다. 책의 한국어 제목·저자·표지·간단한 소개 → 인물별 사진·한 줄 소개·DB 감상 원문 → 등장 인물과 전체 감상 기록으로 이어진다. 책과 연결된 구매·광고 링크까지 독자가 따라갈 수 있도록 한다.

원고는 DB의 한 줄 정의·책 목록·감상 배경에서 뽑는다. 사람은 발행 전 훑어보기만 한다. 기계 문체는 저품질 필터에 걸리므로 「한국인이 한국어로 쓴 글 답게 주의해서 작성」을 기준으로 쓴다.

## 사이트와 블로그의 통합 원칙

같은 목록·같은 인물이 한쪽에만 있으면 다른 쪽에 채운다. 방향은 둘이다.

- **블로그에만 있는 목록 → 사이트.** 블로그의 대학 권장도서·언론 선정 목록은 `sw/web-bo/scripts/curated/.tmp/lists/<slug>.json`으로 옮겨 기관 선정에 적재한다. 규격은 [`service-03-curated-lists.md`](../project/service/service-03-curated-lists.md)를 따르고, 원문 발표처 `source_url`을 반드시 찾는다. 블로그는 2차 출처로 기록한다. 살아 있는 페이지의 특정 시점 전사본은 사이트에 담지 않는다. 발표된 판만 목록으로 세운다. 블로그 글을 살리려고 목록을 만들지 않는다. 발표 주체가 없는 묶음(분야별 책추천 시리즈)은 제3자 채널 출전이라 옮기지 않고 블로그에서도 손대지 않는다.
- **사이트에만 있는 목록·인물 → 블로그.** 아래 양식의 안내글 한 편을 낸다. 사이트가 원본이고 블로그 글은 입구다.

## 안내글 양식

기관 선정 목록과 인물 모두 같은 뼈대를 쓴다. 소개와 안내는 간결하게 쓴다. 읽는 사람이 이 목록이 무엇이고 왜 볼 가치가 있는지, 사이트에 가면 무엇을 더 볼 수 있는지 알아야 넘어온다. 서비스 노출 문구이므로 **정중체(~합니다)** 로 쓴다.

```
제목: [{기관 영문 태그}] {목록명} {수} | {headline}
      {수식어} {인물}이 읽은 {권수}권의 책

📚 전체 목록을 작품별로 보기 → https://feelandnote.com/library/curated/{기관}/{목록}
(빈 줄)
소개 3~4문장. 누가, 언제, 어떤 방식으로 선정했는지 / 이 목록이 왜 참고할 가치가 있는지(권위·역사·특징) / 어떤 독자에게 맞는지.
(빈 줄)
대표 작품의 책 제목·표지·책 소개와 인물 표시·DB 감상 배경 원문을 배치한다.
(빈 줄)
기관편은 서비스의 전체 선정 목록을 표로 표시한다. 표 서식(테두리·회색 머리줄·열 너비)은 인물편과 같은 `listTableHtml`(`lib/person-full-list.mjs`)이 쥔다. 연도 또는 순위·작품명·작가를 목록 성격에 맞춰 보여준다.
인물편은 「전체 감상 목록」 구획에 공개 감상 책 전권을 번호·제목·저자 표 하나로 싣는다. 번역서가 없거나 절판된 책은 같은 표의 뒤쪽 줄에 회색 글씨로 두고, 그런 책이 있을 때만 표 위에 안내 한 줄을 둔다. 판정·문구·표 모양은 `lib/person-full-list.mjs`가 쥔다(26.11.11 사용자 지시: 따로 띄우지 말고 디자인으로만 구분).
(빈 줄)
안내 2~3문장. 필앤노트에서 {N}권 전체를 표지와 함께 볼 수 있고, 각 작품을 읽은 인물과 그 인물의 다른 독서 목록으로 이어진다는 것 / 목록마다 국내 번역 여부를 함께 표시한다는 것.
→ 같은 링크
태그: {기관명} {목록명} 책추천 필독서 권장도서 (인물 글은 {인물명} {직군} 추천도서)
```

기관 글의 현재 제목과 도입문은 `posts.json`의 `title`·`curatedIntro`가 쥔다. 통합 생성기는 이 값을 쓰고, 도입문이 없으면 서비스 설명으로 대체하지 않고 멈춘다. 대표 책 선정이 바뀌어도 맞도록 도입문에는 「세 권을 골라 소개합니다」 같은 선정 문구와 인물 나열을 넣지 않는다. 대표 책을 바꾸면 제목에 내건 인물과 권수가 본문과 맞는지 다시 대조한다. 틀어진 글은 [`restore-curated-format.mjs`](../../sw/web-bo/scripts/naver-blog/restore-curated-format.mjs)로 되돌린다.

### headline — 제목의 파이프 뒤 절반

검색 결과에서 제목의 앞 절반은 무슨 목록인지만 말한다. 누를지 말지는 headline이 정한다. 기관 선정 글에만 붙이고 인물 글에는 붙이지 않는다.

- **그 목록에만 해당하는 사실 하나를 적는다.** 고려대 학부대학 100권은 역자·출판사·출간연도까지 지정하는 유일한 목록이라 `어느 번역본으로 읽을지까지 알아보세요`가 됐다. 어느 목록에 붙여도 말이 되는 문장은 headline이 아니다.
- 15~30자, 정중체로 끝낸다.
- **동사로 끝낸다.** `~받습니다`·`~올랐습니다`·`~빠졌습니다`·`~못 합니다`처럼 무언가가 일어나는 문장이어야 한다. `~목록입니다`·`~상입니다`·`~수상작입니다`처럼 명사로 끝내면 제목 왼쪽 절반을 되풀이한다(폐기 예: 「베니스 영화제 황금사자상 89편 | 1932년에 시작한 가장 오래된 영화제의 수상작입니다」).
- 목록의 흐름을 요약하려 들지 마라. `글쓰기에서 시작해 대학을 묻는 책까지 살펴보세요`는 읽어도 무슨 목록인지 모른다.
- 광고 어휘(`인생을 바꾸는`·`필독`·`놓치면 안 될`)와 사물이 주어인 번역투를 쓰지 않는다.
- **같은 기관의 글끼리 headline이 겹치지 않게 한다.** 비슷한 말로 끝나면 저품질 판정을 부른다.
- **혼자 읽어도 뜻이 통해야 한다.** 주어를 빼먹지 마라 — `상금은 10유로지만 그해 가장 많이 팔립니다`는 무엇이 팔리는지가 없다. `문을 열면 이름이 나오는 유령의 집을 건넵니다`도 트로피라는 말이 없다.
- **agy에 후보 5~10개를 받아 그중에서 고른다. 받아 놓고 손으로 고쳐 쓰지 마라.** 위 두 폐기 사례가 후보를 받아 손으로 다듬은 결과다. 프롬프트에는 목록·기관의 성격, 본문이 말하는 사실, 위 규칙과 좋은 예·나쁜 예(실제 폐기 문장)를 넣는다. 호출법은 [`agy-antigravity`](../../.agents/skills/agy-antigravity/SKILL.md) 스킬이 쥔다.

### 본문 규칙

- 본문의 책 제목·수평선은 중앙 정렬한다. 책 소개·감상 본문은 왼쪽 정렬한다.
- 모바일 판형: 본문 15·소제목 16(네이버 모바일에서 16·17px), 목차는 왼쪽 선 인용구 안 왼쪽 정렬, 책장 카드는 구분선으로 목차 구획에 넘어간 뒤 「목차」 라벨과 목차 인용구 사이에 둔다(인물 사진 바로 아래 두면 사진이 연달아 보였다. 26.11.11 사용자 지시, 3판). 크기는 `UNIFIED_ARTICLE.font`, 카드 디자인은 [`person-shelf-card.mjs`](../../sw/web-bo/scripts/naver-blog/lib/person-shelf-card.mjs)가 쥔다(26.11.11 사용자 승인).
- 소개 책은 최대 5권이다. 유효한 후보가 5권 이상인데 소개가 모자란 글은 후보를 골라 통합 재조립으로 다시 쓴다.
- 인물의 독서 방식은 목차 다음·첫 책 소개 앞에 별도 구획으로 넣고 목차에도 추가한다. 인물 안내와 기존 책 본문은 보존하며, DB 원문을 그대로 쓴다. 인용구 목차 판형 글은 `apply-reading-way`가 거부한다. `prepare-unified-articles --reading-way`로 재료를 만들고 `run-unified-articles`로 다시 쓴다. 구획 디자인은 [`reading-way-section.mjs`](../../sw/web-bo/scripts/naver-blog/lib/reading-way-section.mjs), 크기·서체는 통합 원고 양식을 따른다.
- 링크는 서비스 목록 주소를 첫 줄과 마지막 줄에 두 번 넣는다. 첫 줄은 접힌 미리보기용, 마지막 줄은 읽고 난 사람용이다. 개별 출처 문구·외부 출처 링크는 나열하지 않고 근거는 서비스 감상 기록에 둔다.
- 대표 작품은 사이트에 연결된(표지가 있는) 작품 중에서 고르고 한국어 출간명으로 쓴다. 미연결 작품을 앞세우면 도착 페이지에서 흐리게 보인다.
- 전체 목록의 작품명·저자명도 한국어 표기를 우선한다. 원제와 연결된 한국어판의 작품 범위를 대조하며, 3부작·전집·단편집을 개별 작품으로 바꾸지 않는다. 한국어 표기를 확인하지 못한 작품은 원제를 유지한다.
- 인물 사진은 서비스 대표사진(`celebs.portrait_url`)을 쓴다. 아바타로 대신하지 않는다. 기관 글의 감상자 얼굴은 서비스 아바타(`avatar_url`)를 쓰고 표시 폭은 `apply-institution-revisions.mjs`의 `AVATAR_WIDTH`가 정한다. 네이버 대표이미지는 글의 썸네일 지정이라 별도로 확인한다. 인물 안내글은 상단 인물 사진을 대표이미지로 지정하고 저장 후 다시 열어 유지되는지 대조한다. 액자 5번은 책 표지에만 적용하며 기관 로고와 인물 사진에는 적용하지 않는다.
- **감상 배경은 현재 `celeb_contents.review` 원문을 그대로 쓴다.** 장문도 그대로 싣는다. 요약·발췌·각색·LLM 정제, 라벨 앞 별도 요약을 하지 않는다. DB 감상이 없는 항목은 새로 쓰지 않는다. 원문에 오류가 있으면 서비스 감상·영문·출처부터 고치고(같은 관계 ID 유지·재조회·캐시 갱신 확인) 블로그에 반영한다. 사용자가 서비스에서 정비한 1인칭 원문·번역은 화자·말투·문단을 보존한다.
- 표지 선택·판본 대조 과정 같은 작업용 설명은 본문에 넣지 않는다. 책 소개와 실제 학교 목록의 안내는 구분한다.
- **책마다 검수한 소개 4~5문장을 둔다.** 순서는 `책 제목 → 표지 → 책 소개 → 감상한 인물의 사진·수식어·이름 → 구분된 DB 감상 배경 원문`이다. 기관편은 감상마다 `{celebs.title} {이름}`(예: `봄·봄 작가 김유정`) 한 줄로 인물을 표시해 동명이인 혼동을 막고, 인물편은 글 상단에서 화자를 소개한다. 인물 사진과 이름은 함께 중앙 정렬하고 감상은 왼쪽 정렬한다.
  - 책 소개는 **간결체(~다·~한다)** 로 쓴다. 정중체 종결(~니다·~요)이 섞인 소개는 생성 단계에서 막는다. 첫 문장은 [LLM 문구 처리 기준](../project/agent-rules.md#llm의-작업-구분-없는-문구-처리)에 따라 명사형이나 「이다」형으로 맺고 「…경영서다.」 꼴은 쓰지 않는다. 판정은 [`lib/plain-style.mjs`](../../sw/web-bo/scripts/naver-blog/lib/plain-style.mjs)가 쥔다. 인물 안내·서비스 안내 문구는 정중체를 유지한다.
  - 책 소개는 DB에 없으므로 **agy가 짓는다.** 줄거리의 엄밀함보다 「무슨 책인지 전달되는가」가 기준이다. 확실하지 않으면 좁게 단정하지 말고 넓게 쓴다.
  - **출간 연도·수상 이력·판매량·「명작이다」 같은 평가는 넣지 않는다.** 지어내기가 시작되는 자리다. 결말도 적지 않는다.
  - 소개가 감상 배경과 겹치면 소개를 조정하고 DB 감상 원문은 유지한다.
- 소개와 안내는 사실 문장으로만 쓴다. 기관 설명은 사이트 `description`을 그대로 옮기지 않는다. 번역투·단골 문예 어휘·설교형 마무리는 금지다.
- 기존 글에 넣는 첫 줄 링크 문구(`📚 {인물}의 독서 목록 전체 보기 →`)는 명사형 그대로 둔다. 문장이 아니라 표지다.
- 새 글 카테고리는 블로그의 실제 카테고리에 맞춘다. 인물 글은 「거물의 책추천」 아래 직군(기업가·투자자·정치인·학자·배우·작가·아티스트·스포츠인·인플루엔서), 기관 글은 「기관 선정」 아래 서비스 `curators.kind` 하위 분류를 쓴다. 분류 명칭은 `sw/web/messages/ko/library.json`의 `library.curated.kind`를 따르고 상 이름이나 기관의 인상으로 다시 판단하지 않는다. 기본값이 「공지사항」이라 지정을 빠뜨리면 공지로 나간다.
- 네이버 태그 입력은 공백에서 갈라진다. 인물명은 공백을 빼서 넣는다(`#데스틴샌들린`).

## 현재 본문 양식

새 공통 구성·처리 정책은 [`unified-article.mjs`](../../sw/web-bo/scripts/naver-blog/lib/unified-article.mjs)가 쥔다.

**제목과 권수**

- 인물 제목은 대표작·소속과 직업, 이름, 전체 도서 수, 영문 이름 구조다. 작가 선호를 대표 작품으로 소개하는 경우는 개별 책의 실독으로 단정하지 않도록 제목을 「독서 기록」으로 쓰고 감상에 대표 선정임을 밝힌다.
- 권수는 현재 서비스의 공개 BOOK 기록을 작품별로 중복 제거해 집계하며, 본문 소개분과 구별한다. 상단에는 「전체 권수 중 소개 권수」를, 하단에는 나머지 기록과 필앤노트 이동 링크를 안내한다(문구는 [`unified-library-funnel.mjs`](../../sw/web-bo/scripts/naver-blog/lib/unified-library-funnel.mjs)). 감상 관계를 더하거나 지우면 전체 목록 표·제목·상단·하단 권수와 책장 카드를 함께 맞춘다. 독서 방식·감상배경 백필·판본 처리를 한 묶음 끝낼 때마다 해당 글의 본문 사본을 갱신하고(`portrait-board.mjs --bodies`, 사용자가 보는 점검판 `naver-blog/portraits.html`도 함께 다시 만든다) 권수·카드·독서 방식 대조를 다시 돌린다. 새 글을 예약·수정한 뒤에도 같은 명령으로 점검판을 맞춘다(26.11.13 사용자 지시).
- 책 소개 준비가 남은 글은 `apply-existing-title.mjs`로 본문·사진·서식·설정을 보존한 채 제목만 먼저 복원할 수 있다. 제목 전용 검증은 본문 개편 완료로 세지 않는다. 같은 통합 양식으로 검증된 글의 제목·안내 수정은 기존 검증 원고와 사진·책 소개·감상·출처·본문 순서가 같을 때만 [`apply-unified-title-revision.mjs`](../../sw/web-bo/scripts/naver-blog/apply-unified-title-revision.mjs)로 한다.

**구성**

- 인물 도입은 BIO가 아니라 `celeb_explanations.plain_text`의 안내 전문을 문단대로 쓴다. 안내가 없으면 BIO로 조용히 대체하지 않는다.
- 인물 대표사진과 책 표지만 쓴다. 옛 추가 사진·배경음악·영상·중복 명언은 제외한다.
- 인물 안내 다음에 책 제목·전체 목록·하단 한마디·필앤노트 안내를 본문 순서대로 나열하는 번호 목차를 둔다. 네이버의 같은 글 SE 앵커 링크는 새 창으로 열리고 위치로 이동하지 않아 번호 목록을 쓴다. 하단 한마디 항목은 「인용구」로 표시한다.
- 책마다 「책 소개 → 감상 배경 원문 → 감상 근거·원문 → 작품 상세」 순서다. YES24 상품 또는 검색 링크는 사진 설명란의 굵은 중앙정렬 링크로 표지 바로 아래에 붙인다. 설명란은 네이버가 배경색을 제거하므로 배경색을 전제하지 않는다.
- 하단 한마디는 라벨 없이 문장과 그 아래 인물 서명을 중앙정렬해 한 번만 표시하고, 원본 종류·출처는 입력 자료에 보존한다.
- 마무리는 링크 한 줄로 줄이지 않고 필앤노트의 용도를 설명한 문장과 브랜드·인물명·이동 목적이 담긴 링크를 함께 둔다.
- 대표 책은 다섯 권을 기준으로 고른다. 유효한 서비스 감상·출처·표지가 있는 책 전체가 다섯 권 미만일 때만 그 수를 따른다.
- 기관의 선정 목록 전체를 DB와 대조해 공개 인물 감상 연결이 0건이면 선정 도서 다섯 권의 책 소개와 전체 목록만 싣고, 없는 감상 배경·감상자·발언을 만들지 않는다. 이 분기는 선정 목록 출처와 0건 확인이 일치할 때만 허용하며 첫 입력 화면을 저장 전에 검수한다.

**표시**

- 인물명·목차 제목·책 제목·구획명·한마디·마지막 서비스 링크를 굵게 쓴다. 인물 안내·책 소개·독서 방식·감상 배경 본문도 굵게 쓴다(26.11.09 사용자 지시).
- 독서 방식의 갈색, 인물 안내·책 소개의 검정, 감상 배경의 초록은 각 구획의 전용색이며 다른 구획의 강조색으로 빌려 쓰지 않는다. 책 제목·인용문·짧은 용어는 독서 방식·인물 안내·책 소개에서 남색, 감상 배경에서 같은 녹색 계열의 더 짙은 색으로 강조한다. 괄호 설명은 구획 기본색으로 두어 구획당 두 색으로 제한한다. 색상과 HTML 변환은 [네이버 출력 코드](../../sw/web-bo/scripts/naver-blog/lib/formatted-text.mjs), 인라인 판별·부호 변환은 서비스 [`formatted-text.ts`](../../packages/shared/src/lib/formatted-text.ts)가 쥔다.
- 안내·구획명·내용·마무리 사이에 빈 줄을 넣는다. 감상 배경·책 소개의 제목과 첫 본문 사이에는 빈 문단을 넣지 않는다.
- 제목·저자·구획명·목차·구매 링크·한마디·마지막 서비스 설명은 중앙정렬, 「감상 근거 · 원문」과 「작품 상세」는 우측정렬, 장문 안내·감상·책 소개는 왼쪽 정렬한다.

**생산과 입력**

- [`prepare-unified-articles.mjs`](../../sw/web-bo/scripts/naver-blog/prepare-unified-articles.mjs)가 서비스 재료를 모으고 [`prepare-book-summaries.mjs`](../../sw/web-bo/scripts/naver-blog/prepare-book-summaries.mjs)가 AGM–AGY 책 소개 요약·검수를 맡는다. [`assemble-unified-articles.mjs`](../../sw/web-bo/scripts/naver-blog/assemble-unified-articles.mjs)가 검수 통과 요약만 넣어 HTML과 입력 원고를 조립하고 [`apply-unified-article.mjs`](../../sw/web-bo/scripts/naver-blog/apply-unified-article.mjs)가 전체 본문 입력·저장·재열기를 맡는다. 순차 반영은 [`run-unified-articles.mjs`](../../sw/web-bo/scripts/naver-blog/run-unified-articles.mjs), 저장된 글의 검증만 재개할 때는 [`verify-unified-saved.mjs`](../../sw/web-bo/scripts/naver-blog/verify-unified-saved.mjs)를 쓴다.
- 책 소개는 설명문 앞부분을 잘라 쓰지 않고 원자료를 새로 요약한 4~5문장을 별도 검수한다. 같은 책은 작품·저자·ISBN·원자료가 일치할 때만 요약을 재사용한다.
- 조립·입력·검증 반복 중에는 모델을 호출하지 않는다. 신규 문장이나 선정 판단은 쓰기 전 준비 단계에서 끝낸다. 기존 검수 선정이 없는 대량 도서 인물은 기계가 임의로 책을 고르지 않는다.
- 이미지는 각 글을 쓸 때 현재 서비스 원본을 새로 내려받아 업로드한다. 미리보기 HTML에는 이미지를 내장하고, 공개 PC·모바일 검증은 지연로딩 자리표를 제외한 모든 이미지의 실제 로딩까지 확인한다. 표지 형식과 가로형 전집의 표시 크기는 편집 전에 검사한다.
- 입력 부족·실패는 완료로 세지 않는다. 저장 전 표·사진 검증 오류는 `writer-state.json`의 `deferred`에 원고 해시·실패 자료와 함께 보류하고 다른 글을 진행한다. 같은 원고를 반복 재시도하지 않는다. 저장 후 검증 실패와 세션 오류는 전체 중단한다.
- 네이버 작업은 한 편씩 백그라운드에서 실행하고 원래 글 번호·예약 시각·발행 설정을 보존한다.

## 원고 생산 — 조립이 먼저, LLM은 빈칸만

**LLM에게 글 전체를 쓰게 하지 마라.** 서브에이전트에 인물·기관 원고 전체를 쓰게 했다가 176만 토큰을 태운 적이 있다. 원고 대부분은 이미 DB에 있는 값이었고, 에이전트는 그걸 다시 쓰며 원문에서 멀어졌다.

최종 국문은 분량과 관계없이 AGM–AGY Gemini가 작성한다. 주 작업자는 원문 대조·사실 판단·최종 검수와 오탈자·명백한 오류의 국소 수정만 맡는다. 핵심 문구의 작성·재작성은 Gemini에 검수 지적을 전달해 받으며, 호출 실패 때도 주 작업자가 대신 쓰지 않는다.

### 무엇이 이미 있나

| 원고 요소 | 출처 | LLM이 필요한가 |
|---|---|---|
| 책 5권 고르기 | `celeb_contents` + `content_locales` | **아니다.** 아래 규칙으로 스크립트가 고른다 |
| 책별 감상 본문 | `celeb_contents.review` | **아니다.** 현재 DB 원문을 그대로 배치한다 |
| 책 제목·저자·표지 | `content_locales` (ko) | 아니다 |
| 제목·태그·링크·구분선·이미지 표시 | 양식이 고정 | 아니다 |
| 인물 정리 3~4문장 | `celebs.bio` + 선정한 책의 `review` | **압축만** 시킨다. 새로 조사시키지 마라 |
| 제목 수식어 | `celebs.headline` | 줄이는 것뿐 |
| 도입 한 줄·마무리 | — | 그렇다. 감상 배경은 생성하지 않는다 |

### 책 5권을 고르는 규칙 (스크립트)

1. `contents.type = BOOK`
2. 한국어 `content_locales` 에 표지가 있다 — 없으면 도착 페이지가 흐리게 보인다
3. **국문본 우선 선발 및 원서 후순위 배치 원칙:**
   - 국내 정식 출판본(국내 ISBN 보유 및 `sources.title !== 'translated'`)을 최우선으로 선정한다.
   - 인물의 후보 도서 중 국문본이 5권 이상이면 반드시 전권(5권)을 국문본으로만 구성한다.
   - 국문본이 부족하여 부득이하게 미번역 원서를 수록할 경우:
     - 국문본을 반드시 01번부터 앞 순번에 전진 배치하고, 원서는 맨 뒤(04, 05번)로 미룬다.
     - 01번 책은 독자의 유입 및 구매 연결을 위해 반드시 정식 국문본이어야 한다.
     - 원서 제목에는 반드시 `(원서)` 표기를 명시한다 (스크립트 자동 부여).
4. `review`가 비어 있지 않다. 짧은 감상도 후보로 남기며 분량만으로 선정·발행을 차단하지 않는다.
5. 독서 방식 본문에 제목이 나온 책을 먼저 고른다. 한국어판이 있는데 표지·판본 값이 비어 후보에서 빠지면 판본부터 채운다. 국내 판본이 없거나 다섯 권을 넘는 책은 서비스 책장에만 둔다.
6. 구체적인 독서 경위·반응이 풍부한 감상을 우선한다. 스크립트는 [공통 우선순위 비교](../../sw/web-bo/scripts/naver-blog/lib/blog-review-eligibility.mjs)로 본문 분량이 많은 기록을 앞세우고, 주 작업자가 실제 내용을 읽어 판단한다. URL·서식·출처 라벨은 분량에서 제외한다. 인용부호는 보조 기준이다.
7. 다섯을 못 채우면 그 인물은 아직 쓰지 않는다

감상이 풍부한 책으로 다섯 권을 채우기 어려우면 짧아도 유효한 기록을 활용한다. 짧다는 이유만으로 인물을 보류하거나 기존 예약 글을 재작업하지 않는다. 분량을 늘리려고 원문을 각색하거나 1인칭을 바꾸지 않는다.

### LLM이 채우는 빈칸

한 인물당 아래 JSON 하나만 받는다. 300~400자다. 원고 전체를 쓰게 하면 1,500자이므로 **4분의 1 이하**로 준다.

```json
{ "suffix": "수식어", "profile": "인물 정리", "blurbs": ["책 소개 ×5"], "outro": "마무리" }
```

도입(「오늘 만나볼 인물은 X입니다.」)과 안내(「X이 읽은 책들을 살펴볼까요?」)는 고정 문구라 빈칸이 아니다. 외부 CLI를 쓰지 않을 때는 이 JSON을 slug 키로 담은 파일을 `pnpm naver:compose --slug <slug> --fills <파일>`에 넘긴다. 한국어 판본이 특정 장정·묶음 상품이라 소개에 맞지 않는 책은 빈칸 파일의 `exclude`(content_id)와 `excludeReason`으로 빼고 다음 순번으로 채운다.

- 프롬프트에 넣는 재료는 `headline`·`bio`와 고른 책 다섯의 `review` 뿐이다. DB 덤프를 통째로 주지 마라.
- 여러 인물을 한 번에 묶어 부른다. 출력이 작아 배치가 잘 먹는다.
- 조립은 스크립트가 한다. LLM이 `[img:]`·`━━━`·링크를 쓰게 하면 형식 사고가 난다.

대표 책의 소개 원문이 한두 문장이거나 홍보 문구·판본 안내뿐이면 AGM–AGY 요약이 `needs_source`로 막힌다. 같은 작품의 다른 언어판 소개(DB), 서점·출판사 상세 소개, 위키백과 도입부를 `prepare-book-summaries.mjs --supplements=<JSON>`(`{content_id:[{url,text}]}`)로 넘겨 재구성한다. 판본·번역자 정보는 원래 소개의 것만 쓰고, 검수 통과분도 원자료와 대조해 자료 밖 사실이 있으면 지적을 넣어 다시 받는다. 책 자체를 설명하는 자료가 없으면 저자 문서로 채우지 않는다. 카카오 소개가 한 줄인 책도 YES24 상세에는 전문이 있는 경우가 있다.

### 누구를 쓸지도 LLM이 고른다

후보 명단(`pnpm naver:roster`)은 감상 수로만 줄을 세우므로 위쪽이 국내 인지도 없는 인물로 채워진다. 이름만 배치로 넘겨 **국내 독자가 아는 인물인지**를 판정받는다. 사실 확인이 아니라 선정이므로 LLM의 판단에 맡겨도 되는 영역이다. 한 번에 100명씩 묶고 출력은 판정과 한 마디 이유만 받는다.

### 어느 LLM을 쓰나

**agy(제미니)를 기본으로 쓴다.** 로그인 기반이라 종량 과금이 없다. codex는 종량 한도가 있어 소진되면 며칠을 기다린다. agy도 개인 쿼터가 있어 두세 시간마다 막히지만 계정을 바꾸거나 기다리면 회복된다. 두 경로 다 **재실행 안전**하게 만들어 받은 답은 건너뛰게 한다.

책 소개 요약이 같은 인물에서 「agy 시간 초과 (10분)」로 거듭 막히면 계정 문제가 아니라 원자료 부족이다(홍보 문구뿐인 소개 등). 막힘에 `content_id`가 없어 자동 보충이 돌지 않으므로, 그 묶음 책 전부의 알라딘 ISBN 상품 책소개를 `{content_id:[{url,text}]}`로 모아 `prepare-book-summaries`의 `--supplements`로 다시 돌린다(26.11.13 쇼펜하우어·먼로 3회 실패 뒤 보충으로 통과). 기존 글을 다시 쓸 때 선정이 `pending`이고 후보가 많으면(장동선 55권·신경숙 61권) 선정 호출이 같은 시간 초과로 막힌다. 이때는 지금 글의 소개 책으로 `--selections`를 고정해 돌린다.

## 주기와 순서

- 새 인물 글은 **오늘부터 가까운 빈 칸에 12시간 간격으로 예약한다(26.11.03 사용자 지시, 하루 두 칸).** 칸 시각은 [`publish-unified-new.mjs`](../../sw/web-bo/scripts/naver-blog/publish-unified-new.mjs)의 `RESERVATION_TIMES`가 쥔다. 마지막 예약일 뒤에 이어 붙이지 않고 요일도 고정하지 않는다. 실제 예약 목록과 원장을 확인해 기존 예약이 차지한 칸만 건너뛴다. 자동 실행은 두지 않는다. 발행 직전에 사람이 한 번 훑는 것이 이 채널의 품질 장치다.
- **네이버 예약 글은 100편이 한도다.** 넘으면 발행 버튼 뒤에 「예약 글 개수가 100개가 넘어 예약 글로 발행할 수 없습니다」가 뜨고 저장되지 않는다(26.11.13 모리스 창). 예약 글이 공개되는 만큼(하루 두 편) 자리가 생기므로, 짝 글은 두 자리가 빈 뒤에 함께 넣어 한쪽만 예약되지 않게 한다. 자리를 기다리는 글은 `naver-blog/publish-queue.txt`(한 줄에 「slug YYYY-MM-DD HH:MM」)에 정한 칸과 함께 적고, 점검판 `portraits.html`이 이를 「대기」 카드로 예약 글 사이에 날짜순으로 보인다.
- **먼저 잡힌 예약 위에 새 글을 얹지 않는다.** 요일만 보고 빈 날짜라고 판단하지 않는다. `scheduledAt`을 실제 예약 목록과 대조하고, 기존 글을 수정할 때는 원래 예약 시각을 보존한다.
- 기관 선정 큐는 `drafts.json`의 순서대로 나간다. 순서 기준은 국내 검색 수요다: 국내 문학상 → 대중이 아는 상·매체 목록(퓰리처·아카데미·칸·NYT·타임·BBC) → 장르상(SF·추리·공포·로맨스) → 좁은 목록. 몰아 쓰지 않는다.
- **인물 감상이 붙은 작품이 3편 미만인 목록은 발행하지 않는다.** 이 채널의 차별점이 "그 책을 읽은 인물"이라 없으면 흔한 목록 소개 글이 되고 도착 페이지도 비어 있다. 커버리지는 `npx tsx scripts/curated/celeb-coverage.ts [slug...]`로 재고, 기준 미달 초안은 `drafts.json`에서 `status: hold`와 사유를 적어 큐에서 뺀다. 인물 감상을 먼저 채운 뒤 `draft`로 되돌린다.
- 대응 페이지가 없는 글은 방치하지 않는다. 사이트에 넣을 자격이 있으면 적재한 뒤 링크를 넣어 다시 열고, 자격이 없으면 삭제한다. 닫아만 두는 상태를 남기지 않는다.
- 조사·원고 조립·한국어 메타·출처·중복·링크 대조는 로컬에서 묶어 준비하고, 네이버 편집은 한 번에 한 글만 저장·되읽기·종료까지 처리한다. 완료 표시를 확인한 글은 다시 실행하지 않는다. 시간 추정은 정상 종료까지 검증한 첫 글의 실제 소요시간으로 잡는다.
- 글별 유입과 필앤노트 방문·구매 링크 도달은 작업 비중을 판단할 때 참고하되 신규 인물의 산출 순서는 유지한다. 구매 링크 도달과 실제 구매는 구별하고, 측정되지 않은 전환을 성과로 보고하지 않는다.

## 측정

- GA에서 `blog.naver.com` 리퍼러 세션과 그 세션의 인물 페이지 도달률만 본다. 블로그 조회수는 보지 않는다. 조회수가 높고 유입이 없으면 글이 너무 친절한 것이다.
- 월 1회 확인한다. 3개월 뒤 리퍼러 세션이 월 수백을 넘지 않으면 주 1편으로 줄이고, 넘으면 묶음글 비중을 올린다.

## 하지 않는 것

- 쿠팡·광고 삽입. 상업 블로그 판정과 사이트 이탈 둘 다 손해다.
- 사이트에 없는 정보를 블로그에만 쓰는 것. 두 곳 관리가 시작된다.
- 원장 필드로 완료가 확인된 정비를 같은 원고로 다시 돌리는 것. 다시 고치는 경우는 DB 감상·책장·양식이 바뀌어 대조가 어긋날 때다.

## 편집 자동화

네이버는 글쓰기 API가 없다. 로그인된 실제 브라우저에서 SmartEditor ONE을 조작한다. 도구는 기존 Chrome이 없으면 `getBrowser({background:true})`로 같은 로그인 프로필의 headless Chrome을 쓰고, 작업 탭에 페이지 포커스 에뮬레이션을 적용한다. 창을 복원하거나 앞으로 가져오지 않는다(사용자 요청). 디버그 프로필이 로그아웃돼 있으면 [aside-browser 스킬](../../.agents/skills/aside-browser/SKILL.md)로 로그인된 프로필의 예약 목록과 편집기를 쓴다. Chrome 플러그인 경로는 `chrome:control-chrome` 스킬과 [표 편집 보조 함수](../../sw/web-bo/scripts/naver-blog/lib/korean-table-editor.mjs)를 따른다.

본문 서식 정책(강조색·굵기)을 바꾸면 [`BODY_STYLE_VERSION`](../../sw/web-bo/scripts/naver-blog/lib/formatted-text.mjs)을 올리고 `restyle-body.mjs --logs=all --apply`로 기존 글 전체에 반영한다. 재서식은 서비스 표기대로 문장 부호를 바꾸므로(『』→《》, 곧은 따옴표→“”‘’) 옛 초안 본문은 대조 기준이 아니다. 평문 입력 도구(`apply-editorial-changes`·`apply-review-gaps`·`apply-blurbs`)는 저장한 글에 [`restyle-after-save`](../../sw/web-bo/scripts/naver-blog/lib/restyle-after-save.mjs)로 `restyle-body --apply`를 자동으로 이어 실행해 서식을 되돌리고, 재서식이 끝나지 않은 글이 있으면 실패로 끝난다. 입력 전에 서식 있는 HTML로 변환해 붙여넣고, 저장·재열기와 공개 PC·모바일 화면에서 강조색·볼드를 대조한다. 편집도구를 강조 구간마다 열어 적용하지 않는다.

| 명령 (`sw/web-bo`) | 역할 | 입력·출력 |
|---|---|---|

### 올라간 글을 고치는 기법

**고칠 것이 작으면 수단도 작아야 한다.** 액자 하나 두르려고 본문 통째 재작성을 돌렸다가 사용자가 멈춘 적이 있다. 아래는 좁은 것부터다.

| 고칠 것 | 쓰는 것 |
|---|---|
| 문단 하나·표 셀·제목 권수 | `apply-editorial-changes` |
| 감상 배경(DB 감상을 고친 뒤) | `replace-reviews` |
| 인물 전체 목록 표(관계 추가·삭제 뒤) | `apply-person-full-list --refresh` + 권수는 `apply-editorial-changes` |
| 기관 전체 목록의 작품명·저자명 | `lib/korean-table-editor.mjs` 또는 `apply-editorial-changes`의 표 셀 수정 |
| 독서 방식 | `apply-reading-way --replace` |
| 서식·책 소개 문체 | `restyle-body` (`--blurbs`) |
| 사진에 액자 | `publish-drafts --frame-only` |
| 책을 바꿈 | 재료를 다시 만들어 `apply-unified-article` 통째 입력 |
| 본문이 망가짐(옛 초안 글) | `publish-drafts --rewrite`. **마지막 수단이다** |

- **한 벌 먼저 손으로 만든다.** 일괄 양식은 한 편을 손으로 완성해 사용자가 고친 뒤 그것을 규격으로 삼는다. 규격 없이 일괄 처리부터 돌리면 전부 같은 방식으로 틀린다.
- **검증은 「있는가」가 아니라 「순서까지 같은가」로 한다.** 있는지만 보던 검사는 다른 책의 감상이 끼어들고 라벨이 두 번 나온 글을 통과시켰다.
- **일괄 처리 뒤에는 표본을 눈으로 연다.** 단락 수·이미지 크기 같은 숫자로 먼저 거르고 실제 화면을 캡처해 본다. 숫자만으로는 액자가 두 겹인 것을 잡지 못한다.
- **위험한 편집에는 스스로 멈추는 조건을 건다.** 제목·본문 전체·사진 수·구분선·발행 설정·예약 시각을 전후와 재열기에서 대조하고, 하나라도 달라지면 첫 오류에서 멈추고 완료 표시를 남기지 않는다.
- **편집기가 lazy로 그리는 것은 크기로 판단한다.** 편집 화면 이미지 대부분은 `data:image/svg+xml` 자리표다. 자리표도 실제 크기는 반영하므로 적용 전후의 크기를 대조한다. 화면 캡처는 해당 사진으로 스크롤한 뒤 로딩이 끝나야 찍는다.
- 대량 교체는 한 편씩 저장→재열기 대조를 하고 첫 오류에서 멈춘다. 완료 기록만 재실행에서 건너뛰므로 중단 후 재개가 안전하다.
- 기관의 장문 감상은 유효한 DB 원문을 보존하고, 검수한 간접 독서 경위만 수정 원고의 `dbReviews[].reading_note`에 쓸 수 있다. 이 문장은 원문 SHA-256에 묶어 원문 변경을 감지한다. 수정 원고는 `editorial: true`, 인물 주인공은 `celeb.portrait_url`, 감상 라벨은 `dbReviews[].note_label`로 원문과 분리한다. 문단 조작과 크기는 [`editorial-editor.mjs`](../../sw/web-bo/scripts/naver-blog/lib/editorial-editor.mjs), 공통 서식은 [`editorial-layout.mjs`](../../sw/web-bo/scripts/naver-blog/lib/editorial-layout.mjs)가 쥔다.

크롬을 직접 띄울 때는 아래로 띄운다. 로그인 유지를 켜지 않으면 창을 닫을 때 세션이 사라진다.

```
chrome.exe --remote-debugging-port=9222 --user-data-dir=C:\project\_chrome-naver --disable-features=CalculateNativeWinOcclusion --disable-backgrounding-occluded-windows --disable-renderer-backgrounding
```

### 편집기 함정

한 번 잡힌 함정이라 반복하지 않는다.

**세션·열기**

- **브라우저 작업 전 로그인 상태를 먼저 확인한다.** `postwrite`가 `nid.naver.com` 로그인 화면으로 넘어가면 세션이 끊긴 것이다. 디버그 크롬과 Aside 프로필의 저장된 계정·자동 입력으로 직접 로그인할 수 있는지 먼저 보고, 둘 다 안 되면 사용자에게 열린 창의 로그인을 부탁한다. 여러 경로가 동시에 만료될 수 있다.
- **예약글은 글쓰기 화면의 「예약 발행」 목록에서 불러온다.** `PostUpdateForm.naver?logNo=…`로 예약글을 직접 열면 공개범위가 미선택이고 검색허용이 비활성이며 발행 시간이 「현재」 하나만 나온다. 이 화면에서 저장하지 않는다. 불러온 뒤 제목·본문·예약 시각을 확인하고, 수정 후 같은 목록에서 다시 열어 설정 유지를 검증한다.
- **예약 목록은 원장 제목으로 찾는다.** 제목을 바꾼 뒤 원장 제목이 옛 값이면 다음 도구가 「예약 목록에서 글을 찾지 못했다」로 멈춘다. 저장된 제목을 확인하고 원장 `title`만 그 값으로 맞춘 뒤 재실행한다. 통합 입력 도구는 재열기 검증 뒤에만 원장 `title`·`unified`를 쓰므로, 재열기에서 멈춘 글은 `unified`를 비워 재입력·검증을 다시 거치게 한다.
- **새 글과 불러온 예약글을 URL이나 예약 라디오 개수만으로 구별하지 않는다.** 둘 다 `/postwrite`에서 표시된다. 고른 제목·본문·예약 날짜가 일치해야 기존 글을 불러온 것으로 판단하며, 저장 후 글 번호와 예약 목록도 대조한다.
- Chrome 플러그인에서는 글마다 새 작성 탭에서 예약 목록을 연다. 불러온 예약 글에서 다른 예약 글로 바로 이동하면 이탈 확인창이 걸릴 수 있다. 끝난 작업 탭은 닫는다.
- 확인창 처리는 예외를 삼켜야 한다. 이미 닫힌 창을 다시 닫으려다 프로세스가 죽는다. 편집기 이탈 경고는 수락해 통과시킨다.
- `--target=/celeb/…` 인자는 Git Bash의 MSYS 경로 변환에 깨진다. PowerShell에서 실행하거나 `MSYS_NO_PATHCONV=1`을 붙인다.

**캐럿·입력**

- Home·End·좌우 화살표 키가 먹지 않는다. 캐럿은 첫 글자 실제 좌표의 왼쪽 바깥(`left - 2`)을 클릭해 놓고, 캐럿 앞 글자 수가 0인지 DOM으로 확인한다. 이모지 span은 클릭해도 포커스가 잡히지 않으니 건너뛴다.
- DOM으로 선택 범위를 옮기면 편집기 내부 모델과 어긋나 원문을 덮어쓴다. 편집기가 스스로 처리하는 입력만 쓴다.
- 선택한 문단이 화면에 보여도 `getSelection()`은 빈 문자열을 반환할 수 있다. 부분 수정은 실제 Ctrl+C로 복사된 문자열이 대상 문단과 같은지 확인한 뒤 입력한다. 긴 인용 문단은 Shift 클릭으로 선택하고, 반복 라벨은 occurrence로 구별한다. 이미 왼쪽 정렬인 인용구에는 없는 정렬 메뉴를 누르지 않는다. 링크 문단의 기존 서식·href는 보존한다.
- 단락 시작에서 Enter는 위에 빈 단락을 만든다. URL 뒤 Enter는 자동 링크 확정에 먹히거나 링크 카드를 만든다. 단락 수가 늘지 않으면 한 번 더 치고, 검증은 본문 전체 단락으로 한다.
- **여러 자리를 연속 클릭해 Enter를 칠 때는 클릭 사이를 띄우고 칠 때마다 글자를 대조한다.** 줄 수가 같은 문단은 클릭 좌표가 겹쳐 Enter 뒤 첫 단어가 사라진 적이 있다. 마우스를 치우고 0.9초 띄우면 재현되지 않았다.
- **긴 글을 한 번에 치면 글자가 빠진다.** 30~60자씩 나눠 치고, 친 뒤 결과를 읽어 원문과 다르면 그 줄을 지우고 다시 친다.
- **제목 일부만 지우려 들지 않는다.** 오프셋을 세어 Delete를 누르면 「[OSCAR]」가 「[」로 잘린다. 제목 블록을 통째로 다시 친다. 제목은 `.se-documentTitle .se-text-paragraph`만 읽는다(전체를 읽으면 편집기 UI 글자가 섞인다).
- **감상 원문에 연속 공백이 있으면 새 글 입력이 붙여넣기 대조에서 멈춘다.** 편집기가 공백을 한 칸으로 줄인다. 서비스 감상의 공백부터 고친 뒤 재료를 다시 만든다.
- **감상 문단 사이에는 빈 문단을 둔다. 저장 관문이 이를 강제한다.** 저장 직전 `assertNoReviewGaps`가 붙은 감상 문단을 거부한다. 거부되면 `apply-review-gaps.mjs`로 벌린다. `apply-editorial-changes`의 `after`에서 `\n`은 붙이는 줄바꿈, `\n\n`은 빈 문단이다. 여러 문단 감상은 `\n\n`으로 넘긴다. 일괄 수정 뒤에는 `naver:audit-review-gaps`로 다시 확인한다.
- 네이버 편집기는 본문의 `#단어`를 글 태그로 바꿔 설정 대조가 실패한다. 한국어 감상에 해시태그 기호를 쓰지 않는다.

**표**

- 표 삽입은 CF_HTML 붙여넣기를 쓴다. 한글은 HTML 문자 참조로 전달한다. 기관 목록의 한국어 표기는 `korean-list-labels.mjs`에서 고른다. 표 뒤에 편집기가 만든 빈 문단이 있으면 그곳을 클릭하고, 없을 때만 「본문 추가」를 쓴다.
- 표를 지울 때는 표 바로 앞 문단 끝에서 Delete를 누른다. 첫 Delete가 표를 고르고 다음 Delete가 지운다. 지운 뒤 편집기가 다음 구분선을 골라 두므로 제목을 눌러 선택을 푼 뒤 붙인다([`lib/replace-table.mjs`](../../sw/web-bo/scripts/naver-blog/lib/replace-table.mjs)).

**본문 교체**

- **예약·발행된 통합 글의 감상 교체를 `apply-editorial-changes`로 끝내지 않는다.** 평문 입력이라 감상 안의 인용·제목 강조가 빠지고, 인용 단락 뒤에 넣은 새 단락은 인용 서식을 물려받는다. 감상 배경은 `replace-reviews`, 책을 바꾸면 재료를 다시 만들어 `apply-unified-article --article=<글번호>-article.json --apply`로 다시 넣는다. 그 뒤 `celeb-drafts.json`의 `unifiedMaterial`·`unifiedArticle`·`unifiedImages`와 원장 `unified.articleHash`를 새 값으로 맞추고 `naver:verify-body`로 대조한다.
- **이미 올라간 글의 단락을 고칠 때 「앞선 시도를 정리하는」 코드를 첫 시도에 돌리지 마라.** 재시도용 정리 코드가 첫 시도에 돌아 원래 감상 자리를 지운 사고가 있었다. 정리는 `attempt > 0`에서만 한다. 편집한 글은 소개·라벨·감상이 **전부 살아 있는지** 글 단위로 되읽는다.
- 삽입 뒤 "링크 줄 / 빈 줄 / 원래 단락"이 정확히 일치할 때만 발행한다. 새 글은 한 건이라도 실패하면 멈추고 사람이 본다.

**사진**

- **본문 사진 교체와 대표이미지(목록 썸네일)는 별개다.** 대표 배지(`se-set-rep-image-button.se-is-selected`)가 그 자리에 남는지와, 저장 후 공개 페이지의 `og:image`가 새 파일을 가리키는지를 둘 다 본다. 예약글은 공개 페이지가 없어 편집기의 대표 배지만으로 검증한다.
- **편집기 본문은 가상화돼 있다.** 스크롤 컨테이너는 `.se-content.__se-scroll-target`이고, 긴 글에서는 화면 밖 img 노드가 언마운트된다. DOM 스냅샷이 실행마다 다르면 공개 본문 HTML(`PostView.naver`)을 파싱해 사진 순서·단락·og를 대조한다. 인물 사진 자리는 공개 본문 이미지 순서로 다시 잰다.
- **네이버에서 원본이 삭제된 사진은 `data:image/svg` 자리표로 남는다.** 그 자리의 표현 차이를 변경으로 보지 말고 자리 보존으로 대조한다.
- **지연 로딩 img의 실제 주소는 `data-lazy-src`에 있다.** `data-lazy-src || src` 순으로 읽는다.
- **기존 파일명은 믿지 말고 신호를 모은다.** 과거 업로드는 `reframe-<slug>-`·`retry-<slug>-`·`{닉네임}-`·범용명이 섞여 있다. slug·닉네임 포함과 정사각 원본을 신호로 묶고, 전부 약하면 위치를 공개 본문에서 재확인한다.
- **통합 양식 글의 사진은 사진 감시의 자동 식별에 걸리지 않는다.** 파일명이 `…-revision-…` 형식이라 0건이 나온다. 공개 본문에서 파일명을 확인해 대상 파일의 `changes`에 `{slug, oldBasename}`으로 적고 `replace-person-photos.mjs --live-match --apply`로 실행한다. 이 실행은 `.env`를 읽지 않으므로 환경변수를 넣어 띄운다. 한 번 교체한 글은 `portrait-<slug>-`·`avatar-<slug>-`로 바뀌어 이후 자동 식별된다.
- **「인물 이름이 붙은 사진 = 아바타」로 잡지 않는다.** 같은 인물의 서로 다른 실사진이 여러 자리에 있는 글이 있다. 파일명 매칭으로 전부 교체하면 같은 사진으로 평탄화된다. 같은 사진 반복 정리는 `--dedupe`로 첫 자리만 두고 나머지를 지운다. 삭제마다 DOM을 다시 읽고, 대표 배지가 삭제될 자리에 있으면 먼저 옮긴다. 발행글은 공개 본문 이미지 목록으로 계획하고 대조한다. 이전 건너뜀은 `--retry`로 다시 돈다.
- **사진 삭제 버튼은 두 종류다.** 단독 사진은 `se-delete-toolbar-button`, 스트립 셀은 `se-image-delete-button`. 스트립의 모든 셀을 지우면 빈 껍데기가 남는다.
- 로컬 사진은 업로드 파일명을 `local-<slug>-<hash>`로 ASCII화한다. 한글 파일명은 인코딩돼 마커 비교가 실패한다.
- **액자 5번은 책 표지에만 적용한다.** 사진 편집 → 액자 도구 → 액자 선택 → 「모든 사진」 순서다. 액자 패널은 열 때마다 0번에서 시작하므로 먼저 액자를 골라야 「모든 사진」이 활성화된다. 버튼은 위치가 안정된 뒤 좌표로 누르고 `elementFromPoint`로 대상을 확인한다. 완료는 `button.npe_btn_submit`이다. 처리가 이어질 수 있어 모든 사진이 예상 크기로 바뀔 때까지 기다린다. 「다시 보지 않기」(`.npe_alert_btn_hide`)는 발행 설정 비교에서 제외한다.
- **액자는 누를 때마다 겹쳐 쌓인다.** 800px 사진이 840 → 880 → 920으로 커지는 것이 신호다. 이미 겹친 글은 `--rewrite`로 원본부터 다시 올려야 풀린다.
- **기관 로고는 글마다 한 장을 두고 대표사진으로 지정한다.** 기존 정상 로고는 원본을 우선 보존하고, 서비스 로고가 있다는 이유로 바꾸지 않는다. 기존 블로그 이미지 보관 위치는 `D:/feelandnote/blog-assets/naver-blog/_backup/original-blog-images/`다. 본문 전체를 다시 쓰지 않고 `repair-institution-images.mjs`로 교체한다.

**설정**

- 저장 직전 `lib/publish-options.mjs`로 검색·공개·공유 설정을 검사한다. 비활성이거나 확인되지 않으면 저장하지 않는다. 본문·사진만 대조하는 검사는 검색 차단을 잡지 못한다.
- **비표준 공유 설정 글을 표준으로 바꾸지 않는다.** 「본문 공유 허용」·「외부 공유 비허용」으로 저장된 오래된 글은 설정을 저장 전후 동일성으로 보존하고 사유를 `optionsWarning`으로 기록한다. 표준화가 필요하면 사용자와 상의한다.
- 공개 설정만 바꾸는 작업(비공개·재공개)은 글마다 편집기를 열지 않는다. 블로그 관리 → 글 관리 화면에서 체크박스로 한 번에 바꾼다.
- **예약글 삭제는 예약 목록에서 한다.** `delete-posts.mjs`가 「예약 발행」 목록에서 대상에 마우스를 올려 `button#post_delete_button`을 누르고, 목록을 다시 불러와 대상만 사라졌는지 대조한 뒤에만 원장을 `deleted`로 바꾼다. `PostView.naver`에 보이지 않는다는 이유만으로 삭제됐다고 판단하지 않는다.
