# 팩션 화면 영상화 검토 (Higgsfield)

세력도감(팩션) 영상의 인물 화면을 정지 이미지에서 AI 생성 영상으로 바꾸는 건의 조사 기록이다. **2026-08-01 조사, 생성 미착수.** 확인분에는 무엇을 돌려 나온 결과인지 붙였고, 미확인은 확인 방법을 적었다.

관련: 엔진 구조는 `docs/project/remotion/faction.md`, 제작 규칙·함정은 `docs/project/remotion/faction-rules.md`(§5 영상 미디어 처리가 직결), 발주 프롬프트 원칙은 `docs/project/image-generation.md`.

---

## 1. 목표

인물이 대사하는 동안 화면이 정지 그림으로 서 있는 것을 영상으로 바꾼다. 대사 도중 화면이 바뀌는 연출은 이미 있으므로, 그 자리에 들어가는 재료를 그림에서 영상으로 교체하는 것이 골자다.

수단은 넷이다 — 립싱크(§4), 배경·원소 연출(§5), 정지 유지, 구도를 바꾼 새 연출(§7 B안). **어느 것이 위라고 정해두지 않는다.** 화면마다 조건이 달라 골라 쓴다. 판단 기준은 §4.1.

---

## 2. 확인분 — 우리 쪽 구조

### 2.1 대사 도중 화면 교체는 이미 구현돼 있다

`FactionPerson.imageChanges`(`Faction/types.ts:167`)가 `{ chunk, image, crop?, filter?, zoomFocus? }[]` 형태로 존재한다. `chunk`는 `quoteChunks` 인덱스(0-based, 빈 덩어리 포함)이고, 렌더는 이를 실제 덩어리 인덱스로 환산해 **발화 시각(voiceTiming) 기준 프레임**에 교체한다(`PersonCard.tsx:572~594`). 발화 시각이 없으면 글자 수 비례로 폴백한다.

→ **교체 시점을 AI 생성물에 의존할 이유가 없다.** 프레임 단위 정확도가 이미 확보돼 있다. 다른 그림으로 갈아타므로 화면은 팡 튀어 들어간다. 여기는 손댈 것이 없다.

세게 꽂히는 실질 원인은 **화각 차이**다. 아폴론 사례에서 상반신 → 눈알 클로즈업으로 건너뛰므로 크기 도약이 크다. **이 화각 차이를 지키는 것이 관건이다**(§6-3).

`quoteImage`(도입↔대사 경계 교체)는 `imageChanges`와 독립으로 함께 적용된다.

### 2.2 영상 재생은 이미 된다

`FactionMedia.tsx`가 src 확장자로 판별해 영상이면 `OffthreadVideo`(무음, `<Sequence>` 래핑), 아니면 `Img`를 쓴다. 데이터의 이미지 경로 자리에 mp4를 넣으면 그대로 재생된다.

**단 받은 파일을 그대로 쓰면 안 된다.** AI 생성 클립은 되감기 기준점(키프레임)이 맨 앞 하나뿐인 경우가 흔해 미리보기 seek가 매번 0초부터 디코딩된다. all-intra 재인코딩이 필수다(`faction-rules.md` §5에 명령·검증법 있음). 로고 영상에서 프리뷰 무한로딩으로 이미 겪은 함정이다.

### 2.3 줌 정지 스위치가 있다

`FactionScript.noZoom`(전역)과 인물·세력별 `holdMotion: 'none'`으로 지속 확대를 끌 수 있다. 영상에 켄번스 줌을 얹으면 Studio 미리보기가 떠는 문제도 이미 기록돼 있다(렌더는 정상).

### 2.4 인물 대사 음성은 재생된다 (기존 문서 정정)

`PersonCard.tsx:449`가 `<Audio src={staticFile(voiceRelPath(episodeName, vnPersonQuote(...)))}>`로 인물 대사 음원을 실제로 재생한다. `VOICE_ENABLED` 상수는 코드에 존재하지 않는다(2026-08-01 grep 0건).

→ **`faction-rules.md` §3.1의 "음원은 사용하지 않는다 / VOICE_ENABLED=false" 기록은 낡았다.** 소리가 나므로 입모양이 실제 문제이고, 동시에 **립싱크에 넣을 음원이 이미 완비돼 있다는 뜻이기도 하다**(§4).

## 3. 확인분 — Higgsfield 쪽 (문서·검색 기반, 실사용 전)

### 3.1 립싱크 전용 도구가 있다

**Lipsync Studio / Higgsfield Speak** — 그림 한 장 + 오디오 파일을 올리면 그 소리에 맞춰 입이 움직이는 영상을 만든다. 표정과 고갯짓도 자연스럽게 붙는다.

- **40개 넘는 언어 지원, 한국어 포함.**
- **이미 있는 음성 파일 업로드 가능**(텍스트로 목소리를 만드는 것도 되지만 우리는 음원이 이미 있다).
- 업로드한 개인 사진·그림도 말하는 인물로 만들 수 있다.

**시드댄스 2.0은 이 용도가 아니다.** 오디오를 받긴 하나 리듬·분위기·타이밍을 잡는 구조적 참조로 쓴다. "이 문장을 이 목소리로 정확히 말하게 하라"는 도구가 아니며, 정확한 대사가 필요하면 후반에 소리를 갈아끼우라는 안내가 붙어 있다. 우리는 음성이 이미 확정돼 있으므로 안 맞는다.

### 3.2 그 밖

- **한 영상 안에서 화면을 바꾸는 방법 세 가지**
  - 시작·끝 그림: 그림 2장을 주면 앞에서 뒤로 넘어가는 영상 하나. 클링 2.5부터.
  - 클링 3.0 다중 장면: 한 번의 생성에 **장면 최대 6개**, 장면마다 길이·화각·카메라 움직임 지정.
  - 시드댄스 2.0 참조: 그림 최대 9장(영상 3·오디오 3 포함), 최대 15초.
- **얼굴만 참조로 주고 장면을 새로 짜는 방식이 지원된다**(참조 다중 이미지, 자체 캐릭터 학습 Soul).
- 클립 길이는 대부분 5~15초, 시드댄스 2.0이 최대 30초.
- 요금(2026-05 기준): Starter $15/200크레딧, Plus $39/1,000, Ultra $99/3,000. 무료 하루 10크레딧.
- 클링 3.0 720p 단일 생성 약 7크레딧, 소라·베오는 40~70크레딧.
- 출력물의 상업적 사용에 제한이 없다(2026-07 약관).
- 공식 MCP 서버가 있다. Claude Code 등록은 `claude mcp add --transport http --scope user higgsfield https://mcp.higgsfield.ai/mcp`, OAuth 브라우저 인증이라 API 키가 불필요하다.

## 4. 립싱크

### 4.1 수단 고르기 — 화면마다 조건이 다르다

**어느 수단이 우월하다고 정해두지 않는다.** 아래는 무엇을 볼지에 대한 기준이지 순위표가 아니다.

| 화면의 조건 | 맞는 수단 |
|---|---|
| 배경에 움직일 것이 있다(번개·화염·물·불티·빛) | 배경·원소 연출. 인물을 안 건드려 얼굴 붕괴 위험이 없다 |
| 배경이 조용하다 | 립싱크. 인물이 말하면 배경이 가만히 있어도 화면이 산다 |
| 인물이 화면에 없다(빛의 길·여인의 눈·로고·그룹 사진) | 립싱크 대상이 아니다. 원소 연출 또는 정지 유지 |
| 정지가 이미 세다(아폴론 눈 클로즈업) | 정지 유지. 영상으로 얻는 것보다 컷의 힘을 잃을 위험이 크다 |
| 구도 자체가 문제다(전원 앉은 정면·정사각 비율) | 얼굴 참조로 새 연출(§7 B안) |

**배경 원소가 만능이 아니라는 점만은 분명하다.** 제우스(번개)·아레스(불타는 도시)·헤파이스토스(불티)·포세이돈(물)은 되지만 헤라·아테나·아프로디테·데메테르·헤르메스는 뒤에 움직일 것이 없어 정지 그림과 차이가 없다. 모든 인물 뒤에 번개가 칠 수는 없다. 그래서 립싱크가 없으면 절반이 빈다.

거꾸로 립싱크도 만능이 아니다. 인물이 화면에 없는 구간에는 쓸 수 없고, 품질이 안 나오면 §6-5에 따라 물러선다.

### 4.2 립싱크가 뒤집는 것 세 가지

- **정면 응시 구도가 약점에서 장점이 된다.** 립싱크는 정면 얼굴에서 가장 잘 된다. 13명이 전부 정면인 현재 상태가 오히려 조건에 맞는다.
- **입을 피하는 구도 제약이 사라진다.** 옆모습·아래턱 그림자·눈 클로즈업으로 도망 다닐 필요가 없다.
- **기존 그림을 그대로 쓰는 쪽(§7 A안)의 부담이 줄어든다.** 13개 연출 시나리오를 새로 설계하지 않아도 된다.

### 4.3 재료는 이미 다 있다

| 필요한 것 | 현재 상태 |
|---|---|
| 인물 그림 | 13명 전원 보유(정면 초상) |
| 대사 음원 | ElevenLabs 합성 완료, `voice/F{세력}C{그룹}P{인물}-quote.wav` |
| 발화 길이 | `quoteDuration`에 기록됨 |
| 덩어리별 발화 시각 | 산출 완료 |

### 4.4 화면이 바뀌는 구간과의 관계

립싱크 영상은 **인물이 화면에 있는 구간에만 해당한다.** 아폴론은 12.67초 중 본인이 나오는 것은 앞 3덩어리분뿐이고 나머지는 빛의 길과 여인의 눈이다.

→ 음성을 그 구간만큼 잘라 넣거나, 전체를 넣고 나온 영상의 앞부분만 쓴다. 어느 쪽이 나은지는 실측 후 정한다.

## 5. 배경·원소 연출

인물이 안 나오는 교체 화면, 세력 로고, 그룹 사진, 인물이 말하지 않는 도입 구간, 그리고 **배경에 움직일 것이 있는 인물**에 쓴다. 인물을 안 건드리므로 얼굴이 어긋날 위험이 없다는 것이 이 수단의 강점이다.

정지 그림용 구도와 영상용 구도는 다르다. 시작 화면은 이름·직함을 읽는 구간이라 큰 동작이 안 되므로, **노릴 지점은 동작의 정점 직전이나 직후의 정적이다.** 인물은 멈춰 있는데 주변에 여파만 남은 순간 — 이름을 읽을 시간이 확보되면서도 정지 화면이 아니다.

| 인물 | 현재 | 영상용 제안 |
|---|---|---|
| 제우스 | 왕좌에 앉아 정면 | 번개를 이미 쥐고 멈춰 섬. 손끝에서 전류만 튄다 |
| 아레스 | 계단에 앉아 정면 | 불타는 도시를 등지고 검을 끌며 걸어 나옴. 발치의 먼지만 |
| 헤파이스토스 | 정면 | 망치를 내리친 직후. 불티가 흩어지는 중, 본인은 정지 |
| 헤르메스 | 정면 | 착지 직후. 옷자락만 아직 흔들린다 |

**적용 범위를 분명히 해둔다.** 위 넷은 원소가 강해서 되는 것이고, 원소가 약한 인물에는 이 수단이 안 통한다(§4.1).

## 6. 결정된 원칙

1. **컷 전환은 AI에게 맡기지 않는다.** 팡 튀는 컷은 파일 두 개를 붙이면 생긴다. AI에게 한 영상 안에서 시키면 반드시 이어주는 쪽으로 만든다 — 시작·끝 그림 방식은 태생이 두 그림 사이를 메우는 것이라 원하는 것과 반대로 간다.
2. **"번쩍"은 움직임이 아니라 컷이다.** 눈꺼풀이 올라가는 과정을 보여주면 오히려 느려진다.
3. **카메라 고정을 발주에 못 박는다.** 컷의 힘은 앞뒤 화면의 화각 차이에서 나오는데, 클립이 카메라를 밀고 들어가면 컷 시점의 화각 차이가 줄어 튀는 힘이 빠진다. 움직임은 피사체 안쪽으로만. 지시를 어기고 줌이 들어오면 앞부분만 잘라 쓴다 — 카메라 이동은 뒤로 갈수록 커진다.
4. **강한 정지 컷은 굳이 영상화하지 않는다.** 아폴론 눈 클로즈업(동공에 불꽃)처럼 정지가 이미 센 화면은 영상으로 바꿔 얻는 것보다 컷의 힘을 잃을 위험이 크다.
5. **입은 립싱크로 맞춘다.** 음성이 재생되므로 입이 움직인다면 반드시 그 소리와 맞아야 한다. **어긋난 입모양은 멈춘 입보다 훨씬 나쁘다** — 더빙이 안 맞는 외화처럼 보인다. 립싱크 품질이 기준에 못 미치면 그 인물은 입을 다문 채로 두고 구도로 덜어낸다(눈 중심 클로즈업·아래턱을 어둠에 두는 조명·옆모습). 어중간하게 오물거리게 두는 선택지는 없다.

## 7. 미결정 — 두 갈래

시작 화면을 어떻게 만들지가 갈린다. 인물마다 다르게 가도 된다 — 구도가 아쉬운 인물만 B로 다시 뽑는 식의 혼용도 선택지다(다만 §7-B의 얼굴 일관성 주의를 함께 본다).

### A. 기존 그림을 씨앗으로 쓴다

- **강점**: 발주가 짧다. 씨앗이 이미 있어 새로 설계할 게 없다. 기존 화면들과 얼굴이 어긋나지 않는다. 정면 구도라 립싱크에 유리하다.
- **약점**: 그림이 정사각이라 세로 화면에서 위아래를 확대해 채우고 있다. 13명이 전부 같은 자세다.

### B. 얼굴만 참조로 주고 연출을 새로 짠다

- **강점**: 앉은 정면 구도와 정사각 비율을 둘 다 버린다. 처음부터 세로로 뽑아 화면을 꽉 쓴다. §5의 연출 제안이 이 갈래에서만 가능하다.
- **약점**: 인물마다 장면 시나리오를 새로 써야 한다(13개). 얼굴이 클립마다 미묘하게 달라질 수 있다.
- **얼굴 일관성 주의**: 그리스 신은 `fiction` 티어라 실존 인물 신원 가드의 대상이 아니지만, 한 편 안에서 인상이 흔들리면 시청자가 헷갈린다. 시작 화면을 새로 뽑으면 **그 인물의 나머지 화면도 같이 새로 뽑는 편이 낫다** — 섞으면 경계에서 티가 난다.

## 9. 규모·비용 추산 (Gods-Greek 기준, 추정)

- 인물 13 + 세력 로고 6 + 그룹 사진 6 + 도입·마무리 2 = **생성 27건**
- 인물 발화가 전원 6.5~16초라 대부분 15초 한도 안에 들어간다
- 클링 3.0 기준 7크레딧 × 27 ≈ 190크레딧. 재시도 3배를 잡아도 600 미만 → **Plus($39/1,000크레딧)로 한 편 + 여유**
- **단 립싱크 과금이 미확인이라 위 값은 하한이다.** 립싱크가 별도·고액이면 전면 재계산이 필요하다
