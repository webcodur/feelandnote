# Feel&Note 문서 지도

저장소 전체 작업 규약은 루트 [`AGENTS.md`](../AGENTS.md), 에이전트 운용 원칙은 [`project/agent-rules.md`](project/agent-rules.md)가 쥔다. 작업할 영역의 허브 README만 열고, 모든 문서를 한꺼번에 읽지 않는다.

## 최상위 구조

| 경로 | 성격 | 사용할 때 |
|---|---|---|
| [`project/`](project/README.md) | 현역 프로젝트 규격(SSoT) | 앱·서비스 화면·DB·인물·영상·운영·제작 규칙을 확인할 때 |
| [`games/`](games/README.md) | 현역·실험 게임 규격 | 쉼터 게임, 천도, 실험 게임을 작업할 때 |
| [`todo/`](todo/README.md) | 끝이 있는 남은 작업 | 미완료 작업의 다음 착수 지점을 찾을 때 |
| [`continuous/`](continuous/README.md) | 반복 과제의 현재 도달점 | 인물·회차를 바꾸어 계속 반복하는 작업을 이어갈 때 |
| [`resource/`](resource/README.md) | 프로젝트에서 떼어 낸 범용 지식 | 다른 프로젝트에도 그대로 쓸 수 있는 기법·명세·도구 목록을 볼 때 |

데이터는 문서 폴더에 두지 않는다. 인물 원고·선정 목록·조사 원장·제휴 자료는 저장소 최상단 [`data/`](../data/README.md)에 있다.

## 파일명 규칙

- 현역 규격은 `<영역>-<NN>-<이름>.md`다. 영역 접두사(`platform`·`apps`·`service`·`data`·`ops`·`prod`·`remotion`·`br`·`voice`·`discourse`·`res`)로 탭·검색에서 어느 폴더 문서인지 바로 알 수 있게 하고, 두 자리 번호는 탐색기 정렬 겸 읽는 순서다.
- 인물 문서만 도메인이 많아 두 단계 주소 `celeb-<도메인2자리>-<순서2자리>-<이름>.md`를 쓴다.
- 실행 순서가 있는 문서는 그 순서 번호를 그대로 쓴다(`writer/0-draft.md`~`7-translation.md`, `games/suikoden/01`~`10`).
- 폴더마다 `README.md`가 허브다. 허브는 경로와 책임만 적고 규칙을 복제하지 않는다.
- `todo/`·`continuous/`는 수명이 짧아 번호를 붙이지 않고 도메인 이름으로 시작한다.
- 파일명과 제목에 날짜를 넣지 않는다. 날짜가 필요한 조사 원장은 `data/`에 둔다.

## 배치 원칙

- 현재 동작과 운영 규칙은 `project/` 또는 `games/`에 둔다. 규칙·상수·임계값은 코드와 해당 SSoT 한 곳만 쥔다.
- 끝이 있는 미완료 작업은 `todo/`, 대상을 바꾸어 반복하는 작업의 현재 도달점은 `continuous/`에 둔다. 완료 보고서·회차 스냅샷은 남기지 않고 규칙만 SSoT로 옮긴 뒤 지운다.
- `resource/`에는 프로젝트 고유 내용(저장소 경로·DB·인물·스크립트 이름)을 쓰지 않는다. `project/` 문서가 `resource/`를 링크하고, 반대로는 링크하지 않는다.
- 문서를 이동하거나 이름을 바꾸면 상위 README, 스킬 문서(`.agents/skills/`), 코드 주석의 경로를 함께 갱신하고 옛 경로 참조가 0건인지 확인한다. 루트 `AGENTS.md`는 최상위 허브나 전역 불변사항이 바뀔 때만 수정한다.
