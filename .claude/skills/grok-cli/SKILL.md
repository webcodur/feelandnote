# grok CLI 호출·통제

grok.com 구독 인증으로 도는 로컬 CLI다. 기본 모델은 `grok-4.6`이며 웹 검색이 내장돼 있다.
**사용량 조회 명령이 없다** — `grok usage`를 치면 대화형 UI가 뜬다. 잔여량은 grok.com 대시보드에서 본다.

## 1. 핵심 호출법

**스크립트에서 부를 때는 `scripts/grok-call.mjs`를 쓴다. 아래 규약을 다시 짜지 않는다.**

```js
import { grokJson, safeBatchSize } from '<skill>/scripts/grok-call.mjs'

const { data, turns, costUsd } = await grokJson(prompt, SCHEMA, {
  effort: 'high',
  docs: ['docs/project/celeb/celeb-timeline.md'],  // 먼저 읽힐 문서. 상대경로도 받는다
  repoRoot: REPO_ROOT,
})
```

헬퍼가 셸 우회·작업 폴더 격리·타임아웃·파싱을 처리한다. 연결만 확인하려면
`node <skill>/scripts/grok-call.mjs "3 곱하기 7은?"`으로 직접 실행한다.

**일을 시킬 때는 규칙 문서를 함께 준다.** `docs` 옵션에 경로를 넣으면 「먼저 읽고 그대로 따르라」는
지시가 프롬프트 앞에 붙는다. 문서가 없으면 만들어서 주는 편이 프롬프트에 규칙을 길게 적는 것보다 낫다.
그록은 저장소 관례까지 읽고 따른다 — 실제로 `AGENTS.md`의 「일회성 스크립트는 `.tmp-`를 붙인다」를
읽고 자기가 만든 헬퍼 파일에 그 접두어를 붙였다.

맨손으로 부를 때의 형태는 이렇다.

```bash
node "C:/Program Files/nodejs/node_modules/@xai-official/grok/bin/grok" \
  --prompt-file PROMPT.txt \
  --json-schema '{"type":"object",...}' \
  --always-approve \
  --reasoning-effort high
```

네 가지가 핵심이다.

1. **`grok`이 아니라 `node.exe`로 bin을 직접 실행한다.** 아래 2절 참조.
2. **프롬프트는 `--prompt-file`로 넣는다.** 긴 한국어 프롬프트가 shell 이스케이프에서 깨지는 걸 막는다.
3. **`--json-schema`를 쓰면 출력이 스키마에 맞는 JSON으로 강제된다.** 결과는 응답 JSON의 `structuredOutput`에 담긴다. 파싱이 필요 없다.
4. **`--reasoning-effort`를 명시한다.** 생략하면 기본값으로 돌며, 이것이 품질 차이를 만든다(4절).

응답 JSON에는 `structuredOutput` 외에 `usage`(토큰), `num_turns`(모델 호출 수), `total_cost_usd`가 함께 온다.

## 2. Windows spawn 함정

**`grok`을 셸로 부르면 `--json-schema`가 깨진다.** `grok.cmd`는 내부적으로
`node <bin>\grok %*`를 호출하는 배치 래퍼인데, cmd.exe와 PowerShell 둘 다 스키마 안의 큰따옴표를
신뢰할 수 없게 재해석한다. 증상은 `--json-schema: invalid JSON: key must be a string`이다.

`node.exe`로 bin 스크립트를 직접 실행해 셸 재해석을 건너뛴다. Node의 정상적인 Windows 인자
이스케이프가 그대로 먹는다.

**`spawnSync`를 쓰지 않는다.** 이벤트 루프를 통째로 막아 인물 간 병렬이 무력화된다.
동시 실행을 하려면 비동기 `spawn`으로 감싼 Promise를 쓴다.

**작업 디렉터리를 저장소 루트로 주지 않는다.** 그록은 조사 중 필요하면 파이썬·자바스크립트
헬퍼를 스스로 짜서 쓰는데, 그 파일들이 cwd에 쌓인다. 실제로 좌표 작업 한 번에 루트에
`.tmp-geocode-*.py`, `.tmp-wd-lookup*.js` 등 19개가 남았다. 헬퍼는 임시 폴더를 cwd로 주고
문서는 절대경로로 넘긴다.

## 3. 프로세스 자원 고갈 — 오래 돌리면 죽는다

**한 부모 프로세스로 수백 건을 연속 처리하면 Windows가 새 프로세스를 못 띄우는 상태가 된다.**
증상은 `grok exit 3221225794`(`STATUS_DLL_INIT_FAILED`)다.

실측: 20레인은 300건쯤에서 551회, 8레인은 150건쯤에서 48회 터졌다.
**동시성이 아니라 누적이 원인이다.** 레인을 줄이면 더 오래 버틸 뿐 같은 벽에 닿는다.
이 상태가 되면 재시도가 전부 같은 오류로 죽어 회수도 안 되고, 실패율이 5%에서 33%로 뛴다.

**해법은 회차 분할이다.** 30~40건 단위로 실행하고 프로세스가 완전히 끝나면 자원이 반납된다.
셸 루프로 회차를 반복하고, 회차마다 결과 반영도 함께 돌린다. 회차가 짧으면 레인은 12까지 올려도 된다.

릴레이가 죽은 뒤에는 고아 grok 프로세스가 남으므로 다음 회차 전에 정리한다.

## 4. effort와 묶음 크기는 한 쌍이다

**effort를 올리면 묶음 크기를 함께 줄여야 한다.** 추론이 길어지는 만큼 출력 예산이 줄어
긴 배열을 못 채운다.

| effort | 안전한 묶음 크기 | 실측 |
|---|---:|---|
| 기본 | 50개 | 온전히 반환 |
| high | 15~20개 | 40개로 요청하면 **1개만** 반환 |

effort만 올리고 묶음을 그대로 두면 회차가 통째로 헛돈다. 두 묶음을 버리고 알았다.

## 5. 구조화 출력은 도구 사용을 억제한다

`--json-schema`로 출력을 강제하면 **모델이 검색을 건너뛰고 기억으로 즉답하는 일이 잦다.**
실측으로 검증자 호출의 절반가량이 추론 토큰 60~250개짜리 1턴 응답으로 돌아왔다.
제대로 검색할 때는 8턴에 추론 토큰 1만 개를 넘긴다.

**성실성을 추론 토큰 같은 간접 지표로 재지 마라.** 정당한 「결함 없음」까지 반려하게 된다.
대신 **실제로 연 출처를 산출물에 적게 하고 그것으로 판정한다.**

```jsonc
// 스키마에 넣는다
"sources": { "type": "array", "items": { "type": "object",
  "properties": { "name": {...}, "url": {...}, "used_for": {...} },
  "required": ["name", "used_for"] } }
```

프롬프트에 「검색 없이 답하지 마라. 결함이 하나도 없더라도 무엇을 어디서 확인했는지
sources로 증명해야 그 판정이 인정된다」를 넣고, 출처가 2개 미만이면 재시도한다.
검색을 안 하면 채울 수 없는 값이라 지표가 아니라 증거다.

**이 게이트 하나가 실패율을 29%에서 1%로 낮췄다.**

## 6. 모든 단계에 재시도를 건다

호출이 헛도는 건 특정 단계만의 문제가 아니다. 자료가 넘치는 대상에서도 조사가 0건으로
돌아오고, 수정 단계가 멀쩡한 항목을 무더기로 지운다. 실패한 시도는 몇 초 만에 돌아오므로
**횟수를 늘리는 편이 대상을 통째로 잃는 것보다 싸다.**

권장 상한: 조사 3회, 검증 5회, 수정 2회.

**수정 단계에는 소실 방어선을 둔다.** 「확인 안 됨」을 「없던 일」로 읽고 항목을 지우는 일이
있다. 결함 수보다 훨씬 많이 사라지면 수정이 아니라 사고로 보고 다시 시킨다.

## 7. 신뢰도 등급은 high만 쓴다

판정에 신뢰도를 달게 하면 등급별 품질 차이가 뚜렷하다. 기본 effort에서 medium에 오답이
섞였고(지명 조회에서 브르타뉴 대신 파리 남쪽 좌표), high로 올린 뒤에도 medium에는
일반명사에 억지로 답한 건이 남았다.

**medium을 버려서 얻는 회수 손실보다, 틀린 값 하나가 만드는 왜곡이 비싸다.**
채택 기준을 high로 두고, 모델이 스스로 `none`으로 거부한 것은 그대로 존중한다.

## 8. 위임 판단

**직접 정규식이나 사례별 규칙을 늘리고 있다는 걸 자각하는 순간이 위임 신호다.**
의미 판단(고대 지명의 현대 대응, 동음이의어 구별, 맥락 기반 분류)은 규칙으로 닫히지 않는다.
목록을 묶음으로 넘기고 신뢰도와 근거를 함께 받으면, 사람 몫은 표본 검수로 줄어든다.

반대로 **기계가 할 수 있는 정규화는 먼저 끝낸 뒤 남은 것만 넘긴다.** 문자열 매칭으로
풀리는 것까지 모델에 물으면 호출만 늘어난다.
