# opencode로 muse-spark 호출·통제

`opencode` CLI에 붙어 도는 모델이다. **한국어 문장력이 좋다.** 산문·독백·인물 원고 초안에 쓸 만하다.
대신 **조사를 시키지 않으면 사실을 자신 있게 틀린다.** 이 스킬의 절반은 그 통제에 관한 것이다.

## 1. 두 라인

| 모델 ID | 인증 | 비용 |
|---|---|---|
| `opencode/muse-spark-1.2-contributor-free` | 불필요 | 무료 |
| `opencode-go/muse-spark-1.2-contributor` | OpenCode Go | 크레딧 소모 |

무료 라인이 인증 없이 바로 붙는다. 기본값으로 쓴다.
`opencode auth list`로 등록된 자격을, `opencode models`로 전체 목록을 본다.

## 2. 핵심 호출법

**스크립트에서 부를 때는 `scripts/muse-call.mjs`를 쓴다. 규약을 다시 짜지 않는다.**

```js
import { museCall, museBatch, MUSE_GO } from '<skill>/scripts/muse-call.mjs'

const { text, attempts } = await museCall(prompt)          // 재시도·리드 제거 포함
const results = await museBatch(items, (it) => buildPrompt(it), { concurrency: 16 })
```

`museCall`은 빈 출력이면 3회까지 재시도하고, 본문 앞에 새는 진행 보고를 걷어낸다.
`museBatch`는 동시 실행 수를 묶어 돌린다(6절).

맨손으로 부를 때의 형태는 이렇다.

```bash
opencode run --dir <빈 작업폴더> -m opencode/muse-spark-1.2-contributor-free "프롬프트"
```

두 가지가 핵심이다.

1. **`--dir`로 빈 폴더를 준다.** 생략하면 저장소에서 돌면서 `AGENTS.md`와 주변 파일을 읽어 문맥이 오염된다.
2. **stdout 첫 줄은 `> build · <모델명>` 배너다.** 본문만 쓰려면 걷어낸다.

Windows spawn 함정은 없다. `node_modules/opencode-ai/bin/opencode.exe`가 실체 바이너리라
`.cmd` 래퍼를 거치지 않고 직접 실행할 수 있다. codex처럼 `where`로 경로를 해석할 필요가 없다.

## 3. 반드시 조사를 지시한다

**이 모델은 웹 검색(Exa)을 내장하고 있지만, 시키지 않으면 쓰지 않는다.**
프롬프트에 조사 지시가 없으면 기억만으로 쓰고, 그 결과가 위험하다.

인물 독백 10건 실측(조사 미지시):

| 계통 | 결과 |
|---|---|
| 서구·현대 인물 | 무결. 저명도 낮은 현생 인물도 정확했고 최근 인사 변동까지 반영했다 |
| 한국 전근대 인물 | 3명 전원 오류. 그중 2명은 치명적이었다 |

터진 양상이 나쁘다. 없는 책이나 가짜 인용을 지어내지 않는다 — 10건 전부 직접 인용을 한 줄도
만들지 않았다. 대신 **실재하는 사실들 사이의 시점·인과·정치적 입장을 뒤집는다.**

- 허균이 폐모론에 **반대해 상소를 올렸다**고 썼다. 실제 허균은 폐모론 주도자다
- 정약용이 형 정약종이 죽을 때 **이미 강진에 있었다**고 썼다. 그때 정약용은 서울에서 국문받는 중이었다
- 신사임당이 **어머니가 돌아가신 뒤** 대관령을 넘었다고 썼다. 어머니는 사임당보다 오래 살았다

문장이 매끄럽고 확신에 차 있어 그 인물을 아는 사람이 아니면 통과시킨다. 육안 검수로 못 거른다.

**조사를 지시하면 위 세 건이 전부 교정됐다.** 디테일도 함께 늘었다(정약전의 흑산도 유배와 1816년
사망, 사임당이 남편에게 이기와 가까이하지 말라 한 일화 등). 프롬프트에 이 블록을 넣는다.

```
[먼저 조사한다]
- 쓰기 전에 웹을 검색해 그 인물의 생애, 저술, 발언, 정치적 입장, 주요 사건의 연도를 확인한다.
- 기억에 의존하지 않는다. 특히 다음은 반드시 출처로 확인한다.
  - 사건이 일어난 연도와 그때 인물이 어디에 있었는지
  - 논쟁에서 인물이 어느 편에 섰는지
  - 저작의 성격(자기 저술인지, 남의 글을 엮은 것인지)
  - 가족·동료의 생몰 시점
- 조사로 확인되지 않은 내용은 쓰지 않는다.
```

조사를 붙여도 **서사로 엮는 단계에서 방향이 뒤집힌다.** 실측에서 조선에 온 명나라 사신 주지번을
허균이 명에 가서 만난 것으로 썼다. 그런데 같은 모델에게 「주지번이 조선에 온 연도」를 따로 물으면
1606년 한양 도착까지 정확히 답한다. **지식이 없어서가 아니라 이야기로 짤 때 틀린다.**
그래서 산출물의 사실을 항목으로 뽑아 되물으면 스스로 교정한다. 한국·중국 전근대 원고는 그 단계를 넣는다.

## 4. 본문 앞에 새는 진행 보고

출력 형식을 지정해도 앞에 자기 진행 상황을 붙인다. 실측 사례:

```
허균의 1인칭 독백을 쓰기 전 생애와 사상을 먼저 검증하겠다.
생애 주요 사실과 문학적 입장을 확인했다. 이제 독백 작성을 시작하겠다.
나는 강릉 초당에서 막내로 태어났다. ...
```

프롬프트로 완전히 막히지 않는다. `muse-call.mjs`의 `stripLead()`가 걷어낸다. 직접 짤 거라면
맨 앞 연속된 짧은 줄 중 「독백·초안·본문 + 작성·구성·시작」, 「생애·기록·연보 + 확인·검증」
꼴을 제거한다. 본문 중간에는 나타나지 않으므로 앞부분만 본다.

## 5. 빈 출력과 python3 함정

**호출 4건 중 1건꼴로 본문 없이 끝난다.** 원인 하나는 확인됐다.

모델이 분량을 맞추려고 `python3`로 글자 수를 세는데, **이 환경에는 `python3`가 없다**(`python`만 있다).
실패하면 다른 방식으로 재시도하다 턴을 소진하고 본문 없이 종료한다.

두 가지로 막는다.

1. 프롬프트에 **「글자 수를 세려고 스크립트를 실행하지 않는다. 눈대중으로 맞춘다」**를 넣는다
2. 그래도 남는 무응답은 재시도로 처리한다. `museCall`이 3회까지 자동 재시도한다

재시도하면 대개 살아난다. 같은 인물이 두 번 연속 빈 출력을 내고 세 번째에 나온 사례가 있다.


## 5-1. 빈 출력이 전건으로 번지면 라인부터 확인한다

`exit=null`은 응답이 아예 오지 않았다는 뜻이다. 빈 출력이면서 소요가 타임아웃 값에 딱 붙으면
프롬프트 문제가 아니다.

**진단 순서를 지킨다. 첫째는 라인 상태다.**

```bash
node <skill>/scripts/muse-call.mjs "3 곱하기 7은?"
```

`21`이 안 나오면 라인이 죽은 것이다. 기다리거나 `MUSE_GO`로 넘어간다.
**이 확인 없이 프롬프트나 동시 수를 고치면 오진한다.** 실제로 라인이 죽은 구간을 두고
동시 호출 탓으로 결론 내려 「병렬 불가」라는 잘못된 규칙이 문서에 박힌 적이 있다.

라인이 살아 있는데도 특정 인물만 계속 비면 그 인물만 건너뛰고 나중에 단건으로 처리한다.

## 6. 동시 실행과 429

**Exa 검색이 429를 뱉는 것은 동시 실행 탓이 아니다.** 단독 1건에서도 검색 7회 중 2회가 429였고,
동시 4건일 때의 비율과 차이가 없었다. 무료 Exa MCP 자체의 한도로 보인다.

**429는 치명적이지 않다.** 모델이 재시도하거나 다른 경로로 우회해 답을 얻는다. 429가 두 번 난
회차도 사실을 정확히 확인해 왔다. 429를 보고 결과를 버리지 않는다.

### 병렬은 된다 — 동시 20까지 확인했다

**독립 프로세스로 띄우면 병렬이 문제없이 돈다.** 조사를 겸한 인물 독백 생성으로 측정한 값이다.

| 동시 | 건당 소요 | 실패 |
|---:|---:|---:|
| 1 | 70초 | 0 |
| 6 | 18초 | 0 |
| 12 | 6초 | 0 |
| 20 | 7초 | 0 |

12와 20의 건당 소요가 비슷하므로 그 근처에서 포화된다. **동시 12~20을 쓴다.**
직렬로 돌리면 같은 일이 열 배 걸린다.

1건당 단독 소요는 조사 포함 40~120초다. 타임아웃은 300초 이상 준다.

**동시 수를 빈 출력의 원인으로 먼저 지목하지 않는다.** 5-1절의 진단 순서를 따른다.
같은 프로세스에서 여러 건을 병렬로 돌리든 셸에서 따로 띄우든 결과는 같았다.
다만 **배치 자체는 하나만 띄운다.** 둘 이상 겹치면 DB 경합과 로그 중복이 생긴다.

### stderr로 조사 여부를 판정하지 않는다

**검색 경로가 여러 개고, 그중 일부는 로그를 남기지 않는다.** stderr에 `Exa Web Search`가
한 줄도 없는 회차가 출처 URL을 정확히 인용하며 답한 사례가 있다.
`grep -c 'Exa Web Search'`로 「조사를 안 했다」고 판정하면 오진한다.
조사 여부는 산출물이 출처를 대는지, 사실이 맞는지로 본다.

## 7. 쓸 곳과 쓰지 말 곳

- **쓴다** — 서구·현대 인물 원고 초안, 한국어 산문 다듬기, 대량 초안 생성
- **조사를 붙여 쓴다** — 인물 관련 사실이 들어가는 모든 원고
- **쓰지 않는다** — 검수 없이 DB에 바로 반영하는 경로. 사실 오류가 문장 품질에 가려진다
