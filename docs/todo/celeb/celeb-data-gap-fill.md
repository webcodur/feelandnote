## 무엇을 하는 작업인가

`celebs`의 **텍스트 데이터 빈칸**을 룰북 규격에 맞게 채운다. 2,426명은 최초 회차의 역사
스냅샷이며 현재 모집단은 실행 시 live `celebs`에서 다시 계산한다. 대상 트랙은
basic(이름·수식어·소개·직군·국적·생몰) · 영향력 7축 · 스펙트럼 16항목+종합해설 ·
speech(톤·명언·대사 21개) · 영문(i18n)이다.

**범위 밖**: 감상 여정(`consumption_philosophy*`)과 가상 독백(`virtual_monologue*`). 둘 다
서비스 노출·신규 작성이 중단돼 빈 값을 결손으로 세지 않는다(`docs/project/celeb/retire/`).

**결손으로 세지 않는 것**: `fiction` 티어의 생몰(특정 불가가 정상), `fiction`·`relation`
티어의 영문 필드(번역 대상 아님), `death_date`(생존자는 비어 있는 게 정상).

> **26.08.06 변경 — 직군·국적·성별은 fiction 포함 전 티어 결손이다.** 기존에는 fiction의
> 국적을 "특정 불가 정상"으로 제외했으나, 원전(작품·신화) 배경 지역으로 재구성해 채우는
> 규칙으로 바꿨다. 규칙 SSoT는 `celeb-1-basic-profile.md`의 「국적 결손」·「성별」 절,
> 감사는 `audit-celeb-track-gaps.ts`(전 티어 `basic:nationality`·`basic:gender` 검사)를 따른다.

## 구조 — 조사와 반영을 분리했다

에이전트는 **조사만** 하고 로컬 JSON을 남긴다. DB 반영은 스크립트가 결정론적으로 한다.
이렇게 하면 에이전트가 중간에 죽어도 작업물이 남고, 에이전트 정원을 전부 조사에 쓸 수 있다.

```
선점 → 조사 → research/<slug>.json  (에이전트, 여러 대)
                    ↓
        celeb-fill.ts apply-dir --apply  (오케스트레이터, 1회)
```

### 도구 (모두 `sw/web-bo`에서 실행)

> 정식 식별자는 `influence-spectrum` CLI 값, `spectrum:*` 결손 코드, 입력 JSON의 `spectrum` 키다. 기존 `influence-persona`·`persona:*`·`persona` 입력은 과거 작업물 호환 경계에서만 정규화한다.

| 스크립트 | 역할 |
|---|---|
| `scripts/audit-celeb-track-gaps.ts` | **결손 전수 감사.** 진행 상황의 단일 원천. `--json` 지원 |
| `scripts/audit-celeb-basic-gaps.ts` | basic 필드만 보는 축약 감사 |
| `scripts/claim-celeb-work.ts` | `--worker <레인> --count N --target <묶음>` — 레인별 독립 선점. 중복 선점 차단, lease 30분, 보류 항목 제외. `--target`은 `basic3`(직군·국적·성별, 기본값) / `influence-spectrum` / `i18n`(영문 번역) / `speech-basic`(수식어·말투·대사 21개) 중 하나이며, 그 트랙 결손자만 뽑는다 |
| `scripts/celeb-fill.ts` | `dump` / `apply --file` / `apply-dir --dir` — **빈칸만 채우는** 조건부 반영. 기본 dry-run, `--apply`로 저장 |
| `scripts/defer-celeb-gap.ts` | 근거 부재 항목 보류 기록. 기록분은 선점 대상에서 빠져 큐 앞단을 막지 않는다 |

### 작업 폴더 `sw/web-bo/.tmp-celeb-fill/`

이 폴더는 한 실행 중에만 쓰며 작업이 끝나면 통째로 삭제한다. 영향력·스펙트럼 규격은
`docs/project/celeb/celeb-4-influence.md`와 `celeb-5-spectrum.md`, 영문 규격은
`docs/project/celeb/celeb-i18n.md`를 따른다.

| 경로 | 내용 |
|---|---|
| `work-<lane>.json` | 해당 레인이 이번에 선점한 대상 |
| `research/` | 조사 결과 대기분 |
| `research-applied/` | 이번 실행에서 반영한 결과를 중복 적용하지 않기 위한 임시 이력 |
| `claims/` | 선점 잠금. 반영 성공 시 자동 반납 |
| `deferred.json` | 이번 실행에서 근거 부족 항목을 다시 선점하지 않기 위한 임시 목록 |

> basic 3필드 지시서(`INSTRUCTIONS.md`)는 그 트랙이 26.08.06에 끝나 삭제됐다. 다시 필요하면
> 현행 basic 규격을 따른다.
>
> **레인이 작업 없이 끝나면 그 인물의 선점 잠금이 남는다.** 반영 도구는 성공한 인물만 잠금을
> 푼다. 그래서 "이미 채워져 있었다"로 끝난 레인의 잠금은 30분 뒤 만료될 때까지 그 인물을
> 붙잡고, 잔량이 얼마 안 남은 막바지에는 이것 때문에 NO_WORK 가 뜬다. 가동 중인 레인이 전부
> 끝난 것을 확인한 뒤 `rm -f .tmp-celeb-fill/claims/*.json` 으로 회수하면 된다.

## 반영 도구의 안전 규칙

- **빈칸만 채운다.** 기존값이 있는 필드·대사 슬롯은 무조건 보존한다.
- 신규 셀럽 생성 경로가 없다. 기존 인물의 빈칸 채우기 전용.
- `celeb_influence`·`celeb_persona`·`celeb_dialogues` 행이 없으면 만든다.
- `celeb_persona`는 `persona` jsonb만 쓴다(평면 점수 컬럼은 DB 트리거가 동기화).
- 점수 범위 검사: 영향력 0~10 정수, 스펙트럼 0~100(dispositions는 -100~100).
- 반영 후 DB를 다시 읽어 **왕복 검증**한다. jsonb 키 순서는 무시하고 비교한다.
- 작성자 실수 흡수: 영향력 필드를 입력 JSON의 `celeb` 아래에 넣으면 제 위치로 옮긴다.
  `speech_tone`·`profession`이 규정 코드가 아니면 그 필드만 빼고 나머지는 반영한다.

## 운영 방법 — 동시 실행 대수가 제약이다

🔴 **서브에이전트 동시 실행을 늘리면 처리량이 늘지 않고 서비스 처리량 제한으로 즉시 실패한다.**
실측(2026-07-31~08-01):

| 동시 대수 | 결과 |
|---|---|
| 40 / 14 / 12 | 시작 직후 차단, 산출 0~9건 |
| 10 / 6 / 4 | 조기 차단, 산출 9~22건 |
| 3 | 완주하기도 하고 차단되기도 함 |
| **1 (레인 1개 × 12단계 순차)** | **매번 완주. 회차당 15~36건 산출** |

🟢 **2026-08-07 재실측 — 6대 동시가 정상 완주했다.** 위 표(07-31~08-01)와 정면으로 어긋난다.
영향력·스펙트럼 회차에서 레인 6개 × 인물 4~5명을 약 두 시간 동안 쉼 없이 돌렸고, 실패한 레인은
하나도 없었다. 한 레인이 4~5명을 처리하는 데 5~11분이 걸렸다.

**위 표의 "즉시 차단"은 처리량 제한이 아니라 발주 방식 때문일 수 있다.** Claude Code에서
서브에이전트에 **이름을 붙여 발주하면** tmux(리눅스 도구)를 요구하는 무리 실행 방식으로 전환되어
Windows에서 즉시 실패한다. 이름 없이 발주하면 6대가 문제없이 병렬로 돈다. 07-31 실측 당시의
발주 형태는 기록에 남아 있지 않아 단정할 수 없으나, **"동시 대수를 늘리면 실패한다"는 결론을
그대로 믿고 1레인 순차로 돌아가지 마라.** 먼저 6대로 시험하고, 실패하면 그때 줄여라.

그 이전 운용은 **레인 1개 × 순차 12단계**였다. 각 단계가 새 세션이라 컨텍스트가 초기화되고,
스스로 3명을 선점해 처리한 뒤 끝난다. 단계 사이에 다른 레인을 기다리지 않는다.

한 회차 절차:

```bash
cd sw/web-bo
# 1) 레인 1개 × 12단계로 조사 (subagent, model=claude-opus-5)
#    영향력·스펙트럼: docs/project/celeb/celeb-4-influence.md + celeb-5-spectrum.md
#    영문 번역:       docs/project/celeb/celeb-i18n.md
# 2) 반영
pnpm exec tsx scripts/celeb-fill.ts apply-dir --dir .tmp-celeb-fill/research          # dry-run
pnpm exec tsx scripts/celeb-fill.ts apply-dir --dir .tmp-celeb-fill/research --apply
# 3) 진행 확인
pnpm exec tsx scripts/audit-celeb-track-gaps.ts
```

중단으로 선점이 남았으면 `rm -rf .tmp-celeb-fill/claims`로 회수한다(lease 30분이면 자동 만료).
장시간 돌릴 때는 `caffeinate -dimsu -t 10800 &`로 절전을 막는다.

### 🔴 「없음」은 비우는 게 아니라 표시하는 것이다

이번 회차에서 세 필드 모두 같은 실수를 했다. **규격에 이미 답이 있는데 확인하지 않고 「비우는 게
맞다」고 판단해 결손을 남겼다.** 각 규격 SSoT에 기록했으니 다음부터는 그쪽을 먼저 본다.

| 필드 | 「없음」을 어떻게 적나 | 규격 |
|---|---|---|
| 명언 | `[확인된 어록이 없습니다]` / `[No verified quote]` | `celeb-speech.md` §자료 희박 예외 |
| 국적 | `XX`(화면에 「미확인」) | `celeb-1-basic-profile.md` §국적 결손 |
| 생년 | **비우지 않는다.** 활동 연대에서 역산해 대표 연도 저장 | `celeb-1-basic-profile.md` §생년 결손 조사·추정 규칙 |
| 성별 | 괴물·동물도 원전의 문법적 성·서사 역할로 판정 | `celeb-1-basic-profile.md` §성별 필드 규칙 |

  후반에 선점 8명 중 실제 작업 대상이 1~2명으로 떨어졌다. 선점기는 그 트랙 결손자만 뽑는데도
  이렇게 되는 이유는, 결손으로 잡히는 항목의 **한국어 원문이 없어 번역 자체가 불가능**하기

  트랙으로 옮겨라. 실제 잔량은 감사 수치가 아니라 "원문이 있는데 번역만 빈" 건수로 세야 한다.
