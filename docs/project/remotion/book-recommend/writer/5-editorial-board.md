# 서재탐방 편집국 검토

편집국 검토는 여러 관점으로 원고의 약점을 찾는 절차다. 가상의 전문가 점수를 평균 내는 놀이가 아니다. 고칠 근거가 있는 문제만 고치고, 자료상 넘을 수 없는 한계는 그대로 보고한다.

## 네 관점

| 관점 | 확인할 것 |
|---|---|
| 분야 정확성 | 책·기술·예술·경영 개념을 해당 분야 사람이 들어도 틀리지 않는가 |
| 사료 | 인용·연도·일화·인과관계가 출처가 허용하는 범위를 넘지 않는가 |
| 영상 이야기 | 첫 사건, 선택, 대가, 감정 변화, 등장인물 역할, 결말 회수가 있는가 |
| 한국어 | 번역투·AI식 추상어·평론투 없이 쉽게 들리는가 |

한 사람이 네 관점을 차례로 적용해도 된다. 실제로 독립된 전문가가 검토하지 않았다면 “전문가 4인이 96점을 주었다”처럼 꾸미지 않는다.

## 시작 전

1. `node sw/remotion/scripts/extract-story.mjs <person>`으로 Markdown 원고를 만든다.
2. SOLO는 `--solo` 또는 `--solo=N`을 붙인다.
3. 처음부터 끝까지 읽고 가장 강한 장면을 먼저 표시한다.
4. 사실검증이 필요한 문장을 별도로 모은다.

분석 단계에서는 JSON을 직접 고치지 않는다.

## 문제의 무게

| 판정 | 예 | 처리 |
|---|---|---|
| 치명 | 사실 오류, 허위 인용, 인과 날조, 이해 불가, 장면 구조 파손 | 반드시 수정 |
| 구조 | 첫 사건 부재, 선택·대가 없음, 결말 미회수, 죽은 등장인물 | 재설계 검토 |
| 문장 | 번역투, 추상 나열, 중복, TTS 호흡 | 필요한 곳만 수정 |
| 취향 | 다른 표현도 가능하지만 현재 문장도 자연스러움 | 건드리지 않음 |
| 한계 | 자료가 부족해 더 강하게 쓸 수 없음 | 과장하지 말고 보고 |

## 등장인물 원칙

이름이 나온 사람은 최소 하나를 해야 한다.

- 결정을 내린다.
- 질문하거나 반박한다.
- 물건을 만들거나 건넨다.
- 갈등의 대가를 치른다.
- 핵심 사실을 자기 행동으로 증명한다.

아무 역할도 없다면 이름을 빼거나 그 사람의 행동을 찾는다. 유명하다는 이유만으로 등장시키지 않는다.

## 감정 검토

감정을 직접 이름 붙이기 전에 근거를 찾는다.

- 기쁨: 웃음, 축하, 보상, 안도, 놀이
- 분노: 반박, 충돌, 거절, 처벌, 공개 비판
- 슬픔: 상실, 실패, 침묵, 포기, 관계의 붕괴
- 즐거움: 농담, 호기심, 몰입, 장난, 뜻밖의 성취

모든 감정을 한 편에 할당량처럼 넣지 않는다. 실제 사건이 허용하는 감정만 살린다.

## 수정 절차

1. 책별로 `강점 / 치명 / 구조 / 문장 / 한계`를 적는다.
2. 강한 장면은 보호한다.
3. 치명 문제부터 수정한다.
4. 구조 수정이 사실을 부풀리지 않는지 다시 확인한다.
5. 한국어를 소리 내어 읽는다.
6. 원고가 확정되면 제작 데이터에 반영한다.
7. JSON, 장면 번호, 화자, 출처, 이미지, 음성 영향을 검사한다.

## 종료 조건

다음을 만족하면 종료한다.

- 치명 문제가 없다.
- 등장인물이 모두 역할을 한다.
- 책과 인물의 연결을 증거보다 세게 말하지 않는다.
- 책을 모르는 사람도 사건을 따라간다.
- 더 고치면 사실을 과장하거나 좋은 문장을 평평하게 만들 위험이 크다.

95점·99점 같은 고정 임계값, 모든 책 S급, 무한 반복은 종료 조건으로 사용하지 않는다.

## 보고 형식

책마다 다음만 간결하게 보고한다.

- 가장 강한 장면
- 고친 핵심 문제
- 남은 약점
- 자료상 태생적 한계
- 이미지·음성·번역에 미치는 영향
