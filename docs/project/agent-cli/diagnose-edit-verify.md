# 진단-편집 분업

기존 자료를 대량으로 점검할 때 빠른 CLI는 이상 후보를 넓게 찾고, 최종 문장과 사실 판단은 별도의 작성자·검수자가 맡는다. 진단 결과는 편집 지시일 뿐 근거도 패치도 아니다.

## 실행

1. 메인 에이전트가 대상, 현재값, 수정 금지 필드, 도메인 규칙을 고정한다. 쓰기 전 충돌을 잡아야 하는 데이터에는 현재값 해시도 붙인다.
2. 진단 CLI는 읽기 전용으로 전 대상을 보고 항목마다 **문제 파악**과 **아이디어 제안**만 반환한다. 문제 파악에는 원문과 위치를 넣고, 사실이 의심되면 추측 대신 조사 대상으로 표시한다. 짧다는 이유만으로 결함을 만들지 않고, 아이디어는 입력에서 확인되는 사실 안에 묶는다. 첫 표본이 깨끗한 항목까지 전부 수정 대상으로 만들거나 입력 밖 이력을 보태면 프롬프트를 고친 뒤 다시 판정한다.
3. 작성 CLI는 진단 후보만 받는다. 사람·사건·원전이 들어간 문장은 조사를 명시적으로 수행하고, 진단 결과를 사실 근거로 쓰지 않는다.
4. 새 호출의 독립 검수자는 현재값과 작성본을 함께 비교한다. 작성본이 나빠진 문장은 현재값으로 돌리고, 말투처럼 경계가 좁은 판단만 별도 재심에 보낸다.
5. 메인 에이전트가 최종 패치를 조립한다. 수정 금지 필드와 현재값 해시를 검사한 뒤 dry-run, 승인된 쓰기, DB 재조회 순으로 끝낸다. 재조회가 기대값과 같고 보호 필드가 그대로일 때만 완료다. DB 반영이 확인되면 중간 산출물은 지운다.

## 확인된 조합

- 넓은 진단과 아이디어: [`agy-antigravity`](../../../.agents/skills/agy-antigravity/SKILL.md)의 `gemini-3.8-flash-high`
- 후보 작성: [`codex-gpt`](../../../.agents/skills/codex-gpt/SKILL.md)의 GPT-5.6 Sol, 조사 명시
- 독립 검수: 새 Codex GPT-5.6 Sol 호출
- 좁은 경계 재심: agy에 해당 판단만 다시 제시
- 패치·DB 반영과 readback: 메인 에이전트

이 조합은 기존 신화 인물 상황 대사 감사에서 실제 반영과 재조회까지 통과했다. 확인된 핵심은 agy의 역할을 문제 발견과 방향 제안에 묶고, 완성 문장·사실·최종 말투·쓰기 권한을 넘기지 않는 것이다.

팩션 대사에도 같은 분업을 쓰되, 최종 후보의 반영 가능 여부는 [`faction-dialogue-review`](../../../.agents/skills/faction-dialogue-review/SKILL.md)가 정한다. CLI가 좋은 문장을 만들었다는 이유로 장면 단일원천이나 음성 보호 경계를 우회하지 않는다.
