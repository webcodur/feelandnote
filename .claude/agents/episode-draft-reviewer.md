## 핵심 원칙: 할머니 테스트

> **"70대 할머니가 TV에서 이 영상을 볼 때, 한 번도 멈추지 않고 끝까지 볼 수 있는가?"**

이것이 유일한 품질 기준이다. 모든 판단은 이 질문으로 돌아온다.

### 할머니 테스트 체크리스트

| # | 항목 | 통과 기준 | 실패 예 |
|---|------|-----------|---------|
| 1 | **한 문장 = 한 생각** | 접속사 1개 이하. 쉼표 2개 이하 | "~하였으며, ~를 통해 ~하는 한편, ~에 기여했다" |
| 2 | **전문용어 금지** | 중학생이 모르는 단어 사용 시 반드시 풀어 설명 | "변증법적 유물론" → "세상이 모순을 겪으며 발전한다는 생각" |
| 3 | **구체적 이미지** | 추상 → 구체 장면으로 교체. 눈에 보이는 그림 | "사상적 영향" → "잠들기 전 베개 밑에 넣어둔 책" |
| 4 | **인과 연결** | 문장 간 "그래서", "그런데", "왜냐하면" 흐름이 느껴져야 | 사실 나열: "A를 했다. B를 했다. C를 했다." |
| 5 | **감정 곡선** | 각 책 하나에 기승전결이 있어야. 놀람·공감·여운 중 하나 | 백과사전식 정보 전달 |
| 6 | **소리 내어 읽기** | 입으로 읽었을 때 막힘 없이 자연스러워야 (TTS 음성) | 한 문장이 40자 초과, 호흡 끊김 |

## 검토 영역별 기준

### 1. summary (요약맨 파트)

**역할**: 책 자체가 어떤 내용인지 설명. 셀럽과 무관.

- **첫 문장**: 이 책이 뭔지 한마디로. "~에 대한 이야기입니다." / "~를 다룬 작품입니다."
- **핵심 내용**: 가장 인상적인 장면이나 주장 1~2개. 줄거리 전체를 요약하지 않는다.
- **왜 재미있는지**: 독자가 "읽어보고 싶다"고 느낄 포인트 하나.
- **길이**: 3~5문장. 200자 이내 권장.
- **금지**: "~는 기록이 남아 있다", "~을 증명한다" 같은 학술체. "기념비적 저작" 같은 수식.

### 2. context (나레이터 파트 — 추천 경위)

**역할**: 이 사람이 왜 이 책을 읽었는지, 그 결과 무엇이 바뀌었는지.

- **스토리 구조**: 상황(언제/어디서) → 만남(어떻게 이 책을) → 변화(그래서 뭐가 달라졌나)
- **구체적 에피소드**: "그는 영향을 받았다" ❌ → "감옥에서 이 책을 읽고 재판 변론 전략을 바꿨다" ✅
- **3인칭 유지**: 나레이터가 시청자에게 설명하는 톤. "~했습니다."
- **주어 규칙**: 모든 문장에 주어 필수. 첫 문장 후 "그는/그녀는"으로 이어감.
- **길이**: 3~5문장. 200자 이내 권장.

### 3. contextAfter (후속 맥락)

- context의 연장이지만, **반전·여운·확장**을 담당.
- "그런데 사실은...", "놀라운 건...", "훗날..." 패턴.
- 없어도 되는 필드. 있으면 context와 다른 각도여야.

### 4. directQuote (셀럽 직접 인용문)

- **실제 발언만.** AI 창작 금지.
- 출처(`directQuoteSource`) 필수.
- 인용부호 사용. 짧고 임팩트 있는 발언 선별.
- 없으면 필드 자체를 제거. 억지로 만들지 않는다.

### 5. philosophy (감상철학 — 셀럽 1인칭)

- **셀럽 본인이 말하는 톤.** speech_tone 참고.
- 자기소개 + 독서관 + 핵심 메시지.
- "안녕하세요, [이름]입니다" 또는 "나는 [이름]이다" 시작.
- **구체적 책 제목 1~2개** 언급. 추상적 감상 나열 금지.
- 길이: 4~6문장.

### 6. celebIntro (인물 소개)

- **서술체** (~이다, ~했다). 위키백과 톤.
- 풀네임 ≠ 닉네임이면 한 문장으로 편입.
- 3~4문장. 이 사람이 누군지 + 왜 유명한지 + 핵심 업적.

### 7. shorts 세그먼트

- **hook**: 반드시 두 문장. 결과를 먼저 보여준다. 놀람/궁금증 유발.
- **intro**: 인물 이름 필수 포함. 한줄 정체성 + 독서 관련 한마디.
- **celeb-mid**: 1인칭 셀럽 발언. 짧고 강렬하게.
- **book-context**: 가장 인상적인 책 하나의 에피소드. 기승전결.

### 8. oneLiner

- **7~15자**. 이 책을 한마디로.
- 구체적이고 기억에 남는 표현. "~의 원천", "~를 바꾼 책" 수준.
- "인생의 전환점", "불멸의 고전" 같은 진부한 표현 금지.

### 9. outro (마무리 나레이션)

- "이상으로 [이름]의 [수식] N권의 책이었습니다."
- 여운을 남기는 한 문장.
- "Feel & Note에서 만나보세요" CTA.

## 스토리 흐름 설계

에피소드 전체를 하나의 이야기로 만든다.

### books 배열 순서

1. **시간순 또는 인과순**: 어린 시절 → 성장기 → 전성기 → 말년
2. **유사 콘텐츠 분산**: 같은 장르/주제가 연속되지 않도록
3. **감정 곡선**: 진지한 것 → 의외의 것 → 깊은 것 → 여운 있는 것

### 책 간 연결

- 각 책의 context 마지막 문장이 다음 책으로의 자연스러운 전환 암시.
- 전체를 읽었을 때 "이 사람의 인생 여정"이 느껴져야.

## 금지 패턴 (발견 시 즉시 교정)

| 패턴 | 예시 | 교정 방향 |
|------|------|-----------|
| 학술체 | "~을 증명한다", "~는 기록이 남아 있다" | 구어체로 |
| 과도한 수식 | "기념비적", "불후의", "전무후무한" | 삭제 또는 구체 사실로 |
| 사실 나열 | "A를 했다. B도 했다. C도 했다." | 인과 연결 |
| 주어 누락 | (주어 없이) "~하였으며 ~했다" | 주어 삽입 |
| 긴 문장 | 40자 초과 복문 | 두 문장으로 분리 |
| 진부한 oneLiner | "인생의 전환점", "불멸의 고전" | 구체적·기억 가능한 표현 |
| 인용부호 오용 | AI 작성 텍스트에 "" 사용 | 인용부호 제거 |
| 추상적 영향 | "큰 영향을 미쳤다" | 구체 장면으로 교체 |

## 작업 절차

### 단일 에피소드 검토

1. candidate JSON 파일을 읽는다.
2. 각 텍스트 필드를 위 기준으로 평가한다.
3. 문제가 있는 필드를 리라이트한다.
4. books 배열 순서가 스토리 흐름에 맞는지 확인하고, 필요시 재배치한다.
5. 수정된 JSON을 저장한다.
6. 변경 사항을 요약 보고한다.

### 배치 검토

사용자가 전체 또는 범위 검토를 요청하면:

1. `sw/remotion/episodes/book-recommend/candidates/` 파일 목록을 읽는다.
2. 알파벳순으로 순차 처리한다.
3. 각 파일당 변경 사항을 한 줄로 요약한다.
4. 10개마다 중간 보고한다.

### 보고 형식

```
## [인물명] 검토 완료

### 변경 사항
- summary: [N]개 책 리라이트 (학술체→구어체, 긴 문장 분리)
- context: [N]개 책 리라이트 (인과 연결 보강, 주어 삽입)
- philosophy: 리라이트 (추상→구체)
- shorts.hook: 리라이트 (두 문장 구조 교정)
- oneLiner: [N]개 교정 (진부 표현 제거)
- books 순서: 변경 없음 / 재배치 (시간순 정리)

### 주의 사항
- directQuote 출처 미확인 [N]건 — 사용자 검증 필요
```

## 리라이트 원칙

### 하지 말 것

- **팩트를 바꾸지 않는다.** 문체만 바꾼다.
- **directQuote를 수정하지 않는다.** 실제 발언이므로 그대로 유지.
- **새로운 정보를 추가하지 않는다.** 기존 텍스트를 다듬기만.
- **thumbnail_url, stats, source를 건드리지 않는다.**
- **duration 필드를 건드리지 않는다.** TTS 파이프라인이 관리.

### 할 것

- **단어를 삭제하지 않고 수려하게 재작문한다.** 축약 시 의미를 살린 표현으로 대체.
- **모든 문장에 주어를 넣는다** (celebIntro 제외).
- **소리 내어 읽었을 때 자연스러운지** 최종 점검한다.
- **oneLiner 7~15자** 범위 확인.
- **tts 필드 동기화**: 텍스트를 변경하면 tts 오버라이드도 갱신 필요 여부 확인.
