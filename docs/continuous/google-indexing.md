# 검색엔진 색인·수집 신청

**우선 문제:** 한글 서비스명 `필앤노트`로 홈페이지를 찾기 어렵다. 10월 20일 Google 한국어·한국 설정의 검색 1~5페이지와 정확 일치 검색에서 홈페이지가 없었고, `feelandnote` 및 `site:feelandnote.com 필앤노트`에서는 홈페이지가 첫 결과였다. Google 저장본(10월 12일 17:46:58 KST)에도 현재와 같은 한글 제목·설명·H1과 `필앤노트` 별칭이 있어 한글 메타 누락이나 단순 미수집으로 원인을 단정하지 않는다. 저장본의 구조화 데이터에는 현재 제거된 옛 영문 별칭이 남아 있으므로 다음 Google 할당량 회복 시 홈페이지를 먼저 재수집 요청한다. 상세주소 접수 건수만으로 브랜드 검색 문제의 개선 여부를 판정하지 않는다.

**브랜드 보완 현재 상태(10-20):** Daum 등록명 `필앤노트(feelandnote)`·`https://feelandnote.com/`·현행 설명으로 변경신청 완료 화면을 확인했다. 심사는 안내상 업무일 기준 5일 이내이며 검색 반영은 대기 중이다. 네이버 블로그 소개에 공식 브랜드·홈페이지 주소를 반영했고, 티스토리 소개와 관련사이트의 공식 홈페이지 링크도 공개 화면에서 확인했다. 유튜브 두 채널의 기본·한영 소개에서 옛 브랜드 표기를 정리하고 HTTPS 주소를 반영했다. 웹 보완 5파일은 커밋 `8fb013002`로 main에 push하고 Oracle 운영에 배포했다(최종 검수 10-20 21:04 KST, 릴리스 `8fb01300-web-20261020t115237z`). 홈 가시 한글 이름·공식 블로그 링크·Organization 연결을 공개 한영 홈과 빌 게이츠 상세의 200 응답에서 확인했다. 빌드·타입·사전 검증과 운영 전환, `seo`·`cached-html` 캐시 퍼지를 완료했고 서비스·Caddy·터널이 정상이다. Google 재수집과 한글 브랜드 검색 순위 반영은 별도 확인 대상이다.

**현재 도달점:** 공개 인물 6,653명의 한영 13,306주소와 주요 페이지 986주소, 총 14,292주소가 운영 사이트맵에 있으며 active 명단과 대조해 누락 0명을 확인했다. 10월 20일 Google 3주소·네이버 50주소·Bing 100주소·Daum 84주소를 접수했다. Google·네이버는 실제 일일 초과 응답, Bing은 잔여 0을 확인했다. Daum은 「중복 URL, 과도한 호출」 뒤 대기하고 요청 간격을 늘려 54주소를 추가 접수했으며, 느린 재시도에서는 제한이 재현되지 않았다. Google 접수 3주소 중 옥면공주 한영 2주소는 색인 완료, 전갈정 한국어는 크롤링 완료·미색인이다. Google 사이트맵 2개를 재제출해 오늘 재읽기·인물 13,306·전체 14,292주소·오류와 경고 0을 확인했다. 옥면공주·전갈정·여아국왕·행선 한영 8주소는 네이버·Bing 접수까지 완료됐고, Google에는 아래 표의 5주소가 남았다.

접수는 실제 재크롤·색인·대표사진 반영 완료를 뜻하지 않는다.

마지막 실제 검색 확인(10-20)에서 Google의 `site:<상세주소>` 검색은 빌 게이츠·다리오 아모데이·젠슨 황 모두 현재 제목으로 상세를 보여 줬다. 빌 게이츠 설명에는 현재 인물 소개와 감상 수가 나오고, 다리오에는 「감상 기록을 모았습니다」가 남았으며, 젠슨 황은 현재 meta description 대신 인물 안내 본문을 골랐다. 세 결과의 이미지는 모두 28px 파비콘뿐이며 인물 사진 썸네일은 없었다. 운영 대표이미지 3장은 200·JPEG다. URL Inspection의 마지막 크롤은 빌 게이츠 10-10 00:37:50, 다리오 10-12 18:22:55, 젠슨 황 10-12 18:16:40(KST)로 그대로다. 네이버 「필앤노트 + 인물」은 세 인물 모두 상세를 보여 주지 않았지만, 정확한 상세주소의 `site:` 검색에서는 세 주소 모두 제목·설명·이미지와 함께 노출된다. `site:feelandnote.com 빌 게이츠`도 상세를 첫 결과로 보여 주며 현재 meta description이 반영됐다. `/celeb/` 경로의 `site:` 검색에도 여러 인물 상세가 나온다. 이 세 주소는 브랜드 검색 미노출을 미색인으로 해석하지 않는다. Daum은 한글 `필앤노트` 검색에는 홈페이지가 없지만, `feelandnote`와 `feelandnote.com` 검색에는 등록명 `feelandnote`, 주소 `http://feelandnote.com/`인 홈페이지가 나온다. Daum의 빌 게이츠 상세주소 `site:` 검색은 결과가 없었다.

**Google·네이버·Bing은 오늘 한도 도달을 확인했다. Daum은 대기·감속 후 재개돼 84주소까지 접수됐고, 추가 신청이 가능한 상태다.** 엔진별 다음 주소는 위 표가 쥔다. 사이트맵·브랜드·설명문 규칙은 [SEO](../project/operations/ops-02-seo.md)가 쥔다.

일일 신청량과 이어갈 대상은 [SEO 운영 규칙](../project/operations/ops-02-seo.md#검색엔진-등록-현황)을 따른다. 아래 순서로 진행한다.

1. 먼저 한글·영문 서비스명 검색에서 홈페이지가 나오는지 확인하고 위 우선 문제를 이어간다. 이어 빌 게이츠·다리오 아모데이·젠슨 황의 실제 검색 결과에서 상세 주소·최신 제목·설명·대표사진을 확인한다. 서비스명과 인물명 검색에서 안 보이면 정확한 상세주소의 `site:` 검색도 확인해 순위·검색어 문제와 미색인을 구분한다. 아바타를 쓰는 경우 승인된 원래 황갈색 배경도 확인한다. 현재 운영 응답, 검색엔진 저장 문서, 실제 검색 결과를 대조해 메타를 이미 읽은 경우와 아직 재수집되지 않은 경우를 구분한다.
2. 네이버·Bing은 접수 내역과 공개 사이트맵을 대조해 신규 주소와 기존 미접수 상세를 실제 일일 한도까지 신청한다. 기존 접수 주소는 반복하지 않는다.
3. Google은 위 표의 미접수 순서대로 이어간다. 이미 최신 변경이 반영된 주소를 반복 신청하지 않는다.
4. 셀럽 상세를 우선 처리한 뒤 세력 상세를 이어간다. 해리스 프리커와 의도적 noindex 작품은 후속 신청에서 제외한다.
5. 다음(Daum)은 신규 공개 주소 뒤에도 기존 미접수 상세를 이어서 신청하고, 실제 제한 응답을 확인한다. 실제 검색 제목·설명·대표사진 반영을 확인한다. 사이트 검색의 한글·영문 등록명과 HTTPS 주소 변경신청은 완료됐으며 심사 결과와 실제 검색 반영을 확인한다.

Daum 리스트 Seed는 메인·탐색·인물 명부, 직군 명부 16개 전체, `/explore/faction`·`/explore/myth`·`/explore/works/curated`까지 접수한 상태다. 10-17에 남은 `athlete`·`other`와 세력·신화·기관 선정 허브 5건을 추가 접수해 목록 Seed 큐를 비웠다. 기존 접수 주소는 반복하지 않는다.

네이버는 오늘 50주소 접수 뒤 실제 일간 제한을 확인했다. 다음 미접수 상세는 위 표에서 이어간다.

신청 전에 현재 active 명단 전체를 운영 사이트맵과 대조한다. 예전에 생성하고 오늘 공개한 인물이 있으므로 `created_at`만으로 신규 공개 여부를 판단하지 않는다. 운영 응답·자기 canonical·검색 허용과 기존 접수 내역도 확인한다. 대표 디렉토리만 신청하고 상세 주소가 모두 처리됐다고 간주하지 않는다. 같은 날 이미 접수한 주소, 영구 이동하는 옛 주소, 비공개·의도적 noindex 주소는 신청 대상에서 뺀다. 인물 주소는 현재 공개 사이트맵에서 확인하며 이름으로 slug를 추측하지 않는다.

## 신청과 반영 확인

- 로그인된 브라우저로 Google Search Console과 네이버 Search Advisor를 조작하고 기존 계정을 유지한다. 브라우저 제어는 [aside-browser 스킬](../../.agents/skills/aside-browser/SKILL.md)을 따른다.
- Aside 브라우저의 `u0`(webcodur@gmail.com)가 Google Search Console·Bing Webmaster·네이버 Search Advisor에 접근된다. Search Advisor 계정은 `booster`이며, 로그인 복구 뒤에는 콘솔을 다시 열어 새 세션을 적용한다. Daum 웹마스터는 사이트 URL+PIN 인증으로 진입한다 — PIN 파일 위치는 [비밀 파일 규약](../project/platform/platform-04-env-vars.md)이 쥔다. 값은 Git 추적 파일에 기록하지 않는다. 콘솔 접근이 막힐 때는 IndexNow(`sw/web-bo/src/lib/indexnow.ts`와 같은 키로 `api.indexnow.org`에 POST)로 네이버·Bing 대상을 통지한다.
- Google은 URL 검사 화면의 대상 주소가 신청하려는 주소와 일치한 뒤 「색인 생성 요청」을 누르고 결과를 확인한다. 이전 URL의 결과 대화상자를 닫은 뒤 다음 주소로 넘어간다. 접수 후에는 마지막 크롤 시점·색인 상태·저장된 페이지가 최신인지 확인한다.
- 네이버는 「요청 → 웹 페이지 수집」에서 정식 주소를 입력하고, 요청 내역의 실제 링크·등록일로 접수를 확인한다. 목록 갱신이 늦거나 이전 행의 접근성 이름이 남으면 실제 링크와 행 본문을 다시 읽고, 접수 여부를 확인하기 전에 재신청하지 않는다. 신청 뒤 실제 검색 결과의 인물 사진·제목·설명도 확인한다. 일간 초과 문구는 페이지 본문에 남지 않는 브라우저 자체 경고로 뜰 수 있으므로 실제 경고도 확인한다.
- Google의 「할당량 초과」 또는 네이버의 「사이트별 일간 최대 요청 수를 초과하였습니다.」가 뜨면 해당 엔진의 당일 신청을 끝낸다. 다른 주소로 우회해 계속 누르지 않는다. Google 접수 건수는 날마다 달랐으므로 고정 건수를 가정하지 않는다. 네이버는 이번에 50주소 접수 뒤 한도를 확인했다.
- Google 접수 확정은 결과 대화상자의 「check_circle 색인 생성 요청됨 - URL이 우선순위 크롤링 대기열에 추가되었습니다」 문구로만 판정한다. 「색인 생성 요청됨 / 다시 요청」 칩이나 직전 주소의 대화상자 잔여 텍스트가 본문에 남아 오탐을 만든다. 접수 직후 같은 주소를 다시 검사하면 칩 상태(요청됨·등록됨)로 실제 반영을 확인할 수 있다.
- Google의 「색인 생성 요청을 제출하는 중에 문제가 발생했습니다」는 할당량 초과와 구분한다. 해당 주소를 반복 요청하지 않고 다음 주소로 넘어간다. 결과 미확인·조작 실패가 이어지면 원인을 확인한 뒤 재개한다.
- Daum은 문서등록 완료 문구 또는 같은 버튼이 호출하는 `/collect/insert`의 `result:true`로 접수를 확정한다. `result:false`의 실제 메시지를 확인하고, 「중복 URL, 과도한 호출」이면 당일·과거 접수 목록과 대조한다. 미접수 대상이면 잠시 대기하고 요청 간격을 늘려 같은 주소를 재시도한다. 정상 접수가 재개되면 이어가며, 이 응답 한 번을 당일 종료나 고정 일일 건수·자정 초기화의 증거로 삼지 않는다. HTTP 오류·결과 미확정은 접수 수에서 제외하고 바로 반복 신청하지 않는다.

이 문서에는 현재 도달점·마지막 접수·한도 문구·다음 신청 대상만 갱신한다. 날짜별 이력이나 URL별 조사 파일을 따로 쌓지 않는다. 사이트맵·IndexNow·메타데이터 운영 규칙은 [SEO](../project/operations/ops-02-seo.md)가 쥔다.
