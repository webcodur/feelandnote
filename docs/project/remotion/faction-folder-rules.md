# 팩션 폴더구조 및 데이터 룰북 (Faction Asset & Data Rulebook)

`sw/remotion/public/factions/` 하위에 위치하는 모든 팩션 시리즈(예: `AI-Supremacy`, `Digital-Resistance` 등)의 폴더, 이미지 에셋, 마크다운 문서를 관리하는 SSoT(단일 진실 공급원) 규격입니다.

이 규칙은 팩션 엔진 데이터(`faction-data.json`, `faction-cards.json`)와 물리적 폴더 구조를 일치시키고, 파일 누락이나 경로 파편화를 원천 차단하기 위해 강제됩니다.

---

## 1. 최상위 데이터 설정 파일 (Data Configuration)

팩션 렌더링 엔진 및 백오피스는 전역 검색 시 혼동을 피하기 위해 `data.json` 대신 팩션 전용 접두사가 붙은 아래의 파일명만을 인식합니다.

- **`faction-data.json`**: 팩션의 인물 배열, 클러스터 매핑, 음성/영상 타이밍 메타데이터를 담고 있는 코어 엔진 파일입니다. 각 시리즈 폴더 루트에 위치합니다.
- **`faction-cards.json`**: 카드뉴스 출고를 위한 카드 전용 텍스트/대본 파일입니다. 영상 메타데이터와 분리하기 위해 시리즈 폴더 루트에 분리 저장됩니다.

---

## 2. 폴더 네이밍 및 계층 규칙 (Directory Hierarchy)

팩션 시리즈 내의 모든 세력(Group)과 인물(Person)은 예외 없이 다음 3단계 계층 구조를 따릅니다.

```text
[팩션번호-세력명] / [클러스터번호] / [인물순번-슬러그] /
```

### 1계층: 팩션(세력) 폴더 `[팩션번호]-[세력명]`
- `faction-data.json`의 `groups` 배열 인덱스와 무관하게 고유한 세력 식별 번호를 앞단에 붙입니다.
- 예: `01-pioneers`, `02-google-deepmind`, `11-huggingface`

### 2계층: 클러스터 폴더 `[클러스터번호]`
- 팩션 내부의 인물 그룹(Cluster)을 구분하는 1부터 시작하는 숫자 폴더입니다.
- 세력을 여러 클러스터로 나누지 않은 경우(단일 세력)에도 **반드시 `1` 폴더를 생성하여 한 단계 깊이를 보장**합니다.
- 예: `01-pioneers/1/`, `02-google-deepmind/1/`

### 3계층: 인물 폴더 `[인물순번]-[인물_슬러그]`
- 클러스터 내에서 해당 인물이 등장하는 순서(1부터 시작, 2자리 패딩)와 영문 슬러그를 결합합니다.
- 슬러그 내부의 띄어쓰기나 대시(`-`)는 언더스코어(`_`)로 치환하여 표기합니다.
- **파일이 없는 인물의 경우, 억지로 빈 폴더를 생성하지 않고 실제 에셋이 준비될 때 폴더를 생성합니다.**
- 예: `01-alan_turing`, `02-demis_hassabis`

---

## 3. 팩션 및 클러스터 공통 에셋 규격

인물이 아닌 팩션(세력) 자체나 클러스터(그룹) 자체를 대표하는 시각 에셋들은 다음과 같은 엄격한 파일명을 따릅니다.

### 3-1. 팩션 로고 (Faction Level)
- **위치**: `[팩션번호-세력명]/logo.png`, `[팩션번호-세력명]/logo.mp4`
- **설명**: 팩션의 대문(타이틀 카드)에 쓰이는 기업/팀의 공식 로고 및 배경 영상입니다. 반드시 팩션 최상위 루트에 `logo`라는 이름으로 통일합니다.

### 3-2. 클러스터 화보 단체샷 (Cluster Level)
- **위치**: `[팩션번호-세력명]/[클러스터번호]/group.png` (혹은 `group.jpg`)
- **설명**: 해당 클러스터 인물들이 모여 있는 팀 화보 컷입니다. 반드시 클러스터 폴더 직하위에 `group`이라는 이름으로 통일합니다. (`_founders.png` 등 임의 이름 사용 금지)

---

## 4. 인물 내부 에셋 파일 명명 원칙

인물 폴더 3계층 내부로 들어가는 에셋(이미지, 영상 등) 파일명은 **본래 이름을 그대로 유지하는 것을 원칙**으로 합니다.

- **이유**: AI 스크립트나 시스템이 임의로 `body.png`, `face.png`로 일괄 개명할 경우, 어떤 사진이 전신샷이고 어떤 것이 얼빡샷(Face)인지 논리적으로 역추적하기 힘들어져 매핑 오류가 발생할 수 있습니다.
- 따라서, `데미스 허사비스.png`와 같이 한글로 된 파일명이나 기존에 부여된 고유 파일명이 있다면 강제로 바꾸지 않고 그대로 사용합니다.
- 새롭게 추가되는 에셋을 사람이 직접 명명할 때는 `face.png`, `body.png`, `story-1.png` 등으로 직관적인 이름을 부여하는 것을 권장합니다.

## 5. 기획 및 문서 에셋 파일 규격 (.md)

이미지뿐만 아니라, 팩션이나 인물을 구상한 마크다운 기획 문서(`.md`) 역시 철저히 소속에 맞게 분배되며 파일명이 통일됩니다.

### 5-1. 팩션 기획 문서 (Faction Level)
- **위치**: `[팩션번호-세력명]/concept.md`, `[팩션번호-세력명]/research.md`
- **설명**: 해당 팩션 전체를 아우르는 씬(Scene) 기획안 대본이나 인용구 등 리서치 노트입니다. 팩션 루트에 위치시킵니다. (씬이 쪼개진 경우 `concept-sub.md` 등으로 파생 가능)

### 5-2. 개별 인물 대본 및 프롬프트 문서 (Character Level)
- **위치**: `[팩션번호-세력명]/[클러스터번호]/[인물순번-슬러그]/story-prompt.md`
- **설명**: 해당 인물 단 한 명의 배경 조사, 대본 작성 프롬프트를 담은 문서입니다. 반드시 해당 인물 폴더 안에 `story-prompt.md`로 통일하여 보관합니다.

### 5-3. 글로벌 문서 (Global Level)
- **위치**: `[시리즈루트]/_docs/`
- **설명**: 특정 팩션에 속하지 않는 범용 워크플로우(`WORKFLOW.md`), 공통 프롬프트 모음 등은 시리즈 루트 직하위의 `_docs` 디렉토리에 아카이빙합니다.

## 7. 구조 변경 시 유의점 (데이터 동기화)

물리적 폴더 구조나 순번, 슬러그가 변경될 경우 **반드시 `faction-data.json` 및 `faction-cards.json` 내의 파일 경로를 새 경로에 맞게 100% 동기화**해야 합니다.

- `faction-data.json`: `groups[].clusters[].people[].image` 등
- `faction-cards.json`: `people[].cardFace`, `people[].cardStory[].image` 등

위 JSON 경로들이 물리적 폴더 구조를 벗어나거나 파편화된 옛 경로(`10-china/량원펑.png` 등)를 가리키면 Studio 렌더링 및 백오피스(BO) 뷰어에서 즉각 엑스박스(표시 오류)가 발생하게 되므로, 폴더 이동 시 JSON 갱신 작업을 하나의 트랜잭션으로 취급해야 합니다.
