# AdSense 운영

AdSense 연결, 심사 대응, 광고 게재 시 확인할 기준을 관리한다.
수익화 방향과 상품 제휴는 [수익화](monetization.md), 검색 설정·색인 지표·회복 판정은 [SEO](seo.md)가 쥔다.

## 승인 판단

과거 감사에서는 크롤러가 핵심 본문을 받지 못하는 기술 결함과 자체 해설이 부족한 콘텐츠를 확인했다.
그러나 당시 AdSense 화면의 정확한 거절 문구·문제 코드를 확보하지 못했다.
확인된 결함은 수정 근거이며, Google의 실제 거절 원인을 확정하는 증거는 아니다.

현재 계정 승인 상태도 이 문서에서 확정하지 않는다. 계정 화면과 알림 메일을 확인해야 한다.
스크립트 존재, `ads.txt` 정상 응답, 검색 색인 회복은 각각 다른 사실이다.
어느 하나를 확인했다고 승인이나 수익 발생을 보고하지 않는다.
Google도 구체적인 미승인 사유는 계정 또는 안내 메일에서 확인하도록 안내한다. [공식 미승인 안내](https://support.google.com/adsense/answer/81904)

## 코드 연결

| 확인 대상 | 현행 코드와 의미 |
|---|---|
| 광고 로더·계정 메타 | [`sw/web/src/app/[locale]/layout.tsx`](../../../sw/web/src/app/[locale]/layout.tsx)의 `<head>`에 비동기 `adsbygoogle.js` 로더와 `google-adsense-account` 메타를 둔다. 로컬 코드상 개발·운영 환경 분기 없이 포함된다 |
| 판매자 선언 | [`sw/web/public/ads.txt`](../../../sw/web/public/ads.txt)에 Google 게시자 항목을 둔다. 계정 ID를 바꾸면 로더·메타·이 파일을 함께 대조한다 |
| 게재 설정 | 자동 광고 활성화, 제외 페이지, 계정 심사·정책 상태는 AdSense 콘솔에서 확인한다. 로더가 있다는 이유로 자동 광고가 켜졌다고 추정하지 않는다 |

위 경로는 저장소 코드의 연결 상태를 설명한다. 운영 배포본의 응답이나 계정 상태를 대신하지 않는다.
로더 위치를 변경할 때는 초기 HTML의 `<head>`에서 코드가 확인되는지 본다.
하이드레이션 이후 DOM이나 preload 문자열만 보고 코드 설치 검증을 끝내지 않는다.
Google의 연결 문제 안내도 `<head>` 내 코드와 실제 신청 사이트의 일치를 확인하도록 한다. [코드·접근 문제 확인](https://support.google.com/adsense/answer/12176698)

## 콘텐츠 판단

독창적 기여는 독자가 그 페이지에서 새로 알게 되는 내용으로 판단한다.
인물이 작품을 접한 근거, 그때의 상황, 작품과 인물의 연결을 설명한 감상배경과 자체 큐레이션이 이에 해당한다.
출판사 소개·외부 줄거리·트랙 정보의 분량이 늘었다고 사이트의 기여가 늘어난 것은 아니다.

과거 감사에서 짧은 감상문 하나에 의존하는 작품 상세가 확인됐다.
현재도 같은지 판단할 때는 실제 페이지의 외부 메타 의존도와 자체 해설을 읽는다.
특히 음악 상세처럼 외부 메타가 화면 대부분을 차지하기 쉬운 유형을 함께 확인한다.
과거 건수·글자 수·비율을 현재의 정책 위반률이나 승인 임계값으로 사용하지 않는다.

Google은 가치가 낮거나 제작 중인 화면, 추가 해설·큐레이션 없이 복제한 콘텐츠에 광고를 허용하지 않는다.
광고와 유료 홍보물이 게시자 콘텐츠보다 많아지는 화면도 제한한다. [Google 게시자 정책](https://support.google.com/adsense/answer/10502938)
이 기준은 글자 수를 채우라는 뜻이 아니다. 상품 링크를 늘리는 일도 자체 콘텐츠 보강을 대신하지 못한다.

게재와 색인 여부는 각각 판단한다. `noindex`를 붙였다는 이유로 광고 정책 검토에서 제외됐다고 간주하지 않는다.
Google은 신청 URL뿐 아니라 사이트의 다른 페이지도 검토할 수 있다고 밝힌다. [사이트 콘텐츠 심사](https://support.google.com/adsense/answer/81904)
색인 대상 선정과 서버 본문·구조화 데이터의 정합성은 [SEO](seo.md)를 따른다.

## 기술 접근 확인

심사 문제를 조사할 때는 실제 운영 주소에서 다음을 확인한다.

- 로그인 없이 공개 본문과 탐색 경로에 접근할 수 있고, 빈 화면·오류·인증 대기로 막히지 않는다.
- 초기 HTML에 인물·작품의 핵심 설명과 감상배경이 들어 있다. 로딩 틀이나 메뉴만 반환하지 않는다.
- `Mediapartners-Google`의 접근이 robots나 앞단 차단에 막히지 않는다. 일반 브라우저의 200 응답만으로 판단하지 않는다.
- 신청 도메인의 HTTPS, 광고 코드, `/ads.txt` 응답을 확인한다. 로컬 파일이 있다는 사실과 운영 응답을 구별한다.

코드 누락·접근 실패·독창적 콘텐츠 부족은 Google이 별도로 안내하는 문제다. [사이트 준비 상태 점검](https://support.google.com/adsense/answer/12176698)
robots·canonical·사이트맵·본문 렌더 규칙과 검색 지표는 [SEO](seo.md), 운영 앞단과 배포는 [외부 서비스](../platform/external-services.md)를 참조한다.
검색 노출이 적다는 사실만으로 접근 실패나 미승인 원인을 하나로 확정하지 않는다.

## 계정에서 확인할 항목

AdSense를 다시 다룰 때는 `사이트`의 `feelandnote.com` 상세와 홈의 미완료 계정 설정부터 확인한다.
승인 상태, 표시된 사유·문제 코드·날짜, 계정 설정의 미완료 항목을 원문 그대로 확보한다.
광고 게재 문제가 있으면 정책 센터의 제한 내용과 `ads.txt` 상태도 함께 본다.

| 계정에 표시된 상태 | 확인할 내용 |
|---|---|
| `Requires review` | 계정의 필수 설정과 사이트 준비가 끝났는지 확인한 뒤 검토 요청을 진행한다 |
| `Needs attention` | 표시된 실제 문제를 해결한다. 과거 감사의 추정을 새 거절 사유로 대입하지 않는다 |
| `Getting ready` | 심사 중인지, 미완료 계정 설정 때문에 검토가 시작되지 않았는지 확인한다 |
| `Ready` | 게재 가능한 상태다. 실제 광고 노출·수익·정책 제한은 별도로 확인한다 |

`ads.txt`의 `Authorized`는 게시자 ID 확인 결과이며 사이트 승인 상태가 아니다.
Google은 심사 중 사이트를 삭제했다가 다시 추가하면 처리가 늦어질 수 있다고 안내한다. [계정 상태와 ads.txt 상태](https://support.google.com/adsense/answer/12170222)
기술 결함과 콘텐츠 문제를 처리한 뒤 계정의 검토 요청을 따른다. 검색 색인 회복만으로 승인을 약속하지 않는다.
실제 신청·재신청과 광고 설정 변경은 사용자의 명시적 지시를 받은 뒤 수행한다.

## 광고 게재와 개인정보

광고가 본문을 가리거나 탐색·조작 요소와 섞여 의도하지 않은 클릭을 만들지 않도록 확인한다.
개인정보처리방침에는 Google 광고로 발생하는 데이터 수집·공유·이용과 쿠키 등 사용 기술을 실제 동작에 맞게 알린다. [게시자 정책의 광고 배치·개인정보 기준](https://support.google.com/adsense/answer/10502938)

EEA·영국·스위스 사용자에게 광고를 게재할 때는 Google 인증 및 TCF 연동 CMP 요건을 확인한다. [Google 동의 관리 요건](https://support.google.com/adsense/answer/13554020)
언어가 영어라는 이유만으로 적용 지역이나 동의 상태를 판단하지 않는다.
현재 코드에서 별도 CMP를 찾지 못해도 계정의 메시지 설정까지 미설정이라고 단정하지 않는다.
AdSense의 `개인정보 보호 및 메시지` 설정과 해당 지역에서의 실제 표시를 함께 확인한다. [개인정보 보호 및 메시지](https://support.google.com/adsense/answer/10924669)
