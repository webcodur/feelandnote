# 6. Speech 트랙

> **최종 실측 체크: 26.08.13** — 최소 조사 없이 한마디와 상황 대사를 생성하지 못하도록 조사·평가 게이트를 추가했다.

## 의존 관계

```
basic 완료 → 최소 조사 → speech_tone 확정 → 한마디 선정 → 상황 대사 평가·생성
```

- speech_tone: 최소 조사에서 확인한 실제 화법을 우선하고, 자료가 부족할 때만 직군 기본값을 쓴다.
- 한마디: 최소 조사에서 확보한 검증 가능한 직접 발언 중 하나를 고른다. 조사 그 자체와 동치가 아니다.
- dialogue: 같은 조사에서 얻은 대표 정보·발화 표본과 기본 지식을 결합해 평가·생성한다. **생몰 연대·생존 여부와 무관하게 모든 셀럽이 한국어 21개 전체 대사를 갖는다.**

## 6.0 최소 조사 — 22개 항목의 선행 게이트

`한마디 1개 + 상황 대사 21개`를 합쳐 22개 항목으로 센다. 최소 조사는 23번째 표시 항목이 아니라 22개를 만들고 검수하기 위한 근거 묶음이다. **프로필만 읽고 21개를 자유 생성하거나 공란에 자리 표시 값을 넣는 작업은 금지한다.**

### 조사 묶음

인물마다 다음을 한 묶음으로 확보한다.

1. **신원 닻 1개 이상**: 원어·영문 이름, 직군·소속·시대·작품 속 역할과 출처. 동명이인과 동명 캐릭터를 차단한다.
2. **대표 정보 2개 이상**: 대표 활동·사건·작품·선택·관계처럼 인물을 구별하는 사실과 출처.
3. **실제 발화 표본 1개 이상**: 원문·원문 언어, 자연스러운 한국어·영어 번역, 발화자와 직접 출처. 기자의 요약, 타인 발언, 명언 모음 사이트 단독 근거는 제외한다. 원문이 한국어면 `quoteKo`는 종결·어순·내용을 다듬지 않고 원문 그대로 쓴다. 50자를 넘는 발언은 자르지 말고 더 짧은 완결 발언을 찾는다.
4. **대사 앵커 3개 이상**: 조사 사실에서 뽑은 고유 어휘, 판단 습관, 갈등 방식. 기본 AI 지식은 이 근거를 연결하고 상황화하는 데만 사용하며 새로운 사실이나 실제 발언을 만들어 내는 데 쓰지 않는다.
5. **열어 확인한 출처 2개 이상**: 검색 결과 URL 나열이 아니라 실제 본문에서 무엇을 확인했는지 한 줄씩 기록한다. HTTP 응답 성공이나 검색 스니펫만으로 조사 완료를 선언하지 않는다.

실존 인물은 공식 인터뷰·연설·저서·서한·본인 SNS를 우선한다. 문학가는 작품 구절보다 본인 발언을 우선하되, 작품 구절을 쓰면 작품명과 위치를 특정한다. 허구 인물은 원전의 직접화법과 권·장·행을 확인하고 후대 각색을 섞지 않는다.

### 자료 희박 예외

직접 발언을 찾지 못했다고 즉시 실패 처리하지 않는다. 원어 검색을 포함해 서로 다른 검색 경로 3개 이상과 출처 계열 2개 이상을 확인하고, 본문을 실제로 연 출처 3개 이상·서로 다른 호스트 2개 이상에서 대표 정보와 직접 발화가 실제로 희박한지 판정한다. 검색 서비스가 응답했다는 사실은 출처 확인으로 세지 않는다.

- 대표 정보는 있으나 첫 검색에서 발언이 안 나온 경우: 원전·공식 기록·현지어 자료로 한 번 더 찾는다.
- 검증 가능한 직접 발언을 끝내 확보하지 못한 경우: **`quote`를 비워 두지 말고** 아래 두 값을 그대로 저장한다. 문구를 새로 만들지 말고 이미 쓰이는 값을 복사한다.

  ```
  lines.quote     = [확인된 어록이 없습니다]
  lines_en.quote  = [No verified quote]
  ```

  비워 두면 화면에서 항목 자체가 사라져 **「조사했으나 없음」과 「아직 조사 안 함」이 구분되지 않는다.** 26.08.14에 이 값을 못 보고 19명을 공란으로 남겼다가 되돌렸다.
- 자리 표시 값은 **조사 완료 판정**이지 공란 보정값이 아니다. 검색 경로·확인한 출처 계열·미확보 사유가 조사 묶음에 없으면 적용기가 거부한다.
- 🔴 **검색 요약을 근거로 채우지 마라. 그 문장이 실린 원문 페이지를 직접 열어야 한다.** 26.08.14 회차에서 세 건이 걸렸다 — 두 건은 출처 표기 없는 블로그가 지어낸 문장이었고, 한 건은 **다른 사람(헨리 웰스)의 말**이 윌리엄 파고의 것으로 돌던 것이었다.
- **쓰기는 `set_celeb_quote` RPC를 쓴다.** `celeb-fill.ts`는 `dialogues` 반영에 speech 조사 묶음을 요구해 quote만 넣으려 하면 전량 실패한다. 직접 UPDATE로 우회할 때는 `lines` 전체를 덮지 말고 기존 키를 보존한 채 `quote`만 얹는다. `celeb_dialogues`에는 `id` 컬럼이 없다(PK가 `celeb_id`) — `select('id,...')`로 조회하면 행이 없다고 잘못 판단한다.
- quote가 없어도 대표 정보가 확보되면 그 근거로 21개 대사를 만들 수 있다. 인물 자체의 정보도 희박하면 아는 척해 개별화하지 말고 확인 가능한 범위만 반영한다.

### 기존 대사 재평가

기존 21개가 있어도 같은 최소 조사를 먼저 수행한다.

- **KEEP + QUOTE**: 21개가 사실·말투·상황·고유성 게이트를 통과하면 그대로 두고, 조사에서 고른 한마디만 보강한다.
- **REVISE + QUOTE**: 범용 문구, 사실 오류, 동명이인 혼입, 억지 고유명사 삽입, 말투·상황 불일치가 있으면 한마디를 보강하면서 해당 21개를 함께 교정한다.
- 일부 문장만 나쁘더라도 최종 제출은 7상황 × 3개의 완성본으로 검수한다. 변경하지 않은 슬롯도 새 조사 근거와 충돌하지 않는지 확인한다.
- 기존 `[확인된 어록이 없습니다]` 보유자도 예외 없이 다시 조사한다. 이번 조사에서 직접 발언을 찾으면 교체하고, 예외 게이트를 다시 통과한 경우에만 유지한다.

적용 패치에는 조사 묶음, `KEEP|REVISE|CREATE` 판정, 현재 `lines` 해시를 함께 넣는다. `celeb-fill.ts`는 이 근거가 없거나 현재값이 달라진 패치를 거부한다. 여러 작업자가 나누는 배치는 인덱스·오프셋으로 소유 범위를 추론하지 않고, `--only-slugs`에 담당 slug 전체를 명시해 패치 명단과 정확히 일치할 때만 실행한다.

## 6.1 speech_tone 배정

`celebs.speech_tone` (text 컬럼). **`celebs` 테이블에 직접 존재**한다(celeb_persona 아님).

### 6종 톤

| tone | 설명 | 영문 뉘앙스 | 인물 예시 |
|------|------|------------|----------|
| **bold** | 단언·선언·명령 | assertive, commanding | 나폴레옹, 스티브 잡스 |
| **composed** | 절제·관조 | measured, calm | 마르쿠스 아우렐리우스, 워렌 버핏 |
| **gentle** | 부드러운 구어 | warm, soft-spoken | 아인슈타인, 밥 로스 |
| **free** | 거침없는 구어 | casual, informal | 무하마드 알리, 일론 머스크 |
| **humble** | 겸양 | modest, graceful | 이순신, 간디 |
| **loyal** | 의무·사명 | firm, devoted | 유관순, 윤봉길 |

### 배정 기준

1. **직군 기반 후보 선정**
   - commander → bold, loyal, humble
   - leader → humble, loyal
   - politician → composed, bold
   - entrepreneur/investor → bold, composed, free
   - author/humanities_scholar → composed, gentle
   - actor/musician/influencer → free, gentle
   - scientist → composed, gentle
   - athlete → bold, free
2. **인물 성격·발언 스타일로 최종 결정** — 직군 기본값과 다르면 실제 말투 우선

### 배치 처리

```sql
UPDATE celebs SET speech_tone = CASE id
  WHEN '{id1}' THEN '{tone1}'
  WHEN '{id2}' THEN '{tone2}'
  ELSE speech_tone
END
WHERE id IN ('{id1}', '{id2}', ...);
```

## 6.2 한마디 작성·검수

### quote SSoT

- **SSoT**: `celeb_dialogues.lines.quote`(한국어) / `celeb_dialogues.lines_en.quote`(영어).
- **`celebs.quotes`·`celebs.quotes_en`은 존재하지 않는다.** 두 컬럼을 읽거나 쓰는 SQL은 즉시 에러가 난다.
- **읽기**: 셀럽 서버 액션이 `celeb_dialogues`에서 quote를 추출한다.
- **쓰기**: `set_celeb_quote(p_celeb_id, p_quote_ko, p_quote_en)` RPC로 두 언어를 함께 갱신한다. `lines` 전체 덮어쓰기로 quote를 바꾸지 않는다.

### 포맷

- 표시용 한국어는 **50자 이내**, 한 문장
- 따옴표로 감싸지 않음
- 문자열 내 큰따옴표는 작은따옴표로 대체
- 실제 원문 의미를 유지한 자연스러운 한국어·영어를 함께 저장한다.

### 출처 허용/불허

| 허용 | 불허 |
|------|------|
| 인터뷰, 연설, 기자회견, 저서, 서한, 조서 | 출연작 캐릭터 대사 |
| 공식 SNS 본인 발언 | 타인이 해당 인물에 대해 한 말 |
| 역사서에 기록된 직접 발언 | 노래 가사 |
| **문학가 본인 작품 구절** (문학가 특칙) | |

### speech_tone별 어조 가이드

| tone | 한국어 어조 | 문장 종결 예시 |
|------|-----------|----------------|
| **bold** | 단언·선언·명령체 | `~하겠다`, `~하라`, `~이다` |
| **composed** | 절제·관조체 | `~일 뿐이다`, `~할 따름이다` |
| **gentle** | 부드러운 구어체 | `~이죠`, `~하지 않을까요` |
| **free** | 거침없는 구어체 | `~거든`, `~잖아` |
| **humble** | 겸양체 | `~할 뿐입니다`, `~하겠습니다` |
| **loyal** | 의무·사명체 | `~해야 한다`, `~하겠노라` |

### 검수 체크리스트

#### A. 즉시 탈락 (검색 불필요)

| # | 기준 | 조치 |
|---|------|------|
| A1 | 빈 값 | 웹 검색으로 확보 |
| A2 | 캐릭터 대사 | 본인 발언으로 교체 |
| A3 | 노래 가사 | 본인 인터뷰 발언으로 교체 |
| A4 | 복수 명언 합본 (`/`로 연결) | 가장 상징적인 1문장만 |
| A5 | 따옴표 래핑 | 따옴표 제거 |
| A6 | 원문 미번역 (한문·외국어) | 한국어로 번역 |
| A7 | 50자 초과 | 50자 이내로 축약 |
| A8 | 이스케이프 문자 | 정상 문자열로 교정 |

#### B. 검색 필요 판정

| # | 기준 | 조치 |
|---|------|------|
| B1 | 타인 명언 오귀속 | 원발화자 확인 → 교체 |
| B2 | 중복 귀속 | 원발화자 확인 → 비원발화자쪽 교체 |
| B3 | AI 생성 의심 | 실제 발언 확인 → 교체/빈 문자열 |
| B4 | 슬로건/구호 | 인물 철학이 담긴 발언으로 교체 |
| B5 | 풍자 대상의 말을 본인 말로 | 출처 확인 후 교체 |

#### C. AI 생성 의심 판별

아래 중 **2개 이상** 해당 시 AI 생성 의심:
1. "X는 Y이다" 정의형 문장
2. 고유 맥락/사건/작품이 없는 범용 문장
3. 같은 직군 다른 인물이 말해도 어색하지 않음
4. 웹 검색 시 연결 출처 없음

#### D. 품질·임팩트

| # | 기준 | 조치 |
|---|------|------|
| D1 | 범용 자기계발 문구 | 인물 고유 발언으로 교체 |
| D2 | 기업 슬로건형 | 구체적 경험에서 나온 발언으로 교체 |
| D3 | 의미 불명확 | 맥락 살아있는 발언으로 교체 |
| D4 | 인물 불일치 | 인물 철학에 부합하는 발언으로 교체 |
| D5 | 밋밋한 발언 | 더 대표적인 검증 발언을 조사해 교체 |
| D6 | 번역이 speech_tone을 훼손 | 원뜻을 바꾸지 않는 범위에서 자연스럽게 다시 번역 |

### 문학가·시인 특칙

**본인 작품 구절 사용 허용**. 작품명과 위치를 특정하고 원문을 확인한다.

적용 대상: author, poet, playwright, humanities_scholar + 고대 문인(소동파, 칼리다사, 허난설헌, 황진이 등)

### 검수 배치 처리

```sql
-- 읽기 전용 후보 조회 예시. 이 페이지 순서는 작업 소유권이 아니다.
SELECT p.id, p.nickname, p.profession, p.speech_tone,
       d.lines->>'quote' AS quote
FROM celebs p
JOIN celeb_dialogues d ON d.celeb_id = p.id
ORDER BY p.nickname LIMIT 30 OFFSET {offset};

-- 교정은 서버 전용 RPC로 한·영 동시
SELECT set_celeb_quote('{id1}', '{한국어}', '{English}');
```

`celebs`에는 quote 컬럼이 없으므로 quote 조회·갱신은 `celeb_dialogues`만 대상으로 한다.
실제 조사·교정 대상은 고정한 slug 명단으로 기록하고, 적용할 때 그 명단 전체를 `--only-slugs`에 명시한다. 조회용 `LIMIT/OFFSET`이나 당시 정렬 순서로 담당 범위를 다시 계산하지 않는다.

### 검수 보고 형식

```
## 배치 N (slugs: {slug1}, {slug2}, ...)
- 검수: {총}명 / KEEP: {n}명 / REVISE: {n}명 / CREATE: {n}명
  - A1(빈값): n건, B3(AI): n건, D5(밋밋): n건 ...
- dry-run: WOULD UPDATE {n} / SKIPPED {n} / FAILED {n}
- apply: UPDATED {n} / SKIPPED {n} / FAILED {n}
- 왕복 검증 및 예상 밖 변경: {결과}
```

## 6.3 dialogue 생성

유저가 대사를 읽을 시간은 없다. 한마디로 순간의 호흡을 나타내라. 최소 조사 묶음 없이 생성하지 않는다.

### 말투 규칙

commander 직군 외 모든 인물은 존댓말(~합니다/~해요). deploy·clash_attack은 명령형 허용.

### 생성 범위 — 전원 전체 대사

**모든 셀럽이 7상황 × 3변형 = 한국어 21개 전체 대사를 갖는다.** 생몰 연대·생존 여부·저작권 상태로 범위를 줄이지 않는다.

2026-07-31 DB 전수 감사 기준 활성 `full`·`light` 1,476명의 한국어 결손과 구조 오류는 모두 0이다. 적용이 끝난 배치 JSON·진행 장부·인물별 검토 문서는 보존하지 않는다.

- 7상황: greeting, roll_call, deploy, battle_win, battle_draw, battle_lose, clash_attack
- 각 상황 3변형. 빈 문자열을 남기지 않는다.
- 현대 인물도 동일하게 21개를 채운다. 출연작 캐릭터 대사·노래 가사가 아닌, 본인 화법·철학·업적에 기반한 창작이면 된다.

> 과거 규칙(옛 인물만 전체, 현대는 인사말만)은 폐기됐다. 인사말만 있는 기존 인물은 나머지 18개를 채워 전체로 승격한다.

### 길이·상황 게이트 — 대사는 평전이 아니다

웹·게임 대사는 버튼 한 번에 튀어나오는 **한 호흡의 반응**이다. 조사한 사실을 대사 안에 모두 설명하지 않는다. 근거는 적용 전 임시 조사 묶음에 두고, 대사에는 인물의 짧은 판단과 행동만 남긴다. 적용·왕복검증 뒤 임시 조사 파일은 삭제하며 완료 보고서나 진행 문서로 보존하지 않는다.

길이 기준은 임의 작문치가 아니라 2026-07-29 기준 **유튜브 출품 완료 팩션 인물의 비어 있지 않은 기존 대사**를 실측한 값이다. 한국어 중앙값은 등장 24자·배치 22자·승무패 24~25자·충돌 15자, 영어 중앙값은 각각 8·9·9~10·5단어였다.

- `clash_attack`: 돌격·기합·도발. 한국어 **3~18자 목표, 25자 상한**. `점화!`, `가속!`, `실행하라!`처럼 한 단어도 정상이다. 이유 설명이나 두 번째 문장을 붙이지 않는다.
- `deploy`: 즉시 실행할 짧은 명령·결단. 한국어 **12~25자 목표, 35자 상한**.
- `roll_call`: 자기소개 평전이 아니라 등장·호명 반응이다. 한국어 **18~30자 목표, 40자 상한**. 생몰연대와 업적 목록을 나열하지 않는다.
- `battle_win`·`battle_draw`·`battle_lose`: 결과에 대한 한 문장 반응. 한국어 **18~30자 목표, 40자 상한**. 두 문장 해설은 쓰지 않는다.
- `greeting`: 인물의 대표 호흡 한 줄. 긴 직접 인용을 보존해야 하는 기존값이 아니라면 한 문장으로 쓴다.
- 글자 수는 문장 앞의 기존 ELE 태그를 제외하고 센다. 길이를 맞추려고 ELE 태그를 삭제·축약·변경하지 않는다.

판별: `clash_attack`이 “누가 무엇을 왜 했는지” 설명하면 실패다. 이순신의 `발포하라!`, `단숨에 돌파하라!`처럼 그 순간 실제로 외칠 수 있어야 한다.

### 인물 고유성 게이트 — 조사 사실과 캐릭터는 다르다

출처가 있고 사실과 맞는 문장도 대사로는 실패할 수 있다. 사실을 요약한 문장이 아니라, 그 인물의 어휘·판단 습관·갈등 방식이 들려야 한다.

1. **이름 삭제 시험**: 이름과 고유명사를 지운 뒤 같은 직군의 다른 인물에게 그대로 붙여도 자연스러우면 실패다.
2. **직군 표어 금지**: `고객을 생각하십시오`, `결과로 증명하겠습니다`, `책임을 지겠습니다`, `다시 시도하겠습니다`처럼 누구나 말할 수 있는 운영·자기계발 문구는 쓰지 않는다.
3. **팩트 나열 금지**: 업적·연대·수상·사건을 한 줄에 압축한 평전은 `sources`와 검토 메모에 남기고, 대사에는 그 사실에서 드러난 고유한 선택만 남긴다.
4. **상황 교체 시험**: `roll_call`, `deploy`, 승·무·패, `clash_attack`의 라벨을 서로 바꿔도 어색하지 않으면 상황 반응으로 실패다.
5. **소리 내기 시험**: 실제 화면에서 한 번 재생한다고 가정해 입으로 읽는다. 설명을 듣는 느낌이면 줄이고, 화자의 반응이 들리지 않으면 다시 쓴다.
6. **적용 보류**: 형식·사실 검사를 통과해도 고유성 시험을 통과하지 못하면 DB에 쓰지 않고 조사 재료로만 남긴다.

### 한국어 문장 게이트

대사는 짧아 부자연스러운 문장이 즉시 드러난다. 한국어 규격의 단일원천은 `docs/project/production/writing-rules.md` §1이다. 한국어 21줄을 한국어 어휘·어순으로 작성한다. 영문은 현재 만들지 않는다.

작성 뒤 한 번 소리 내 읽고 아래 항목에 걸린 문장만 고친다. 검토 회차·후보·승인 상태를 별도 문서로 만들지 않는다.

| # | 금지 | ❌ | ✅ |
|---|------|----|----|
| 1 | **사물·추상명사 주어** | 승리가 우리를 부른다 | 우리가 승리를 거머쥔다 |
| 2 | 동격 구문 (~인 N이다) | 내가 택한 길은 죽음뿐인 길이었다 | 나는 죽음을 각오하고 이 길을 택했다 |
| 3 | 수동태·사역 직역 (되어졌다·로 하여금) | 적은 무너뜨려졌다 | 적을 무너뜨렸다 |
| 4 | 번역 관용구 (~에 다름 아니다·~에 있어서·~을 통하여) | 이 전투에 있어서 | 이 전투에서 |
| 5 | em dash(—) | 나아가라 — 멈추지 말고 | 나아가라, 멈추지 마라 |
| 6 | 부자연 도치 | 결코 물러서지 않을 나다 | 나는 결코 물러서지 않는다 |

자가 점검: **"이 한마디의 주어가 사람(나·우리·그대·장졸)인가, 사물인가?"** 사물이면 십중팔구 번역투다. 한국어 대사의 골격은 *[사람]은 [대상]을 [동사]한다*.

### 데이터 스키마

```json
{
  "celeb_id": "UUID",
  "nickname": "인물명",
  "profession": "직군",
  "speech_tone": "(celebs.speech_tone)",
  "lines": {
    "greeting":     ["[emotion, emotion] 대사", "× 3"],
    "roll_call":    ["[emotion, emotion] 대사", "× 3"],
    "deploy":       ["[emotion, emotion] 대사", "× 3"],
    "battle_win":   ["[emotion, emotion] 대사", "× 3"],
    "battle_draw":  ["[emotion, emotion] 대사", "× 3"],
    "battle_lose":  ["[emotion, emotion] 대사", "× 3"],
    "clash_attack": ["[emotion, emotion] 대사", "× 3"]
  }
}
```

> **각 상황의 원소는 반드시 문자열**이다. 기존 감정 태그가 있으면 `"[emotion] 대사"`처럼 문자열 맨 앞에 인라인되어 있다. **`{ "text": ..., "quote": ... }` 같은 객체 원소로 저장하지 않는다.** 화면·게임·홈 모든 소비처가 문자열 배열을 전제하므로, 객체를 넣으면 셀럽 페이지가 서버 렌더에서 즉시 크래시(500)한다. (2026-07-14: 이 규칙을 위반한 18명 일괄 교정, 마이그레이션 `fix_dialogue_object_lines_to_string`.)

> **발화 지시 태그 운영권(2026-07-29 사용자 확정)**: 감정 태그는 대사 문체를 분류하는 장식이 아니라 **ELE 보이스를 실제 육성으로 들어 본 뒤 사용자가 보완하는 합성 지시**다. AI 대사 작업자는 감정 태그를 새로 생성·교체·삭제하지 않는다. 기존 태그는 그대로 보존하고 대사 본문만 작성·교정한다. 태그가 없는 신규 원문에도 AI가 임의로 붙이지 않는다. `mild`처럼 거친 발화를 누그러뜨리는 보정도 사용자가 청취 후 결정한다.

### 기존 데이터 감사 시 먼저 볼 결함

2026-07-16 한·영 전수 감사에서 반복된 결함이다. 새 대사를 만들기 전에 기존 구조를 감사할
때 아래 순서로 확인한다.

1. `answer`는 폐기된 옛 상황 키다. 표준 키는 `roll_call`이며, `roll_call`이 이미 있으면
   `answer`만 제거한다. 비어 있으면 한국어 원문을 기준으로 `roll_call`을 채운 뒤 제거한다.
2. `lines_en`의 줄 수가 맞아도 한국어 원문과 무관한 범용 전투 대사나 다른 인물의 내용이면
   번역 완료로 세지 않는다. 원문이 빈 경우 영문도 같은 구조의 빈값으로 두며 새 내용을
   창작해 메우지 않는다.
3. 이름·소개·한국어 대사·영문 대사가 서로 다른 동명이인을 가리킬 수 있다. 여러 필드와
   독립 근거를 대조해 정체성을 확정하고, 방향이 모호하면 임의로 합치지 않는다.
