### 실행자 처리

조사·한국어 작성·최종 수정은 사용자 Chrome의 Claude in Chrome 확장으로 Ultra 계정 웹 Gemini의 Carbon 높음에 맡긴다(26.11.11 사용자 지시). Carbon이 없는 Pro 계정이나 Argon으로는 보내지 않는다. 다만 Carbon이 한도·연속 오류로 막히면 아래 「Carbon은 독서방식 본문에만」의 대체 경로를 따른다. 모델 이름과 선택 확인 조각은 [mode.mjs](../../../scripts/browser/reading-way-web/mode.mjs)가 쥐고, 발송 JS는 메뉴에 Carbon이 없거나 높음이 잠겨 있으면 보내지 않는다. 인물마다 새 대화를 열고 인물 식별 정보, 위 작성 규칙, 최소한의 참조 링크와 한국어 JSON 출력 형식만 보낸다. 영어 번역이나 책 목록·근거표·책별 감상경위 같은 다른 작업을 작성 요청에 붙이지 않는다. 실행자의 사실 목록·맥락 지적·구성안·대체 문장도 덧붙이지 않는다. 시빅뉴스 [김윤환의 책과 사람](https://www.civicnews.com/news/articleList.html?sc_sub_section_code=S2N65)에 해당 인물의 기사가 있으면 그 링크를 우선 전달한다.

이름·날짜·수치·책 제목처럼 개별 값의 국소 오류는 실행자가 그 값만 바로 고친다. 근거 없는 일화나 문단처럼 맥락 자체가 틀렸으면 문장·문단을 덜어내거나 이어 붙이지 않는다. 덜어 내면 글이 비고, 부분 수정은 글을 어색하게 만든다(26.11.12 사용자 지시). 확인되지 않는 대목은 먼저 원고를 만든 대화에 그 대목의 출처를 묻고(아래 「문장별 근거 받기」), 실제 출처가 나오면 대조해 살린다. 출처가 없으면 새 대화에 원고 원문을 첨부하고 근거를 찾지 못한 대목을 짚어 「이 대목은 출처를 확인하지 못했습니다. 확인되는 사실로 글 전체를 다시 쓴 최종 한국어 JSON을 주세요.」라고 전체 재작업을 요청한다. 재작업한 원고가 같은 이유로 다시 걸리면 조사 미달로 둔다. 검수 의견만 받았으면 수정 완료한 최종 JSON까지 받는다. 실행자가 제안과 원문을 조합해 문장을 만들지 않는다.

한국어가 확정되면 별도의 새 Gemini 무료 웹채팅에서 영어 번역만 맡긴다. 무료 모델을 사용하며 작성 대화와 API는 사용하지 않는다. 확정한 한국어 원문과 인물 영문명만 넘기고, 같은 뜻의 자연스러운 영어를 받는다. 실행자가 원문과 번역을 대조한 뒤 한국어를 그대로 보존해 한영 JSON을 합친다.

전송 직전에 High를 명시적으로 선택하고 생성 중에도 High 표시를 확인한다. 회수 때 현재 표시도 기록한다. 현재 선택 표시와 실제 응답 모델은 구별하며, 현재 설정만으로 과거 응답의 모델이나 생성 도중 변경을 단정하지 않는다. 전송 전·생성 중 High를 확인했고 회수 때 사고 수준만 표시되지 않으면 그 상태를 그대로 기록해 처리한다. Low·Flash가 관찰되거나 High 확인이 부족한 응답은 원본을 보존해 보류하며, 자동 모델 대체·계정 순환 재시도는 하지 않는다. 한도와 초기화 시각은 실제 표시가 있을 때만 확정한다. 명시적인 한도가 확인되면 사용자가 맡긴 다른 로그인 계정에서 현재 상태와 High 선택을 확인해 이어간다. 초기화 예정 시각이 지났다는 이유만으로 갱신됐다고 세지 않는다. 본인 확인 화면이 나오면 요청을 멈춘다.

병렬 작업은 탭 두 개까지 진행한다. 같은 Ultra 계정의 두 탭으로 동시에 돌려도 회수에 문제가 없었다(26.11.11). 한쪽 탭의 오류·한도 대기 때문에 다른 쪽 회수·저장을 멈추지 않는다. 이름 보고는 착수·종료 때 한 번씩 하고, 끝난 작업 탭은 닫는다.

조사 순서는 네이버 게시 → 네이버 예약 → 서비스 조회수 → 영향력 → 나머지다. 같은 우선순위에서는 조회수·영향력 순으로 고른다.

**감상 책이 있는 인물의 결과가 빈 값이면 바로 재조사한다.** 그 인물의 책 제목·감상 경위·출처 목록을 단서로 만들어 새 Carbon 높음 대화에 첨부한다(`--only SLUG --retry-insufficient SLUG --feedback SLUG=<목록 파일 절대경로>`). 재조사도 빈 값이면 조사 미달로 확정한다. 감상 책이 없는 조사 미달 인물은 사용자의 재조사 지시가 있을 때만 다시 처리한다.

**감상 기록이 부실한 인물은 배움의 태도로도 쓴다(26.11.13 사용자 지시).** 독서 방식은 책 감상이 없어도 배움을 대하는 태도로 쓸 수 있다. 스승을 섬긴 일, 학문을 장려하거나 도서관·장서를 일군 일, 기록과 문헌을 대한 방식 등이다. 하후돈은 감상 책이 없지만 『삼국지』 「하후돈전」의 스승을 욕보인 자를 죽인 일화와 군중에서도 스승을 맞아 배운 기록으로 썼다. 이 보완은 모든 인물의 요청에 붙이지 않는다. 감상 책이 없거나 근거가 빈약해 조사 미달이 됐거나 될 인물만 대상이다. 실행자는 그런 인물의 배움 일화를 출처와 함께 [지속 과제](../../continuous/celeb-reading-way.md)의 「배움의 태도 소재」에 모아 둔다. 그 인물을 조사·재조사할 때 일화와 출처를 적은 파일을 `export-packets.mjs --feedback SLUG=<파일>`로 함께 보낸다. 파일 머리말은 「이 인물은 남은 독서 기록이 적습니다. 아래 일화처럼 배움·스승·학문·책과 기록을 대하는 태도가 드러나는 사실도 출처로 확인해 독서 방식의 일부로 함께 써 주세요. 확인되지 않는 일화는 쓰지 마세요.」로 한다. 소재가 모인 조사 미달 인물은 묶어서 재조사 대상으로 사용자에게 보고한다.

작업자는 본문 작성부터 번역·저장·누락 도서 메타·감상 관계와 맡겨진 블로그 반영까지 직접 수행한다. 블로그·판본 전담 세션은 필수가 아니다. 본문에 나온 책과 실제 감상 근거를 기존 책장과 대조하고, [콘텐츠 조사](celeb-02-01-content-research.md)·[등록](celeb-02-02-content-registration.md)·[감상경위](celeb-02-03-content-review.md)에 따라 빠진 작품·한영 판본·감상배경을 채운다. 메타 등록이나 원고 수신만으로 책장 연결을 완료했다고 세지 않는다. 책장 조사가 근거 없음으로 돌려준 책이 본문에 남으면 실행자가 고치지 않고, 원고·지적 없이 새 Carbon 높음 대화에서 조사부터 다시 쓴다.

사용자가 전담 세션을 연결하고 인계를 맡긴 경우에만, 10명마다 새로 필요한 책은 '대기 - 판본'에, 본문 저장·검증을 마친 인물명은 '독서방식 블로그'에 보낸다. 인계한 항목도 실제 반영 결과를 확인한다. 전담 세션이 없으면 같은 작업을 본인이 처리한다.

받은 최종 원문은 탭을 닫기 전에 작업 폴더에 회수한다. 원문과 저장값을 대조하고, DB 재조회·캐시 갱신·한영 서비스 표시를 확인한다. 완료·검증한 작업 자료는 폐기하고 보류 자료는 유지한다.

반복 실행은 [reading-way-argon.mjs](../../../scripts/browser/reading-way-argon.mjs)가 한국어 원고를 회수한다. `--resume`으로 같은 작성 대화를 이어받는다. 번역 요청문은 `readingWayTranslationPrompt`, 번역 결합은 `combineReadingWayTranslation`을 사용하고, 별도 번역과 대조를 마친 뒤 최종 저장한다.

본문과 책장 전수 대조는 [reading-way-shelf-scan.mts](../../../scripts/browser/reading-way-shelf-scan.mts)로 후보를 뽑는다. 초벌이므로 번역 제목 차이와 비도서를 LLM이 문맥·책장으로 먼저 거르고, 남은 후보만 원문을 확인한다. 한국어 제목만 대조하면 번역 제목이 다른 같은 책이 미등록으로 잡히므로(160인 정비에서 후보의 절반 이상), 조사 전에 영문 제목·저자로 기존 책장과 다시 대조한다. **소장·선물·책장에 꽂힘은 감상 근거가 아니다.** 추천만 한 책, 사전·수표 같은 도구, 이름만 언급한 책, 그 인물을 다룬 작품, 본인 저서(집필 탭 대상)도 감상 관계로 등록하지 않는다. 근거를 못 찾은 책은 등록하지 않고, 글이 원문보다 앞서 나갔으면 그 문장을 확인된 범위로 고친다. 검증한 책장 보완은 [reading-way-books-apply.mjs](../../../scripts/browser/reading-way-books-apply.mjs)로 반영한다. 장시간 실행은 [reading-way-watch-start.mjs](../../../scripts/browser/reading-way-watch-start.mjs)와 [reading-way-watch.mjs](../../../scripts/browser/reading-way-watch.mjs)를 사용하며, 원고 검수·저장은 실행자가 맡는다.

### 사실 대조와 우회 경로

Carbon 전체 검수는 같은 모델이 만든 근거 없는 일화를 걸러내지 못하므로, 저장 전 사실 대조를 대신하지 않는다. 회수한 원고는 실행자가 출처와 대조한다.

- **문장별 근거 받기:** 원고를 만든 대화에 “본문은 고치지 말고 각 문장이 근거로 삼은 출처 URL을 문장별로 표로 주세요. 실제로 열람한 출처와 그 출처 원문의 해당 대목도 함께 적어 주세요. 출처가 없는 문장은 ‘없음’이라고 적어 주세요.”라고 후속 요청한다. 받은 URL은 실행자가 직접 열어 문장과 맞춘다. 모델이 “없음”이라고 답했거나 연 출처에 없는 내용은 미확인이다.
- **빠른 대조:** 인물의 감상 기록(`celeb_contents.review`)과 먼저 키워드로 맞춘다. 유튜브 받아쓰기로 만든 기록이 많아 방송 출연 인물에 특히 잘 맞는다. 유튜브 출처는 `yt-dlp --skip-download --write-auto-subs --sub-langs "ko.*,ko"`로 받은 자막에서 확인한다. 자동 자막은 고유명사가 틀리게 적히므로 음이 비슷한 표기도 함께 찾는다.
- **막히는 사이트:** WebFetch가 막히는 언론사는 헤드리스 브라우저로 렌더링해 본문을 읽는다. 네이버 뉴스 검색도 렌더링한 결과 화면의 요약문으로 대조할 수 있다. TLS를 위장한 직접 요청은 봇 차단 우회라 쓰지 않는다. 사람 확인 화면이 나오는 사이트는 넘어가지 않는다.
- **Gemini 웹채팅은 Chrome으로:** 오류나 로봇 확인을 사용자가 직접 풀 수 있도록 Gemini 웹채팅은 사용자 Chrome의 Claude in Chrome 확장으로 하고 Aside는 쓰지 않는다(26.11.10 사용자 지시). 러너와 같은 요청 묶음을 입력창에 넣어 보내고, 긴 응답은 페이지 텍스트 읽기로 통째로 회수한다. 응답 오류가 뜨면 새 대화로 다시 보낸다. 「다시 시도」는 대화가 통째로 사라지는 일이 있었다. 입력창에 보내지 않은 글이 남지 않았는지도 확인한다. 모드 메뉴에 “한도가 … 초기화됩니다”가 보이면 그 계정은 멈춘다. 사용자 Chrome까지 로봇 확인으로 넘어가면 IP 단위 차단이므로 모든 Gemini 요청을 멈춘다. 이 경로에는 러너의 `modelObservation`이 없으므로 저장은 독서방식이 비어 있는 행에만 조건부로 쓰고 재조회·`revalidate`한다. 책장 반영기가 요구하는 모델 확인값은 전송 직전·생성 중·회수 때 모드 단추에서 실제로 읽은 라벨로 기록한다. 회수 때 라벨에 사고 수준이 빠지면 모드 메뉴를 열어 체크된 수준을 읽는다. 그 사이 계정 한도가 차 「낮음」으로 돌아가 있으면 높음이 관찰되지 않은 원본이므로 반영하지 않고 다시 돌린다.
- **Carbon은 독서방식 본문에만:** Carbon 한도는 다른 작업에 나눌 여유가 없으므로 웹 Carbon 높음은 독서방식 본문의 작성·재작성·문장별 근거 받기에만 쓴다(26.11.11 사용자 지시). 확정 한국어의 영어 번역, 감상배경, 서점 소개문, 영문 감상평 같은 다른 작업에는 쓰지 않고 실행자가 직접 쓴다. Flash도 쓰지 않는다. 울트라 계정 agy의 `gemini-4-carbon-*`(26.11.11 확인)도 같은 한도라 쓰지 않는다. Carbon이 한도·연속 오류로 막히면 Pro 계정 웹 Gemini의 Argon 높음으로 미비한 인물의 본문을 이어 쓴다(26.11.11 사용자 지시). 검증·저장 절차는 Carbon 원고와 같고, 모델 기록에 Argon을 남긴다. 번역은 실행자가 `finals/<slug>.json`의 한국어를 영어로 옮기고 러너의 `combineReadingWayTranslation`으로 `finals/<slug>.combined.json`을 만든다.

### 단독 실행 도구

현재 재개 지점과 미확정 책 후보는 [지속 과제](../../continuous/celeb-reading-way.md)에 있다. 아래 도구는 저장소에 있는 실행점이며, 이전 작업자의 임시 스크립트나 채팅 기억을 요구하지 않는다.

export 함수를 직접 호출하는 임시 파일은 자기 작업 폴더에 두고 `sw/web-bo/.env`를 로드해 실행한다. Windows 절대경로의 모듈은 `pathToFileURL()`로 import한다.

**웹채팅 경로(현행):** 저장소 루트에서 [reading-way-web](../../../scripts/browser/reading-way-web/)의 도구를 쓴다. 작업 폴더는 `RW_WORK`, 없으면 OS 임시 폴더의 `feelandnote/rw-chrome`이며 요청 묶음·발송 JS·회수 원문·확정본·출처 사본이 쌓인다. 저장소에는 두지 않는다. 경로는 [paths.mjs](../../../scripts/browser/reading-way-web/paths.mjs)가 쥔다.

1. `node --import tsx scripts/browser/reading-way-web/export-packets.mjs slug1,slug2`로 러너와 같은 요청 묶음을 만든다.
2. 룰북 작성 규칙을 고쳤으면 `mk-init-A.mjs`로 `scoped/init-A.js`를 다시 만들고 Gemini 탭에서 한 번 실행해 localStorage `rwBookA`에 심는다. `mk-call-body.mjs slug`가 만든 `scoped/call-<slug>.js`를 새 대화에서 실행하면 Carbon 높음 확인과 전송까지 한다.
3. 응답의 `ko`를 `web/<slug>.body.txt`로 회수해 브라우저 쪽 SHA-256과 맞춘다. 같은 대화에서 출처표를 받아 원문과 대조하고 고친 뒤 `finals/<slug>.json`(`slug`·`ko`·`sources`·`model`)을 쓴다.
4. 실행자가 영어 번역을 붙여 `finals/<slug>.combined.json`을 만들고(「Carbon은 독서방식 본문에만」) 영어 인용을 원문 표현으로 되돌린다. `save.mjs slug --apply`가 빈 행에만 저장·재조회·캐시 갱신한다. 값이 있는 인물의 재작성은 `overwrite-save.mjs`, 국소 교정은 `fix-body.mjs`를 쓴다.
5. `shelf.mjs slug`로 본문의 책을 책장과 대조하고, 빠진 책은 지속 과제의 책장 대기 목록에 적는다. 책장 보완(감상배경)은 `export-books2.mjs`(발송 JS) → `webrecv.mjs`(회수) → `precheck.mjs`·`match.mjs`(초벌 대조) → `mkdec.mjs`(결정 파일) → `meta.mjs`(메타 후보) → `books-step.mjs`(번역·반영 계획, `--apply`) 순서다. 이미 연결된 책의 감상평 교체는 `replace-existing.mjs`, 국소 교정은 `fix-review.mjs`를 쓴다. 실행자가 직접 쓴 감상배경(「Carbon은 독서방식 본문에만」)은 원고 파일(`{slug, books:[{title_ko, title_en, author_ko, author_en, source_url, evidence, review_ko}]}`)과 결정 파일을 직접 만들고, 결정 파일의 `modelObservation`을 `{route:'executor', author, verifiedSources}`로 둔 뒤 `books-step.mjs`로 반영한다. `verifiedSources`에는 실행자가 직접 열어 대조한 출처만 넣고, 영어는 각 책의 `review_en`에 미리 넣는다.

아래 1~6은 Aside 러너 경로다. 지금은 대상 집계·확인과 위 도구가 import하는 export 함수에 쓴다.

1. **대상 선정·한국어 회수:** 저장소 루트에서 `node --import tsx scripts/browser/reading-way-argon.mjs --summary`로 현재값을 보고, `--limit 10`으로 다음 대상을 확인한다. 실제 확인한 계정을 `--pool`에 넣어 `--apply --collect-only`로 한국어만 회수한다. 본문 요청에는 책장 조사를 합치지 않는다.
2. **회수·전체 검수:** 러너의 `submit`·`collect`를 쓴다. 새 High 대화의 전체 검수는 `lane.reviewOriginal = {output, sha256}`에 회수 원본을 지정해 `submit`한다. `--resume`은 기존 요청·완료 응답의 회수용이다. 완료 JSON 대신 의견만 받으면 같은 검수 대화에서 최종 JSON까지 받는다. 생성 중이 아닌데 요청과 응답이 사라졌다면 완료로 세지 않고 실제 대화 상태를 확인한 뒤 새 High 요청으로 복구한다.
3. **무료 번역·본문 저장:** Aside에서 실제 무료 계정을 확인하고 새 Gemini 대화를 연다. `readingWayTranslationPrompt(artifact.p, person)`으로 번역 요청을 만들고, 응답을 `combineReadingWayTranslation(artifact.p, translation)`으로 합친다. 이 함수가 인물과 한국어 SHA-256을 검사한다. 착수 때 읽은 `person.id/slug/ko/en`을 유지한 채 `save(person, result, work, artifact.modelObservation)`와 `revalidate(person)`로 저장·재조회·캐시 갱신한다. 중간에 다른 사람이 바꾼 값을 새 기준으로 바꿔 덮어쓰지 않는다.
4. **책장 후처리:** `--apply --books-only --only SLUG`로 별도 High 대화에서 한국어 감상경위를 받는다. 범위를 지정할 때는 `person.bookScope`에 작품·작가·시리즈를 넣는다. 확정한 감상경위의 영어도 별도 무료 Gemini 대화에서 받고, 원본의 책 순서와 한국어를 보존해 `review_en`만 결합한다. 메타는 기존 작품부터 찾고 [등록 규칙](celeb-02-02-content-registration.md)의 카카오·OpenLibrary 경로로 직접 확인한다. ko·en 행의 존재, 같은 작품·판본인지, 소개·표지까지 확인한다. 제목만 영어인 행이나 소개가 빈 행의 집계로 영어 행 결손을 대신 검사하지 않는다. 본문을 저장한 인물은 이 단계를 생략하지 않는다. 끝낼 때 본문의 《》·『』 제목을 하나씩 책장과 대조해 등록하거나, 언론·영화·본인 저서처럼 대상이 아닌 이유를 확인한다. 등록 건수만 보고 끝난 것으로 치지 않는다.
5. **관계·메타 반영:** [책장 반영기](../../../scripts/browser/reading-way-books-apply.mjs)의 `--plan ABSOLUTE_JSON`으로 미리 보고 같은 계획에 `--apply`한다. `originals`에는 결합 파일의 `path/sha256`과 회수 때의 실제 `modelObservation`을, `relations`에는 `content_id/original_index/book_index`를 넣는다. 한국어 원본과 번역 결합값도 대조한다. 새 작품·빠진 언어 행은 `newWorks/newLocales`로 넣을 수 있다. 기존 관계는 삽입기로 덮어쓰지 않고 현재 행 비교 transaction으로 갱신한다. 기존 메타 교정은 [guarded-catalog-repairs.mjs](../../../sw/web-bo/scripts/figure-books/lib/guarded-catalog-repairs.mjs)의 `captureCatalogRepairSnapshot` → `planGuardedCatalogRepairs` → `guardedCatalogRepairs`를 사용한다. 마지막 함수는 실제 쓰기다.
6. **기존 블로그 반영:** 블로그 반영을 맡은 작업은 10명마다 본인이 [네이버 편집 경로](../../continuous/blog-naver-book.md#편집-자동화)를 실행한다. `D:/feelandnote/blog-assets/naver-blog/posts.json`·`celeb-drafts.json`과 실제 게시·예약 목록, 내부 검색으로 대응 글을 찾는다. `readingWay.sourceHash`가 현재 DB 본문과 같으면 건너뛴다. `sw/web-bo`에서 `node --import tsx scripts/naver-blog/apply-reading-way.mjs --log=LOG_NO --work=ABSOLUTE_DIR --apply`를 사용하며, 기존 구획 교체는 `--replace`, DB 본문이 비어 구획을 걷을 때는 `--remove`를 쓴다. 브라우저 연결이 없으면 같은 편집 규칙을 Aside로 직접 수행한다. 기존 글이 없으면 미반영으로 보고하고 신규 발행은 별도 지시를 따른다. 저장·재열기와 공개 본문 또는 예약 설정을 확인하고 기존 사진·링크·예약 시각을 보존한다.

본문은 `/celeb/SLUG`와 `/en/celeb/SLUG`, 감상배경은 해당 책의 `/content/ID?category=book` 한영 화면에서 실제 저장값과 대조한다. 완료한 원문·출처 사본·SQL·일회성 실행 파일은 [데이터 원칙](../data/README.md#작업-파일백업)에 따라 정리한다.

### 본문이 바뀔 때 함께 처리

독서 방식을 새로 쓰거나 고치면 아래 연결 자료를 같은 작업 안에서 맞춘다. 거꾸로 책장·판본·감상배경을 고친 쪽도, 그 책이 독서 방식 본문에 나오면 이 순서로 본문을 대조한다.

1. **책장:** `shelf.mjs SLUG`로 본문에 나온 책과 책장을 맞춘다. 본문은 읽었다고 하는데 책장에 없는 책은 감상 근거를 확인해 연결하고, 처리 전까지 [지속 과제](../../continuous/celeb-reading-way.md)의 책장 대기 목록에 적는다. 본문에서 빠졌거나 「읽지 않았다」로 바뀐 책은 기존 감상 관계의 근거를 다시 본다.
2. **작품·판본:** 새 책은 기존 작품부터 찾고, 없으면 [콘텐츠 등록](celeb-02-02-content-registration.md)의 한국어판(카카오)·영문판(OpenLibrary)·표지·절판 규칙으로 ko·en 행을 채운다. 작품에 판본 행이 있으면 같은 언어 행까지 맞춘다.
3. **감상배경:** 새로 연결하는 책의 `review`·`review_en`은 [감상경위](celeb-02-03-content-review.md) 규칙으로 쓴다. 기존 감상배경이 고친 본문과 사실(시기·횟수·계기)이 어긋나면 출처로 어느 쪽이 맞는지 가려 틀린 쪽을 고친다. 반영은 [책장 반영기](../../../scripts/browser/reading-way-books-apply.mjs) 또는 웹채팅 경로의 `books-step.mjs`·`replace-existing.mjs`·`fix-review.mjs`로 한다.
4. **영문:** 한국어를 고치면 `reading_way_en`·`review_en`도 다시 번역해 맞춘다. 표기 규칙은 [영문 데이터](celeb-09-01-i18n.md)를 따른다.
5. **표시·캐시:** 재조회·캐시 갱신 뒤 위의 한영 화면에서 확인한다.
6. **블로그:** 그 인물의 네이버 글이 있으면 `readingWay.sourceHash`와 새 본문 해시를 비교하고, 다르면 [네이버 편집 경로](../../continuous/blog-naver-book.md#편집-자동화)로 구획을 교체한다. 고친 감상배경이 블로그에 실렸으면 그 문단도 함께 고친다.

## 데이터 정의

대상은 `celeb_reality`가 `REAL` 또는 `BOTH`인 인물이다. 조사 완료 여부는 [active 요건](celeb-00-02-active-requirements.md)과 [공유 판정 함수](../../../packages/shared/src/constants/celeb-reading-way.ts)를 따른다.

백오피스는 `/celebs/[slug]#reading-way`에서 한영 본문과 조사 상태를 제공한다. 사용자 웹의 노출 규격은 [인물 상세](../service/service-04-celeb-detail.md)를 따른다.

## 컬럼

`celebs.reading_way`, `celebs.reading_way_en`에 한영 본문을 저장한다. 컬럼 정의는 [마이그레이션](../../../sw/web/database/migrations/20261025074710_add_celeb_reading_way.sql)을 따른다.

- `reading_way IS NULL`: 미조사.
- 두 필드가 모두 빈 문자열: 조사했으나 본문을 구성할 자료가 부족한 조사 미달.
- 한국어 본문이 있고 영어만 NULL: 한국어 원문이 있으며 영어 번역은 미완료.

조사 미달 문구는 공개 본문에 넣지 않는다. 사용자 화면은 해당 언어의 본문이 있을 때만 독서 방식 구획을 노출한다.
