## 현재 인프라 상태

### 제휴 링크 (26.08.08 가동)

- `content_locales.affiliate_url` JSONB 컬럼에 플랫폼별 링크를 담는다. 백오피스 콘텐츠 상세에서 편집한다
- `sw/web/src/constants/affiliatePlatforms.ts`: 플랫폼별 라벨·색·**locale**·대가성 문구. locale이 노출 국가를 가른다
- **조회 단일 지점은 `sw/web/src/actions/home/getAffiliateBooks.ts`다.** 링크가 걸린 도서 풀을 한 번 캐시하고 화면별로 걸러 쓴다 — 화면마다 다시 조회하면 그만큼 egress가 는다

**노출 지점과 선택 근거** (26.08.11 실측)

| 화면 | 무엇을 뽑나 |
|------|------|
| 홈·작품·탐색 | 서점 순위에 오른 책 먼저, 남는 칸은 현역 인물 지지 순 후보 24권을 날마다 돌린다 (`PopularBooks`) |
| 콘텐츠 상세 | 그 작품의 링크. 화면 locale과 플랫폼 locale이 맞을 때만 |
| 인물 상세 | 등장 원전 → 읽은 책 → 같은 직군 → 인기 순 폴백 (`CelebAffiliateBooks`) |
| 세력도감 진영 소개 | **그 진영이 다루는 분야의 책** (`TagOriginBooks variant="topic"`) |
| 세력도감 서재 모드 | 그 진영 인물이 쓴 책, 없으면 그들이 읽은 책 (`variant="people"`) |

**진영에 어울리는 책을 고르는 기준** — 낱말 목록은 `sw/web/src/constants/factionBookTopics.ts`가 쥔다.

진영 인물이 **읽은** 책은 그 사람 취향일 뿐 진영 주제가 아니다. 실제로 디지털 레지스탕스에 『이솝 우화』가, 위대한 해커들에 『금강경』이, 반도체 제국에 『우리는 왜 잠을 자야 할까』가 떴다. 그래서 진영마다 분야 낱말을 적어 두고 그 책을 먼저 낸다. 신화 진영은 인물들이 나오는 원전이 곧 분야다.

🔴 **낱말을 짧게 쓰면 오탐이 터진다.** 「록」 한 글자는 자성록·회상록·고백록·어록을, 「신화」는 『시지프 신화』를, 「우주」는 아동 과학동화를 통째로 끌어왔다. 두 낱말 이상으로 좁히거나(그리스 신화) 그 분야에서만 쓰는 말을 골라라(자율주행).

- 카드에서 **표지·제목은 콘텐츠 상세로, 버튼만 판매처로** 간다. 카드 전체를 외부 링크로 두면 무엇을 눌러도 서비스를 떠난다
- 모바일은 가로 스크롤, 데스크톱은 줄바꿈 배치다(`AffiliateBookList`)
- BOOK 판매처는 판본 locale과 함께 확정한다. `ko`는 한국어판의 쿠팡·알라딘·YES24·교보문고, `en`은 실제 영문판의 Amazon 링크를 해당 `content_locales` 행에 저장한다. 한국어판 링크를 `en`으로 복사하거나 제목만 번역해 영문 구매 경로로 간주하지 않는다.

**🔴 자료를 SQL로 직접 넣으면 화면에 안 뜬다.** 화면 조각을 보관하므로 백오피스를 거치지 않은 변경은 반영되지 않는다. 이럴 땐 `/api/revalidate`에 `{tag, secret}`을 POST한다(secret은 `CRON_SECRET`).

**고친 건수만큼만 비워라.** 한 건이면 `{"tag":"contents:<content_id>"}`, 여러 건이면 그 목록을 배열로 보낸다. `{"tag":"contents"}`처럼 도메인만 보내면 작품 화면 10,640장이 전부 낡은 것으로 처리되고 그 뒤 방문·크롤링마다 재생성이 쌓인다. 26.08.08에 이 작업을 하며 도메인 비우기를 여러 번 부른 탓에 하루 만에 ISR 쓰기가 61만에서 110만으로 늘었다(한도 20만). 목록 화면(홈·탐색의 추천 도서)은 1시간 수명이라 따로 비울 필요가 없다.

### 쿠팡 파트너스 (26.08.08 실측)

- **최종 승인 전이다.** 오픈API 키 발급 화면(`추가 기능 > 파트너스 API`)은 있으나 「생성」 버튼이 비활성이다. **누적 매출 15만원**을 넘겨야 최종 승인이 나고 그때 키가 열린다
- 따라서 링크는 **파트너스 사이트에서 한 건씩 만드는 수밖에 없다.** 상품 검색은 `#affiliate/ws/link/0/<검색어>`로 바로 열리고, 상품 카드의 「링크 생성」을 누르면 `link.coupang.com/a/xxxx` 단축 주소가 나온다
- **Claude in Chrome 확장은 쿠팡 도메인을 차단한다.** 사이트 허용 목록으로 풀리지 않는다. 대신 크롬을 `--remote-debugging-port=9222`로 띄우고 사람이 직접 로그인한 뒤 puppeteer로 붙여 조작했다
- 최종 승인 조건에는 실적 외에 **활동 페이지에 링크가 게시된 화면 캡처 제출**이 있다. 그래서 링크 노출이 승인의 선행 조건이지 결과가 아니다
- 등록 사이트는 `https://feelandnote.com`으로 이미 올라가 있다

🔴 **열쇠가 없는 동안에는 상품을 자동으로 고르지 마라.** 화면을 긁는 방식은 상품명과 값밖에 못 얻어서, 점수로 1등을 뽑아 봐야 명백한 오탐만 걸러낼 뿐 "더 나은 후보가 있었는지"를 보지 못한다. 26.08.08 회차에서 그렇게 넣은 363권을 되짚으니 76권이 개별 서점 재고·묶음 상품·엉뚱한 판본이었다.

**열쇠가 나오면 이야기가 달라진다.** 오픈API는 검색 결과를 `categoryName`·`isRocket`·`productPrice`·`productId`로 준다([상품 조회](https://developers.coupang.com/ko/api/products/querying-product)). 이번에 겪은 오탐은 대부분 여기서 자동으로 사라진다 — 카테고리로 도서만 남기면 풀잎→조화·롤리타→향수·티마이오스→식품·아이 로봇→DVD가 걸러지고, 로켓배송 여부로 개별 서점 재고를 배제하며, 값으로 자치통감 165만원짜리를 뺀다. 그때 사람이 볼 것은 **같은 책의 어느 판본을 쓸지 애매한 경우**뿐이고, ISBN이 맞는 상품이 있으면 그것도 자동으로 정해진다.

**올바른 순서** — 도구와 쓰는 법은 `sw/web-bo/scripts/coupang/README.md`가 쥔다. 후보만 수집(`candidates.mjs`) → 사람이 판단 → 고른 것 하나만 생성(`pick.mjs`), 점검은 `audit.mjs`다.

1. **책 제목만으로** 검색해 후보 12개를 그대로 받는다. 저자·출판사를 붙이면 후보가 좁아져 더 나은 상품을 놓친다
2. 사람이 목록을 읽고 어느 상품이 맞는지 고른다
3. 고른 것 하나만 링크를 만들어 넣는다

픽션 인물의 신규 등장 도서는 순서를 앞에서부터 그대로 적용한다. 서비스에 있는 책을
먼저 정해 쿠팡에서 같은 판본을 찾는 것이 아니라, 쿠팡에서 실제 판매 중인 적절한 책을
먼저 고른다. 본문·목차·색인에서 대상 인물의 등장 범위를 확인한 뒤 같은 작품이 서비스에
있으면 재사용하고, 없으면 카카오에서 ISBN과 서지를 확인해 등록한다. 마지막으로 쿠팡
링크와 인물 관계를 붙인다.

판단 기준은 우리 판본과의 일치 > 정식 유통(개별 서점 재고 회피) > 완질·단권의 적절성 > 값이다. 같은 제목이 둘 이상인 책(자본론·로마제국 쇠망사 등)은 반드시 content_id로 지정한다.

**제목만으로 못 찾는 책이 있다.** 「풀잎」은 조화·인조식물, 「롤리타」는 향수, 「티마이오스」는 식품, 「자연학」은 자연 도감, 「해커스」는 토익 교재가 나온다. 이럴 때만 저자를 붙여 다시 찾는다.

**상품 고르기 함정** — 검색 첫 결과를 그대로 쓰면 엉뚱한 물건이 걸린다. 실제로 파운틴헤드→비치 텐트, 세븐 파워→편의점 장난감, 에누마 엘리시→화장품 세럼, 픽윅 클럽 여행기→데이비드 코퍼필드가 잡혔다. 상품명에 **ISBN이 박힌 상품이 가장 정확**하고(서경·마하바라타를 이걸로 맞췄다), 해설서·부교재 문구(입문·풀이·만화·필사)는 감점해야 원전이 잡힌다. 자동 선별 후 **사람이 제목 불일치 목록을 눈으로 훑는 단계를 반드시 둔다** — 26.08.08 회차에서 299건 중 21건을 이 단계에서 걸러냈다.

**26.08.08 기준 링크 보유 도서 322권.** 신화 원전 20종 중 아르고 호 이야기·아서 왕의 죽음·에누마 엘리시 3종은 쿠팡에 한국어판이 없어 비워 뒀다(카멜롯 왕실 진영은 그래서 구획이 접힌다).

### 서점 순위를 어디서 얻나 (26.08.11 실측)

| 출처 | 접근 | 비고 |
|---|---|---|
| 알라딘 주간 종합 | `www.aladin.co.kr/shop/common/wbest.aspx?BranchType=1` | 열쇠·로그인 없이 열린다. 제목은 `a.bo3`에 있다 |
| 예스24 종합 | `www.yes24.com/product/category/bestseller?categoryNumber=001` | 열쇠 없이 열린다. 참고서·문제집이 섞여 걸러야 한다 |
| 교보 주간 종합 | `store.kyobobook.co.kr/bestseller/total/weekly` | **화면을 띄워야 읽힌다.** 본문 링크(`/detail/`)에서 제목을 줍는다. 집계 기간이 한 주 늦다 |
| 알라딘 TTB API | `ItemList.aspx?QueryType=Bestseller` | 키 필요. 하루 5,000회 |

🔴 **요약해 주는 도구로 순위를 확인하지 마라.** 페이지 요약만 믿고 『일리아스』를 명단에 넣었는데 세 서점 어디에도 없었다. 브라우저로 직접 띄워 순위표의 이름을 눈으로 확인한다. **함께 팔릴 것 같다는 짐작은 근거가 아니다.**

🔴 **한 서점만 보면 틀린다.** 오디세이아는 알라딘·예스24 앞자리인데 교보 20위 밖이다(알라딘은 굿즈·특별판 이벤트를 크게 걸어 순위가 부풀 여지가 있다). 세 서점이 모두 앞자리에 둔 책이 가장 안전하다 — 26.08.11에는 세네카(1·1·5위)와 싯다르타(3·5·3위)였다.

**자동화하려면 알라딘 TTB 키가 답이다.** `ItemList.aspx`에 `QueryType=Bestseller`를 주면 순위·표지·값·ISBN이 오고, `includeKey=1`을 붙이면 **상품 링크에 우리 식별자가 자동으로 박혀** 링크를 한 건씩 만들 필요가 없다. 쿠팡은 열쇠가 없어 링크가 전부 수동이라 매주 갈리는 순위를 따라갈 수 없다. 다만 알라딘 보상은 현금이 아니라 적립금 3%다.

지금은 세 페이지를 사람이 훑어 `affiliateBookPicks.ts`를 갈아끼운다. 링크가 없는 책은 명단에 적어도 뜨지 않으므로 판매처 링크 만들기가 선행이다.
