## 왜 662명만 내보내는가

전량 2,670행을 백업본(`backup-20260814.json`)과 대조해 두 갈래로 갈랐다.

- **탐구가 실제로 다시 쓰인 1,012명** → `ai_reviewed` 유지, 공개 상태인 662명에 `published_at` 부여
- **탐구가 원문 그대로인 1,658명** → `published_at` 해제, `review_status` 초기화. 재작업 대상

1,658명 slug는 `data/celeb/reading-relay/redo-queue.json`에 있다.
이 중 522명은 릴레이를 한 번 태웠으나 판정이 PASS이거나 안내만 고친 경우다. 히포크라테스
표본에서 **"플라톤은 그를 이름난 코스의 의사로 언급했다"** 같은 뜻이 통하지 않는 문장이 나와,
PASS 판정 자체를 신뢰할 수 없다고 결론냈다. 나머지 1,136명은 아예 손대지 못했다.

## 남은 작업

**1,658명 재작성.** 실측 인당 ~1.4만 토큰 → 약 2,300만 토큰. 크레딧 한도 때문에 보류 중이다.

### 결함 세 종류

1. **탐구가 안내를 의미만 바꿔 되풀이** — 어휘가 겹치지 않아 기계로 못 잡는다
2. **평판으로 끝나는 공허한 마무리** — "영향을 미쳤다", "널리 알려졌다" 류. 정규식으로 잡힌다
3. **무정보 문장** — 아리스토텔레스 사례. 사람이 읽어도 판정이 갈린다
   > ❌ 보잘것없어 보이는 생물도 자세히 살피면 몸의 구조와 기능에서 이해할 만한 원인을 찾을 수 있다고 보았다
   > ✅ 아리스토텔레스는 하찮은 벌레도 연구 대상으로 삼았다. 사소한 생물 하나하나가 자연이 어떻게 돌아가는지 알아내는 재료였기 때문이다

1·3번은 기계 검사가 무력하다. 재작성 지침에 판정법을 넣어 두는 것 외에 방법이 없다.

## 판정 기준 (2026-08-15 변경)

**"고칠 것 없음"은 선택지에서 뺐다.** 판정은 B(문장 교정) 아니면 A(조사 재작성) 둘 중 하나다.

재개 첫 회차에서 48명 중 16명이 그대로 통과했다. 히포크라테스 사례로 이미 폐기하기로 한
판정이 지침에 남아 있어서다. 16명은 되돌려 다시 대상에 넣었고 지침에서 그 선택지를 없앴다.
되돌리기는 `scripts/revert-untouched-readings.ts`가 한다 — 백업본과 인물탐구가 한 글자도
다르지 않은데 검수 표시만 찍힌 행을 찾아 표시를 지우고 원장에서 뺀다.

## 실행 체계 (sw/web-bo에서)

| 구성 | 경로 |
|---|---|
| 품질 검사기(표층 위반 집계) | `scripts/audit-celeb-reading-quality.ts` |
| 묶음 생성기 | `scripts/make-celeb-reading-bundles.ts --out=<폴더> --count=N --size=8` |
| DB 반영 관문 | `scripts/apply-celeb-reading-relay.ts --file=<결과.json>` |
| 단건 회수기 | `scripts/recover-celeb-reading-singles.ts --dir=<결과폴더>` |
| 스냅샷 재생성 | `scripts/refresh-celeb-reading-snapshot.ts` — 회차 발주 전 필수 |
| 무수정 통과분 되돌리기 | `scripts/revert-untouched-readings.ts [--dry]` |
| 전량 스냅샷·백업 | `data/celeb/reading-relay/all-readings.json`, `backup-20260814.json` |
| 진행 원장 | `data/celeb/reading-relay/ledger.json` |
| 재작업 큐 | `data/celeb/reading-relay/redo-queue.json` (1,658명) |

한 웨이브 절차:

1. 묶음 생성기 실행 → 원장 미완료 인물을 slug 순 8명 묶음으로 산출
2. 묶음마다 서브에이전트 1개 발주. 지침은 별도 파일 하나로 몰아 Read시킨다(문서 세 개를
   따로 읽히면 묶음당 토큰이 5분의 1 더 든다)
3. **한 명 끝낼 때마다 즉시 파일로 쓰고 반영 관문에 태운다.** 8명을 모아 마지막에 쓰면
   한도 소진 시 전량 날아간다(14차 웨이브에서 240명 손실)
4. 관문 통과분만 반영, 원장 기록. 반려는 다음 웨이브에 자동 재등장

### 재개 시 주의

- 레인은 6개를 넘기지 않는다. 한도로 죽을 때 손실이 레인 수에 비례한다
- `review_status` 초기화 같은 일괄 갱신을 하면 `updated_at`이 바뀌어 **기존 스냅샷이 전부
  충돌한다.** 초기화 후에는 `all-readings.json`을 반드시 다시 뽑는다
- 스냅샷이 낡아 튕긴 원고는 버리지 말고 단건 회수기로 살린다
- 보류 판정은 원장에 직접 적어야 남는다. 반영 관문을 타지 않으므로 기록하지 않으면
  다음 회차에 같은 인물이 계속 다시 뽑힌다
