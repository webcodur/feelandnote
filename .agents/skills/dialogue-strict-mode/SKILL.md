# Dialogue Strict Mode (엄격모드) — LLM 품질검증

저성능 모델이 쓴 셀럽 고유 대사(celeb_dialogues.lines, 7상황 × 3변형 = 21개)를 **별도 LLM 품질검증**으로 통과시켜야만 산출물로 인정하는 임시 워크플로다. "내가 잘 썼다"는 작성자 자기 판단을 신뢰하지 않는다. 기계적 포맷 검사(길이·키 수)가 아니라, **검증 LLM이 품질 게이트를 판정**하는 것이 핵심이다.

> **임시 모드다.** 정식 룰북(`docs/project/celeb/celeb-speech.md`)을 대체하지 않는다. 테스트가 끝나면 폐기하거나 SSoT에 흡수한다.

## 역할 2개

| 역할 | 주체 | 일 |
|---|---|---|
| **작성자** | 저성능 모델(오케스트레이터) | 이름(또는 이름+직군+톤)만 보고 21개 대사 작성 |
| **완결자** | 서브에이전트 LLM | 작성본을 받아 **블라인드**(기존 DB·그라운드트루스 열람 금지)로 품질검증 → **수정까지 스스로 완주** → 완결본 산출. 중간 판정 보고로 되돌려주지 않는다. |

> **핵심**: 검증은 "리뷰 보고"가 아니라 **완결 프로세스**다. 서브에이전트가 검증 게이트를 돌리고, 실패한 줄을 스스로 고쳐, 최종적으로 통과한 21개 완결본을 낸다.

## 검증 게이트 (검증자가 적용)

작성본의 각 줄을 아래 게이트로 판정한다. **통과한 줄은 손대지 않고, 실패한 줄만 수정한다.** 실패가 없으면 "통과" 판정만 내린다.

### G1 구조
- 7상황(`greeting·roll_call·deploy·battle_win·battle_draw·battle_lose·clash_attack`) × 3 = 21줄
- 전부 문자열, 빈 문자열 금지, `{text, quote}` 객체 금지

### G2 ELE 태그
- 작성자는 감정 태그(`[emotion, emotion]`)를 새로 만들지 않는다. 검증자는 태그를 추가·제거·변경하지 않는다(태그는 사용자가 음성 청취 후 보완하는 구역). 태그가 붙은 줄은 본문만 검증한다.

### G3 길이·구조 상한 (태그 제외)
- `clash_attack` 25자(목표 3~18) — **한 호흡 외침 한 단어~한 문장.** 두 번째 문장·이유 설명 금지. `발포하라!` `다르게 생각하라!`가 정상형.
- `deploy` 35자(12~25) — 즉시 실행할 짧은 명령·결단. 두 번째 문장 해설 금지.
- `roll_call` 40자(18~30) — 등장·호명 반응 **한 문장.** 생몰·업적 나열 금지.
- `battle_win`·`battle_draw`·`battle_lose` 40자(18~30) — 결과 반응 **한 문장.** 두 문장 해설 금지.
- `greeting` 50자 — **대표 호흡 한 문장.** 3절 문장·인사말 나열 금지.

### G4 tone 어조
- `bold` 단언·선언·명령 / `composed` 절제·관조 / `gentle` 부드러운 구어 / `free` 거침없는 구어 / `humble` 겸양 / `loyal` 의무·사명
- **어조는 예시 어미 하나가 아니라 변주 범위다.** loyal = `~하겠노라`·`~해야 한다`·`~겠습니다`·명령형을 골고루 섞는다. 특정 어미 하나로 전 줄을 채우는 것은 G4 위반.
- commander 직군 외 존댓말. deploy·clash_attack은 명령형 허용.

### G5 인물 고유성
- **이름 삭제 시험**: 고유명사·직업 단서를 지우고 같은 직군 타인에게 붙여도 자연스러우면 실패
- **직군 표어 금지**: `고객을 생각하십시오`류 누구나 말할 문장 실패
- **팩트 나열 금지**: 업적·연대를 한 줄에 압축한 평전형 문장 실패

### G6 상황 구분
- **상황 교체 시험**: `roll_call`(등장·호명 반응), `deploy`(즉시 명령·결단), 승·무·패(결과 반응), `clash_attack`(돌격·기합·도발 한 마디) 라벨을 서로 바꿔도 어색하지 않으면 실패

### G7 한국어 문장 게이트 (번역투 + 문장력)
- **번역투 전문**(`ko-detranslate` 스킬 진단표 11종): 사물·추상명사 주어, 동격 구문(`~인 N이다`), 수동태 직역(`되어졌다`·`로 하여금`), 명사화 남용, 소유격 남발, 부정·강조 도치, It/What-cleft, 추상명사 인과, 번역 관용구(`~에 있어서`·`~을 통하여`·`~이라 할 수 있다`), em dash(`—`)
- **문장력·AI slop**(`no-trash-prose` 스킬): 설교형·인생역전 마무리, 드라마 과장어, 작위적 대구·반복, 문예 어휘 블랙리스트(포개다·벼리다·빚어내다·꿰뚫다·스며들다·벼랑 끝 등), 종결 어미 패턴(`~한 셈입니다`·`~인지 모릅니다`·`~터였습니다`), 은유는 1회 이내
- **AI slop 적발 패턴 (구체)**: `~이/가 전부입니다`(그것이 전부다) · `~의 주인은 ~입니다`(바다의 주인) · 문답식 자문(`~인가? 그것이 ~다`) · `X는 Y다` 정의형 남발 · 부자연 연어(전선을 고치다, 승부를 본다) · 평전형 업적 나열. 걸리면 **문장째 재작문**(단어 치환 금지)
- 검증 시 **"이 문장을 신문 기자가 쓸까?"** 질문을 한 번 던진다. 아니면 재작문.

### G8 소리 내기
- 입으로 읽었을 때 설명을 듣는 느낌이 아니라 화자의 반응이 들려야 한다

### G9 반복·변주 게이트
- **같은 종결 어미가 3문장 연속이면 변주**한다. 같은 상황 3줄 안에서도 `~노라`·`~겠습니다`·명령형을 섞는다.
- **같은 키워드·수사는 전체 21줄에서 2회 이하.** `설계`·`승부`·`바다`·`지킨다`를 돌려쓰지 않는다.
- **같은 문형·시작부 몰림 금지**: 전 줄이 `이~는/이~는`으로 시작하거나 `예, ~` 응답으로 도배되면 변주한다.
- 고유성(G5)을 확보하려고 **상황마다 같은 프레임**(설계·증명·승부)을 재탕하면 G9 위반. 프레임이 아니라 소재로 고유하게 만든다.

## 검증 결과물

완결자가 아래를 산출한다.

- **완결본 JSON**: 실패 줄을 전부 고쳐 21개가 전 게이트를 통과한 최종 대사. 실패가 없으면 원본 그대로.
- **처리 보고**: 판정(통과/수정) + 실패 줄 목록(위치·게이트·사유) + 수정 내역. 보고는 부산물이고 완결본이 본산출물이다.

## 완결자 자기 보고 불신 — 오케스트레이터 기계 검증 (필수)

서브에이전트가 "G1 통과·G3 통과"라고 보고해도 그대로 신뢰하지 않는다. 완결자가 낸 JSON에 **오케스트레이터가 기계 검증을 한 번 더 돌린다.**

- **G1 기계**: 키 7종(`greeting·roll_call·deploy·battle_win·battle_draw·battle_lose·clash_attack`) 정확 일치, 이외 키 0개, 각 키 정확히 3줄 문자열
- **G3 기계**: 각 줄 글자 수(태그 제외) 상한 위반 0건
- **G2 기계**: ELE 태그 추가·제거 0건

> 실전 사례: 완결자가 `battle_draw` 대신 `outro` 키를 넣고 "G1 통과"라 보고했다. 기계 검증이 아니면 잡히지 않는 오류다. 기계 검증 실패 시 완결자에게 재수정을 되돌려 보낸다(이 경우만 리뷰 루프가 발생한다).

