# 인물 타임라인

인물 상세의 타임라인과 활동 반경이 읽는 최종 사건 데이터의 규격이다. 서비스 SSoT는 `public.celeb_timeline_events`이며 조사 이력·작업 큐·클레임·실패 상태는 이 테이블에 넣지 않는다.

실존 인물은 달력 시점이 있는 생애 사건으로, fiction은 연결된 원전 안의 서사 순서로 표시한다. 좌표는 검증된 사건에만 선택적으로 붙이며, 좌표가 없는 중요한 사건도 타임라인에는 남긴다.

## 책임과 구현 원천

| 책임 | 원천 |
|---|---|
| 테이블과 컬럼 | [`../data/03-celeb.md`](../data/03-celeb.md), 최신 DB migration |
| 사건 종류 허용값 | `sw/web-bo/src/constants/timeline.ts`와 DB 제약 |
| 수동 입력 검증 | `sw/web-bo/src/actions/admin/timeline.ts` |
| fiction 후보 계약 | `sw/web-bo/scripts/celeb/timeline/fiction-candidate-contract.ts` |
| 사용자 조회·정렬 | `sw/web/src/actions/celebs/getCelebTimelineEvents.ts` |
| 카드·활동 반경 상호작용 | `JourneySection.tsx` 아래 타임라인 컴포넌트와 회귀 검사 |

허용값·좌표 범위·후보 개수 경고를 문서에 복제하지 않는다. 문서는 각 필드의 뜻과 작성 판단을 쥔다.

## 사건 형식

모든 사건은 인물 ID, 국·영문 제목과 서술, 사건 종류, 표시 순서를 가진다. 장소명·좌표는 선택값이다. 시점은 인물 티어에 따라 둘 중 하나만 쓴다.

| 인물 | 달력 필드 | 서사 단계 |
|---|---|---|
| full·light | 확인된 `year`, 선택 `year_end`; 날짜 미상은 둘 다 `null` | `sequence_label`, `sequence_label_en` 모두 `null` |
| fiction | `year`, `year_end` 모두 `null` | `sequence_label`, `sequence_label_en` 모두 필수 |

실존 인물의 날짜 미상 사건에 임의 연도나 서사 라벨을 만들지 않는다. fiction 사건을 실제 역사 연도로 환산하지 않는다. 화면 순서는 `sort_order`, 값이 같으면 `id` 순이며 연도가 정렬을 대신하지 않는다.

`source`는 등록 경로를 구분한다. 백오피스에서 손질한 행은 `manual`로 저장한다. 사건 근거 URL, 장소 QID, 작업 상태 같은 화면 비소비 필드를 새로 만들지 않는다.

## 커버리지

사건 수를 목표로 채우지 않는다. 인물의 상태·목표·관계·행로가 독립적으로 바뀌는 전환점만 남긴다.

- 사망한 실존 인물은 확인된 출생과 사망을 포함한다.
- 생존한 실존 인물은 출생을 포함하고 사망을 만들지 않는다.
- fiction은 연결된 원전에서 확인되는 기원이나 첫 등장부터 결말까지 이어 간다.
- 죽지 않는 신·개념에게 사망 사건을 만들지 않는다.
- 기록이 끊긴 죽음이나 시점을 확정값으로 쓰지 않는다.

같은 장면의 이동·대사·전투를 숫자를 채우려고 쪼개지 않는다. 반대로 한 사건 안에서 인물의 지위나 목표가 실제로 바뀌면 독립 사건으로 나눈다.

## 장소와 좌표

장소명과 좌표는 모두 선택값이다.

- 사건 도시를 확인하지 못하면 장소명과 좌표를 모두 비운다.
- 도시만 확인했으면 국·영문 장소명만 쓰고 좌표를 비운다.
- 좌표를 쓰면 위도와 경도를 함께 쓰고, 같은 실제 도시의 검증된 좌표인지 확인한다.
- 학교·회사·극장 이름은 제목이나 서술에 쓰고 장소 필드에는 확인된 도시를 쓴다.
- 온라인 공개·출간·계약 사건에 회사·출판사·레이블 소재지를 대신 붙이지 않는다.
- 여러 도시를 포괄하거나 현실 좌표가 없는 가상 무대에는 좌표를 만들지 않는다.

백오피스의 Wikidata 후보를 쓸 때는 같은 지명의 설명을 대조하고 해당 장소의 좌표인지 확인한다. 기억이나 이름만으로 좌표를 고르지 않는다.

## 사실 조사와 서술

사건은 외부 자료에서 직접 확인한 사실만 쓴다. 링크를 DB에 모으는 대신 조사 중 원문과 사실관계를 대조하고, 외부 문장을 복사하지 않은 서비스 문장으로 한영을 함께 작성한다.

한 사람의 제목과 서술을 위에서 아래로 이어 읽었을 때 어떤 선택이 다음 변화를 불렀는지 보여야 한다. 연혁 메모나 수상 목록만 늘어놓지 않는다.

- 제목·이름·연도를 서술 첫 문장에서 그대로 되풀이하지 않는다.
- 사건에서 누가 무엇을 했고 무엇이 달라졌는지를 쓴다. 사실이 허용하지 않는 인과나 내면은 보태지 않는다.
- 후반 생애를 수상·직함 목록으로 대체하지 않는다. 그 사건이 앞뒤 행보에서 어떤 변화를 만들었는지 확인되는 범위에서 연결한다.
- 팀·조직의 일을 개인의 단독 행동으로 돌리지 않는다.
- 한국어에 번역되지 않은 외국어와 직역 어순을 남기지 않는다. 영문도 같은 사실 범위와 확신을 유지한다.
- 교훈·영웅화·다큐멘터리식 여운으로 사건을 닫지 않는다.

짧게 끝나도 충분한 사건과 설명이 더 필요한 사건을 같은 문장 수로 맞추지 않는다. 규칙 개수를 세는 것보다 실제로 읽어 사건과 인물의 변화가 이해되는지를 우선한다.

## 사용자 화면 계약

- 현재 locale의 제목·서술·장소·fiction 서사 단계를 사용하고, 영문값이 없을 때만 한국어로 물러난다.
- life는 연도 또는 연도 범위, fiction은 서사 단계 라벨을 시점으로 표시한다.
- 모바일 활동 반경은 장소명이 있으면 좌표가 없어도 정거장으로 표시하고, 장소명도 없으면 미상 정거장으로 남긴다.
- 데스크톱 지구본의 마커와 경로에는 위도·경도가 모두 있는 사건만 포함한다.
- 사건 조회 실패를 빈 연표로 위장하지 않는다.
- `/explore/timeline`의 국가별 연대기는 생몰년 기반의 별도 기능이다.

픽셀 크기·제스처·애니메이션은 구현과 `check-celeb-timeline-scroll.mjs`, `check-globe-layout.mjs`가 쥔다. 이 문서에 구현 이력을 복제하지 않는다.

## 편집과 일괄 실행

수동 편집은 web-bo `/celebs/timeline/[slug]`에서 한 행씩 추가·수정·삭제한다. 저장 뒤 사용자 웹 캐시를 갱신하고 다시 읽는다.

일괄 조사·교정은 대상에 따라 문서가 갈린다.

- 실존 인물 부분 수리: [`celeb-06-02-timeline-real-relay.md`](celeb-06-02-timeline-real-relay.md)
- fiction 원전 기반 교정: [`celeb-06-03-timeline-fiction-relay.md`](celeb-06-03-timeline-fiction-relay.md)

두 경로 모두 기존 사건 ID와 현재 DB 지문을 고정하고, 후보 검수·dry-run·반영·DB readback까지 한 인물을 끝낸 뒤 다음 대상으로 이동한다. 국·영문 JSON과 DB 쓰기는 UTF-8로 처리하며 대체 문자나 예상 밖 물음표가 생기면 같은 인물에서 복구하고 재검증한다.
