## 결론

이 패키지는 탐지기나 통계 모델이라기보다 **한국어 원고를 보수적으로 윤문하는 Claude Code용 편집 스킬**이다. AI 냄새를 단어 목록으로 지우는 방식이 아니라, 장르·독자·말투를 먼저 진단하고 작은 패스로 문장을 고친다.

실제로 쓸 만한 핵심은 다음 다섯 가지다.

1. 원본 파일을 절대 덮어쓰지 않는다.
2. 의미·사실·수치·인용·불확실성을 문체보다 우선한다.
3. 번역투, 추상 명사, 반복 연결어, 에이전트 작업어, 평평한 리듬을 분리해서 본다.
4. 한 번의 대규모 의역이 아니라 8개 패스로 나눠 고친다.
5. 결과 파일에서 보호 리터럴과 Markdown 구조가 사라졌는지 별도 가드로 확인한다.

### AI 어휘 목록의 성격

`references/ai-word-bank.md`는 `결론적으로`, `혁신적`, `깊이 파고들다`, `새로운 지평`, `시사하는 바가 크다` 같은 후보를 모아 둔다. 하지만 스킬 자체가 명시하듯 단어 하나는 증거가 아니다.

- 반복과 밀집을 먼저 본다.
- 정확한 전문 용어와 공식 제품명은 유지한다.
- 단어를 일괄 금지하거나 하나의 대체어로 통일하지 않는다.
- 근거 없는 문장을 더 그럴듯하게 만들기 위해 사실을 추가하지 않는다.

## 작업 순서

`SKILL.md`의 8개 패스는 다음 순서다.

```text
Meaning Map
  → Machine Trace Scan
  → Motion Word & Metaphor Repair
  → Terminology
  → Register
  → Rhythm
  → Proof
  → Guardrail
```

특히 좋은 부분은 다음이다.

- 격식체 자체를 AI 말투로 보지 않는다.
- 블로그·에세이·회고에서는 기능 표지 문장, 평행 단문, 추상적인 문단 마무리를 우선 점검한다.
- 연결어를 먼저 삭제하지 않고, 문장 관계가 끊겼는지 마지막에 다시 확인한다.
- `단순히 X가 아니라 Y`가 한 번만 쓰였고 의미가 분명하면 `KEEP`한다.
- 기술 피동문에서 행위자를 억지로 만들어 넣지 않는다.
- 보안 의미의 `SQL 주입`, `프롬프트 인젝션`, `명령 주입`은 일반적인 `주입` 표현과 구분해 보존한다.

- 외부 문서에 남은 에이전트식 작업어
- YAML frontmatter

- Markdown 표의 행 수와 파이프 구조
- 각주 정의·참조
- 코드 펜스와 언어 태그

실행 자체는 Python 표준 라이브러리만 사용하며, 이 폴더에서 문법 검사와 `--help` 실행은 통과했다.

## 한계와 주의점

### 1. “사람처럼 보이게”는 품질 보장이 아니다

README의 표현은 사람처럼 읽히는 윤문을 목표로 하지만, 이 패키지에는 탐지기 점수나 인간 판정 정확도를 입증하는 모델·벤치마크가 없다. 따라서 `undetectable`, `검사기 통과` 같은 약속으로 사용하면 안 된다.

### 2. 가드는 의미 검증기가 아니다

`rewrite_guard.py`의 보호 검사는 대부분 “원문 값이 결과에 한 번이라도 존재하는가”를 본다. 값의 위치·순서·중복 횟수·문장 의미·인과관계가 그대로인지까지 증명하지 않는다. 수치·법률·보안·인용 원고에는 사람이 문장 단위로 역검증해야 한다.

### 3. AI 어휘 검사는 완전한 탐지기가 아니다

`--check-ai-words`는 몇 개의 어휘군을 밀도로 경고할 뿐이다. 자연스러운 문장을 AI라고 판정하거나, 반대로 모든 AI식 구조를 잡아내는 기능이 아니다. 경고는 `REVIEW` 신호로만 사용한다.

### 4. 한국어 형태소·문장 의미를 자동 판정하지 않는다

조사·어미·문단 기능·사실성 판단은 스킬 지침을 따르는 모델과 사람의 몫이다. `grep`식 치환으로 돌리면 `효율적`, `중요한`, `통해`처럼 정상적인 말까지 망가질 수 있다.

### 5. Claude Code 전용 설계가 있다

`AskUserQuestion`, `Write`, `Read`, `Grep`, `Glob`, `Bash`를 전제로 한다. 다른 에이전트에서 쓸 때는 파일 무수정·새 파일 출력·2문항 프로필 게이트를 별도로 구현해야 한다.

### 6. 공식·기술 원고의 모든 구조를 지켜 주지는 않는다

Markdown 표·체크박스·frontmatter·각주는 검사하지만, HTML·DOCX·PDF 레이아웃이나 JSON 스키마를 검증하지 않는다. 그런 파일은 별도 렌더·구조 검사가 필요하다.

## 실행·보안 점검

- `requirements.txt`, `package.json`, 외부 서버 호출 코드는 없고 `rewrite_guard.py`는 Python 표준 라이브러리만 사용한다.
- 다만 `SKILL.md`의 `Bash` 허용은 Claude Code 세션의 명령 권한을 자동으로 제한하지 않는다. 이 스킬이 보안 샌드박스는 아니다.
- 원문 속 “이전 지시를 무시하라” 같은 문장을 데이터로 취급하라는 지침은 들어 있지만, 실제 안전성은 사용하는 에이전트가 그 지침을 따르는지에 달려 있다.
- `Write`만 허용하고 `Edit`를 제외한 원본 보호는 좋은 방어선이지만, 다른 에이전트에 복사하면 frontmatter의 도구 제한이 강제되지 않을 수 있다.

## 이 패키지를 쓸 때의 권장 조합

1. 원문을 먼저 복제하고, 보호할 링크·코드·인용·숫자를 목록화한다.
2. 장르와 말투를 유지한 채 `Machine Trace Scan`만 먼저 돌린다.
3. 문단의 기능이 깨질 때만 문장 구조를 다시 잡는다.
4. `rewrite_guard.py --mode external --check-ai-words`를 실행한다.
5. AI 어휘 경고는 삭제 명령이 아니라 사람이 볼 후보로 취급한다.
6. 최종 글은 원문과 대조해 사실·불확실성·인용·링크·보안 용어를 확인한다.

## 최종 평가

이 폴더에서 실제로 건질 것은 “AI가 쓴 글을 탐지해 사람으로 위장하는 도구”가 아니라, **한국어 글을 의미 손실 없이 덜 기계적으로 고치는 편집 절차**다. Humanizer의 33개 패턴을 참고하되, 이 패키지의 원문 보호·장르/말투 진단·과교정 방지·구조 가드를 중심으로 쓰는 편이 안전하다.
