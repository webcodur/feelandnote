# 신화 이미지 설명문

신화의 대표 그림과 신화·팩션의 주요 장면을 보고 어떤 인물과 사건인지 이해하도록 돕는 한·영 설명이다. 일반 팩션 표지는 대상에 넣지 않는다.

주요 장면의 확장·보완은 **이미지 생성 모듈을 사용할 수 있고, 사용자가 해당 작업을 허용했을 때만** 진행한다. TODO 등록 자체는 실행 허용이 아니다. 이미지 발주·권장 규격은 [이미지 제작 규칙](prod-01-image-generation.md), 얼굴 REF의 출처·누락 처리는 [faction-image 스킬](../../../.agents/skills/faction-image/SKILL.md)을 따른다.

기존 이미지가 없으면 원전에서 이야기의 전환점과 꼭 필요한 사건을 먼저 고른다. 장면마다 인물·행동·장소와 앞뒤 연결을 정하고, 승인된 REF를 확인해 순서대로 제작한다. 인물끼리 너무 닮거나 개성이 약하면 장면 제작 전에 인물부터 정비한다. 보유 이미지 수에 맞춰 이야기를 늘리거나, 필요한 장면 대신 단체 화보를 채우지 않는다. 생성 결과를 직접 검수한 뒤 그 최종 그림에 맞춰 해설을 쓴다.

문화권이 바뀌면 해당 지역의 복식·문신·장식 자료를 따로 확인한다. 기존 얼굴 REF의 장식을 고증 근거로 삼거나 이웃 문화의 문양을 공통 양식처럼 옮기지 않는다. 박물관 유물을 REF로 쓸 때는 지역과 제작 시기를 기록하고, 후대 유물을 전승 속 인물의 실제 소지품처럼 단정하지 않는다.

- 서비스에 연결된 최종 이미지를 직접 보고 쓴다. 생성 프롬프트는 의도 확인에만 쓰며, 폐기한 컷의 동작을 설명에 옮기지 않는다.
- 대표 그림은 인물과 행동을 짧은 한 문장으로 적는다. 인물이 없는 그림은 장소·대상과 전승의 관계를 설명한다.
- 주요 장면은 실제 사건을 식별할 수 있는 그림을 고른다. 사건 속 발언자를 먼저 소개하는 인물 정면 컷도 앞뒤 장면과 연결되면 사용할 수 있다. 단체 화보나 애매한 컷은 제외해도 된다. 장면 제목과 함께 눈에 보이는 행동과 사건의 맥락을 설명한다. 원전은 사실 확인에 사용하되 권·장 표기를 화면 해설의 고정 꼬리말로 붙이지 않는다.
- 기존 영상 자료를 이관할 때는 `faction-data.json`의 재생 순서와 장면별 이미지 전환을 먼저 확인한다. 기존 주요 장면 목록도 함께 대조하며, 영상의 대사 목록에 없다는 이유로 기존 사건 컷을 빼지 않는다. `beats[].media`·`mediaChanges` 앞에 재생되는 `clusters[].image` 도입 컷도 포함한다. 실제 지정된 등장 컷·모멘트 컷을 그대로 연결하고, 만들기만 한 미사용 이미지나 수정 전 후보를 임의로 골라 넣지 않는다. 사용자가 작성한 대사를 사용할 때는 화자와 따옴표를 붙여 문구를 그대로 옮기며, 등장 설명을 덧붙이거나 다른 대사로 바꾸지 않는다. 같은 화자의 대사가 바로 다음 컷으로 이어지면 이름은 첫 컷에만 쓰고 이후에는 따옴표 안의 대사만 남긴다. 화자가 바뀌거나 해설 뒤에 대사를 다시 시작하면 이름을 표시한다. 영상의 창작 대사를 원전의 직접 인용으로 표시하지 않는다. 사용자 대사가 없는 전승은 원전에 실제로 있는 직접 화법·노래만 같은 `화자: “대사”` 형식으로 옮기고, 원문·번역 대조본으로 문구를 확인한다. 대사가 사건의 동기·감정을 전하는 장면에 쓰고, 그림에 없는 화자의 말은 넣지 않는다. 장면 해설 칸은 데스크톱 3줄·모바일 4줄 높이라 대사를 넣은 장면도 대략 이 안에 맞춘다.
- 같은 사건을 반복 설명하는 컷은 합치거나 각 장면의 역할을 나눈다. 한 해설에서 뒤 장면의 결과까지 모두 말한 뒤 다음 컷에서 되풀이하지 않는다. 인물의 얼굴·갑옷이 앞뒤와 어긋나는 컷은 대체하거나 제외한다. 최종 장면 뒤의 후속 이야기는 별도 엔딩 카드에서 읽게 할 수 있다.
- 해설은 **장면당 두 문장 안팎**으로 쓴다. 인물의 목적·감정과 사건의 원인·조건·결과가 빠지면 장면을 나누고 필요한 이미지를 보탠다. 두 문장에 맞추려고 여러 사건을 긴 복문으로 몰아넣지 않는다. 비슷한 컷을 둘 다 쓸 때는, 예를 들어 환대를 청하는 컷에서 제우스가 지키는 크세니아를 설명하고 다음 컷에서 거인의 거부와 행동을 보여 주듯 새로 전달할 내용을 나눈다.
- 세력 개요는 별도로 다루므로 전체 줄거리는 붙이지 않는다. 구도·색감·제작 방식에 대한 평론도 쓰지 않는다.
- 눈에 보이지 않는 사건, 단정할 수 없는 인물의 신원·감정·소품을 지어내지 않는다. 여러 이야기를 합친 상징 장면은 특정 사건의 한순간처럼 설명하지 않는다.
- 고유명사와 사건의 맥락은 등록된 인물·전승 자료와 원전 또는 신뢰할 만한 문화기관 자료로 확인한다. 그림의 오류를 정당화하려고 전승을 바꾸지 않는다.
- 영어는 한국어와 같은 인물·행동·시점·인과관계를 담되, 통용되는 영문 이름과 자연스러운 문장으로 쓴다. 한국어를 줄이거나 장면을 합치면 영어 제목·해설·엔딩도 함께 맞춘다.
- 검수할 때 최종 그림, 한국어, 영어를 함께 대조한다. 이미지가 바뀌면 설명도 다시 확인한다.

저장은 기존 `faction_lv2.team_images`의 해당 이미지 항목에 `caption`·`captionEn`을 둔다. 검수한 주요 장면에만 `kind: "scene"`을 붙이고 이야기 순서로 배열한다. 장면 편집은 제목(`label`·`labelEn`)·해설·배열 순서에 함께 반영한다. 장면과 무관한 기존 항목과 인물 대표사진은 보존한다. 엔딩은 마지막 장면의 `ending`에 한·영 제목과 본문을 저장한다. 정규화·저장 형식과 언어별 장면 선택은 [faction-team-image.ts](../../../packages/shared/src/lib/faction-team-image.ts)가 쥔다.

화면에서는 이미지 확대 창의 그림 아래에 해당 언어의 설명을 표시한다. 원본 비율을 유지하고 설명 때문에 그림을 자르지 않는다. 주요 장면은 해당 언어의 제목과 해설이 있는 항목만 노출한다. 반영 후 한·영 장면 수와 순서, 제목·해설의 누락, 번호·검색 이동, 마지막 엔딩을 실제 모달에서 확인한다. 화면 규칙은 [탐색](../service/service-01-explore.md)이 쥔다.

단체·장면 업로드는 원본을 R2에 보관하고, 비율·해상도를 유지한 WebP가 더 작을 때 표시용 주소로 연결한다. 변환은 [faction-team-display.ts](../../../sw/web-bo/src/lib/faction-team-display.ts), 품질 설정은 [responsive-artwork.ts](../../../packages/shared/src/constants/responsive-artwork.ts)가 쥔다. 애니메이션은 원본을 유지한다. 용량을 셀 때는 표시용 이미지와 보관 원본을 구분하며, 전체 묶음의 용량을 첫 화면 다운로드량으로 계산하지 않는다.

현재 그림이 로드된 뒤 오른쪽 두 장만 미리 받고, 번호 이동 시에도 이동한 위치를 기준으로 받는다. 재방문은 브라우저 HTTP 캐시를 사용하며, 디코딩된 이미지 객체를 전부 메모리에 붙잡지 않는다. 구현과 검증은 [FactionArtworkViewer](../../../sw/web/src/components/features/faction/FactionArtworkViewer.tsx)·[usePreloadImages](../../../sw/web/src/hooks/usePreloadImages.ts)·[캐러셀 로딩 검사](../../../sw/web/scripts/check-artwork-preload.mjs)를 따른다. R2의 긴 캐시 수명을 활용하되 교체본은 새 주소로 연결한다.
