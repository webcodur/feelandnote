## 운영 흐름

1. 서버 레이아웃이 프로필을 조회하고 `resolveCelebWorld`로 세계 하나를 정한다.
2. 서버 페이지가 해당 세계의 PC·모바일 파일 쌍을 확인하고, 순수 표시부 `CelebWorldBannerView`에 경로만 넘긴다. 파일이 없으면 임시 무늬로 안전하게 폴백한다.
3. `CelebWorldMaterialScope`가 같은 세계 ID를 5개 재질 계열 중 하나로 바꾸고 상세 전체에 색·표면 CSS 변수를 건다.
4. 상세 본문은 같은 세계 ID로 대표 화보 액자와 구획 번호를 정한다. 구획 제목은 세계와 무관하게 Pretendard를 쓴다.
5. 첫 화면은 배너 아래로 인물 화보가 겹쳐 올라오는 단일 입장부이며, 이름을 유일한 `h1`으로 둔다. 별도 대형 선언문은 두지 않는다. 화보와 아바타가 모두 있으면 원형 아바타를 이름 블록 옆의 작은 식별 인장으로 함께 보여준다. 화보가 없으면 기존 큰 원형 아바타 폴백만 쓰며 중복 표시하지 않는다.
6. 직군은 `CelebProfessionMark`와 직군명으로만 표시한다. 배너·배경·박스 색을 바꾸지 않는다.
7. PC 왼쪽 레일은 중복 아바타·이름·구획 번호 없이 구획 목차만 맡는다. 상단에는 글자 제목 대신 가로선 사이의 원형 나침반 인장 하나만 표시하고 접근성 이름은 `네비게이션`으로 유지한다. 외곽선 하나로 끝내지 않고 재질색 외곽선·낮은 안쪽 선·상단 빛·바닥 그림자를 겹친 얇은 기록 장부 인덱스로 만든다. 각 항목은 가운데 정렬한다. 현재 구획 또는 마우스·키보드가 짚은 항목에는 실제 버튼 위치를 측정한 포커스 띠가 위아래로 이동한다. 띠는 사각 테두리 대신 위·아래선과 양끝 마름모 표식을 쓰며, 손을 떼면 현재 구획으로 돌아온다. 글자색은 즉시 반응하고 띠 이동만 150ms를 쓴다. 목차는 본문 열을 차지하지 않고 1024px 본문 바깥의 왼쪽 여백에 둔다. 본문 구획은 반복 이중 박스 대신 얇은 윗선과 낮은 면을 쓴다.

26.08.03에 제거한 직군색 체계는 다음과 같다.

- 지도자·정치인·지휘관을 금색, 과학자를 파랑, 배우를 분홍, 기업가를 초록처럼 연결한 8개 색 계열
- 같은 계열 안에서 slug 해시로 고르던 강조색 3종·빛 위치·배경 각도
- 배너 위에 직군색을 덮을 수 있던 `tintRgb` API
- 폐기 체계 전용 `theme.ts`, `CelebTheme` 컴포넌트·CSS, 기존 색 비교 lab

## 재질 조합 원칙

색상표를 먼저 만들지 않는다. 서비스에서 반복 사용할 재질 원형을 정하고, 각 세계가 그중 세 가지 역할을 조합한다.

1. **주재질 — 바깥 배경:** 공간의 공기와 넓은 면을 만든다. 낮은 대비의 종이·회벽·석재·콘크리트·유리 결이다.
2. **보조재질 — 기록 박스:** 글이 올라오는 더 고르고 조용한 표면이다. 배경과 같은 재질을 단순 반복하지 않는다.
3. **결구재질 — 테두리:** 목판 결구·청동 홈·흑철 모서리·구리선·알루미늄처럼 구조를 붙드는 데만 쓴다.
한 세계에 재질을 많이 섞지 않는다. 텍스처는 장식 그림이 아니라 미세한 결로만 만들며, 본문보다 먼저 보이면 실패다. 넓은 방사형 번짐, 반복 격자, `backdrop-filter` 블러는 26.08.03 실화면에서 피로와 간섭이 확인되어 제거했다.

같은 날 시험한 박스 가장자리 구조 장식(로마 석주·동아시아 결구선·중세 철제 모서리·산업기 리벳·근현대 레일)은 선묘가 인위적이고 본문 UI와 따로 놀아 전량 폐기했다. CSS 선 몇 개로 시대 건축물을 흉내 내는 접근은 다시 사용하지 않는다. 구조물을 재검토한다면 박스 장식이 아니라 화면 공간 전체의 구도부터 별도 시안으로 만든다.

### 공간 구도 원칙

- 세계 배너는 환경을 먼저 알리되 인물보다 오래 화면을 점유하지 않는다. 모바일 200px·PC 340px을 유지하고 인물 입장부를 배너 하단에 겹친다.
- PC 배너와 입장부는 같은 1024px 파노라마 면을 쓴다. 3:1 PC 원본이 이 면을 직접 채우므로 넓은 모니터에서도 배너 내부에 검은 좌우 칸이 생기지 않는다. 화면의 나머지 폭은 배너 일부가 아니라 상세 바깥 배경이다.
- 이름·화보·생몰·직군·소개·명언은 한 입장부에 모은다. 같은 첫 화면에 별도 선언문이나 PC 목차용 인물 카드를 반복하지 않는다.
- 배너와 프로필 면은 시대별 `material-edge` 색의 얇은 외곽선 하나로 함께 묶는다. 배너 박스와 프로필 박스가 서로 무관한 두 장처럼 보이거나, 개별 장식 테두리를 중복하지 않는다.
- 인물 정보는 `수식어·이름·메타 → 소개·명언`의 한 흐름으로 읽는다. 1024px 이상에서 정보와 서사를 좌우 두 상자로 갈라 `品`자처럼 보이게 했던 과도기 배치는 폐기했다. 우상단의 남는 곳에는 단일 공유 버튼만 두며, 모바일에서는 공유 버튼도 본문 뒤로 내려간다.
- 개인 아바타는 PC 목차 카드로 되돌리지 않는다. 대표 화보와 아바타가 모두 있는 경우에만 이름 옆 64px(모바일 52px) 원형 식별자로 둬, 별도 행과 추가 세로 공간을 만들지 않는다.
- PC 입장부의 인물 열은 240px로 고정한다. 대표 화보가 있으면 사각 화보를, 없으면 176px 원형 아바타를 같은 축에 놓는다. 원형 아바타는 배너 하단 경계에 24px 더 걸쳐 두 영역을 잇는다. 모바일에서는 둘 다 중앙 축을 쓰며 아바타도 144px로 키운다. 대표 화보 미보유 상태를 예외 폴백이 아닌 정식 두 번째 레이아웃으로 취급한다.
- 기록 구획은 내용 자체가 카드 구조를 요구할 때만 내부 카드를 쓴다. 바깥 구획을 전부 `ClassicalBox`로 다시 감싸지 않는다.
- 상단 입장부와 하단 기록 본문은 PC 최대 1024px, 모바일 `100% - 8px`의 같은 가로축을 쓴다. PC 목차는 이 폭을 나눠 갖지 않고 본문 왼쪽 바깥 여백에 24px 간격을 두고 붙인다. 목차 폭은 아이콘·번호 없이 가장 긴 구획명에 맞춰 자동 결정하며, 한국어 기준 `인물과 시대`가 폭의 기준이다. 영문처럼 그 폭이 바깥 여백보다 길면 단어 단위로 줄을 바꾸고 화면 밖으로 넘기지 않는다. 외곽선과 제목까지 한 줄로 안전하게 놓을 수 없는 1340px 미만에서는 목차를 숨긴다.

26.08.03 실제 캡처(`1448×732` PC, `346×802` 모바일) 육안 검수에서 PC 입장부는 1120px에서 1024px로 줄였고 기록 시작 간격은 48px에서 36px로 줄였다. 배너와 화보의 대형 블러를 제거한 뒤, 단색 좌우 여백도 검은 박스처럼 읽혀 배너 자체를 입장부와 같은 1024px 면으로 한정했다. 대표 화보 미보유 인물은 PC 240px 인물 열의 큰 원형 아바타를 정식 레이아웃으로 쓴다. 후속 공간 검토에서는 `LEGACY` 표식을 삭제하고 조회수를 메타 행으로 옮겼다. 펼쳐 놓았던 공유 채널은 40px 단일 공유 버튼으로 축약했으며, 클릭한 뒤 모달에서 X·Facebook·LinkedIn·이메일·링크 복사를 고른다. 배너·프로필에는 하나의 얇은 외곽 프레임만 쓴다. 마지막으로 하단 300px 목차 열을 폐기해 기록 본문도 상단과 같은 1024px 축으로 넓히고, 목차를 그 축 바깥 왼쪽 여백으로 이동했다. 목차는 나침반 아이콘·얇은 외곽선·가운데 정렬 항목을 가진 폭 122.25px 박스로 확정했으며 본문과 24px 떨어진다. 이로써 상단 대문 아래에 좌측 목차 상자와 우측 본문 상자가 갈리던 전체 `品`자 구도도 해소했다.

### 운영 재질 5계열

lab은 조합 화면부터 보여주지 않는다. 아래 표의 재질을 역할별 낱장 15종으로 먼저 펼치고, 그 뒤에 세계별 조합 5종을 배치한다. 개별 재질의 결이 불합격이면 조합 전체를 손대지 않고 해당 원형만 교체할 수 있어야 한다.

| 계열 | 바깥 배경 | UI 박스 | 테두리 | 적용 세계 수 |
|---|---|---|---|---:|
| 동아시아 전근대 | 먹빛 한지 | 옻칠 목재 | 무광 황동 | 10 |
| 고대·석조 | 거친 응회암 | 다듬은 석회암 | 산화 청동 | 6 |
| 전근대 목조·회벽 | 그을린 회벽 | 짙은 참나무 | 망치질한 흑철 | 13 |
| 산업·전쟁기 | 분진 콘크리트 | 무광 강철 | 산화 구리 | 3 |
| 근현대 | 훈연 유리 | 무광 코팅지 | 냉간 알루미늄 | 7 |

세계별 정확한 배정은 `WORLD_MATERIAL_BY_WORLD`가 단일원천이다. 26.08.03 적용 시 `world.ts` 39개와 대조해 누락·여분 0건을 확인했다.

현재 시안은 CSS gradient·미세 noise·선만 사용한다. 새로운 비트맵 텍스처는 만들지 않았으며, 실제 화면에서 CSS만으로 부족하다고 판정된 재질만 별도 자산을 검토한다.

## lab 검수 기준

- 배너에서 본문으로 내려왔을 때 같은 세계의 공간처럼 이어지는가.
- 바깥 배경과 UI 박스의 표면이 구별되면서도 서로 충돌하지 않는가.
- 테두리와 모서리가 정보보다 먼저 보이지 않는가.
- 긴 한국어 본문과 작은 보조 문구가 재질 위에서 안정적으로 읽히는가.
- 모바일에서 텍스처 때문에 화면이 답답하거나 세로로 더 길어 보이지 않는가.
- 넓은 얼룩·격자·블러 없이 미세한 결만 남았는가.
- 재질을 제거했을 때보다 시대 구분이 명확해지는가.

`/[locale]/lab/celeb-worlds`는 39개 세계 배너·배정·액자·번호를 계속 점검한다. `/[locale]/lab/celeb-themes`는 경로를 유지하되 내용은 세계 재질 연구 화면으로 교체했다.

## 적용 후 검수 순서

1. 대표 5세계의 실제 인물 상세를 PC·모바일에서 열어 바깥 배경과 박스 결의 강도를 확인한다.
2. 대표 5세계가 통과하면 같은 계열의 나머지 세계에서 배너 색과 재질색이 충돌하지 않는지 확인한다.
3. 특정 세계만 어색하면 직군이나 인물 예외를 만들지 않고 세계→재질 배정만 바꾼다.
4. CSS만으로 재료가 읽히지 않는 경우에만 별도 비트맵 텍스처를 검토한다.
5. 이후에도 직군은 색 결정과 분리한다.

## 접근성·성능 기준

- 강조 텍스트는 배경 대비 WCAG AA 4.5:1 이상을 유지한다.
- 텍스처는 `pointer-events: none`이며 조작과 스크롤을 막지 않는다.
- 미세한 질감은 CSS와 기존 전역 noise 자산을 우선 사용한다.
- 재질 때문에 레이아웃 크기나 콘텐츠 순서가 바뀌지 않는다.
- 서버가 첫 HTML에서 세계와 재질을 확정할 수 있는 순수 매핑으로 구현한다.
