# 인물 발언 채굴

실존 인물이 **실제로 한 말**을 출처별로 전량 긁어 대사화 자료로 만든다. 핵심 원칙 셋: **verbatim(원문 그대로)만**, **동명이인 차단**, **추측·창작 절대 금지**. 발언이 없으면 없다고 솔직히 보고한다. 지어내면 자료 전체가 오염된다.

## 작업 순서 (절대 어기지 말 것)

1. **인물 식별 확정** — 본인이 직접 검색해 정체를 못 박는다. 위임 전에 한다.
2. **소스별 병렬 발주** — 서브에이전트 5종 동시 발주
3. **종합·중복 제거** — 같은 발언이 여러 소스에서 잡힌다. 하나로 합치고 출처 병기
4. **주제 분류 + 대사화 우선순위**
5. **루트에 md 산출** (요청 시)

식별을 건너뛰고 바로 위임하면 동명이인 발언이 섞여 들어와 전부 다시 걸러야 한다.

## STEP 1 — 인물 식별 (본인이 직접)

위임 전에 WebSearch 1~2회로 정체를 확정한다. 확정 항목:

- 풀네임(영문 철자 포함), 현재·과거 소속, 직함
- **본인 계정 핸들** — X(@핸들), 링크드인 URL, 개인 사이트, GitHub. 이게 동명이인 차단의 닻이다
- 대표 이력 한 줄 (검색 키워드로 쓸 맥락)

식별 결과를 모든 서브에이전트 프롬프트에 **그대로 복붙**한다. 모호하면 사용자에게 객관식으로 되묻는다(`feedback_ask_multiple_choice`).

## STEP 2 — 소스별 병렬 발주 (general-purpose 5종)

의존성 없으므로 **단일 메시지에서 동시 발주**한다. 소스를 쪼개는 이유: 한 에이전트가 전 영역을 훑으면 깊이가 안 나온다. 채널마다 검색 쿼리·접근법이 다르다.

| # | 소스 | 핵심 쿼리 패턴 | 특이사항 |
|---|------|---------------|---------|
| 1 | 링크드인 | `"이름" LinkedIn post / announcement` | 프로필 헤드라인·이직 공지. 본문 1:1 대조 안 되면 출처 플랫폼 명시 |
| 2 | 팟캐스트·영상 | `"이름" podcast / interview / YouTube / talk` | 유튜브 자막은 봇 차단으로 막히는 경우 많음 → 기사가 인용한 문장만 확보. 미확보 명시 |
| 3 | 블로그·에세이 | `"이름" blog / medium / substack / github / 개인사이트` | 장문 글 없는 인물 많음. 개인 사이트·GitHub README까지 확인 |
| 4 | X(트위터) | `"이름" X twitter / tweet / @핸들` | x.com 직접 fetch는 HTTP 402로 막힘 → 검색 인덱스 스니펫으로 확보, 잘린 부분 명시 |
| 5 | 기사 인용 | `"이름" said / quote / "이름" interview <매체>` | 기자 서술과 본인 직접 인용을 **반드시 구분**. 타인 발언과 혼동 금지 |

각 서브에이전트 프롬프트에 공통으로 박을 지시:

- 인물 식별 블록 복붙 (STEP 1 결과)
- "**동명이인 주의.** <소속> 맥락의 그 인물만 채택. 의심되면 `[동명이인 의심]` 표시"
- "발언마다: ①원문(원어 그대로) ②한국어 번역 ③출처 URL+날짜 ④주제 태그"
- "발언이 거의 없으면 **솔직히 그렇게 보고**. 추측·창작 절대 금지. 실제 확인된 것만"
- 우선 주제 명시 (사용자가 지정한 것: 성공·도전·열정·AI 등)

## STEP 3 — 종합·중복 제거

- 같은 발언이 X·링크드인·기사에 다 잡히면 **하나로 합치고 출처를 병기**
- **기자 패러프레이즈를 본인 발언으로 올리지 말 것** — 따옴표 직접 인용만 verbatim. 서술은 맥락 참고로만
- 타인(공동창업자·CEO 등) 발언이 섞여 들어왔는지 교차 확인. 이직 보도엔 본인 인용이 없고 제3자 발언만 있는 경우 흔함
- 발언이 빈약하면 빈약하다고 보고서 첫머리에 명시한다. 부풀리지 않는다(`feedback_no_fabricated_recommendations`)

## STEP 4 — 산출물 형식

주제별로 묶는다(열정·커리어 / AI·성공 / 철학·도전 등). 발언마다:

```
**N. 한 줄 라벨** (필요 시 「대사화 1순위」 등 메모)

> 원문 (원어 그대로)

번역: "자연스러운 한국어"

- 출처: URL (날짜)
- 태그: 주제
```

끝에 반드시:

- **대사화 우선순위 표** — 용도별(대표 1줄 / 신념 블록 / AI 감각 / 도전 일화)로 어느 발언을 쓸지
- **미확보 영역** — 막힌 소스(유튜브 자막, x.com fetch, 유료 기사)를 솔직히 적는다. "있을 텐데 못 캤다"를 숨기지 않음

## 대사화 변환 (요청 시 추가 단계)

이 프로젝트의 대사 규격으로 다듬을 때:

- 간결체 = 비정중 종결(~다)이되 **축약 아님**. 정보·호흡 유지, 종결만 바꿈 (`feedback_faction_quote_terse_not_abbreviation`)
- 직접인용 슬롯은 사건·감정·전환 발화 전용. 단순 정보 진술은 나레이터에 양보 (`feedback_narrator_carries_when_dialogue_static`)
- 한국어 자연 어순, em dash 금지, 두괄식
- **원문 발언의 뜻을 비틀지 말 것.** 다듬는 건 종결·어순이지 내용이 아니다

## 흔한 함정

- **식별 건너뛰기**: 바로 위임하면 동명이인 발언이 섞인다. 본인 계정 핸들을 닻으로 박고 시작
- **기자 서술을 인용으로 착각**: "그는 ~라고 설명했다"(패러프레이즈) ≠ "그가 따옴표로 직접 말한 문장"
- **빈약함 숨기기**: 발언이 적은 인물이 대부분이다. 7건뿐이면 7건이라고 보고. 채우려 지어내면 자료가 죽는다
- **타인 발언 혼입**: 공동 이직·공동창업 기사엔 파트너·CEO 발언이 섞인다. 화자를 반드시 확인
- **막힌 소스를 캤다고 착각**: 유튜브 자막·x.com 본문이 차단되면 그 사실을 적는다. 검색 스니펫으로 메운 부분은 "스니펫 의존, 끝부분 잘림" 명시
