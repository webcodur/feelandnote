# KO/EN 의미·문장·레이아웃 검수 기준

## 판정 순서

한 화면을 한국어와 영어로 각각 처음부터 끝까지 읽고, 그 뒤 같은 구획끼리 비교한다. 문장만 떼어 번역 품질을 보지 말고 제목, 탭, 안내, 데이터, 다음 행동이 함께 만드는 뜻을 본다.

## 1. 의미와 정보 위계

- 섹션명은 하위 탭을 포괄해야 한다. 상위명이 하위 항목 하나와 동의어이면 위계가 무너진다.
- 한국어와 영어가 같은 정보 범위를 가리켜야 한다. 직역보다 서비스 안에서의 역할이 우선이다.
- 사용자가 이미 알고 있는 말을 반복하지 않는다. 제목, 한 줄 정의, 본문은 각각 `식별 → 핵심 개념 → 상세/제약`을 맡긴다.
- 미등록·미개방 상태는 세 가지를 짧게 알려야 한다.
  1. 이 구획이 원래 보여 주는 것
  2. 어떤 인물·자료가 대상이 되는지
  3. 이 인물에게 지금 보이지 않는 이유
- “자료가 없다”와 “기능이 미개방이다”를 섞지 않는다.
- 인물 지표 문장에는 DB 내부 key를 노출하지 않는다. 예: `diligence`는 “성실성”, `loyalty`는 “충실성”, `cautious_bold`는 문맥에 맞게 “신중함–대담함”으로 풀어 쓴다.
- 이름, 시대, 직군, 관계 방향, 사망 시 나이는 사실과 논리까지 확인한다. 문자열 대응만으로 통과시키지 않는다.

## 2. 영어 자연스러움

- 한국어 어순과 명사 나열을 그대로 옮기지 않는다. 영어 UI 사용자가 처음 읽어도 역할이 즉시 드러나야 한다.
- 섹션명은 가능한 한 짧은 명사구, 안내는 완전한 문장으로 쓴다.
- 같은 화면에서 `Figure`, `Person`, `Celebrity`를 무분별하게 섞지 않는다. 현재 서비스 문맥과 기존 메시지 용례를 따른다.
- 한국어 수식어를 영어 명사 앞에 겹겹이 쌓지 않는다. 필요하면 제목과 설명으로 나눈다.
- 한국어에 없는 과장, 확정, 가치판단을 영어에 추가하지 않는다.
- 원문 인용과 서비스 설명을 구분한다. 인용·명언은 자연스럽게 보이게 하려고 새로 쓰지 않는다.

## 3. fallback과 혼용

- 영문 화면에서 한국어 본문이 조용히 대신 나오면 누락이다.
- 원문을 보존할 가치가 있어 한국어를 함께 보여 주는 경우에는 언어 표시와 영문 설명을 둔다.
- 영문 데이터가 없으면 한국어 장문을 그대로 노출하기보다, 해당 구획의 개념과 “이 인물의 영문 등록 정보가 아직 없다”는 상태를 영어로 안내한다.
- `data-i18n-fallback`은 이 의도가 화면에 드러날 때만 사용한다.

## 4. 레이아웃

각 locale에서 최소 1440×1000과 390×844를 본다. 상세 페이지의 PC 전용 aside가 있다면 1024~1280px 경계도 추가로 확인한다.

- 문서 전체에 가로 스크롤이 없어야 한다.
- 버튼, 탭, 필터, 제목은 텍스트가 잘리지 않아야 한다. 의도된 ellipsis는 전체 값을 다른 방식으로 확인할 수 있어야 한다.
- 영어는 한국어보다 30~60% 길어질 수 있다고 보고 폭과 줄바꿈을 설계한다.
- 세 개 이상의 모바일 필터를 한 줄에 억지로 압축하지 않는다. 두 줄 배치, 내부 스크롤, 축약 라벨 중 의미가 가장 잘 보존되는 방식을 고른다.
- 탭의 아이콘과 문구는 수평·수직 중앙에 놓고, baseline 차이 때문에 아래로 처지지 않는지 본다.
- sticky/floating aside는 본문을 가리거나 viewport 밖으로 잘리지 않아야 한다. 긴 영어 프로필명과 섹션명을 넣어 본다.
- 이전·다음 섹션 컨트롤은 중앙 정렬, 올바른 번호·아이콘·대상, 실제 scroll 이동을 확인한다.
- 빈 상태는 충분한 높이와 명확한 행동/설명을 가져야 하지만 실제 콘텐츠보다 더 화려하게 만들지 않는다.
- hover는 프로젝트 원칙대로 즉각적인 색·테두리 반응이 하나 이상 있어야 한다. 키보드 focus도 보인다.

## 5. 스크린샷 육안 검수

자동 생성된 네 스크린샷을 모두 연다.

1. 상단 프로필과 aside가 첫 viewport에서 균형 잡혔는지 본다.
2. 전체 페이지를 훑어 섹션 간 간격·제목 크기·탭 위치가 일관적인지 본다.
3. KO와 EN에서 같은 섹션이 사라지거나 순서가 바뀌지 않았는지 본다.
4. 영문 장문이 카드 높이, 그래프 라벨, 필터 행, footer를 밀어 깨뜨리지 않는지 본다.
5. 파란 placeholder, 미로딩 이미지, 겹친 fixed UI처럼 번역과 무관해 보여도 실사용을 막는 이상은 별도 결함으로 보고한다.

## 6. 심각도

- 오류: route 실패, 잘못된 locale/SEO URL, 번역 key 부재, 중복 ID, 끊어진 앵커, 문서 가로 넘침, JSON 구조 불일치
- 경고: 번역 데이터 누락, 영문 화면의 한글, 하드코딩 literal, 잘림 가능성, 어색한 의미·문장
- 정보: 의도된 고유명사, 명시된 원문 병기, 아직 데이터가 없는 정상 빈 상태

경고는 “문제 아님”으로 일괄 폐기하지 않는다. 각 항목마다 실제 화면 문맥을 보고 `수정 / 의도됨 / 데이터 제약` 중 하나로 판정한다.
