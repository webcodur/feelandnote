# 모델·에이전트 운영 기준

## 역할 분담

- 고성능 모델: 목표 정의, 구조 설계, 어려운 판단, 최종 검토
- 빠르고 저렴한 모델: 자료 분류, 반복 변환, 초벌 작성, 보조 코딩
- 별도 검증 모델: 요구사항 누락, 근거 부족, 논리와 톤 점검

모델별 성능 순위는 개인 환경의 경험담으로만 기록하고 일반 법칙으로 확대하지 않는다.

## 병렬화

병렬화는 작업 사이에 의존성이 없을 때만 사용한다. 서브에이전트를 수십 개 이상 동시에 실행하면 메모리 부족과 컴퓨터 다운으로 이어질 수 있다. 기본 동시 실행 수를 낮추고, 작업을 작은 묶음으로 나눈다.

자동 실행 모드를 쓸 때는 파일 변경 범위와 외부 명령 실행 범위를 먼저 확인한다.

### Windows에서 서브에이전트가 전부 실패할 때

발주하는 족족 "you need tmux which requires WSL"이 돌아오면 **tmux를 설치할 일이 아니다.** 설정을 본다.

- 원인은 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`이다. 이 값이 켜져 있으면 서브에이전트를 별도 터미널 창(teammate)으로 띄우려 하고, 그 경로가 tmux를 쓴다.
- **Windows 빌드에는 그 길이 아예 없다.** 실행 파일 안에서 tmux 설치 여부를 검사하는 줄보다 앞에서 `--tmux is not supported on Windows`로 끝나 버려, 검사 자체가 실행되지 않는다. WSL에 우분투를 얹든 별도 도구 모음을 깔든 결과가 같다.
- 개인 설정과 프로젝트 설정 양쪽에서 그 키만 지우면 된다. 프로그램을 다시 켤 필요 없이 바로 in-process 경로로 돈다.

키를 지운 뒤에도 **이름을 붙여 발주하면 같은 이유로 실패한다.** `name`을 준 에이전트는 teammate로 취급된다. 익명으로 띄우면 정상 동작한다. 여러 갈래를 동시에 돌릴 때는 이름 대신 발주 프롬프트에 담당 대상을 적어 구분한다.

## 장기 작업

1. 목표와 완료 조건을 고정한다.
2. 태스크 목록과 결정 사항을 파일에 남긴다.
3. 중간 보고에는 실제 변경·실패·남은 위험만 기록한다.
4. 종료 뒤 로그와 릴리즈 노트를 실제 날짜와 실제 변경에 맞춰 작성한다.

임의의 작업 시간이나 가짜 릴리즈 노트를 만들어 작업한 것처럼 보이게 하지 않는다.

## 자동화의 경계

기존에 검증된 수집 코어가 있다면 유지하고, 옵션·저장·UI만 얇게 확장하는 하이브리드 접근을 우선한다. 유지보수 봇은 코드를 마음대로 고치는 봇보다 변경 사항을 모아 요약하고 사람이 승인할 후보를 만드는 역할부터 시작하는 편이 안전하다.
