# 현역 문서 실측 점검

`docs/project/`와 `docs/games/`의 현역 문서를 실제 코드·DB와 대조해 낡은 경로, 완료 상태, 규칙, 수치를 교정한다. 진행률과 모집단은 손으로 고정하지 않고 매번 명령으로 산출한다.

## 판정 원칙

- 문서의 경로·명칭·구현 상태를 저장소에서 직접 확인한다.
- 프로그램이 쓰는 허용값·임계값·모집단은 코드 상수를 정본으로 삼는다.
- 날짜가 있는 수치는 그날의 스냅샷으로만 읽고 현재 규약으로 재사용하지 않는다.
- 완료 보고서에 현행 규칙이 섞여 있으면 규칙을 담당 SSoT로 회수한 뒤 보고서를 아카이브한다.
- 미구현 계획, 폐기 경로, 존재하지 않는 도구를 현행 기능처럼 서술하지 않는다.

## 재현 명령

```bash
rg -L "최종 실측 체크" docs/project docs/games -g "*.md"
rg -n "TODO|미착수|진행 중|구현 완료|폐기" docs/project docs/games
```

첫 명령의 결과는 다음 점검 후보일 뿐이다. 문서 성격상 코드 대조가 불필요한 글쓰기 원고·자료 파일은 모집단에서 제외한다.

## 완료 처리

1. 현행 규칙을 담당 SSoT에 반영한다.
2. 남은 실행 과제가 있으면 `docs/todo/`에 다음 착수 지점을 남긴다.
3. 완료 이력만 남은 문서는 지운다. 경위가 필요하면 커밋 이력에서 꺼낸다.
4. 상위 README·스킬·코드 주석을 갱신하고 옛 경로 참조가 0건인지 확인한다.
5. 이 문서에 고정 진행률을 적지 않는다.
