# 화면 캡처로 UI 점검하기

## 확장을 쓰지 마라

로컬 개발 화면을 볼 때 `mcp__claude-in-chrome__*` 확장 도구를 쓰지 않는다. **유저가 쓰는 크롬에 얹혀 들어가는 방식**이라 이런 일이 벌어진다.

- 유저가 자기 창인 줄 알고 닫으면 작업이 끊긴다. 반대로 내가 연 탭이 유저 화면을 차지한다.
- 창이 최소화되거나 뒤에 가리면 **그리기가 멈춰** 캡처가 이전 장면을 돌려준다. 스크롤 명령도 먹지 않는다. 이 상태를 모르고 옛 화면을 보며 판단하면 엉뚱한 결론이 나온다.
- 뷰포트 크기를 마음대로 못 정한다. 확장 패널이 자리를 차지해 창을 넓혀도 페이지는 좁은 채로 뜬다.

확장은 **로그인이 걸린 남의 사이트**를 다룰 때만 쓴다. 내 컴퓨터에서 도는 개발 화면에는 아래 방식을 쓴다.

## 쓰는 법

```bash
# 개발 서버가 떠 있어야 한다 (pnpm dev:web 등)
node .claude/skills/ui-shot/shoot.mjs <url> <mobile|desktop|tablet> <출력폴더> [--full]
```

```bash
# 예: 인물 상세를 휴대폰 크기로, 구획마다 한 장씩
node .claude/skills/ui-shot/shoot.mjs "http://localhost:3000/ko/celeb/bill-gates" mobile .tmp/shots

# 같은 화면을 넓은 화면으로
node .claude/skills/ui-shot/shoot.mjs "http://localhost:3000/ko/celeb/bill-gates" desktop .tmp/shots
```

찍고 나면 표준출력으로 페이지 높이·구획 목록·저장한 파일 경로가 JSON으로 돌아온다. 그 경로를 Read 도구로 하나씩 열어 눈으로 본다.

**출력 폴더는 저장소 밖(스크래치패드)에 둔다.** 저장소 안에 둘 거면 찍고 확인한 뒤 지운다.

## 규격

| 이름 | 크기 | 쓰는 곳 |
|------|------|---------|
| `mobile` | 390×844, 2배 밀도, 터치 | 휴대폰. 이 서비스의 주 사용 환경 |
| `tablet` | 834×1112 | 중간 폭에서 배치가 깨지는지 |
| `desktop` | 1440×900 | 넓은 화면 |

구획(`section[id]`)마다 한 장씩 찍고, 구획이 화면보다 길면 화면 높이만큼 잘라 여러 장으로 낸다. `--full`을 붙이면 구획 단위 대신 페이지 전체를 한 장으로 뽑는다(세로로 아주 길어지므로 배치 흐름을 볼 때만).

## 함정

- **지연 로드**: 스크립트가 페이지를 한 번 훑어 내린 뒤 위로 돌아온다. 이걸 빼면 아래쪽 사진이 빈 채로 찍힌다.
- **`networkidle2` 대기**: 지구본·차트처럼 그리기가 늦는 요소는 그 뒤로도 시간이 걸린다. 비어 보이면 스크립트의 마지막 대기 시간을 늘린다.
- **스크롤바**: `--hide-scrollbars`로 숨긴다. 안 숨기면 좌우 여백이 어긋나 보여 없는 문제를 만들어낸다.
- **`section[id]`가 없는 페이지**: 구획을 못 찾으면 화면 높이 단위로 처음부터 끝까지 자른다.
- 개발 서버가 안 떠 있으면 그냥 실패한다. 먼저 `curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/`로 확인한다.

## 눈으로 볼 때 무엇을 보나

수치로 재는 것(글자 크기·여백·넘침)은 별도로 훑을 수 있다. **캡처는 수치로 안 잡히는 것을 보려고 찍는다.**

- 사진·표지가 잘려 알아볼 수 없게 됐는지
- 같은 줄에 놓인 조각들의 생김새가 제각각인지(어떤 건 테두리 상자, 어떤 건 맨 글자)
- 빈 자리가 어색하게 남는지, 한쪽으로 쏠렸는지
- 한글에 영문용 자간이 걸려 글자가 흩어져 보이는지
- 기호만 있고 뜻을 알 수 없는 조작 단추
- 값이 없어 허공에 뜬 구분 기호(예: 생몰 표기의 줄표)
