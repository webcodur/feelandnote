# 한국어 AI 문체 편집 기준

## 목표

목표는 AI 탐지기를 속이는 것이 아니다. 사실을 보존하면서 사람이 쓴 글처럼 읽히게 하고, 작성자의 구체적인 경험과 판단을 남기는 것이다.

## 자주 보이는 AI식 흔적

- 중요성·의미·역사적 의의를 근거 없이 부풀린다.
- `새로운 지평`, `깊은 의미`, `중요한 역할`처럼 정보가 없는 평가를 반복한다.
- `전문가들은`, `많은 사람들이`, `업계에서는`처럼 주체 없는 출처를 쓴다.
- `살펴보자`, `알아보자`, `이 글에서는`으로 도입을 길게 끈다.
- `첫째·둘째·셋째`와 세 항목 나열을 습관처럼 쓴다.
- `결론적으로`, `종합하면`, `앞으로가 기대된다`로 자동 결말을 붙인다.
- 같은 문단 안에서 `~을 통해`, `~함으로써`, `~에 있어`, `~라고 할 수 있다`를 겹친다.
- 문장마다 작은 결론이나 펀치라인을 만들어 문단의 호흡을 깨뜨린다.

## Humanizer에서 가져온 33개 점검 항목

아래 목록은 [blader/humanizer](https://github.com/blader/humanizer)의 영어권 패턴 분류를 한국어 편집용 질문으로 바꾼 것이다. 영어 단어 목록을 한국어에 기계적으로 금지하지 않는다. 문장의 기능과 근거를 먼저 본다.

### 내용·주장

1. 중요성 부풀리기: `전환점`, `새 시대`라고 쓰면서 실제 사건을 제시하지 않는가?
2. 유명 매체 이름 나열: 출처가 필요한 만큼만 남겼는가?
3. `상징한다·반영한다·보여준다`식 분석: 원문 근거가 있는가?
4. 홍보성 표현: 멋진 형용사가 사실을 대신하지 않는가?
5. 모호한 출처: `전문가들은` 대신 실제 주체가 있는가?
6. 공식적인 도전 서사: `어려움에도 계속 성장했다`가 구체적 사실을 가리는가?

### 언어·문장

7. 모델 단골 어휘: 영어의 `testament`, `landscape`, `showcasing`에 해당하는 번역투가 반복되는가?
8. 쉬운 서술을 복잡하게 우회: `이다·있다`로 쓸 수 있는 문장을 `역할을 한다·특징을 보인다`로 늘이지 않았는가?
9. 부정 대조 공식: `단순히 A가 아니라 B`를 습관처럼 쓰지 않는가?
10. 세 항목 공식: 자연스럽지 않은데 억지로 셋을 맞추지 않는가?
11. 동의어 돌려쓰기: 같은 사람·사물을 필요 이상으로 다른 이름으로 부르지 않는가?
12. 거짓 범위: `A부터 Z까지`처럼 실제로 다루지 않은 범위를 암시하지 않는가?
13. 행위자 없는 수동태: 누가 했는지 숨기는 문장이 아닌가?

### 서식·리듬

14. 대시 남용: 쉼표·마침표로 충분한 곳에 긴 대시를 반복하지 않는가?
15. 굵은 글씨 남용: 강조가 정보를 대신하지 않는가?
16. 인라인 제목 반복: `성능: 성능이 좋아졌다`처럼 목록과 문장이 겹치지 않는가?
17. 제목식 대문자·명사열: 한국어에서도 제목과 본문이 모두 표어처럼 되지 않는가?
18. 이모지 장식: 정보가 아닌 분위기 장식이 문서를 점령하지 않는가?
19. 인용부호·문장부호를 일관되게 쓰는가?
20. 하이픈식 복합어·번역어를 필요 이상으로 만들지 않는가?
21. 권위 호소 공식: `핵심은`, `무엇보다 중요한 것은` 뒤에 실제 주장이 있는가?
22. 안내문형 도입: `지금부터 알아보자`를 지우고 내용부터 시작할 수 있는가?
23. 쪼개진 표어형 소제목: 제목과 짧은 문장이 같은 말을 반복하지 않는가?
24. 변경 내역 중심 서술: 결과물보다 `무엇을 추가했다`는 편집 과정을 앞세우지 않는가?
25. 제조된 펀치라인: 짧은 문장을 연속해 긴장감을 억지로 만들지 않는가?
26. 격언 공식: `X는 Y의 언어다`처럼 근거 없는 문구를 만들지 않는가?
27. 가짜 대화 도입: `솔직히 말하면`, `좋은 질문이다`가 본문을 대신하지 않는가?

### 대화·완충어

28. 챗봇 마무리: `도움이 되었길 바랍니다`, `더 필요하면 알려 달라`를 자동으로 붙이지 않는가?
29. 지식 부족 면피: `자료가 제한적이지만`으로 끝내지 말고 출처를 찾거나 주장을 줄였는가?
30. 아첨: 사용자를 무조건 칭찬하거나 동의하지 않는가?
31. 불필요한 완충어: `~하기 위해서`, `~라는 사실 때문에`를 짧게 쓸 수 있는가?
32. 헤지 중첩: `아마도·어쩌면·가능할 수 있다`를 한 문장에 겹치지 않는가?
33. 일반 결론: `앞으로가 밝다` 대신 확인 가능한 계획·결과를 썼는가?

## 고치는 방법

- 추상 명사보다 사람·조직·사물을 주어로 둔다.
- 평가를 실제 행동, 발언, 날짜, 결과로 바꾼다.
- 한 문장에 기능을 너무 많이 넣지 말고 문장을 나눈다.
- 정확한 명사는 억지로 바꾸지 말고 필요하면 반복한다.
- 도입 예고를 줄이고 첫 문장부터 정보를 준다.
- 자동 결말 대신 마지막에 남겨야 할 구체적인 사실을 둔다.
- 문장마다 강한 표현을 넣지 말고 문단 전체가 한 가지 일을 하게 한다.

## 보존 목록

- 고유명사, 숫자, 날짜, 인용, 링크, 법령 조항
- 이상하지만 실제로 있었던 구체적인 디테일
- 작성자의 1인칭 판단, 망설임, 복합적인 감정
- 분야에 필요한 전문 용어
- 이미 자연스럽고 힘이 있는 문장

## 편집 판정

| 판정 | 기준 | 처리 |
|---|---|---|
| `유지` | 자연스럽고 구체적이며 제 역할을 함 | 손대지 않음 |
| `부분 수정` | 한두 표현만 번역투·추상어임 | 해당 표현만 교체 |
| `재작성` | 추상 평가와 평론투가 사실을 가림 | 사실의 뼈대를 유지해 다시 씀 |
| `삭제 검토` | 그럴듯하지만 정보가 없음 | 삭제하거나 구체적 근거로 대체 |
| `사실 확인` | 문장은 자연스럽지만 주장 근거가 불명확함 | 발행 전 독립 검증 |

## 최소 수정 원칙

좋은 문장을 전부 모델식 문체로 평탄화하지 않는다. 단어 하나가 어색하면 구조를 보존한 채 그 단어만 고친다. 중요한 내용의 무게를 낮추는 것과 과장을 걷어내는 것은 다르다.
