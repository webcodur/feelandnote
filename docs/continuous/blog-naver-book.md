# 네이버 블로그

블로그 [`blog.naver.com/dmx777`](https://blog.naver.com/dmx777)는 책과 인물에 관심 있는 독자가 필앤노트의 기록을 보고 책의 구매·광고 링크까지 도달하게 하는 입구다. 사이트 링크를 넣는 데서 끝내지 않고, 글에서 소개한 책과 인물의 기록이 실제 광고 링크까지 이어지는지 확인한다. 독자가 원문으로 들어올 수 있도록 블로그·카페 링크 공유와 외부 공유를 허용하며, 본문 전체를 복제하는 공유는 허용하지 않는다.

현재 사이트는 인물 페이지 `/celeb/{slug}`의 서재(`#library`)에서 실제 감상 기록과 책별 구매 단추를 보여 준다. 작품 상세 `/content/{contentId}?category=book`에서도 구매 링크로 이어진다. 2026-10-23 재편 시안의 네 권에서 작품 상세를 열고 서점 선택창을 직접 눌러 YES24 상품 주소와 쿠팡 구매 경로가 표시되는 것을 확인했다. 서점 링크는 선택창을 연 뒤에 나타나므로 첫 화면의 링크 목록만으로 구매 경로의 부재를 판정하지 않는다. 글마다 소개할 책의 작품 상세가 열리고 YES24 단추와 인물의 감상이 실려 있는지 확인한다. 인물 하단 「관련 상품」에는 독서 기록 외의 연관 상품도 섞일 수 있어, 그 목록 전체를 그 인물이 읽은 책으로 소개하지 않는다. 구매 버튼 규칙은 [ContentPurchaseAction.tsx](../../sw/web/src/components/features/commerce/ContentPurchaseAction.tsx)가 쥔다.

## 왜 운영하는가

- 사이트 유입의 9할이 네이버 검색이다. 한국에서 "OO 추천 책"을 치는 사람은 네이버에 있고, 네이버는 외부 사이트보다 자기 블로그 글을 위에 올린다.
- 2020년부터 쌓인 글 217건과 방문 32만이 있는 계정이다. 새 채널을 키우는 비용 없이 쓸 수 있다.
- 블로그 글이 사이트 링크를 늘리고 네이버 유입이 실사용 신호를 만든다. 구글 회복에도 보탬이 된다.

## 현재 도달점

인물 안내글의 주인공 사진은 서비스의 대표사진(portrait_url), 기관 안내글의 감상자 얼굴은 서비스 아바타(avatar_url)를 쓴다. 감상자 표시 폭은 apply-institution-revisions.mjs의 AVATAR_WIDTH가 정한다. [`sync-person-photos.mjs`](../../sw/web-bo/scripts/naver-blog/sync-person-photos.mjs)의 `--apply --watch`가 인물·기관 안내글의 공개·예약 글을 순회한 뒤 역할별 서비스 이미지의 변경을 감시한다. 기존 파일명과 검수된 인물 매핑으로 현재 사진 자리를 다시 식별하며, 저장 전후에 본문·책 표지·사진 배치·대표 지정·발행 설정·예약 시각을 대조한다. 식별 불명은 저장하지 않고 보류하며, 저장 후 검증 실패는 자동 처리를 중단한다. 사진 변경 감시는 사용자 요청으로 중지했고 Windows 예약 작업 `Feelandnote-NaverPortraitSync`도 비활성화했다. 현재 실행 위치는 예약 작업의 `--work` 인자가 가리키며 실행 상태·검증 자료는 OS 임시 작업 폴더에 둔다. 과거 교체 자산과 매핑은 `D:/blog-assets/naver-blog/{portrait-images,local-images,reframe-images}/`에 있다.

**기관 51편과 신규 인물 안내글 59편의 본문 개편은 끝났고, 그 뒤로 신규 인물 27편을 같은 양식으로 예약했다(2026-10-04 기준).** 먼저 완료한 기관 18편과 이후 기관 33편·신규 인물 59편을 합친 수다. 책 소개·인물 사진과 이름·DB 원문 감상·서비스 링크를 적용했고 기관편에는 전체 목록 표를 넣었다. 사용자 요청에 따라 사진 교체 첫 순회 뒤 인물·기관 글의 구성을 다시 정비한다.

**59명은 전체 인물 수나 인물 작업의 종료 수가 아니다.** 2026-10-04 `pnpm naver:roster` 대조에서는 기존 인물 144편(142명)과 신규 86편(86명), 합계 230편(228명)이 잡혔다. 기존 인물 글은 링크 정비를 한 대상이며 이번 59편의 본문 개편에 포함되지 않는다. 미작성 인물의 추가 선정·작성도 남아 있다. 아래 후보 집계와 「다음 할 일」에서 이어간다.

- **전체 목록 한국어 교정:** 북클럽 221804018469의 100행에 이어 다른 35편(공개 9·예약 26)의 1,906행을 고쳤다. 35편 모두 저장 후 다시 열어 표와 표 밖 본문·링크·사진·대표이미지를 대조했고 예약 날짜·시간도 유지됐다. 저장 원고·목록 파일 71개를 교정본과 동기화했다. 원문을 유지한 미확인 항목은 아래 「다음 할 일」에 남겼다.
- **기관 로고:** 현대문학상·이상문학상을 포함한 누락 7편을 채웠다. 가디언 2편(221804070055, 221804048431)과 서울대(221802539119)는 기존 블로그 로고를 한 장씩 복구하고 대표사진으로 지정했다. 기존 기관 글 16편의 로고를 확인했으며 원본 이미지 65개는 D:/blog-assets/naver-blog/_backup/original-blog-images/에 보존했다. 로고의 1:1 정리는 별도 작업으로 남았다.

- **`--target` 인자는 Git Bash에서 깨진다.** `--target=/celeb/…`가 MSYS 경로 변환에 걸려 대상이 잡히지 않는다. PowerShell에서 실행하거나 `MSYS_NO_PATHCONV=1`을 붙이거나, 초안 순서를 믿고 건수만 지정한다.

저장 원고와 대상 기록은 D:/blog-assets/naver-blog/의 drafts.json, celeb-drafts.json, posts.json이 쥔다. 기관별 원고는 revisions/와 remaining-institution-revisions/, 인물별 원고는 celeb-revisions/에 있다. 인하대 최종 원고는 remaining-institution-revisions/corrected/이며 저장 완료 표시는 원고의 revisionSha256으로 대조한다.

한국어 교정의 글별 결과는 table-ko/results.json, 예약 최종 대조는 table-ko/reservation-check.json에 있다. table-ko/targets.json은 **이번에 반영한 표의 전후 데이터**이지 미실행 큐가 아니다. 미확인 표기를 더 조사할 때는 이 파일의 rows와 service.json·reviewed-labels.json을 참고하고 현재 원고를 기준으로 수정분만 준비한다. table-ko의 before/, before-live/, before-local/은 교정 전 원본으로 보존한다.

완료된 개편의 실행용 합본·미리보기·빈 진단 파일과 일회성 한국어 표 준비기는 폐기했다. 개별 최종 원고와 재사용하는 편집·검증 함수는 보존했다. 이전 복구 폴더의 continue.txt도 이 문서를 가리키도록 바꿨다.

`pnpm naver:roster`를 2026-10-04에 도서 기준으로 다시 실행했다. 기존 글·신규 86편을 제외한 **신규 인물 후보는 375명**, 같은 책에 감상 기록이 둘 이상 연결된 **책 중심 후보는 1,162권**이다. 이는 원고 재료 후보 수이며 출처 검수나 구매 링크 확인을 마친 편수는 아니다. 후보와 기존 글 번호는 `D:/blog-assets/naver-blog/_roster.md`에서 확인한다. 선정 조건은 `sw/web-bo/scripts/naver-blog/lib/roster-data.mjs`가 쥔다.

글 번호·대상·처리 상태는 `D:\blog-assets\naver-blog/posts.json`이 쥔다. 사이트 URL이 바뀌거나 인물이 비공개되면 이 표로 고칠 글을 찾는다. 비공개로 닫은 글은 사이트에 대응 페이지가 생기면 링크를 넣고 다시 연다.

## 글 유형

글의 출발점은 인물, 기관의 선정 목록, 책 한 권이다.

1. **인물 안내글.** 한 사람의 책과 감상 기록을 소개한다. 기존 인물 글 재작성과 신규 인물 글에 같은 구성을 쓴다. 인물 소개·책 소개·DB 감상 원문에서 사이트의 독서 기록과 구매·광고 링크로 이어진다.
2. **기관 선정 안내글.** 선정 목록 전체와 대표 책의 감상 기록을 소개한다. 현재 51편이 있으며 인물 안내글과 함께 본문을 재편한다.
3. **책 안내글.** 책 한 권에서 시작해 그 책을 실제로 읽은 인물들의 감상을 모은다. [티스토리의 작품 편 구성](blog-tistory-cinema.md#글의-짜임)을 참고한다. 책의 한국어 제목·저자·표지·간단한 소개 → 인물별 사진·한 줄 소개·DB 감상 원문 → 등장 인물과 전체 감상 기록으로 이어지는 순서다. 책과 연결된 구매·광고 링크까지 독자가 따라갈 수 있도록 한다.

원고는 DB의 한 줄 정의·책 목록·감상 배경에서 뽑는다. 사람은 발행 전 훑어보기만 한다. 기계 문체는 저품질 필터에 걸리므로 「한국인이 한국어로 쓴 글 답게 주의해서 작성」을 기준으로 쓴다.

## 사이트와 블로그의 통합 원칙

같은 목록·같은 인물이 한쪽에만 있으면 다른 쪽에 채운다. 방향은 둘이다.

- **블로그에만 있는 목록 → 사이트.** 블로그의 대학 권장도서·언론 선정 목록은 `sw/web-bo/scripts/curated/.tmp/lists/<slug>.json`으로 옮겨 기관 선정에 적재한다. 규격은 [`service-03-curated-lists.md`](../project/service/service-03-curated-lists.md)를 따르고, 원문 발표처 `source_url`을 반드시 찾는다. 블로그는 2차 출처로 기록한다. 살아 있는 페이지의 특정 시점 전사본은 사이트에 담지 않는다. 발표된 판만 목록으로 세운다. 블로그 글을 살리려고 목록을 만들지 않는다. 발표 주체가 없는 묶음(분야별 책추천 시리즈)은 제3자 채널 출전이라 옮기지 않고 블로그에서도 손대지 않는다.
- **사이트에만 있는 목록·인물 → 블로그.** 아래 양식의 안내글 한 편을 낸다. 사이트가 원본이고 블로그 글은 입구다.

## 안내글 양식

기관 선정 목록과 인물 모두 같은 뼈대를 쓴다. 소개와 안내는 간결하게 쓴다. 읽는 사람이 이 목록이 무엇이고 왜 볼 가치가 있는지, 사이트에 가면 무엇을 더 볼 수 있는지 알아야 넘어온다. 서비스 노출 문구이므로 **정중체(~합니다)** 로 쓴다.

```
제목: [{기관 영문 태그}] {목록명} {수} | {headline}
      {수식어} {인물}이 읽은 {권수}권의 책

📚 전체 목록을 작품별로 보기 → https://feelandnote.com/library/curated/{기관}/{목록}
(빈 줄)
소개 3~4문장. 누가, 언제, 어떤 방식으로 선정했는지 / 이 목록이 왜 참고할 가치가 있는지(권위·역사·특징) / 어떤 독자에게 맞는지.
(빈 줄)
대표 작품의 책 제목·표지·책 소개와 인물 표시·DB 감상 배경 원문을 배치한다.
(빈 줄)
기관편은 서비스의 전체 선정 목록을 표로 표시한다. 연도 또는 순위·작품명·작가를 목록 성격에 맞춰 보여준다.
(빈 줄)
안내 2~3문장. 필앤노트에서 {N}권 전체를 표지와 함께 볼 수 있고, 각 작품을 읽은 인물과 그 인물의 다른 독서 목록으로 이어진다는 것 / 목록마다 국내 번역 여부를 함께 표시한다는 것.
→ 같은 링크
태그: {기관명} {목록명} 책추천 필독서 권장도서 (인물 글은 {인물명} {직군} 추천도서)
```

### headline — 제목의 파이프 뒤 절반

검색 결과에서 제목의 앞 절반은 무슨 목록인지만 말한다. 누를지 말지는 headline이 정한다. 기관 선정 글에만 붙이고 인물 글에는 붙이지 않는다.

- **그 목록에만 해당하는 사실 하나를 적는다.** 고려대 학부대학 100권은 역자·출판사·출간연도까지 지정하는 유일한 목록이라 `어느 번역본으로 읽을지까지 알아보세요`가 됐다. 어느 목록에 붙여도 말이 되는 문장은 headline이 아니다.
- 15~30자, 정중체로 끝낸다.
- **동사로 끝낸다.** `~받습니다`·`~올랐습니다`·`~빠졌습니다`·`~못 합니다`처럼 무언가가 일어나는 문장이어야 한다. **`~목록입니다`·`~상입니다`·`~순위입니다`·`~수상작입니다`처럼 명사로 끝내면 제목 왼쪽 절반을 다시 말하는 꼴이 된다.** 「베니스 영화제 황금사자상 89편 | 1932년에 시작한 가장 오래된 영화제의 수상작입니다」가 그렇게 폐기됐다 — 왼쪽에 이미 있는 말을 오른쪽에서 되풀이했다. 36편 중 20편이 이 함정에 빠졌다.
- 목록의 흐름을 요약하려 들지 마라. `글쓰기에서 시작해 대학을 묻는 책까지 살펴보세요`는 읽어도 무슨 목록인지 모른다는 이유로 폐기됐다.
- 광고 어휘(`인생을 바꾸는`·`필독`·`놓치면 안 될`)와 사물이 주어인 번역투를 쓰지 않는다.
- **같은 기관의 글끼리 headline이 겹치지 않게 한다.** 네 편이 비슷한 말로 끝나면 저품질 판정을 부른다.
- **혼자 읽어도 뜻이 통해야 한다.** 본문을 읽은 사람만 아는 문장은 실패다. 주어를 빼먹지 마라 — `상금은 10유로지만 그해 가장 많이 팔립니다`는 무엇이 팔리는지가 없어 폐기됐다(`선정된 책은`을 넣어야 말이 된다). `문을 열면 이름이 나오는 유령의 집을 건넵니다`도 트로피라는 말이 없어 폐기됐다.
- **agy에 후보 5~10개를 받아 그중에서 고른다. 받아 놓고 손으로 고쳐 쓰지 마라.** 고쳐 쓰면 뜻이 안 통하는 문장이 다시 나온다 — 위의 두 사례가 전부 후보를 받아 놓고 내가 다듬은 것이다. 프롬프트에는 목록의 성격, 기관의 성격, 본문이 말하는 사실, 위 규칙과 좋은 예·나쁜 예(실제로 폐기한 문장 그대로)를 넣는다. 호출법은 [`agy-antigravity`](../../.claude/skills/agy-antigravity/SKILL.md) 스킬이 쥔다.

- 본문의 책 제목·수평선은 중앙 정렬한다. 책 소개·감상 본문은 왼쪽 정렬한다.
- 링크는 서비스 목록 주소를 첫 줄과 마지막 줄에 두 번 넣는다. 첫 줄은 접힌 미리보기용, 마지막 줄은 읽고 난 사람용이다. 개별 출처 문구·외부 출처 링크는 나열하지 않고 근거는 서비스 감상 기록에 둔다.
- 대표 작품은 사이트에 연결된(표지가 있는) 작품 중에서 고르고 한국어 출간명으로 쓴다. 미연결 작품을 앞세우면 도착 페이지에서 흐리게 보인다.
- 전체 목록의 작품명·저자명도 한국어 표기를 우선한다. 원제와 연결된 한국어판의 작품 범위를 대조하며, 3부작·전집·단편집을 개별 작품으로 바꾸지 않는다. 한국어 표기를 확인하지 못한 작품은 원제를 유지한다.
- 인물 사진은 서비스 대표사진(`celebs.portrait_url`)을 사용한다. 아바타로 대신하지 않는다. 서비스 대표사진은 본문에 넣을 원본이고, 네이버 대표이미지는 글의 썸네일 지정이므로 별도로 확인한다. 인물 안내글에서는 상단 인물 사진을 네이버 대표이미지로 지정하고 저장 후 다시 열어 유지되는지 대조한다. 액자 5번은 책 표지에만 적용하며 기관 로고와 인물 사진에는 적용하지 않는다.
- **감상 배경은 현재 `celeb_contents.review` 원문을 그대로 쓴다.** 장문도 그대로 싣는다. 요약·발췌·각색·LLM 정제, 라벨 앞에 붙이는 별도 요약을 하지 않는다. DB 감상이 없는 항목은 새로 쓰지 않는다.
- 표지 선택·판본 대조 과정 같은 작업용 설명은 본문에 넣지 않는다. 책 소개와 실제 학교 목록의 안내는 구분한다.
- **책마다 소개를 두세 문장 세운다.** 순서는 `책 제목 → 표지 → 책 소개 → 감상한 인물의 사진·이름·직군 → 구분된 DB 감상 배경 원문`이다. 기관편은 감상마다 인물을 표시하고, 인물편은 글 상단에서 화자를 소개한다. 티스토리의 업로드 준비본 인물편·기관편을 참고하며, 감상을 소개 뒤에 일반 단락으로 붙이지 않는다. 인물 사진과 이름은 함께 중앙 정렬하고 감상은 왼쪽 정렬한다.
  - 책 소개는 DB에 없으므로 **agy가 짓는다.** 줄거리의 엄밀함보다 「무슨 책인지 전달되는가」가 기준이다. 확실하지 않으면 좁게 단정하지 말고 넓게 쓴다.
  - **출간 연도·수상 이력·판매량·「명작이다」 같은 평가는 넣지 않는다.** 지어내기가 시작되는 자리다. 결말도 적지 않는다.
  - 소개가 감상 배경과 겹치면 소개를 조정하고 DB 감상 원문은 유지한다.
- 소개와 안내는 사실 문장으로만 쓴다. 기관 설명은 사이트 `description`을 그대로 옮기지 않는다. 번역투·단골 문예 어휘·설교형 마무리는 금지다.
- 기존 글에 넣는 첫 줄 링크 문구(`📚 {인물}의 독서 목록 전체 보기 →`)는 명사형 그대로 둔다. 문장이 아니라 표지다.
- 초안은 `D:\blog-assets\naver-blog/drafts.json`에 쌓고, 발행하면 `posts.json`으로 옮긴다.

## 원고 생산 — 조립이 먼저, LLM은 빈칸만

**LLM에게 글 전체를 쓰게 하지 마라.** 26.09.03에 인물 8편과 기관 36편을 Claude 서브에이전트로 썼다가 176만 토큰을 태웠다. 그 원고의 대부분은 이미 DB에 있는 값이었고, 에이전트는 그걸 다시 쓰느라 토큰을 쓰면서 원문에서 멀어지기까지 했다.

### 무엇이 이미 있나

| 원고 요소 | 출처 | LLM이 필요한가 |
|---|---|---|
| 책 5권 고르기 | `celeb_contents` + `content_locales` | **아니다.** 아래 규칙으로 스크립트가 고른다 |
| 책별 감상 본문 | `celeb_contents.review` | **아니다.** 현재 DB 원문을 그대로 배치한다 |
| 책 제목·저자·표지 | `content_locales` (ko) | 아니다 |
| 제목·태그·링크·구분선·이미지 표시 | 양식이 고정 | 아니다 |
| 인물 정리 3~4문장 | `celebs.bio` + 선정한 책의 `review` | **압축만** 시킨다. 새로 조사시키지 마라 |
| 제목 수식어 | `celebs.headline` | 줄이는 것뿐 |
| 도입 한 줄·마무리 | — | 그렇다. 감상 배경은 생성하지 않는다 |

### 책 5권을 고르는 규칙 (스크립트)

1. `contents.type = BOOK`
2. 한국어 `content_locales` 에 표지가 있다 — 없으면 도착 페이지가 흐리게 보인다
3. `review` 가 80자 이상 — 그 아래는 인물 발언이 아니라 목록에 올렸다는 사실뿐이다
4. 인용부호가 든 것을 앞세운다 — 본인 발언이 실려 있다는 신호다
5. 다섯을 못 채우면 그 인물은 아직 쓰지 않는다

26.09.03 실측: 인물 8명 중 7명이 이 조건으로 5권을 채웠다. 타란티노만 4권이었고, 이는 사람이 직접 조사한 결과와 일치했다.

### LLM이 채우는 빈칸

한 인물당 아래 JSON 하나만 받는다. 300~400자다. 원고 전체를 쓰게 하면 1,500자이므로 **4분의 1 이하**로 준다.

```json
{ "suffix": "수식어", "profile": "인물 정리", "blurbs": ["책 소개 ×5"], "outro": "마무리" }
```

도입(「오늘 만나볼 인물은 X입니다.」)과 안내(「X이 읽은 책들을 살펴볼까요?」)는 고정 문구라 빈칸이 아니다. 외부 CLI를 쓰지 않을 때는 이 JSON을 slug 키로 담은 파일을 `pnpm naver:compose --slug <slug> --fills <파일>`에 넘긴다. 조립 결과는 기존 59편의 최종 양식(`[avatar:]` 인물 사진·「이름 · 직군」·정중체 정리·`[q]` 감상 원문·`━━━━━━` 구분선)과 같고, 고른 다섯 권은 초안의 `books`에 남는다. 한국어 판본이 특정 장정·묶음 상품이라 소개에 맞지 않는 책은 빈칸 파일의 `exclude`(content_id)와 `excludeReason`으로 빼고 다음 순번으로 채운다.

- 프롬프트에 넣는 재료는 `headline`·`bio`와 고른 책 다섯의 `review` 뿐이다. DB 덤프를 통째로 주지 마라.
- 여러 인물을 한 번에 묶어 부른다. 출력이 작아 배치가 잘 먹는다.
- 조립은 스크립트가 한다. LLM이 `[img:]`·`━━━`·링크를 쓰게 하면 형식 사고가 난다.

### 누구를 쓸지도 LLM이 고른다

후보 명단(`pnpm naver:roster`)은 감상 수로만 줄을 세우므로 위쪽이 국내 인지도 없는 인물로 채워진다. 이름만 배치로 넘겨 **국내 독자가 아는 인물인지**를 판정받는다. 사실 확인이 아니라 선정이므로 LLM의 판단에 맡겨도 되는 영역이다. 한 번에 100명씩 묶고 출력은 판정과 한 마디 이유만 받는다.

### 어느 LLM을 쓰나

**agy(제미니)를 기본으로 쓴다.** 로그인 기반이라 종량 과금이 없다. codex는 종량 한도가 있어 소진되면 며칠을 기다린다(26.09.03 실측: 5일). agy도 개인 쿼터가 있어 두세 시간마다 막히지만 계정을 바꾸거나 기다리면 회복된다. 두 경로 다 **재실행 안전**하게 만들어 받은 답은 건너뛰게 한다.

## 주기와 순서

- 새 글은 **오늘부터 가까운 빈 날짜에 오전 09:00으로 예약한다.** 마지막 예약일 뒤에 이어 붙이지 않고 요일도 고정하지 않는다. 실제 예약 목록과 글 대장을 확인해 어느 시각이든 글이 예약된 날짜는 건너뛰며 하루 한 편씩 배정한다. 자동 실행은 두지 않는다. 발행 직전에 사람이 한 번 훑는 것이 이 채널의 품질 장치다.
- **먼저 잡힌 예약 위에 새 글을 얹지 않는다.** 요일만 보고 빈 날짜라고 판단하지 않는다. `posts.json`의 `scheduledAt`을 실제 예약 목록과 대조하고, 기존 글을 수정할 때는 원래 예약 시각을 보존한다.

  ```bash
  pnpm naver:publish N --time=09:00   # 실제 예약과 대조해 가까운 빈 날짜부터
  ```
- 기관 선정 큐는 `drafts.json`의 순서대로 나간다. 순서 기준은 국내 검색 수요다: 국내 문학상 → 대중이 아는 상·매체 목록(퓰리처·아카데미·칸·NYT·타임·BBC) → 장르상(SF·추리·공포·로맨스) → 좁은 목록(세인트존스·왕립학회·케임브리지 철학·심리학자 117인). 몰아 쓰지 않는다.
- 인물 안내글은 「다음 할 일」대로 `pnpm naver:roster`가 만든 실행 순서를 따른다. 후보 선정 조건은 `roster-data.mjs`, 기존 글·작성한 인물·다음 후보는 `D:\blog-assets\naver-blog/_roster.md`가 쥔다.
- **인물 감상이 붙은 작품이 3편 미만인 목록은 발행하지 않는다.** 이 채널이 다른 블로그와 갈리는 지점이 "그 책을 읽은 인물"인데, 그게 없으면 쓸 말이 수상 연도와 줄거리뿐이라 흔한 목록 소개 글이 된다. 도착 페이지도 비어 있다. 커버리지는 `npx tsx scripts/curated/celeb-coverage.ts [slug...]`로 재고, 기준 미달 초안은 `drafts.json`에서 `status: hold`와 사유를 적어 큐에서 뺀다. 인물 감상을 먼저 채운 뒤 `draft`로 되돌린다.
- 대응 페이지가 없는 글은 방치하지 않는다. 사이트에 넣을 자격이 있으면 적재한 뒤 링크를 넣어 다시 열고, 자격이 없으면 삭제한다. 닫아만 두는 상태를 남기지 않는다.

## 측정

- GA에서 `blog.naver.com` 리퍼러 세션과 그 세션의 인물 페이지 도달률만 본다. 블로그 조회수는 보지 않는다. 조회수가 높고 유입이 없으면 글이 너무 친절한 것이다.
- 월 1회 확인한다. 3개월 뒤 리퍼러 세션이 월 수백을 넘지 않으면 주 1편으로 줄이고, 넘으면 묶음글 비중을 올린다.

## 하지 않는 것

- 쿠팡·광고 삽입. 상업 블로그 판정과 사이트 이탈 둘 다 손해다.
- 사이트에 없는 정보를 블로그에만 쓰는 것. 두 곳 관리가 시작된다.
- 완료한 링크 삽입·신규 59편·기관 51편 정비를 반복하지 않는다. 기존 인물 144편의 본문 재작성은 아래 새 목표로 진행한다.

## 편집 자동화

### 올라간 글을 고치는 기법

59편을 한 양식으로 맞추면서 쓴 수단이다. **고칠 것이 작으면 수단도 작아야 한다.** 26.09.04에 액자 하나
두르려고 58편을 `--rewrite` 로 돌렸다. 하루 종일 다듬은 본문을 통째로 다시 쓰는 짓이었고 사용자가 멈춰
세워 첫 편에서 끊었다. 아래는 좁은 것부터다.

| 고칠 것 | 쓰는 것 | 어떻게 |
|---|---|---|
| 전체 목록의 작품명·저자명 | `lib/korean-table-editor.mjs` | 기존 표와 일치하는지 확인한 뒤 표만 교체하고, 저장 후 새로 열어 표 밖 본문·사진·대표이미지·링크와 함께 대조한다 |
| 사진에 액자 | `--frame-only` | 첫 사진 → 사진 편집 → 액자 → 「모든 사진」. 본문은 읽어 대조하고 수정하지 않는다 |
| 감상 문구 | `sync-reviews.mjs` | 단락 수를 바꾸지 않고 그 자리 글자만 갈아 끼운다 |
| 소개 끼워 넣기 | `apply-blurbs.mjs` | 감상 단락 하나를 「소개 + 감상」 둘로 가른다 |
| 자리가 뒤바뀜 | `fix-blurb-order.mjs` | 초안과 대조해 어긋난 자리만 맞바꾼다 |
| 본문이 망가짐 | `--rewrite` | 통째로 갈아 끼운다. **마지막 수단이다** |

- **한 벌 먼저 손으로 만든다.** 59편에 적용할 양식은 `한강-완성본.txt` 한 편을 손으로 완성해 사용자가
  고친 뒤 그것을 규격으로 삼았다. 규격 없이 일괄 처리부터 돌리면 59편이 같은 방식으로 틀린다.
- **검증은 「있는가」가 아니라 「순서까지 같은가」로 한다.** 소개·라벨·감상이 있는지만 보던 검사는
  다른 책의 감상이 끼어들고 라벨이 두 번 나온 글을 통과시켰다. `verify-body.mjs` 는 초안의 텍스트 줄을
  순서대로 늘어놓고 편집기 단락과 한 줄씩 맞춘다. 초안에 없는 줄·빠진 줄·초과 등장을 함께 본다.
- **일괄 처리 뒤에는 표본을 눈으로 연다.** 스크립트가 「OK」를 찍고 지나간 사고가 두 번 있었다. 단락 수와
  이미지 크기 같은 숫자로 먼저 거르고, 그다음 실제 화면을 캡처해 본다. 숫자만으로는 액자가 두 겹인 것을
  잡지 못한다.
- **위험한 편집에는 스스로 멈추는 조건을 건다.** `--frame-only`는 액자 적용 전후와 저장 후 재열기에서
  제목·본문 전체 텍스트·사진 수·구분선·발행 설정·예약 시각을 대조한다. 하나라도 달라지면 첫 오류에서 중단하고 완료 표시를 남기지 않는다. 예약 목록 진입과 본문·설정 읽기는 `repair-search.mjs`와 `lib/existing-editor.mjs`를 공유한다.
- **편집기가 lazy 로 그리는 것은 크기로 판단한다.** 편집 화면의 이미지 대부분은 `data:image/svg+xml`
  자리표다. 파일명으로 액자 적용 여부를 가르려 하면 판별이 안 된다. 자리표도 실제 크기는 반영하므로
  적용 전후의 가로·세로 크기를 대조한다. 화면 캡처는 해당 사진으로 스크롤한 뒤 실제 이미지 로딩이 끝나야 찍는다.

초안 파일은 `NB_DRAFTS` 환경변수로 바꿀 수 있다. 인물 안내글은 `D:\blog-assets\naver-blog/celeb-drafts.json` 에 따로 쌓는다.

크롬은 아래로 띄운다. 로그인 유지를 켜지 않으면 창을 닫을 때 세션이 사라진다.

```
chrome.exe --remote-debugging-port=9222 --user-data-dir=C:\project\_chrome-naver --disable-features=CalculateNativeWinOcclusion --disable-backgrounding-occluded-windows --disable-renderer-backgrounding
```

새 글 카테고리는 블로그의 실제 카테고리에 맞춘다. 인물 글은 「거물의 책추천」 아래 직군(기업가·투자자·정치인·학자·배우·작가·아티스트·스포츠인·인플루엔서), 기관 글은 「기관 선정」 아래 서비스 `curators.kind`에 해당하는 하위 분류를 쓴다. 분류 명칭은 `sw/web/messages/ko/library.json`의 `library.curated.kind`를 따른다. 상 이름이나 기관의 인상으로 유형을 다시 판단하지 않는다. 기존 기관 글 분류는 `migrate-institution-categories.mjs --ids=글번호,글번호 --service=실서비스기관조회JSON --apply`로 맞추며, 본문·사진 크기·다른 발행 설정·예약 시각을 저장 전후로 대조한다. 기본값이 「공지사항」이라 지정을 빠뜨리면 공지로 나간다. `publish-drafts.mjs`는 신규·예약·본문 재작성·액자 적용 모두 저장 직전에 `lib/publish-options.mjs`로 검색·공개·공유 설정을 검사한다. 설정이 비활성이거나 확인되지 않으면 저장하지 않는다. 수정 뒤에도 검색·공유 설정을 다시 확인한다. 본문·사진만 대조하는 검사는 검색 차단을 잡지 못한다.

편집기 조작에서 확인된 제약이다. 한 번 잡힌 함정이라 반복하지 않는다.

- **브라우저 작업 전 로그인 상태를 먼저 확인한다.** `postwrite`를 열어 `nid.naver.com` 로그인 화면으로 넘어가면 세션이 끊긴 것이다. 끊겼을 때 바로 사람에게 넘기지 않는다 — 디버그 크롬과 Aside 프로필 각각의 저장된 계정·자동 입력으로 직접 로그인할 수 있는지 먼저 본다. 둘 다 안 되면 그때 사용자에게 열린 창의 로그인을 부탁한다. 세 경로(디버그 크롬·Aside u1·u0)가 동시에 만료될 수 있다(26.10.14 실측).
- Home·End·좌우 화살표 키가 먹지 않는다. 캐럿은 첫 글자 실제 좌표의 왼쪽 바깥을 클릭해 놓고, 캐럿 앞 글자 수가 0인지 DOM으로 확인한다. 이모지 span은 클릭해도 포커스가 잡히지 않으니 건너뛴다.
- DOM으로 선택 범위를 옮기면 편집기 내부 모델과 어긋나 원문을 덮어쓴다. 편집기가 스스로 처리하는 입력만 쓴다.
- 편집기에서 선택한 문단이 화면에 보여도 DOM `getSelection()`은 빈 문자열을 반환할 수 있다. 부분 수정은 실제 Ctrl+C로 복사된 문자열이 대상 문단과 같은지 확인한 뒤 입력한다.
- 기관 본문 개편의 전체 목록은 `apply-institution-revisions.mjs`의 CF_HTML 표 삽입을 쓴다. 한국어 표기는 `korean-list-labels.mjs`에서 고르며 `prepare-remaining-institutions.mjs`도 이 함수를 사용한다. 한글은 HTML 문자 참조로 전달한다. 표 뒤에 편집기가 만든 빈 문단이 있으면 그곳을 클릭하고, 없을 때만 「본문 추가」를 쓴다. 인용 구획 뒤에도 같은 순서로 본문으로 나온다.
- 단락 시작에서 Enter는 위에 빈 단락을 만든다. URL 뒤 Enter는 자동 링크 확정에 먹히거나 링크 카드를 만들어 텍스트 블록을 가른다. 단락 수가 늘지 않으면 한 번 더 치고, 검증은 첫 블록이 아니라 본문 전체 단락으로 한다.
- **본문 사진 교체와 대표이미지(목록 썸네일)는 별개다.** 본문 첫 사진을 갈아 끼웠다고 목록 썸네일이 바뀌지 않는다. 대표 배지(`se-set-rep-image-button.se-is-selected`)가 그 자리에 남는지와, 저장 후 공개 페이지의 `og:image`(blogthumb)가 새 파일을 가리키는지를 둘 다 본다. 예약글은 공개 페이지가 없어 og 확인이 불가하니 편집기의 대표 배지만으로 검증한다.
- **편집기 본문은 가상화돼 있다.** 스크롤 컨테이너는 창이 아니라 `.se-content.__se-scroll-target`이고, 긴 글에서는 img 노드가 화면 밖으로 나가면 언마운트된다. DOM 스냅샷이 실행마다 다르면 공개 본문 HTML(`PostView.naver`)을 파싱해 사진 순서·단락·og를 전후로 대조하는 경로(`publicVerified` 대상)를 쓴다. 인물 사진 자리는 편집기 인덱스가 아니라 공개 본문 이미지 순서로 다시 잰다 — 원장의 인덱스가 실제와 어긋난 글이 있었다.
- **네이버에서 원본이 삭제된 사진은 `data:image/svg` 자리표로 남는다.** 저장해도 공개 본문의 원본 주소는 그대로 유지되므로, 그 자리의 표현 차이를 변경으로 보지 말고 자리 보존으로 대조한다. 인물 사진 자리 자체가 깨진 경우도 교체로 그 글이 복구된다.
- **기존 파일명은 믿지 말고 신호를 모은다.** 과거 업로드는 `reframe-<slug>-`·`retry-<slug>-`·`{닉네임}-`·`kim-0.jpg` 같은 범용명까지 섞여 있다. slug·닉네임 포함(공백·언더스코어 정규화)에 정사각 원본(아바타 시그니처)까지 신호로 묶고, 전부 약하면 위치를 공개 본문에서 재확인한다.
- **비표준 공유 설정 글을 표준으로 바꾸지 않는다.** 오래된 글 중 「본문 공유 허용」·「외부 공유 비허용」으로 저장된 글이 있다. 설정이 표준과 달라도 사진만 교체하고 설정은 저장 전후 동일성으로 보존하며, 사유를 `optionsWarning`으로 기록한다. 표준화가 필요하면 별도 작업으로 사용자와 상의한다.
- 대량 교체는 한 편씩 저장→재열기 대조를 하고 첫 오류에서 멈춘다. 완료 기록(`results.jsonl`의 `saved-and-reopened`)만 재실행에서 건너뛰므로 중단 후 재개가 안전하다. 사진 원본 백업(`original-<logNo>-<idx>`)과 전후 스냅샷·캡처는 run 폴더에 남긴다.
- **「인물 이름이 붙은 사진 = 아바타」로 잡지 않는다.** 본문에 같은 인물의 서로 다른 실사진이 여러 자리에 있는 글이 있다(사용자가 보너스로 넣은 사진). 파일명 매칭으로 전부 교체하면 같은 사진으로 평탄화된다 — 10월 1차 교체 때 그렇게 됐고, 복구는 사용자가 포기하고 「중복 사진은 두 번째 자리부터 삭제」로 정리했다. 다중 인물 사진 글은 육안 또는 자리별 구분 없이 일괄 교체하면 안 된다.
- **같은 사진 반복 정리는 `--dedupe` 모드다.** 인물 사진 자리를 인덱스가 아니라 현재 src 파일명 마커(`portrait-<slug>-`·`local-<slug>-`)로 찾고, 첫 자리만 새 이미지로 두고 나머지 반복 자리를 삭제한다. 삭제할 때마다 스트립 셀 id가 리플로우되므로 매 삭제 전 DOM을 다시 읽는다. 대표 배지가 삭제될 자리에 있으면 생존 자리로 먼저 옮긴다. 사용자가 손으로 고쳐 사진 수·마커가 어긋난 글은 `state-mismatch`/`no-marker`로 안전 건너뛴다.
- **발행글의 DOM 스냅샷 수가 기대와 다르면 공개 본문으로 판정한다.** 가상화가 심한 글은 img가 수 개만 마운트돼 `state-mismatch`로 빠지지만, 실제로는 중복이 남아 있을 수 있다. dedupe는 발행글이면 `publicPost()`의 본문 이미지 목록으로 계획을 세우고 저장 후에도 공개 본문으로 대조한다. `og:image` 썸네일 URL은 저장마다 재생성되니 파일명으로 비교한다. 이전 건너뜀을 다시 돌릴 때는 `--retry`를 쓴다.
- **사진 삭제 버튼은 두 종류다.** 단독 사진은 `se-delete-toolbar-button`, 스트립 셀은 사진 위 오버레이의 `se-image-delete-button`(「사진 삭제」). 스트립의 모든 셀을 지우면 빈 껍데기가 남아 통째로 삭제 패스가 필요하다.
- **지연 로딩 img의 실제 주소는 `data-lazy-src`에 있다.** `img.src`는 플레이스홀더일 수 있어 파일명 마커 매칭이 빗나간다 — `data-lazy-src || src` 순으로 읽는다.
- 로컬 폴더 사진으로 교체할 때는 업로드 파일명을 `local-<slug>-<hash>`로 ASCII화한다 — 네이버가 업로드 URL에 원본 파일명을 남기므로 마커로 검증할 수 있다. 한글 파일명은 인코딩돼 `src.includes(marker)` 비교가 실패한다.
- 공개 설정만 바꾸는 작업(비공개·재공개)은 글마다 편집기를 열지 않는다. 블로그 관리 → 글 관리 화면에서 체크박스로 골라 한 번에 바꾼다. 편집기 경로는 링크 삽입처럼 본문을 고칠 때만 쓴다.
- **제목 앞에 글자를 넣을 때는 첫 글자의 실제 좌표 왼쪽 바깥을 누른다.** `Home`·`Ctrl+Home` 이 먹지 않아 캐럿이 그대로 끝에 남는다. `Range` 로 첫 글자의 사각형을 구해 `left - 2` 를 클릭하고, **캐럿 앞 글자 수가 0인지** 확인한 뒤에 친다(`rename-reserved.mjs`·`link-existing.mjs`).
- **제목 일부만 지우려 들지 않는다.** 오프셋을 세어 `Delete` 를 누르면 위치가 어긋나 「[OSCAR]」가 「[」로 잘리는 일이 난다(26.09.05). 고칠 것이 있으면 제목 블록을 통째로 다시 친다 — 24자씩 끊어 치고 결과를 대조한다.
- **제목을 읽을 때 `.se-documentTitle` 전체를 읽지 않는다.** 「위치이동제목」 같은 편집기 UI 글자가 섞여 들어와 대조가 늘 실패한다. `.se-documentTitle .se-text-paragraph` 만 모아 읽는다.
- **긴 글을 한 번에 치면 글자가 빠진다.** 제목과 본문 모두 30~60자씩 나눠 치고, 친 뒤 결과를 읽어 원문과 다르면 그 줄을 지우고 다시 친다. 2,000자짜리 글에서 문장 한 토막이 통째로 사라진 적이 있다.
- 확인창 처리는 예외를 삼켜야 한다. 이미 닫힌 창을 다시 닫으려다 프로세스가 죽는다. 편집기 이탈 경고는 수락해 통과시킨다.
- 삽입 뒤 "링크 줄 / 빈 줄 / 원래 단락"이 정확히 일치할 때만 발행한다. 어긋나면 발행하지 않고 실패로 기록한다. 새 글은 한 건이라도 실패하면 멈추고 사람이 본다.
- **예약글 삭제는 예약 목록에서 한다.** `delete-posts.mjs`가 `/dmx777/postwrite` → 「예약 발행」 목록에서 대상 제목을 찾고, 해당 `li`에 마우스를 올려 나타난 `button#post_delete_button`을 누른다. 예약글 1편 삭제 확인창을 수락한 뒤 목록을 다시 불러와 대상만 사라지고 나머지 제목·날짜가 그대로인지 대조한다. 검증 뒤에만 `posts.json`을 `deleted`로 바꾼다. `PostView.naver`에 보이지 않는다는 이유만으로 삭제됐다고 판단하지 않는다.
- **발행 여부는 `drafts.json` 의 `status` 가 아니라 `posts.json` 을 봐야 안다.** `status: check` 인 초안이 이미 예약되어 `posts.json` 에 행을 갖고 있는 일이 있다. 한쪽만 보고 「아직 안 나갔다」고 판단하면 같은 소재를 다른 채널에 또 올리게 된다.
- **예약글은 글쓰기 화면의 「예약 발행」 목록에서 불러온다.** `/dmx777/postwrite` → 상단 「예약 발행」 → 대상 제목을 선택하면 실제 본문과 공개·검색·예약 날짜 설정이 함께 로드된다. `PostUpdateForm.naver?logNo=…`로 예약글을 직접 열면 공개범위가 미선택이고 검색허용이 비활성이며 발행 시간이 「현재」 하나만 나온다. 이 화면에서 저장하지 않는다. 예약 목록에서 불러온 뒤에는 제목·본문·예약 시각을 확인하고, 수정 후 같은 목록에서 다시 열어 설정이 유지됐는지 검증한다.
- **이미 올라간 글의 단락을 고칠 때는 「앞선 시도를 정리하는」 코드를 첫 시도에 돌리지 마라.** 26.09.04에 소개를 끼워 넣으면서 재시도용 정리 코드가 첫 시도에도 돌아 `idx+1`(그때는 아직 원래 감상이던 자리)을 지웠다. **7편에서 감상 17곳이 통째로 날아갔고**, 소개와 라벨만 남은 글이 나갔다. 정리는 `attempt > 0` 에서만 한다.
- **편집한 글은 반드시 되읽어 대조한다.** 위 사고는 스크립트가 "OK"를 찍으며 지나갔다 — 새로 쓴 두 줄만 확인하고 그 아래가 사라진 것은 보지 않았기 때문이다. 초안의 소개·라벨·감상이 **전부 살아 있는지** 글 단위로 확인한다(`verify-blurbs.mjs`).
- **액자 5번은 책 표지에만 적용한다.** 「낡은 액자」로, 거친 검은 테두리와 흰 여백이 생긴다. 기관 로고·인물 사진이 함께 있는 글은 책 표지를 개별 선택한다. 책 표지만 있는 글에서 「모든 사진」을 쓸 때는 사진 편집 → 액자 도구 → 액자 선택 → 「모든 사진」 순서다. 액자 패널은 열 때마다 0번(액자 없음)에서 시작하므로, 먼저 액자를 골라야 「모든 사진」이 활성화된다.
- **액자 버튼은 위치가 안정된 뒤 좌표로 누른다.** 사진 선택 뒤 편집 툴바가 나타났는지 확인하고, 스크롤·패널 애니메이션 뒤 좌표를 연속 측정한다. `elementFromPoint`로 클릭 지점에 대상이 있는지도 확인한다. 패널이 열리지 않거나 닫히지 않으면 다음 단계로 넘어가지 않고 중단한다. 완료는 사진 편집기의 `button.npe_btn_submit`을 누른다. 사진 편집기가 닫힌 뒤에도 처리가 이어질 수 있어 `--frame-only`는 모든 사진이 예상 크기로 바뀔 때까지 기다리고, 저장 후 재열기에서도 같은 크기를 확인한다. 사진 편집기의 「다시 보지 않기」(`.npe_alert_btn_hide`)는 발행 설정 비교에서 제외한다.
- **기관 로고 교체는 본문 전체를 다시 쓰지 않는다.** `repair-institution-images.mjs --replace-map=JSON`으로 실측한 글 번호·기관·사진 컴포넌트·원본 URL·자연크기를 지정해 사진 교체 버튼을 사용한다. 신규 PNG/JPEG는 원본 바이트를 보존하고, 다른 단일·묶음 사진과 본문·발행 설정·예약 시각은 저장 전후로 대조한다.
- **기관 로고는 글마다 한 장을 두고 대표사진으로 지정한다.** 기존 글에 정상 로고가 있으면 기존 대표 로고 원본을 우선 보존한다. 서비스 로고가 있다는 이유로 바꾸지 않으며, 검수는 사진 유무뿐 아니라 기존 원본과의 일치도 확인한다. 기존 블로그 이미지 보관 위치는 `D:/blog-assets/naver-blog/_backup/original-blog-images/`다.
- **액자는 누를 때마다 겹쳐 쌓인다.** 같은 글에 두 번 두르면 테두리가 두 겹, 세 번이면 세 겹이 된다. 원래 크기 800px 사진이 840 → 880 → 920으로 커지는 것이 신호다. 초안의 `framed` 표시로 이미 두른 글을 가른다. 이미 겹친 글은 `--rewrite`로 이미지를 원본부터 다시 올려야 풀린다.
- Chrome 플러그인에서는 글마다 새 작성 탭에서 예약 목록을 연다. 불러온 예약 글에서 다른 예약 글로 바로 이동하면 이탈 확인창이 걸릴 수 있다. 저장 후 검증도 새 탭에서 하고 끝난 작업 탭은 닫는다. 대표사진은 선택 표시가 로드된 뒤 실제 선택된 사진 요소로 대조한다.

YES24 상품 또는 검색 링크는 사진 설명란의 굵은 중앙정렬 링크로 표지 바로 아래에 붙인다. 설명란은 네이버가 배경색을 제거하므로 배경색을 전제하지 않는다. 감상 배경·책 소개의 제목과 첫 본문 사이에는 빈 문단을 넣지 않고 구획 사이 여백만 둔다. 목차의 하단 한마디 항목은 「인용구」로 표시한다. 마지막 서비스 설명문도 중앙정렬한다. 대표사진 개편이 완료된 현재 서비스 주소를 대조해 사용하고, 각 글을 쓸 때 원본 파일을 새로 내려받아 업로드한다. 미리보기 HTML에는 내려받은 이미지를 내장해 외부 표지 서버에 다시 의존하지 않으며, 공개 PC·모바일 검증은 흐린 지연로딩 자리표를 제외한 모든 이미지의 실제 로딩까지 확인한다. 책 소개는 설명문 앞부분을 잘라 쓰지 않고 AGM–AGY로 원자료를 새로 요약한 4~5문장을 별도 검수한다. 같은 책은 작품·저자·ISBN·원자료가 일치할 때만 요약을 재사용한다. 마무리는 링크 한 줄로 축약하지 않고 필앤노트의 용도를 설명한 문장과 브랜드·인물명·이동 목적이 담긴 링크를 함께 둔다. [`prepare-unified-articles.mjs`](../../sw/web-bo/scripts/naver-blog/prepare-unified-articles.mjs)가 서비스 재료를 모으고 [`prepare-book-summaries.mjs`](../../sw/web-bo/scripts/naver-blog/prepare-book-summaries.mjs)가 AGM–AGY 요약·검수를 맡는다. [`assemble-unified-articles.mjs`](../../sw/web-bo/scripts/naver-blog/assemble-unified-articles.mjs)가 검수 통과 요약만 넣어 HTML과 입력 원고를 조립하고 [`apply-unified-article.mjs`](../../sw/web-bo/scripts/naver-blog/apply-unified-article.mjs)가 전체 본문 입력·저장·재열기를 맡는다. 조립·입력·검증 반복 중에는 모델 호출을 하지 않는다. 신규 문장이나 선정 판단이 필요하면 쓰기 시작 전 별도 준비 단계에서 해결하며, 기존 검수 선정이 없는 대량 도서 인물은 기계가 임의로 책을 고르지 않는다. 입력 부족·실패는 완료로 세지 않고, 이전 editorial 표시만으로 새 양식 완료로 취급하지 않는다. 검수 통과 원고의 순차 반영은 [`run-unified-articles.mjs`](../../sw/web-bo/scripts/naver-blog/run-unified-articles.mjs)가 맡고, 작업 폴더의 writer-state.json과 글별 native-verified.json으로 실제 저장·재열기 및 공개 PC·모바일 검증을 대조한다. 표지 형식과 가로형 전집의 표시 크기는 편집 전에 검사한다. 저장 전 개별 글의 표·사진 검증 오류는 writer-state.json의 deferred에 원고 해시·실패 자료와 함께 보류하고 다른 준비된 글을 진행한다. 보류는 완료로 세지 않으며 같은 원고를 반복 재시도하지 않는다. 저장 후 검증 실패와 세션 오류는 전체 중단한다. 저장된 글의 검증만 재개할 때는 [`verify-unified-saved.mjs`](../../sw/web-bo/scripts/naver-blog/verify-unified-saved.mjs)를 사용한다. 네이버 작업은 한 편씩 백그라운드에서 실행하고 원래 글 번호·예약 시각·발행 설정을 보존한다.

글별 유입과 필앤노트 방문·구매 링크 도달은 작업 비중을 판단할 때 참고하며 신규 인물의 산출 순서는 유지한다. 구매 링크 도달과 실제 구매는 구별하고, 측정되지 않은 전환을 성과로 보고하지 않는다.

조사·원고 조립·한국어 메타·출처·중복·링크 대조는 로컬에서 묶어서 준비하고, 네이버 편집은 한 번에 한 글만 저장·되읽기·종료까지 처리한다. 완료 표시를 확인한 글은 다시 실행하지 않는다. 연결이나 이탈 경고가 막히면 같은 탭을 계속 열지 않고 해당 상태를 처리한다. 발행 전 작업 탭이나 이탈 경고가 남아 있으면 먼저 처리한다. 시간 추정은 정상 종료까지 검증한 첫 글의 실제 소요시간을 보고 잡는다.

빌 게이츠 기존 원고 `D:/blog-assets/naver-blog/legacy-celeb-revisions/221829484745.json`과 같은 이름의 Markdown·HTML에는 대표 책 3권과 연도별 목록 49권이 들어 있다. 이는 통합 결정 전의 미반영 견본이며, 위에서 정한 기존 인물 양식에 맞춰 다시 정리할 대상이다. 『이번엔 다르다』·『그리드』의 국내 출간명 확인 자료는 재사용한다. 본문 원본·이미지 URL·공개 설정은 `before/`, DB 재료는 `data/bill-gates.json`에 보관했다. 로그인한 편집 화면을 열었으나 본문 교체·저장은 하지 않았다. 별도 『대변동』 글 `221812441722`와 합치지 않는다. 대표 책 3권의 사이트 상세 화면에서 쿠팡 구매 버튼을 확인했으며, 『여섯 번째 대멸종』은 연결된 한국어판 상품명·저자까지 확인했다.

기존 인물 글의 URL이 비어 있을 때 slug로 대조하고, 기존 초안이 없는 글도 명시된 대상·초안 메타가 일치하면 검증하도록 적용 코드를 보완했다. 완료 원고 재실행 차단은 유지한다. 관련 테스트 78개와 실제 빌 게이츠 원고·posts.json의 대상 및 본문 검증을 통과했다. 기존 글 첫 편의 실제 편집·저장·재열기 검증과 구성 확인은 남아 있다.

빌 게이츠 기존 본문 사진 37장은 `legacy-celeb-revisions/before/221829484745-images/`에 저장하고 각 파일 해시를 대조했다. URL·해시·크기는 같은 상위 폴더의 `221829484745-images.json`이 쥔다. 이후 인물 이미지 교체에서 저장·재열기 검증과 작업 탭 종료를 확인했다. 위의 본문 개편 견본은 아직 미반영이다.

책 재료는 `sw/web-bo`에서 `node scripts/naver-blog/book-material.mjs --id <content_id>`로 추출한다. 기존 파일은 보존하며 `--refresh`에만 갱신한다. 첫 『사피엔스』의 재료 29명과 세 인물(마크 저커버그·크리스틴 스튜어트·알리 압달)을 배치한 JSON·HTML 견본은 `D:/blog-assets/naver-blog/book-drafts/15dbc203-1e2f-4715-997f-24d17cb4c47e.*`에 있다. DB 감상 원문 일치를 확인했고 미발행 상태다. 스튜어트의 영상 발언 대조, 네이버 편집 화면 검수와 책 상세 구매 동선 확인은 남았다. 로컬 HTML 열기는 브라우저 URL 정책이 차단해 실화면 검수를 완료하지 못했다.

같은 이름의 Markdown으로 원고를 읽을 수 있다. `sw/web-bo/scripts/naver-blog/lib/book-draft.mjs`의 `parseBookDraft`는 책 표지와 인물별 사진·소개·DB 감상·링크를 대조하고 기존 편집기가 쓰는 삽입 단위로 변환한다. 실제 『사피엔스』 견본과 오류 회귀 테스트 25개를 통과했다. 브라우저에 삽입하고 되읽는 단계는 아직 연결하지 않았다.
