# 문서·전자책·출판 파이프라인

## 안정적인 순서

1. HTML·Markdown·DOCX·PDF 원문을 확보한다.
2. 본문 구조와 코드 블록을 보존한 중간 Markdown을 만든다.
3. 문서 유형에 맞는 편집 규칙을 적용한다.
4. 표지·도표·이미지를 넣는다.
5. PDF를 렌더링한다.
6. 실제 페이지를 눈으로 검수한다.

HTML이 깔끔해도 PDF로 변환하면 여백·표·코드·이미지 배치가 무너질 수 있다. “생성 완료”와 “출판 가능한 결과”를 구분한다.

## 참고 도구

- [KLIC-BOOK](https://github.com/klic-co-kr/KLIC-BOOK): 한국어 전자책 제작 스킬과 책 보관소
- [korean-writing-reviewer](https://github.com/CreatoonForge/korean-writing-reviewer): 한국어 교정·문체·구조 검토
- [firecrawl/anydoc](https://github.com/firecrawl/anydoc): 문서 형식을 Markdown으로 변환한다는 도구. 기능·라이선스 확인 필요
- [magicrew/doc7](https://github.com/magicrew/doc7): 문서 시각 구조를 읽어 Markdown으로 변환한다는 도구. 검증 필요
- [DoHyun468/claw-hwp](https://github.com/DoHyun468/claw-hwp): 한글 문서 처리 관련 링크. 검증 필요

저작권 안내가 붙은 원문은 출처·허가·상업 이용 조건을 확인하기 전까지 출판 자료로 사용하지 않는다.
