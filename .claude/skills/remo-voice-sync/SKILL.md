# Voice Sync — 음성 파이프라인 4단계 실행

음성 파일 변경 후 voiceTimings 동기화와 자막(sub) 의미 단위 분할을 수행한다.

## 필수 사전 읽기

실행 전 반드시 아래 문서를 Read tool로 읽는다:

- `docs/project/remotion/book-recommend/voice/tts.md` — 4단계 규칙, sub 분할 규칙, 안티패턴

## 작업 흐름

사용자가 다음 중 하나로 호출한다:

- `/voice-sync <에피소드명>` — 신규 sub 생성 (기존 sub 없는 세그먼트만)
- `시맨틱컷 <에피소드명>` — 기존 sub 전량 삭제 후 **재분할** (= force 모드)

### Step 1: 대상 판별 및 에피소드 JSON 로드

에피소드 파일 위치:
- 콘텐츠: `sw/remotion/public/episodes/{stage}/{person}/{locale}.json`
- 타이밍: `sw/remotion/public/episodes/{stage}/{person}/{locale}.timing.json` (voiceTimings 포함)

**sub 작업 가능 여부 판별 (3단계 완료 확인):**

| 조건 | 판정 | 조치 |
|------|------|------|
| `voiceTimings` 필드 없음 | **작업 불가** | "1~3단계 미완. 음성 파이프라인 먼저 실행 필요" 안내 |
| `voiceTimings` 있으나 `start/end` 비어있음 | **작업 불가** | "3단계(analyze) 미완" 안내 |
| `voiceTimings`에 `start/end/text` 모두 있음 | **작업 가능** | 진행 |

여러 에피소드 요청 시, 각각 판별하여 불가한 건은 건너뛰고 사유를 보고한다.

`voiceTimings` 객체의 모든 세그먼트를 순회한다.

### Step 2: 기존 sub 처리

**시맨틱컷(force 모드)일 때:**
1. 대상 에피소드의 voiceTimings 전 세그먼트에서 `sub` 필드를 **먼저 전량 삭제**한다
2. 삭제 후, `text` 필드(원문)만을 기준으로 새로 분할한다
3. 기존 sub는 절대 참조하지 않는다 — 기존 분할이 오염원이다

**/voice-sync(일반 모드)일 때:**
- sub가 이미 있는 세그먼트 → **건너뜀** (기존 sub 존중)
- sub가 없는 세그먼트만 → **분할 대상**

**공통:**
- 텍스트가 짧아(하나의 의미 덩어리) 분할 불필요 → sub 없이 둔다

### Step 3: 의미 단위 분할

**tts.md 4단계 규칙을 엄격히 따른다.** 핵심:

#### ⛔ 절대 금지

- 글자 수 기반 중간점 분할 (텍스트를 N등분하여 가까운 공백에서 자르기)
- 고유명사 파괴 (`"맨해튼" / "프로젝트"`, `"원자" / "폭탄 만들기"`)
- 지시사+체언 분리 (`"이" / "책을"`, `"그" / "점에"`)
- 보조용언 분리 (`"할 수" / "없는"`, `"읽은" / "적이"`)
- 관형절+피수식어 분리 (`"위험한 순간을 역사에서" / "먼저 찾습니다"`)

#### ✅ 분할 기준 (우선순위)

1. **절 경계**: 연결어미(`~고`, `~며`, `~지만`, `~면`, `~서`) **뒤**에서 끊기
2. **주어/목적어 뒤**: `~은/는/이/가`, `~을/를` 뒤. 단 서술어까지 10자 이내면 합침
3. **수식절+피수식어 묶기**: 관형절 + 피수식 명사는 반드시 한 덩어리

#### 자기 검증 체크리스트

분할 후 각 청크에 대해 확인:

- [ ] `sub.join(' ') === text` (불변식)
- [ ] 고유명사(인명, 책제목, 지명)가 한 청크 안에 있는가?
- [ ] `수 없는`, `수 있는`, `적이 있다` 등 보조용언이 찢어지지 않았는가?
- [ ] `이 책`, `그 점`, `이 구절` 등 지시사+체언이 한 청크인가?
- [ ] 각 청크가 홀로 읽었을 때 의미가 통하는가?

### Step 4: JSON 기록

`<locale>.timing.json`의 `voiceTimings[segId][idx].sub` 배열에 직접 기록하고 저장한다.

### Step 5: 검증

```bash
pnpm sub:check -- --episode <name>
```

깨진 sub 0건, 누락 sub 0건 확인.
