# Devin CLI로 SWE-2에 위임

Cognition의 Devin CLI다. 계정에 딸린 모델 중 **SWE-2 묶음만 무료**다. 나머지(Claude·GPT·Gemini, SWE-1.7 Lightning)는 토큰당 과금이다. 이 스킬은 무료 라인으로 큰 일을 통째로 넘기는 법을 쥔다. 공통 원리는 [`docs/resource/cli-agent-invocation.md`](../../../docs/resource/cli-agent-invocation.md)에 있다.

## 핵심 호출법

```bash
devin -p --model swe-2-max --permission-mode dangerous \
  --respect-workspace-trust false --prompt-file PROMPT.md [--export CONVERSATION.md]
```

- **모델은 무료 변형명까지 적는다.** `swe-2-max`·`swe-2-high`·`swe-2-medium`이 `Free`다. 별칭 `swe`도 지금은 SWE-2를 가리키지만 이름이 비슷한 SWE-1.7 Lightning은 유료($2.5/1M 입력)다. 별칭 해석이 바뀌어도 과금되지 않게 변형명을 쓴다. 단가는 `devin models list`에 나온다.
- **권한 모드는 `dangerous`뿐이다.** 값은 `auto`·`accept-edits`·`smart`·`dangerous`이고 `bypass`는 없다. `--sandbox`는 macOS·Linux 전용이라 Windows 무인 실행은 모든 도구가 자동 허용된다. 그래서 작업 폴더 격리와 지시서의 금지 조항이 유일한 울타리다.
- **`--respect-workspace-trust false`를 늘 붙인다.** `-p`는 신뢰 확인 창을 띄우지 못해 처음 보는 폴더에서 그냥 실패한다.
- **긴 프롬프트는 `--prompt-file`로 넣는다.** 인라인이면 `-p -- "프롬프트"`처럼 `--` 뒤에 둔다.
- **`--export 파일`**을 주면 대화 기록이 턴마다 파일로 떨어진다. 긴 작업을 지켜보는 창구다.

호출 헬퍼 `scripts/devin-call.mjs`의 `devinCall(prompt, { cwd, model, timeoutMs, exportPath })`가 실행 파일 해석·격리 cwd·무료 모델·UTF-8 수신·시간 제한을 한곳에 가둔다. 새 스크립트는 이것을 쓴다. 실측(26.09.12): 번들 경로를 스스로 찾아 부르고, 작업 폴더를 cwd로 준 호출이 547초 만에 결과 파일과 한국어 답을 깨짐 없이 돌려줬다.

```js
import { devinCall } from 'file:///C:/project/feelandnote/.agents/skills/devin-swe/scripts/devin-call.mjs'
const reply = await devinCall('BRIEF.md를 읽고 그대로 수행한다. …', { cwd: 작업폴더, timeoutMs: 60 * 60_000, exportPath: `${작업폴더}/logs/conversation.md` })
```

## 실행 파일은 PATH에 없을 수 있다

Devin Desktop만 깔린 PC(winget `CognitionAI.DevinDesktop`)에는 `devin` 명령이 없다. PATH에 들어가는 `devin-desktop`은 앱 런처이고 CLI가 아니다. CLI는 앱 안에 번들로 들어 있다.

```
%LOCALAPPDATA%\Programs\Devin\resources\app\extensions\windsurf\devin\bin\devin.exe
```

헬퍼는 `where devin`이 비면 이 경로를 쓴다. 번들 CLI는 `.exe`라 `.cmd` 래퍼 함정(ENOENT)이 없다.

## 사람이 한 번 해 줘야 하는 것 — 둘 다 에이전트가 못 넘긴다

두 가지 모두 콘솔 키 입력을 직접 읽는 메뉴라서, 에이전트가 백그라운드로 띄우거나 stdin에 Enter를 흘려 넣어도 넘어가지 않는다(26.09.12 두 번 실측). **보이는 터미널 창을 띄워 주고 사람에게 고르게 한다.**

```powershell
Start-Process powershell.exe -ArgumentList '-NoExit','-Command',"& '<devin.exe 경로>' auth login"
```

1. **로그인** — `devin auth login` → 「1 Log in with browser」 → 브라우저에서 계정 로그인. Desktop에 로그인해 있어도 CLI는 따로다(자격 증명 `%APPDATA%\devin\credentials.toml`).
2. **첫 실행 설정** — 로그인 뒤 첫 호출은 비대화여도 「Git 연결 권장 — 1 GitHub / 2 다른 Git / 3 지금은 건너뛰기」에서 멈춘다. `devin setup`을 같은 방식으로 띄워 「3 Skip for now」를 고르게 한다.

확인은 이 순서로 한다.

- `devin auth status` → `Logged in (via Devin)`
- `devin models list` → 목록이 나온다(로그인 전이면 `Not logged in`)
- 빈 폴더에서 `hi` 한마디 → 실측 13초에 「안녕하세요, 무엇을 도와드릴까요?」

## 함정 — 대부분 조용히 멈춘다

| 증상 | 원인 | 대응 |
|---|---|---|
| `-p`가 오류 없이 몇 분째 무응답(실측 180초 뒤 끊음) | 로그인 전 | `auth status`부터 본다 |
| 로그에 Git 연결 메뉴만 찍히고 결과가 없다 | 첫 실행 설정 미완 | 사람이 `devin setup`에서 건너뛴다 |
| 한국어가 `?덈뀞?섏꽭??`처럼 깨진다 | Windows PowerShell 5.1이 UTF-8 출력을 기본 코드페이지로 읽는다 | 파일로 받아 `Get-Content -Encoding UTF8`로 읽거나 Node에서 `setEncoding('utf8')`로 받는다 |
| 백그라운드 명령이 곧바로 exit 1 | 셸 리다이렉트 대상 폴더가 없다 | 로그 폴더를 먼저 만든다 |
| 몇 시간째 결과 파일도 대화 기록도 없다 | 헬퍼가 stdout을 끝날 때 한 번에 돌려주고, `--export`는 첫 턴이 끝나야 파일을 쓴다. 돌고 있어도 흔적이 없다 | `devinCall`에 `logPath`를 준다. 끊기 전에 그 파일부터 본다 — 멈춘 것과 느린 것이 구별된다 |
| 한 항목에 두 시간 넘게 매달린다 | 후보 목록 같은 큰 입력 파일을 통째로·거듭 읽는다(실측: 3,284줄 catalog에서 2시간 초과) | 지시서에서 통독을 금지하고 검색 스크립트를 함께 준다. 입력은 작업당 필요한 만큼만 넣는다 |
| `exit 1`과 함께 `Reached overall message rate limit. Your limit will reset in N minutes` | 계정 단위 메시지 한도다. 세션 수가 아니라 **주고받은 메시지 총량**에 걸린다(실측: 하루 230세션 + 동시 3 러너에서 8분 한도) | 드물게 조용하지 않은 실패라 로그에 그대로 찍힌다. `retryable: true`지만 **두드릴수록 한도가 늘어난다**(실측: 8분 → 재시도 5초 만에 실패하며 16분 → 17분). **이미 돌고 있던 세션도 진행 중에 같이 죽는다** — 한도에 걸린 동안에는 계정 전체가 막힌다고 봐야 한다. 안내된 시간을 다 기다린 뒤 하나만 띄워 풀렸는지 확인하고, 그다음 동시 실행을 올린다. **대기 시간이 회차마다 줄면 회복 중이라는 신호다**(실측: 28분 → 6분 → 4분 → 2분 → 90초 → 「50초」). **다른 세션이 같은 계정을 쓰면 회복이 더뎌 재시도 여덟 번으로 모자란다** — 헬퍼 기본값을 12회로 뒀고, 그래도 모자라면 같은 명령을 다시 돌린다 |
| 세션이 3~10초 만에 `exit 1`, 로그에 `Reached overall message rate limit … reset in N seconds` | 계정 전체 메시지 속도 제한. 짧은 세션(2~3분짜리 번역 묶음)을 동시 3으로 35건쯤 연달아 보내자 걸렸다(26.09.13). 러너가 실패로 넘기면 남은 묶음이 몇 초 간격으로 전부 실패한다 | 러너가 이 문구를 잡아 `N+30초`(최소 90초) 쉬고 같은 묶음을 다시 맡긴다(최대 8회). **단위가 `seconds`·`minutes`로 바뀐다** — 첫 제한은 「0 seconds」였고 곧바로 「19 minutes」가 왔다. 초만 잡으면 재시도 없이 전부 실패한다. 동시 수는 2로 내린다. 실측: 대기 뒤 그대로 통과했다 |
| 몇 시간짜리 감시를 맡겼는데 45분 만에 `exit 4294967295`(-1)로 끊긴다 | 세션이 긴 대기를 버티지 못한다. `timeoutMs`를 8시간으로 줘도 CLI 쪽이 먼저 죽는다(26.09.12 실측) | 긴 일은 층을 나눈다. 본 작업은 `Start-Process`로 독립 프로세스로 띄워 Devin의 자식이 되지 않게 하고, Devin에게는 기동과 사유 판정만 맡긴다. 실측: 이렇게 띄운 배치는 Devin이 죽은 뒤에도 1시간 45분을 더 돌아 완주했다 |

**러너 생존은 `tasklist //FI "PID eq <pid>"`로 본다.** Git Bash의 `ps -W` 첫 칸으로 PID를 찾으면 Windows 프로세스를 놓쳐 「죽었다」로 오판한다(26.09.13 실측). 오판해서 러너를 다시 띄우면 둘이 같은 큐를 돌아 같은 배치를 두 번 처리한다 — 배치 두 개에 30분을 버렸다. 러너가 진짜 죽었는지는 `Get-CimInstance Win32_Process`로 `run.mjs`가 든 `node.exe`를 세어 확인하고, 하나만 남길 때는 세션과 독립인 쪽을 남기고 다른 쪽의 `devin.exe` 자식까지 `ParentProcessId`로 골라 끊는다.

**끊을 때는 내가 띄운 프로세스만 끊는다.** Desktop이 떠 있으면 `devin.exe`가 스무 개 가까이 돈다(실측 19개). 이름으로 쓸어 죽이지 말고 명령줄에 내 프롬프트 파일명이나 고유 문구가 든 것만 골라 끊는다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='devin.exe'" | Where-Object { $_.CommandLine -match '<내 프롬프트 파일명>' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## 대량 위임 패턴

Devin은 저장소 코드를 고치는 에이전트지만, 여기서는 **조사·집필 작업자**로 쓴다. 결과를 DB에 바로 쓰게 두지 않는다.

1. **작업 폴더를 따로 만든다.** 저장소 밖(세션 scratchpad 등)에 `BRIEF.md`(지시서) · `input/`(DB 스냅숏·후보 목록) · `output/`(결과) · `logs/`를 둔다. cwd를 여기로 주면 저장소의 `AGENTS.md`와 파일을 물려받지 않는다.
2. **지시서에 울타리를 적는다.** 「이 폴더 밖에 쓰지 않는다」, 「DB·저장소를 건드리지 않는다」, 「다른 에이전트나 CLI를 부르지 않는다」. 결과 형식(JSON 스키마), 사실 조사 지시, 글쓰기 원칙, 견본 파일을 넣는다.
3. **항목 하나에 세션 하나.** 수십 개를 한 세션에 몰면 문맥이 넘쳐 뒤로 갈수록 품질이 떨어진다. 러너가 항목마다 `devinCall`을 부르고, 결과 파일이 이미 있는 항목은 건너뛴다(재실행 안전).
4. **완료는 파일로 판정한다.** 결정론적 검사기(현재 명단과 대조·필수 칸·중복)를 통과한 결과만 사람이나 다른 모델이 원전과 대조해 검수한다.
5. **DB 반영은 우리 쪽 스크립트가 한다.** 모의 실행 → 백업 → 한 트랜잭션 반영 → 대조.
6. **검수에서 걸리면 고쳐 주지 말고 되돌려 보낸다.** 옛 산출물을 `output/_rejected/`로 치우고 지적문 한 줄을 프롬프트에 실어 같은 항목을 다시 맡긴다. 실측(26.09.12): 1명짜리 그룹이 생긴 테마 5개를 「그룹마다 2명 이상」 한 줄로 되돌려 보내자 156~322초 만에 다섯 모두 축을 새로 잡거나(소속 → 시대, 메뉴 → 사업 방식) 명단이 얇으면 그룹을 없앴다. 사람이 손으로 고치는 것보다 결과가 낫고, 같은 지적이 지시서에 반영되면 다음 항목부터 재발하지 않는다.
7. **구조 설계도 통째로 맡길 수 있다.** 항목별 정비가 끝난 뒤 그 결과를 입력으로 주면 목록 자체를 다시 그리게 할 수 있다. 실측: 테마 121개의 명단·겹침·빈자리를 입력으로 주고 「지도를 새로 설계하라」고 맡겨 687초 만에 합침 14·없앰 2·신설 5의 재편안을 받았다. 이때 울타리는 「대상을 잃지 않는다」 하나로 족하고, 그것을 검사기가 기계로 확인한다.

실례: 신화 도감 정비(26.09.12) — 신화 33개를 신화당 세션 하나로 돌려 명단 판정·그룹·한 줄 소개·그룹 설명 정비안을 받았다. 절차와 결과는 [`docs/todo/myth-atlas-handoff.md`](../../../docs/todo/myth-atlas-handoff.md)에 있다.

## 층을 나눠 맡긴다

한 세션에 「명단도 짜고 그룹도 나누고 소개도 써라」를 시키면 **뒤 층이 밀린다.** 세력도감 1회차가 그랬다 — 명단은 좋았는데 그룹이 대충 끝난 테마가 여럿이었고, 1명짜리 그룹과 축이 섞인 그룹 이름이 남았다.

층을 나누고 각 패스가 **자기 층만 건드리게** 하면 품질이 올라간다. 실측(세력도감 26.09.12):

| 층 | 바꾸는 것 | 건드리지 않는 것 |
|---|---|---|
| 1. 대상 | 명단·이름·소개 | — |
| 2. 구조 | 목록 자체(합침·나눔·신설·없앰) | 각 항목의 내부 |
| 3. 묶음 | 그룹 축·이름·설명·배정·차례 | 명단, 이름, 소개 |
| 4. 글 | 상세 소개 | 명단, 그룹, 한 줄 소개 |

「하지 않는 일」을 지시서 맨 앞에 적는 것이 핵심이다. 3층 전용 패스를 164개 테마에 돌린 결과 **1명짜리 그룹이 0개**가 됐고, 그중 상당수는 `changed: false`로 그대로 지나갔다.

**순서는 명단 → 구조 → 묶음 → 글이다.** 명단을 바꾸는 일이 뒤에 오면 앞 결과가 무효가 된다. 실제로 편입이 끝난 뒤 그룹 밖 인원이 생겨 해당 테마만 3층을 다시 돌려야 했다.

**다시 돌릴 때는 「손댈 것이 남은 항목」만 고른다.** 그룹 밖 인원이 생긴 테마 77개 중 14개는 앞 회차가 「6명 이하라 그룹을 두지 않는다」고 사유까지 적어 판정한 것이었다. 산출물과 지금 상태를 견줘 **명단이 실제로 자란 곳만** 골라 63개로 줄였다. 앞 회차의 판단을 존중하는 것이 비용을 줄이고 결과도 낫다 — 다시 물으면 모델은 없던 이유를 만들어서라도 답을 바꾼다.

### 층 안에서도 쪼갠다 — 한 항목이 크면

한 항목의 대상이 많으면 층을 나눈 것만으로는 부족하다. 항목마다 웹을 찾아 두 언어로 쓰는 일에서 명단 105명을 한 세션에 맡기면 뒤로 갈수록 글이 얇아진다. 대상을 **25개 안팎의 조각**으로 끊고 조각마다 세션을 준다. 이때 지켜야 할 것이 셋이다.

- **맥락은 조각마다 통째로 다시 준다.** 항목의 이름·소개·그룹은 조각이 달라도 같은 것을 준다. 조각만 주면 「이 무리에서의 자리」를 쓸 수 없다.
- **조각이 일부임을 명시한다.** `part: "2/5"`를 넣고 「이 파일에 있는 대상만 쓴다」고 못 박는다. 없는 대상을 지어내는 것을 막는다.
- **검사기·반영기의 드리프트 검사를 조각에 맞춘다.** 「스냅숏에 없는데 원본에 있다」는 조각에서는 정상이다(다른 조각이다). 조각에서는 **사라진 쪽만** 막는다. 이걸 빼먹으면 모든 조각이 드리프트로 막힌다.
- **손댈 대상이 없는 조각은 아예 보내지 않는다.** 이미 좋은 글을 다시 쓰게 하면 품질이 떨어진다.

## 배치는 서로를 못 본다 — 통합 단계를 둔다

대상이 많아 배치로 쪼개면, 배치마다 **같은 결론에 따로 도달한다.** 실측: 미소속 인물 1,287명을 직군별 27개 배치로 돌렸더니 「액션 스타」를 세 배치가, 「한국 배우」를 네 배치가 각각 새 테마로 제안했다. 나쁜 신호가 아니라 판단이 수렴한다는 신호지만, 그대로 반영하면 지도가 조각난다.

**해결은 통합 단계다.** 배치들의 제안을 한 세션이 통째로 보고 최종 목록을 정하게 한다. 이때 요령이 있다.

- **인물 명단은 넘기지 않는다.** 「제안 A를 최종 테마 X로」 같은 **매핑만** 받고, 인물은 그 매핑대로 기계가 옮긴다. 출력이 작아지고 검사가 쉬워진다.
- **다시 가를 길은 열어 둔다.** 최종 테마가 `members`에 대상 id를 직접 적을 수 있게 하면 자루를 쪼갤 수 있다. 이 길이 없으면 「자루를 만들지 마라」고 해도 못 고친다.
- **검사기가 배치 간 충돌을 잡되 오류로 막지는 않는다.** 같은 이름 제안은 통합이 합칠 일이라 경고면 족하다.

실측: 제안 101개 → 최종 53개. 수상·성별·자리로 묶은 자루 22개를 근거를 적어 버렸다(「올림픽 영웅은 우승 이력으로 묶은 자루다」).

## 지시서 쓰는 법 — 값을 치르고 배운 것

**규칙보다 예시를 따라간다.** 지시서 앞에서 「직군 자루는 세력이 아니다」를 표까지 그려 금지하고, 뒤쪽 이름 규칙의 예시에 「한국 배우」·「액션 배우」를 남겨 뒀다. 결과는 정확히 그 예시대로 나왔다 — 139명짜리 「할리우드 배우」 자루. **금지 조항을 쓸 때 문서 전체의 예시를 같은 기준으로 훑어야 한다.**

**상한은 품질 기준을 대체하지 못한다.** 「직군당 테마 6개」 상한을 걸었더니 오히려 자루가 커졌다. 본인이 notes에 적었다 — 「여섯 자리에 맞추느라 흡수했다」. 상한은 쏠림을 막는 장치일 뿐이고, 품질은 「무엇이 좋은 결과인가」를 정의해야 나온다.

**「그대로 둔다」와 「버린다」를 허용한다.** 이 둘이 없으면 억지로 바꾸고 억지로 채운다.
- `changed: false` — 「지금 것이 기준을 다 만족하면 그대로 두고 억지로 바꾸지 마라」. 실측: 그룹 재검토 164건 중 상당수가 그대로 통과했고, 근거를 적어 냈다(「시대로 나누면 경계가 어색하다」).
- `skipped` / `drop` — 「갈 데가 없으면 두는 게 부끄러운 결과가 아니다. 억지로 넣은 명단은 전체를 망친다」를 **문장으로 적는다.** 실측: 1,287명 중 206명을 넣지 않았고, 통합에서 164명을 더 버렸다. 그 판단들이 결과 품질의 핵심이었다.

**판단 근거를 남기게 한다.** `notes`와 항목별 `reason`이 검수 비용을 절반으로 줄인다. 「20명이 넘는 항목은 나누든 두든 근거를 남겨라」처럼 **근거를 의무화할 자리**를 지정하면 더 낫다.

## 검사기가 막아야 할 것

기계 검사는 스키마 검사에 그치지 않는다. 이번에 실제로 사고를 막은 것들이다.

- **대상 손실** — 「적용하면 어디에도 속하지 않게 되는 항목이 있는가」. 구조 재편에서 가장 중요한 한 줄이다.
- **스냅숏 드리프트** — 「입력을 뜬 뒤 원본이 바뀌었는가」. 단계가 병행되면 앞 산출물이 낡는다. 실측: 편입이 테마에 2명을 넣은 뒤라 그룹 안이 낡아 반영이 막혔고, 입력을 새로 떠 다시 돌렸다.
- **전역 유일 제약** — DB가 이름 유일을 걸고 있으면 반영 트랜잭션이 아니라 **검사에서** 잡아야 한다.
- **되돌림 경로** — 반영 스크립트는 기본을 모의 실행으로 두고, `--apply`일 때만 백업을 남기고 한 트랜잭션으로 건다.

반영 스크립트에서 실제로 났던 구멍 넷을 적어 둔다. **새로 만든 항목의 노출 스위치를 형제에 맞춘다**(재편으로 테마 85개를 새로 만들면서 공개 칸을 안 켜 기본값 「꺼짐」으로 들어갔다. 열려 있던 다섯을 합친 테마가 닫힌 채 떠서 재편 결과 전체가 화면에 안 보였고, 사용자가 운영 화면에서 발견했다. 반영 뒤 「새 항목 중 형제와 공개 상태가 다른 것」을 센다). **판정 종류를 늘렸으면 반영 경로도 같이 늘려야 한다**(나눔 판정을 추가했는데 원본을 지우는 코드가 없어 인물이 양쪽에 겹쳤다). **목록이 빌 때를 처리해야 한다**(`slug in ()` 문법 오류). **부분 반영을 허용하지 않는다**(한 건이 틀리면 트랜잭션째 롤백되므로 낡은 참조 하나가 배치 전체를 막는다 — 그래서 드리프트를 미리 잡는다).

### 도구 결함은 모델의 판단으로 위장한다 — 가장 잡기 어려웠던 것

2회차를 돌릴 때 추출기의 원천 폴더만 `place`에서 `place2`로 바꾸고 **검사기와 반영기는 1회차를 가리킨 채 두었다.** 그래서 2회차 제안의 인물이 전부 「없는 사람」이 됐다.

무서운 것은 실패한 방식이다. 오류가 나지 않았다. Devin은 검사 풀을 성실히 조회하고 없다는 답을 받아, **「명단 전원이 검사 풀에 없어 최종 테마로 세워도 명단을 채울 수 없다」는 조리 있는 사유를 달아 멀쩡한 제안 넷을 버렸다.** 검사는 오류 0으로 통과했다. 산출물만 보면 나무랄 데가 없다.

붙잡은 단서는 **버린 사유 넷이 서로 똑같았다**는 것이다. 판단이라면 제각각인 이유가 나온다. 사유가 한 틀로 찍어낸 듯 같으면 모델이 아니라 도구를 본다. 고치고 다시 돌리니 넷 모두 살아났고, 내가 눈치채지 못한 다섯 번째 피해(다른 테마에서 인물 하나가 조용히 빠진 것)까지 Devin이 함께 짚었다.

- **회차를 늘릴 때는 그 원천을 읽는 파일을 전부 찾아 고친다.** 파이프라인 한 곳만 고치면 나머지가 조용히 어긋난다. `grep`으로 옛 경로가 0건인지 확인하고 넘어간다.
- **산출물이 아니라 사유의 분포를 본다.** 버린 건이 있으면 사유를 나란히 놓고 읽는다.
- 버린 산출물은 지우지 말고 `output/_rejected/`에 남긴다. 다시 돌린 결과와 견줘야 무엇이 도구 탓이었는지 가려진다.

## Windows 운용 — 메모리가 한계선이다

세션 하나가 수백 MB에서 1GB 남짓을 쓴다. 여유 메모리가 4GB 아래로 떨어지면 **harness가 백그라운드 작업을 죽인다**(실측: 동시 2~7에서 반복해서 끊김). 대응은 이렇다.

- **동시 실행은 메모리로 정한다.** 여유 4GB 미만이면 1개, 8GB면 2~3개, 16GB면 3~4개.
- **끊겨도 이어지게 만든다.** 러너가 산출물 파일이 있는 항목을 건너뛰면, 끊긴 지점부터 자동으로 이어진다. 손실은 진행 중이던 항목 하나뿐이다.
- **반영 기록을 파일로 둔다**(`applied.txt`). 산출물과 반영이 어긋나면 같은 것을 두 번 걸거나 빠뜨린다.
- **여러 러너를 쓸 때는 구간을 나눠 준다**(`--only`). 같은 항목을 두 러너가 잡지 않게 한다.
- 원인을 찾을 때는 **내가 띄운 것과 남의 것을 구분한다.** Devin Desktop 앱만으로 프로세스 19개·3.6GB를 쓴다. CLI는 앱과 별개로 도니 앱을 닫아도 작업에 지장이 없다.

**실측 — 시험 1건(『아이네이스』, `swe-2-max`)**

- 1,408초(약 23분)가 걸렸다. 지시서·견본·후보 874명을 읽고 스스로 조사한 뒤 파일을 쓰고, 검사기까지 돌려 보고 끝냈다.
- 결과
  - 규칙 검사 오류는 0건이다.
  - 원전과 대조해 사실 오류가 없었다. 권 번호와 장면까지 짚었다.
  - 후보 목록에서 올바른 동명이인을 골랐다(바람의 왕 아이올로스와 조상 아이올로스를 구별).
  - 애매한 판단의 근거를 notes에 남겼다.
- 흠
  - 한국어 활용 오류가 1건 있었다(「도운」을 「돕은」으로 씀).
  - 뜻이 흐린 표현이 1건 있었다.
  - 그룹 이름을 장면 이름처럼 지은 것이 1건 있었다.
  - 그래서 지시서에 「쓰기 전에 한국어를 다시 읽고 활용을 고친다」, 「그룹 이름은 무리를 부르는 말」을 더했다. 사람의 검수는 글 다듬기 위주로 남는다.

**실측 — 대량 32건(신화 도감, `swe-2-max`, 동시 2)**

- 32건 모두 결과 파일을 냈다(실패 0). 한 건에 251~2,207초가 걸렸고, 대개 13~25분이다.
- 규칙 검사 오류는 드물었다. 33건(시험 포함) 중 13건은 손질 없이 반영했다.
- 검수에서 손질한 흠은 아래 결이다. 검수 때 이것부터 본다.
  - 한국어 활용·오기(「잃린」, 「깁은」)
  - 후대 판본·개작 장면을 원전에 섞음
  - 친족 관계 방향 뒤집기(조카를 아들로, 아들을 손자로)
  - 근거 약한 세부를 사실처럼 씀
  - 전설·논란을 사실로 단정함
  - 고유명사 오역(작품 속 지명을 나라 이름으로)

**실측 — 대량 운용(세력도감 재편, 26.09.12~13, `swe-2-max`)**

하루 동안 세션 약 230개를 돌렸다. 전 구간 **규칙 검사 오류 누적 0건**, 러너 실패 0건이다.

| 패스 | 세션 | 한 건 소요 | 결과 |
|---|---:|---|---|
| 테마별 명단·그룹·소개 | 113 | 3~13분 | 영상 자막 투 이름 30개를 일상어로 바꿈 |
| 구조 재설계(1·2차) | 2 | 각 20~22분 | 테마 121 → 172, 나눔 3·합침 14·없앰 2·신설 68 |
| 미소속 인물 편입 | 28 | 5~25분 | 미소속 1,287 → 433명 |
| 제안 통합(1·2차) | 2 | 각 21~23분 | 제안 101 → 최종 53 |
| 그룹 재검토 | 164 | 2~9분 | 그룹 323 → 458, **1명짜리 그룹 0** |

사람이 손댄 것은 개명 판단 8건, 토막 문장 상세 소개 8건, 깨진 문자열 3곳, 픽션 테마의 작가 제외, 인물 7명 이동뿐이다. 나머지는 산출물 그대로 들어갔다.

## 작업 폴더 구성 — 그대로 복제해 쓴다

패스마다 폴더 하나를 만들고 파일 여섯을 둔다. 이름만 바꾸면 다른 도메인에도 그대로 쓴다.

```
devin-<패스이름>/
  BRIEF.md              지시서 — 하는 일 / 하지 않는 일 / 판정 기준 / 울타리 / 출력 스키마
  extract-<x>.mjs       DB → input/ (항목별 스냅숏 + 후보 목록 + 판정에 필요한 맥락)
  run-<x>.mjs           항목마다 devinCall. 산출물 있으면 건너뜀. --concurrency --only
  validate-<x>.mjs      규칙 검사. 오류면 종료 코드 1 (반영 스크립트가 먼저 호출한다)
  apply-<x>.mjs         모의 실행 기본, --apply로 백업 + 한 트랜잭션 반영 + 대조
  rework.mjs            검수에서 걸린 항목을 지적문과 함께 되돌려 보냄
  input/ output/ logs/ applied.txt
```

세력도감 실례는 `devin-faction`(항목별) · `devin-atlas`(구조) · `devin-place`(편입) · `devin-themeset`(통합) · `devin-cluster`(그룹) · `devin-detail`(글) 여섯 폴더였다.
