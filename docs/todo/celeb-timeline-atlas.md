# 인물 타임라인·활동반경 계획서

> **최종 실측 체크: 26.07.26** — 대상 인원·위키데이터 수확량·천도 지구본 코드 실측 대조

인물 상세 화면에 **생애 행적 연표**와 그 행적의 **활동 범위 지도**를 붙인다. 연표 항목 중 위치를 가진 것만 지도에 뜬다 — 지도는 연표의 파생이지 별도 데이터가 아니다.

## 1. 확정 사항 (유저 결정 26.07.26)

| 항목 | 결정 |
|------|------|
| 대상 범위 | 영향력 **60점 이상 73명** (정식 등록 인물 1,273명 중) |
| 데이터 확보 | 위키데이터 자동 수집으로 뼈대 → 조사로 살붙이기 |
| 지도 표현 | 좌표를 연도순으로 이어 **이동 경로**까지 표시 |

## 2. 실측 근거

### 대상 인원 (DB 실측 26.07.26)

`celeb_influence` × `profiles`(CELEB·full) 기준.

| 기준 | 인원 |
|------|------|
| 70점↑ | 21 |
| **60점↑** | **73** |
| 50점↑ | 205 |
| 40점↑ | 452 |
| 전체 full | 1,273 |

60점 이상 73명은 **전원 위키데이터 식별자·생년 보유**(73/73). 자동 수집의 전제가 성립한다.

### 위키데이터 수확량 (WDQS 실측 26.07.26)

73명 전원에 대해 출생지·사망지·거주지·활동지·교육기관·소속·참가사건(P19/P20/P551/P937/P69/P108/P1344) 중 **좌표를 가진 것**만 조회했다.

| 지표 | 실측 |
|------|------|
| 좌표 보유 장소 (연결 건수) | 439건 |
| 중복 제거 장소 | 365곳 |
| 최소 1곳 확보 인물 | 70 / 73 |
| **연도까지 아는 건수** | **428건 중 166건 (39%)** |
| 한국어 지명 보유 | 365곳 중 267곳 (73%) |

인물별 분포는 극단적이다.

| 확보 장소 수 | 인물 수 |
|---|---|
| 0곳 | 3 |
| 1~2곳 | 23 |
| 3~5곳 | 17 |
| 6~10곳 | 18 |
| 11곳 이상 | 12 |

**이 실측이 설계를 정한다.**

1. **위키데이터는 연표를 만들지 못한다.** 좌표는 잘 나오지만 "언제"를 아는 건 39%뿐이다. 나머지 61%는 지도에 점만 찍힐 뿐 연표 줄에 놓을 자리가 없다.
2. **인물 절반이 사실상 빈 화면이다.** 26명(0곳 3 + 1~2곳 23)은 자동 수집만으로는 지도가 텅 빈다. 고대 동아시아 인물이 특히 얇다 — 이사·이세민·손문·유철·아소카 왕이 각 1곳뿐이다.
3. **한국어 지명 98곳은 직접 붙여야 한다.** 서비스가 한·영 이중이므로 영문만 있는 지명은 그대로 못 쓴다.

따라서 위키데이터의 역할은 **연표가 아니라 장소 사전**이다 — 좌표와 지명을 공짜로 확보해 조사 부담을 줄이는 밑재료다. "언제 무엇을 했는가"는 조사가 만든다.

## 3. 데이터 설계

### `celeb_timeline_events` (신설)

한 인물의 생애 사건 하나가 한 행이다. **위치는 있어도 되고 없어도 된다** — 위치가 있는 행만 지도에 뜬다.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | uuid PK | |
| `celeb_id` | uuid FK → profiles | |
| `year` | int NOT NULL | 시작 연도. 기원전은 음수 |
| `year_end` | int | 기간형 사건의 끝 연도. 단발이면 null |
| `month`, `day` | smallint | 아는 경우만 |
| `title`, `title_en` | text NOT NULL | 한 줄 제목 |
| `description`, `description_en` | text | 2~4문장 서술 |
| `kind` | text | birth·death·education·work·publish·battle·travel·office·meeting·other |
| `place_name`, `place_name_en` | text | 지명 |
| `lat`, `lng` | double precision | 좌표. **둘 다 있거나 둘 다 없거나**(CHECK) |
| `place_qid` | text | 장소의 위키데이터 식별자. 좌표 검증·재조회용 |
| `source` | text | wikidata · research · manual |
| `source_url` | text | 조사분 근거 링크 |
| `sort_order` | int | 같은 연도 안 순서 |

- INDEX(celeb_id, year, sort_order)
- 좌표 정규화(장소 사전 분리)는 하지 않는다. 같은 지명이라도 시대마다 부르는 이름이 다르고(콘스탄티노폴리스↔이스탄불), 조사가 만드는 장소는 위키데이터 식별자가 없는 경우가 있다. 중복 수백 행은 문제가 아니다.

**활동반경은 테이블을 따로 두지 않는다.** 좌표를 가진 행을 연도순으로 뽑으면 그것이 곧 이동 경로다.

## 4. 화면 설계

### 인물 상세 새 구획

현재 11개 구획(소개·서재·관계·동시대·영향력·성향·독백·대사·영상·세력도감·방명록) 뒤에 12번째를 넣는다. 위치는 **관계 다음, 동시대 앞** — 인물 자신을 설명하는 구획끼리 모으고, 남과의 비교는 그 뒤로 미룬다.

한 구획 안에 왼쪽 연표, 오른쪽 지구본을 나란히 둔다(좁은 화면에서는 지구본이 위, 연표가 아래).

- 연표 항목을 누르면 지구본이 그 지점으로 돌아간다.
- 지구본 점을 누르면 연표가 그 항목으로 스크롤되고 강조된다.
- 좌표 없는 항목은 연표에만 있고 지도 표식이 없다는 것을 눈에 띄게 구분한다.
- 이동 경로는 연도순 곡선으로 잇되, 지구 뒷면으로 넘어간 구간은 끊는다.

### 이름 충돌 주의

`/explore/timeline`이 이미 있다. 그건 **국가별 연대기**로 생몰년만 쓰는 다른 화면이다. 이번 건은 인물 상세 안의 구획이므로 주소는 겹치지 않지만, 다국어 문구 키와 부품 이름은 반드시 구분한다.

### 지구본 공용 부품

`sw/web/src/components/shared/Globe/` 신설.

- 입력: 좌표 점 목록(라벨·색·강조 여부), 경로 표시 여부, 초점 좌표.
- 담당: 회전·확대·크기 대응·좌표 변환·클릭 판정·뒷면 숨김.
- 그리기는 바깥에서 넘긴 함수에 맡긴다. 게임 세력 색이든 인물 행적 점이든 부품은 모른다.

**천도 이관은 마지막 단계로 미룬다.** 게임은 현재 비활성이고(`docs/project/suikoden-dev.md`), 그리기 코드 532줄이 게임 개념과 얽혀 있어 지금 손대면 확인할 방법 없이 깨질 위험만 진다. 다만 공용 부품은 처음부터 게임이 얹힐 수 있는 형태로 만든다.

### 조사 형식 (P2에서 확정)

- 인물당 **12~18건**. 출생·사망을 양 끝에 두고 그 사이를 굵직한 전환점으로 채운다.
- 제목은 **동사로 끝나는 한 줄**("훈민정음을 반포하다"). 명사 나열을 쓰지 않는다.
- 서술은 **2~3문장**. 사건이 무엇이었는지와 그것이 무엇을 바꿨는지까지 적고, 미사여구를 넣지 않는다.
- 좌표는 **위키데이터에서 확인**해 넣는다. 기억으로 적지 않는다 — 시범에서 "온양"이 울산 근처로 잡히는 오배정이 실제로 나왔다(세종이 간 곳은 충남 아산, `Q27309340`).
- 장소의 위키데이터 식별자를 함께 적어 나중에 좌표를 재확인할 수 있게 한다.
- 좌표를 못 붙이는 사건도 넣는다(연표에만 뜨고 지도에는 안 뜬다).
- 영문은 직역하지 않는다. 사실·연대·무게만 지키고 영어 리듬으로 다시 쓴다(프로젝트 번역 원칙).

### P4 주의 — 사료 다루기

- 조사분은 근거 링크를 반드시 남긴다. 근거 없는 사건은 넣지 않는다.
- 고대 인물은 연도 자체가 학설마다 갈린다. 확정할 수 없으면 서술에 그 사실을 적고, 지어내지 않는다.
- 좌표는 그 시대의 장소를 가리켜야 한다. 현대 도시 좌표를 그대로 쓰면 어긋나는 경우를 걸러낸다.
- 조사 산출물의 사료 판정은 그대로 믿지 않는다. 핵심 사건은 직접 대조한다.

**보기 전환(26.07.26 추가)**: 한 구획 안에 「나란히 · 생애 연표 · 활동 반경」 세 가지 보기를 둔다. 유저가 두 기능을 처음부터 별개로 이름 붙인 이유가 여기 있다 — 한쪽만 크게 보는 상태가 필요하다. 지도에 찍을 곳이 하나도 없는 인물은 고를 것이 없으므로 전환 자체를 띄우지 않는다.

구현에서 지킨 것 두 가지.

- **지구본을 옮겨 심지 않는다.** 보기를 바꿔도 같은 자리에 두고 배치 클래스만 바꾼다. 다른 위치로 옮기면 부품이 다시 만들어져 사용자가 돌려놓은 각도가 풀린다.
- **회전 지시에 표를 붙여 한 번만 수행한다.** 이 처리는 다시 그릴 때마다 딸려 재실행되는데(마우스가 점 위를 스치기만 해도 그렇다), 그때마다 회전을 되돌리면 손으로 돌린 각도가 제자리로 튕겨 간다. 실제로 그렇게 동작해 26.07.26에 교정했다.

**부품 이름은 `WorldGlobe`다.** `Globe`는 이미 아이콘 이름으로 쓰여 겹친다. 화면 부품도 `TimelineSection`이 국가별 연대기에 이미 있어 `JourneySection`으로 지었다.

**계획과 달라진 점**: 계획서는 "그리기를 바깥에 맡긴다"고 했으나, 실제로는 점과 경로라는 공통 표현을 부품이 직접 그린다. 게임을 얹을 때 그리기 주입 지점을 열면 된다 — 지금 없는 요구에 맞춰 미리 열어두지 않았다.
