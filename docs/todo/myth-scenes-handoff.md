# 신화 주요 장면 제작 인수인계

## 작업 개요

신화를 모르는 사람도 그림과 짧은 해설을 따라 사건·인물의 목적·감정을 이해하도록, `/explore/myth`에 주요 장면을 구성하는 작업이다. 시작은 `D:\remotion-assets\factions`의 영상용 자료 이관이었고, 현재는 일본 신화의 신규 제작·얼굴 정비·서사 보완·이미지 재검수를 진행하고 있다. 필요한 자료를 DB·R2로 이관한 뒤 그 백업 폴더를 폐기하려는 목적도 있다.

사용자는 일본 신화를 끝까지 제작하고 적용하도록 승인했다. 다음 신화 선정에서는 중국·일본을 하나씩 다루라는 요청이 있었다. 중국은 당장 깊게 확장할 리소스가 없으므로 현재 장면의 이야기 연결을 정리하라는 것이 최신 지시다. 이미지 생성 모듈을 사용할 수 있을 때 기존 승인 범위에서 제작을 이어가며, 사용할 수 없다고 임의의 유료 API로 전환하지 않는다.

일본 이후에는 간단한 전승부터 여러 나라를 이어서 처리하라는 지시가 있었다. 기존 얼굴이 준비되어 있고 짧은 사건 연결로 이해할 수 있는 전승부터 진행한다.

먼저 읽을 문서:

- [주요 장면 룰북](../project/production/prod-02-myth-image-captions.md): 자료 선별, 이야기 구성, 두 문장 해설, 한·영 대응, 저장·표시·용량.
- [faction-image 스킬](../../.agents/skills/faction-image/SKILL.md): 승인된 얼굴 REF, 캐스팅, 인물 배치와 이미지 검수.
- [이미지 제작 규칙](../project/production/prod-01-image-generation.md): §1.6 자체 검수, §2 행동·시선·몸 방향, §7.1 GPT 질감 문제.
- [신화 화면·데이터 인계](myth-handoff.md): 신화 공개·명단·그룹 구조. 인물 미등록·공개 문제는 그 문서가 연결하는 별도 과제를 따른다.

1. **아직 없는 전승.** 진무의 이스케요리히메 혼인과 타기시미미의 반란, 사루타히코가 조개에 손이 물려 빠지는 최후, 닌토쿠 이후 하권 설화는 넣지 않았다. 《고사기》 중권이 오진에서 끝나 그 뒤는 엔딩 카드가 안내한다. 류큐·아이누는 별도 신화다.

3. **일본 신화 미등록 인물 등록(사용자 결정 대기).** 장면의 주인공·주요 인물인데 celebs 미등록이라 celebIds 연결이 비어 있다(56·99~106, 45·46번). 등록 판정이 난 명단: 사호비메(101~104, 스이닌 편 비극의 주인공), 스이닌 천황(101~106), 오모노누시(97~100), 이쿠타마요리비메(99~100), 사호비코(101·103·104), 스쿠나비코나(58), 야가미히메(56), 호무치와케(105)·타지마모리(106). 비중 큰 인물(사호비메·스이닌·오모노누시·스쿠나비코나)부터 할지 사용자 지시가 필요하다. 사호비메는 장면 속 얼굴을 기준으로 아바타를 만든다. 절차는 `celeb-00-03-new-figure-checklist.md`와 [셀럽 파이프라인](../project/celeb/celeb-00-01-pipeline.md)을 따른다.
## 사용자가 반복해서 지적한 사항

### 이야기와 글

- **장면당 두 문장 안팎.** 이해에 필요한 내용이 많으면 장면을 늘린다. 한 장에 긴 설명을 몰아넣거나 두 개의 긴 복문으로 포장하지 않는다. 사용자는 분량보다 전달을 우선했지만, 글을 길게 쓰는 방식은 명확히 거부했다.
- 인물의 목적·감정·사건의 원인과 결과가 읽혀야 한다. “이자나기와 이자나미가 왜 싸우는지 모르겠다”는 지적이 실제로 있었다. 이미지가 설명해야 할 행동은 이미지로 보여 준다.
- 비슷한 이미지와 사건은 합치거나 역할을 나눈다. 오디세이아에서 출항·저승을 떠남·나우시카아의 도움 등이 중복됐고, 뗏목을 부순 뒤 다시 발견하는 역전도 지적됐다. 이미지가 있다는 이유로 모두 넣지 않는다.
- 제목은 자연스러운 한국어 사건문으로 쓴다. 번역투·추상적인 수식·AI식 명사구를 피한다. 사용자의 예: “괴물에게 빼앗긴 여섯 명” → “괴물에게 병사 여섯을 빼앗기다”. 화면에 원전의 권·장 번호를 일괄 덧붙이지 않는다.
- 등장인물 소개와 클로즈업을 배분한다. 새 인물·무장한 인물의 컷을 맥락 없이 끼워 넣지 않는다. 저승 장면에서 인물 정면 컷으로 발언자를 먼저 소개하는 방식은 사용자가 요청한 유효한 방법이다.
- 한·영은 같은 사건·시점·정보를 담는다. 마지막 후속 이야기는 이미지 위치에 별도 엔딩 카드로 안내한다. 상세는 [해설 룰북](../project/production/prod-02-myth-image-captions.md).

### 얼굴 REF와 신격

- 주요 여성 인물은 한 번 이상 얼굴이 크게 읽히는 클로즈업을 둔다. 같은 전승에서 이어 나오는 인물끼리는 겉옷 색을 겹치지 않는다.
- **아름다운 얼굴이 모두 같은 얼굴일 필요는 없다.** 인물끼리 너무 닮거나 개성이 없으면 장면보다 얼굴부터 정비한다. 쿠시나다히메가 아마테라스와 비슷해졌고, 토요타마히메가 기본 AI 얼굴처럼 보였던 문제가 있었다. 복식·머리·장식도 구별하되 신을 일반인처럼 낮추지 않는다.
- 모델은 단순히 예쁜지뿐 아니라 해당 신의 성격·역할·신격과 전승의 출신 문화권에 맞는지 판단한다. 승인된 익명 모델의 실명을 추측하지 않는다. 사용자가 모델 재료로 `D:\image\_재료\female\EastAsian`과 Pinterest를 허용했고, 새로 채운 폴더에 얼굴 크롭을 돌려 재검토하라고 했다. **선택한 재료는 모델 POOL에서 제외**하라는 지시도 있다. 사용 이력·보존본을 확인하고 처리한다.
- 신화 인물의 최종 얼굴은 현재 `celebs.avatar_url`·`portrait_url`로 대조한다. 사용자 승인 없이 다른 후보로 바꾸지 않는다. 새 모델 후보는 [faction-image의 REF 승인 규칙](../../.agents/skills/faction-image/SKILL.md)을 따른다.
- 사루타히코에서 “온순한 인간 얼굴에 코만 늘린” 형상이 지적됐다. 사료·도상 REF를 찾아 구조를 설계하되 삽화의 과장과 기괴함을 그대로 실사 얼굴에 복사하지 않는다. 코·눈 한 부분의 변형으로 개성을 대신하지 않는다.
- 코노하나사쿠야히메의 **얼굴 REF는 정면·고개를 숙이지 않은 모습**을 요구받았다. 장면마다 정면 응시를 강제하라는 뜻은 아니다. 아마테라스 시작 그림은 얼굴 일치, 동굴 근처의 클로즈업과 돌아오는 빛을 원했고, 거울은 스포일러라 제외하라고 했다.
- 아바타·대표사진·주요 장면은 서로 다른 자산이다. 도감 확대 시 도감용 사진이 표시되는 현상을 얼굴의 임의 교체로 단정했던 대화가 있었다. 어느 필드의 이미지를 보고 있는지 먼저 확인한다.

### 구도·시선·질감

- **“전보다 나아졌다”는 합격 근거가 아니다.** 직전 두 실패 컷은 고개가 상대 쪽으로 돌아간 것만 보고 통과시켰다. 상대를 실제로 보는지, 누구에게 말하는지, 어떤 반응인지가 최종 그림에서 읽혀야 한다. 프롬프트의 의도를 그림에 대신 읽어 넣지 않는다.
- 첫 만남에서는 숙인 여자와 아래에서 올려다보는 남자의 자세에 이유가 없었다. 약속 장면에서는 상대 얼굴이 가려지고, 빗나간 시선·찌푸린 표정·칼을 쥔 손이 위협처럼 보였다. **몸·카메라·상대 위치가 틀리면 눈동자만 고치지 말고 새 구도로 다시 발주한다.**
- 전체 그림과 원본 크기에서 얼굴·두 눈·손발·목·소품 연결을 직접 본다. 춤추는 우즈메의 다리와 자세, 여러 신의 제각각 시선도 앞서 지적됐다. “생성 성공”·파일 저장·검사 코드 통과는 육안 검수의 대체물이 아니다.
- GPT 특유의 질척함·파충류 같은 잔무늬·갈라짐이 피부뿐 아니라 옷·나무·사물·배경에 퍼지는 것을 피한다. 피부를 거칠게 만드는 것이 실사감이 아니다. 자연스러운 큰 명암과 재료별 표면을 유지하며 최종 WebP도 직접 본다.
- 조명은 광원·명암·인물과 배경의 밝기 차이로 연출한다. 디지털 컨셉아트처럼 보이는 결과나 고르게 밝은 일상사진 수준을 최종본으로 인정하지 않는다. 신화의 규모를 줄여 실사처럼 보이게 하지 않는다. 스사노오의 난동을 밭에서 소꿉장난하는 모습이나 팔만 뻗는 동작으로 만든 것도 지적됐다.
- 여와의 갈대재·하늘 기둥 같은 컷은 물질·큰 형태·무슨 행동인지부터 읽혀야 한다. 복잡한 질감으로 구조 오류를 덮지 않는다. 장면상 필요한 무기·상징도 실제 사건과 원전에 맞게 정한다.
- 생성 → 직접 검수 → 필요하면 수정 또는 재발주 → 반영 → 확인까지 맡는다. 사용자가 지적할 때까지 대충 한 번 만들고 올리는 방식을 반복하지 않는다. 상세 검수 규칙은 [이미지 제작 규칙](../project/production/prod-01-image-generation.md)에 있다.

### 규격·자료·사용자 편집 보존

- 주요 장면은 최종 지시가 **1:1**이다. 초기에 말한 3:2로 되돌리지 않는다. 배경을 포함한 인물 대표사진은 **4:5**를 요청했다. 기존 다른 비율 이미지도 DB·R2에서 수용한다.
- 표시용 WebP, 현재 그림 로드 뒤 오른쪽 두 장 선로딩, 재방문 캐시가 기존 구현이다. 그림 전체를 한 번에 로딩하거나 디코딩된 전 장면을 무제한 붙잡는 식으로 바꾸지 않는다. 용량은 원본 보관량·표시용 합계·실제 첫 로딩을 구분한다. 구현은 [해설 룰북의 링크](../project/production/prod-02-myth-image-captions.md)를 따른다.
- 영상 재료는 먼저 `faction-data.json`의 장면 순서와 실제 사용 파일을 찾는다. 파일을 무작정 전부 열거나, 대사 배열 밖에 있다는 이유로 도입 이미지와 기존 사건 컷을 버리지 않는다. 얼굴·갑옷이 바뀐 컷은 실제 사건에 맞는 대체본을 찾거나 재제작한다.
- 사용자가 백오피스에서 **90곳 이상 직접 수정**한 적이 있다. 저장 문제 때 과거 DB 값이나 일부 필드만 보고 복구됐다고 판단하면 안 된다. 편집 중에는 새로고침·이동 전에 현재 브라우저 초안을 보존하고, 현재값 내보내기를 활용한다. 오래된 배치 JSON으로 사용자 원고를 되돌리지 않는다.
- 임시파일 정리는 요구사항이지만 사용자 확인 전 생성 이미지는 보존한다. 삭제·덮어쓰기 전 원본 보호와 경로 확인은 루트 [AGENTS.md](../../AGENTS.md)를 따른다.

## 얼굴·산출물·반영 경로

**현재 서비스 값은 DB·R2가 정본이다.** 신화 장면의 로컬 제작 폴더와 임시 도구는 모두 정리했다. 수정할 때는 DB의 현재 URL에서 원본을 받아 편집 입력으로 쓴다.

쿠시나다히메의 앞머리 모델 `1790268856`은 사용자가 부적격으로 지정했으므로 REF로 재사용하지 않는다. 일본 신화 핵심 얼굴은 slug `kushinadahime`, `toyotamahime`, `konohanasakuya-hime`, `suseribime`, `okuninushi`, `susanoo`, `sarutahiko`로 현재 DB URL을 조회해 쓴다. 승인 얼굴이 확인되면 다시 사용자에게 위치를 묻지 않는다.

저장은 기존 `faction_lv2.team_images`의 해당 항목을 고친다. 새 테이블·컬럼은 필요 없다. 편집기 계약은 [faction-team-image.ts](../../packages/shared/src/lib/faction-team-image.ts), 검증은 [faction-scene-editor.ts](../../sw/web-bo/src/lib/faction-scene-editor.ts), 저장 액션은 [faction-scenes.ts](../../sw/web-bo/src/actions/admin/faction-scenes.ts), WebP는 [faction-team-display.ts](../../sw/web-bo/src/lib/faction-team-display.ts)를 따른다.

반영 전 현재 DB를 다시 읽고 원본을 보존한다. 수정 대상 외 값이 유지되는지 비교하고, 동시 편집은 revision/xmin으로 감지한다. R2는 내용 해시가 포함된 새 주소로 올려 기존 자산을 덮어쓰지 않고 공개 URL의 바이트를 대조한다. DB 반영 뒤 운영·로컬 캐시를 갱신하고 한·영 응답을 확인한다. 이번에는 첫 요청에 이전 캐시가 나왔다가 후속 요청에 새 URL이 확인됐으므로, 즉시 서버 재시작이나 재배포부터 하지 않는다.

로컬 실행에서 `tsx/cjs`로 백오피스 코드를 불러올 때 작업 디렉터리는 `C:/project/feelandnote/sw/web-bo`를 썼다. 루트에서 실행하면 `@/lib/db/admin` 경로 해석이 실패할 수 있다. 환경변수 값은 출력·문서화하지 않는다. 새 생성은 최근 작업과 동일하게 내장 `image_gen`을 사용했으며 사용자 개발 서버 재시작·빌드·커밋·push는 하지 않았다.
