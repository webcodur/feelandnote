# 팩션 대사 순환 검토

잘 쓴 한 번보다 새 결함을 발견하는 여러 번의 읽기를 우선한다. 작성과 수정은 언제나 다음 검토를 위한 후보를 만들 뿐이다.

## fiction 인물의 상위 원천

신화·전설·허구 인물은 먼저 `fiction-profile-monologue`로 본 서비스의 `profiles.virtual_monologue`를 작성·검토한다. 이 긴 독백이 인물의 행동·동기·사상·꿈에 대한 단일원천이다.

- 팩션 대사는 가상 독백에서 핵심 갈등 하나를 골라 압축한다.
- 독백에 없는 새 철학을 팩션 대사에서 만들지 않는다.
- 더 좋은 해석이 생기면 원전을 확인해 가상 독백을 먼저 고친다.
- 가상 독백이 바뀌면 파생된 팩션 대사는 `revision`으로 돌아간다.

## 상태

대사마다 다음 상태만 사용한다.

1. `unreviewed` — 기존 대사지만 이 절차를 거치지 않음
2. `draft` — 새로 작성함
3. `reviewing` — 검토 중이며 중대 문제가 열려 있음
4. `revision` — 문제를 반영해 고쳤지만 재독하지 않음
5. `candidate` — 서로 다른 두 차례 이상의 검토를 통과한 승인 후보
6. `approved` — 사용자가 명시적으로 승인함

대사를 고친 순간에는 반드시 `revision`으로 돌아간다. 작성자가 스스로 `approved`로 올리지 않는다. 숫자 점수나 S등급은 이 상태를 대신할 수 없다.

## 기록 위치

에피소드마다 다음 파일을 사용한다.

```text
sw/remotion/public/factions/<episode>/_docs/dialogue-review/
  index.md       # 전원 상태와 열린 중대 문제
  <slug>.md      # 인물별 검토 이력
```

새로 만들 때 `assets/index-template.md`와 `assets/person-review-template.md`를 복사해 채운다. 대사 원문은 `faction-data.json`이 단일원천이다. 검토 문서에는 원문 전체를 복제하지 말고 문제를 입증하는 짧은 구절만 남긴다.

## 한 차례의 검토

### 1. 첫인상 읽기

이전 평가와 수정 의도를 읽기 전에 현재 대사만 읽는다. 다음을 짧게 기록한다.

- 처음 듣는 사람이 실제로 받아들일 뜻
- 이 인물이 지금 왜 이 말을 하는지
- 세력 인물들이 함께 놓인 영상에서 이 독백이 어떤 행위로 들리는지
- 가장 강한 구절과 처음 걸린 구절

바로 고치지 않는다.

### 2. 원전의 저항 확인

`quoteOrigin`과 출처 원문을 대조한다. 가상 독백은 가능하지만 원전이 불편하게 만드는 모순·실패·폭력·권력관계를 매끈한 철학으로 지우지 않는다.

- 원문 인용, 번역, 가상 독백을 구분한다.
- 합성한 장면과 해석은 `quoteOrigin`에 밝힌다.
- 실존 인물은 실제 발언의 사실 검증을 우선한다.
- 신화·문학 인물은 한 장면만이 아니라 생애의 반례도 찾는다.

### 3. 이번 원고의 렌즈 생성

고정된 평가 항목부터 대입하지 않는다. 현재 문장의 주장·생략·모순·말투에서 검토 렌즈 4~7개를 새로 만든다. 각 렌즈 옆에 `왜 이번 원고에서 나왔는가`를 한 줄로 쓴다.

렌즈가 막힐 때만 다음 질문을 발화점으로 쓴다. 이 질문 자체를 상시 체크리스트나 렌즈 이름으로 복사하지 않는다.

- 이 문장이 현명해 보이기 위해 감춘 반례는 무엇인가?
- 인물의 적·동료·피해자·초심자는 무엇을 반박할까?
- 원전의 거친 면을 현대적인 미덕으로 세탁하지 않았는가?
- 다른 인물의 이름을 붙여도 성립하는 구절은 어디인가?
- 원하는 결말은 누구의 비용·침묵·복종 위에 서 있는가?
- 팀 안에서 이 말은 독백·명령·변명·선언 중 무엇으로 들리는가?
- 앞선 수정 이유 자체가 새 약점이 되지는 않았는가?

서로 겹치지 않는 렌즈를 최소 3개 골라 따로 읽는다. 두 번째 검토부터는 이전 렌즈를 전부 재사용하지 말고, 수정된 문장이 새로 만든 렌즈를 최소 1개 포함한다.

### 4. 렌즈별 판정

각 발견은 다음 다섯 요소를 갖춘다.

1. 정확한 문제 구절
2. 진단
3. 시청자 이해·인물 정체성·원전 해석에 생기는 결과
4. 현재 문장을 지킬 수 있는 반론
5. `유지 | 수정 | 삭제 | 보류` 결정

심각도는 `blocking | major | minor`만 사용한다. 취향 차이를 치명 결함처럼 부풀리지 않는다.

### 5. 수정 전 합성

다음 셋을 분리한다.

- 반드시 고칠 결함
- 의도적으로 감수할 한계
- 어떤 수정에서도 보존할 강한 구절

진단을 마치기 전에 문장을 고치지 않는다. 여러 렌즈가 같은 문제를 가리킬 때만 우선순위를 높인다.

### 6. 수정과 구조 검사

필요한 범위만 고친다. 수정 후 `quoteOrigin`도 새 해석과 맞춘다. 대사 덩어리는 아래 명령으로 검사한다.

```bash
node .agents/skills/faction-dialogue-review/scripts/check-dialogue.mjs <episode> [slug]
```

대사나 `quoteChunks`가 바뀌면 `faction-voice-sync` 대상이다. 음성이 없으면 동기화를 실행했다고 보고하지 않는다.

### 7. 새 검토 순환

수정안은 곧바로 `candidate`가 아니다. 다시 1단계로 돌아가 첫인상과 렌즈를 새로 만든다. 이전 수정 논리를 방어하려 하지 말고, 오히려 그 논리가 만든 과잉·미화·설명조를 공격한다.

## 승인 후보 조건

다음을 모두 만족할 때만 `candidate`로 올린다.

- 수정 전후를 포함해 서로 다른 검토 순환을 최소 2회 기록함
- 두 번째 순환에 이전과 다른 렌즈가 최소 1개 있음
- 열린 `blocking` 문제가 없음
- 열린 `major` 문제는 의도적으로 감수한 이유가 기록됨
- 보존할 구절과 남은 한계를 함께 기록함
- 원전·번역·가상 독백의 경계가 `quoteOrigin`에 보임
- 구조 검사를 통과함

사용자가 승인하기 전에는 최종본·완성·승인이라는 표현을 쓰지 않는다.

## 보고 방식

사용자에게 점수보다 다음을 먼저 보고한다.

- 이번에 새로 생긴 렌즈
- 그 렌즈가 발견한 가장 큰 문제
- 보존한 강점
- 현재 상태와 다음 검토에서 열어 둘 질문

문제를 전부 장황하게 나열할 필요는 없지만, 기록 파일에는 근거와 결정을 남긴다.
