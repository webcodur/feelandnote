# 글 생성·검증 하네스

## 기본 순서

```text
자료·법령·도메인 근거 수집
  ↓
초안 생성
  ↓
문장 단위 근거 확인
  ↓
규칙 검증
  ↓
의미·품질 검증
  ↓
실패 이유를 반영한 제한적 재시도
  ↓
최종 문장 편집
```

## 규칙 검증

코드나 정규식으로 먼저 확인할 항목이다.

- 필수 섹션·필수 필드가 있는가
- 금지어·금지 패턴이 과도하게 반복되는가
- 제목·목록·JSON·Markdown 구조가 깨지지 않았는가
- 숫자·날짜·고유명사·링크가 바뀌지 않았는가
- 인용문에 임의의 의역이나 새 문장이 붙지 않았는가

## 의미·품질 검증

LLM 심사나 사람이 확인할 항목이다.

- 원래 질문에 답하는가
- 문단마다 중심 정보가 있는가
- 주제가 이탈하지 않는가
- 과장·논리 비약·근거 부족이 없는가
- 자연스럽게 만들려고 새 사실을 발명하지 않았는가
- 작성자의 목소리를 평균적인 모델 문체로 평탄화하지 않았는가

## 출처 기록

최종 글에서 독자용 근거 표기를 줄이더라도 내부 기록은 남긴다.

- 원문 주장
- 출처 URL 또는 문서 식별자
- 출처가 주장을 실제로 뒷받침하는지에 대한 판정
- 최종 문장에서 삭제·압축한 이유

참고 자료는 사실 확인과 구조 비교에만 사용한다. 경쟁사 문장을 베끼거나 출처를 숨기는 재창작은 하지 않는다.

## 재시도와 사람 검토

- 한 번에 하나의 결함군만 고친다.
- 재시도는 2~3회로 제한한다.
- 반복 실패 시 새로 생성하지 말고 해당 문장을 사람에게 넘긴다.
- 에이전트 결과를 사람이 전부 읽고 승인하는 방식은 규모가 커지면 병목이 된다.
- 자동 규칙·근거 검사·의미 검사를 먼저 걸고, 애매한 항목만 사람이 확인한다.

## 발행 전 체크리스트

- [ ] 사실·인용·숫자·날짜·링크가 보존되었는가
- [ ] 새 인물·사례·출처를 발명하지 않았는가
- [ ] 문단마다 하나의 기능이 있는가
- [ ] 추상 평가를 구체적인 행동·장면으로 바꿨는가
- [ ] 자연스러운 문장을 괜히 다시 쓰지 않았는가
- [ ] 근거와 최종 문장의 연결이 내부 기록에 남아 있는가
- [ ] 법령·가격·성능·저작권·라이선스를 별도로 확인했는가
- [ ] 결과물을 실제 화면·PDF·코드 실행으로 검수했는가

“90% 이상 막는다” 또는 “AI 검사기를 통과한다” 같은 수치는 독립 근거가 없으면 원칙으로 채택하지 않는다.
