# 인물 읽어보기

> `celeb_explanations`의 `인물 안내`와 `인물 탐구`를 만드는 유일한 규칙 SSoT다.
> 실행 도구는 `.agents/skills/celeb-reading/`과 `sw/web-bo/scripts/`에 있으며, 문장 규칙을
> 다른 문서에 다시 만들지 않는다.

## 목표

인물을 처음 만난 독자가 `인물 안내`에서 누구인지 이해하고, `인물 탐구`에서 확인된 사실
사이의 관계를 하나 더 읽게 한다. 위키식 이력 요약에서 한 걸음 더 나가되, 자료보다 큰
심리 분석이나 결정적인 인물 해석을 자처하지 않는다.

한 인물의 작업 단위는 한국어와 영어 두 탭 전체다. 여섯 필드 가운데 일부만 고쳐 놓지 않는다.

## 1. 재료 조사

먼저 동명이인을 막고 인물을 확정한다. 그다음 안내와 탐구에 각각 쓸 수 있는 구체적 재료를
찾는다. 이름·소속·직군만 확인한 자료는 신원 근거일 뿐 탐구 재료가 아니다.

- 원전·본인 저작·직접 인터뷰·공식 기록·학술·권위 자료를 우선한다.
- 위키백과와 위키데이터는 신원과 생애 개관에 쓸 수 있다. 본문이 직함과 역할만 제공하면
  거기서 조사를 끝내지 않는다.
- 현대 인물은 본인의 모국어로도 검색한다. 직접 인터뷰, 팟캐스트, 공식 영상, 본인 글과
  계정, 확인 가능한 라이브 보도, 작품 제작 자료를 먼저 찾는다. 직접 발언이 없으면 없다고
  판단하고, 권위 매체가 확인한 구체적 작품·사건·결정으로 넓힌다.
- SNS·라이브·영상은 화자와 계정을 확인한다. 검색 결과의 잘린 문장이나 기자의 요약을 본인
  발언으로 바꾸지 않는다.
- 탐구를 쓰기 전, 안내와 다른 사건·작품·관계·선택과 결과를 최소 하나 확보한다. 현대
  대중문화 인물을 재작성할 때는 신원 자료를 제외한 실질 자료를 두 건 이상 찾는다.
- 자료가 단순하면 짧게 쓴다. 같은 사실을 늘여 쓰는 것은 조사 부족을 가리지 못한다.

조사 자료는 집필 중 사실을 확인하는 재료다. URL을 서비스 DB에 따로 적재하지 않으며 조사
캐시에만 임시로 남긴다. 기존 가상독백·영향력·페르소나는 관점 후보일 뿐 사실 근거나 문체
원본이 아니다.

## 2. 말투와 표현 방식 결정

### 인물 안내

누구이며 무엇을 했고 왜 알려졌는지 설명한다. 생애를 모두 나열하지 않고 정체를 이해시키는
중심 행동이나 생각 하나를 고른다. 전문용어는 지우지 말고 같은 문장에서 일상어로 푼다.

### 인물 탐구

안내를 다시 요약하지 않는다. 확인된 사실 둘이 서로 돕거나 충돌하는 방식, 한 선택이 다음
결과로 이어지는 방식 가운데 하나를 읽는다. `A가 아니라 B다`로 앞의 모습을 지우지 않고,
대개 `A이면서 B다`에 가까운 실제 긴장을 쓴다.

안내가 소속과 직군을 말한 뒤 탐구가 보컬·랩·춤·기타 같은 팀 안 역할을 풀어 설명하면
실패다. “두 역할을 맡아 활동 폭을 넓혔다”도 새 해석이 아니다. 작품·사건·결정·관계가
하나도 없는 탐구는 조사를 다시 한다.

탐구에서 한 작품이나 사건을 깊게 다룬다면, 안내만으로 정체가 설명되는 한 그 소재를 안내에서
미리 요약하지 않는다. 같은 글을 탭 둘로 자르지 않는다.

## 3. 작성

한국어 초안을 쓰고, 같은 재료를 다시 읽어 한국어 최종본을 새로 정리한다. 초안의 표현만
손보지 않는다. 한국어는 `docs/project/production/writing-rules.md`를 따른다.

최종 한국어가 확정되면 같은 작업 안에서 영어를 쓴다. 영어는 별도 후속 배치에 맡기지 않는다.
사실·인과·평가·확신의 정도를 더하거나 빼지 않고, 영어권 독자가 자연스럽게 읽도록 문장을
재구성한다.

분량은 목표가 아니다. 보통 안내 180~420자, 탐구 220~500자지만 재료가 단순하면 더 짧게
끝낸다. 하한은 사실상 빈 산출물을 막는 안전망일 뿐이다.

## 4. 검토하며 수정

초안과 별개로 최종본을 다음 순서로 읽고 바로 고친다.

1. 안내만 읽고 인물의 정체와 핵심 행동을 말할 수 있는지 본다.
2. 안내와 탐구를 각각 한 문장으로 줄인다. 같은 사실이 남으면 탐구를 다시 쓴다.
3. 탐구의 핵심 문장마다 어느 자료가 받치는지 확인한다. 자료보다 큰 동기·감정·찬양·단죄를
   지운다.
4. 직함, 팀 내 역할, 장르 범위를 말만 바꿔 반복하지 않는지 본다.
5. 한국어의 번역투·사물 주어·설교조를 걷어낸다.
6. 영문을 한국어와 필드별로 대조한다. 누락·추가·강화와 고유명사 오류를 고친다.

하나라도 통과하지 못하면 저장하지 않는다. 기계 검수는 누락·숫자·마크다운·한영 문단 수와
명백한 반복을 막는 안전망이다. 최종 품질 판정은 글과 재료를 함께 읽어서 한다.

## 전량 재검수와 선택적 재작성

기존 읽어보기 전체를 새 기준의 검수 대상으로 삼되, 전부 기계적으로 덮어쓰지 않는다. 한
인물씩 현재 한국어와 영어를 먼저 읽고 다음 둘 중 하나로 결정한다.

- **통과**: 안내만으로 인물을 이해할 수 있고 탐구가 다른 구체적 사실과 관계를 제공하며,
  한국어와 영어가 일치한다. 본문은 그대로 두고 `review_status = 'ai_reviewed'`만 기록한다.
- **재작성**: 이력·직함·역할을 다시 배열하거나, 구체적 사건 없이 추상어를 늘이거나, 처음
  보는 독자가 사건을 파악할 수 없거나, 사실 오류·한영 불일치가 의심된다. 이때만 조사하고
  한국어 초안부터 한영 최종본까지 다시 만든다.

짧다는 이유만으로 고치지 않는다. 단순한 인물을 정확하고 짧게 설명했다면 통과시킨다. 반대로
분량이 길어도 같은 말을 반복하면 재작성한다. 선검수는 현재 글을 살릴 수 있는지 판정하는
단계이지 기존 글을 재료로 새 글을 만드는 단계가 아니다.

`review_status`의 의미는 다음 셋뿐이다.

| 값 | 의미 | 자동화 처리 |
|---|---|---|
| `NULL` | 새 기준 미검수 | 현재 글을 읽고 통과 또는 재작성 결정 |
| `ai_reviewed` | AI 검수 완료 | 이후 전량 배치에서 스킵 |
| `human_reviewed` | 인간 검수 완료 | 자동화가 절대 덮어쓰지 않고 스킵 |

재작성한 글은 최종 검수를 통과하고 DB 재조회까지 맞아야 `ai_reviewed`가 된다. 인간이 직접
승인한 글은 `human_reviewed`로 올린다. 사람 승인 원고를 다시 자동 처리하려면 사람이 먼저
상태를 `NULL`로 되돌려 재검수 대상으로 명시해야 한다.

## 저장과 배치

- 한국어 3필드와 영어 3필드를 한 행 갱신으로 함께 저장한다.
- 기존 글 통과 시 본문은 건드리지 않고 검수 상태만 조건부 갱신한다.
- 재작성 성공 시 한영 여섯 필드와 `review_status = 'ai_reviewed'`를 함께 저장한다.
- 재작성 시작 뒤 행이 바뀌었으면 `updated_at` 조건부 갱신을 실패시키고 다시 생성한다.
- 활성 프로필만 게시한다. 비활성·정지는 글을 보관하되 `published_at`을 비운다.
- 선검수 결과·초안·최종본·조사 캐시·실패 사유는 `.tmp-celeb-reading/`에 둔다.
- 한 배치는 8명, 기본 24개 독립 릴레이를 쓴다. 공유 작업 탈취나 `Promise.race`를 쓰지 않는다.
- **각 릴레이는 현재 묶음을 끝까지 완결한 뒤에만 다음 묶음을 받는다.** 현재 묶음의 기존 글을
  판정했으면 통과자는 즉시 상태를 기록하고, 재작성자는 즉시 조사·집필·검수·DB 반영까지
  끝낸다. `전원 판정 → 전원 조사 → 전원 재작성`처럼 전체 명단을 단계별로 가르는 구조는
  금지한다. 모델 호출 효율을 위한 최대 8명의 작은 묶음은 허용하지만, 묶음 사이의 순서는
  반드시 `판정 → 통과 반영 또는 재작성 → 다음 묶음`이다.
- 판정 캐시가 있더라도 같은 원칙을 따른다. 입력 해시가 같은 통과 캐시는 상태만 즉시
  반영하고, 재작성 캐시는 판정 호출만 생략한 채 바로 조사·재작성으로 이어간다.
- 한 인물 또는 현재 묶음이 실패하면 검수 상태를 `NULL`로 남기고 실패 사유를 기록한 뒤 해당
  릴레이의 다음 묶음으로 간다. 다른 릴레이의 진행을 기다리게 하지 않는다.
- 조사·생성 프로세스는 락 하나를 잡는다. 기존 행 재작성은 명시한 slug에만 허용한다.
- 혼합 표본을 두 차례 읽고 품질과 속도를 확인한 뒤에만 명단 전체를 실행한다.

```powershell
# 소규모 표본: 현재 글 선검수 후 실패한 인물만 조사·한영 재작성
pnpm exec tsx scripts/generate-celeb-readings.ts --slugs=jiwoo,brad-pitt,bai-juyi --rewrite-existing --review-existing --research --deep-research --generate --apply --resume

# 전량: AI·인간 검수 완료는 스킵하고 NULL만 선검수
pnpm exec tsx scripts/generate-celeb-readings.ts --all --rewrite-existing --review-existing --research --deep-research --generate --apply --resume

# 검수 상태와 게시 무결성 확인
pnpm exec tsx scripts/generate-celeb-readings.ts --stats
```
