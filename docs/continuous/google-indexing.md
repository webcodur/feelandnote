# 검색엔진 색인·수집 신청

**현재 도달점:** 공개 인물 6,643명의 한영 13,286주소와 주요 페이지 994주소, 총 14,280주소가 운영 사이트맵에 있다. 10월 15일 active로 바뀐 17명이 인물 사이트맵 캐시에 빠져 있어 해당 경로만 갱신했고, 현재 active 명단 전체와 대조해 누락 0명을 확인했다. 오늘 공개한 17명과 감상 연결을 수정한 4명의 한영 42주소를 IndexNow 공용 접수로 통지해 HTTP 200을 받았다. Google은 전체·인물 사이트맵을 재제출·재읽기했으며 인물 13,286주소와 오류·경고 0을 확인했다. 전체 사이트맵의 콘솔 집계는 아직 14,246주소다. 같은 날 개별 신청으로 응룡·공공의 한영과 정위 한국어 주소 5건이 우선순위 크롤링 대기열을 거쳐 즉시 색인됐다.

**엔진별 마지막 작업:** 아래 일시는 콘솔의 접수·재읽기 시각 또는 마지막 검수 시각이며 모두 한국시간(KST, UTC+9)이다. 재개 시 먼저 이 표의 일시·한도 결과를 확인한다. 기록 교체 규칙은 [지속 과제](README.md)가 쥔다.

접수는 실제 재크롤·색인·대표사진 반영 완료를 뜻하지 않는다.

마지막 실제 검색 확인에서 Google은 빌 게이츠·다리오 아모데이·젠슨 황 상세와 현재 제목을 보여 줬다. URL Inspection도 세 주소 모두 색인 정상이다. 다만 Google 이미지 묶음의 젠슨 황 썸네일은 도시 사진이고, 운영 `og:image`는 정상 인물 사진이므로 이미지 반영은 미완료다. 네이버 「필앤노트 빌 게이츠」 검색은 여전히 인물 상세 대신 탐색 페이지를 보여 줬다. 10-15 재확인에서도 `site:feelandnote.com` 기준 세 인물 상세가 현재 제목 그대로 1순위로 나오며, 젠슨 황 상세 결과에는 여전히 인물 사진 썸네일이 붙지 않았다.

**다음 착수는 Google 할당량 회복 뒤 미접수 주소의 개별 신청 재개다.** 대상과 순서는 위 표의 Google 행이 쥔다. 사이트맵·브랜드·설명문 규칙은 [SEO](../project/operations/ops-02-seo.md)가 쥔다.

다음 일일 작업은 아래 순서로 진행한다.

1. 빌 게이츠·다리오 아모데이·젠슨 황의 실제 검색 결과에서 상세 주소·최신 제목·설명·대표사진을 확인한다. 아바타를 쓰는 경우 승인된 원래 황갈색 배경도 확인한다. 현재 운영 응답, 검색엔진 저장 문서, 실제 검색 결과를 대조해 메타를 이미 읽은 경우와 아직 재수집되지 않은 경우를 구분한다.
2. 네이버는 세력·신화 허브, 남은 직군 명부부터 실제 일일 한도까지 신청한다. 오늘 처리한 주요 인물 29명과 직군 명부 4개는 반복하지 않는다.
3. Google은 위 표의 미접수 순서대로 이어간다. 이미 최신 변경이 반영된 주소를 반복 신청하지 않는다.
4. 셀럽 상세를 우선 처리한 뒤 세력 상세를 이어간다. 해리스 프리커와 의도적 noindex 작품은 후속 신청에서 제외한다.
5. 다음(Daum)은 오늘 공개 17명의 개별 수집과 인물 사이트맵·목록 Seed를 접수했다. 실제 검색 제목·설명·대표사진 반영을 확인한다. 사이트 검색에 남은 `Feel&Note`·HTTP 등록 변경은 최초 신청자 확인이 남았다.

Daum 리스트 Seed는 메인·탐색·인물 명부와 직군 명부 14개, 총 17개를 접수한 상태다. 직군 중 남은 목록은 `athlete`·`other`다. 이후 `/explore/faction`·`/explore/myth`·기관 선정 첫 목록을 이어간다. 기존 접수 주소는 반복하지 않으며 「중복 URL, 과도한 호출」 응답이 해제된 뒤 재개한다.

네이버의 다음 신청은 **`/explore/faction` → `/explore/myth`**다. 이후 미접수 직군 명부 `scientist`·`humanities_scholar`·`social_scientist`·`visual_artist`·`author`·`influencer`·`athlete`·`other`와 작품 탐색·기관 선정 첫 목록을 이어간다.

신청 전에 현재 active 명단 전체를 운영 사이트맵과 대조한다. 예전에 생성하고 오늘 공개한 인물이 있으므로 `created_at`만으로 신규 공개 여부를 판단하지 않는다. 운영 응답·자기 canonical·검색 허용과 기존 접수 내역도 확인한다. 대표 디렉토리만 신청하고 상세 주소가 모두 처리됐다고 간주하지 않는다. 같은 날 이미 접수한 주소, 영구 이동하는 옛 주소, 비공개·의도적 noindex 주소는 신청 대상에서 뺀다. 인물 주소는 현재 공개 사이트맵에서 확인하며 이름으로 slug를 추측하지 않는다.

## 신청과 반영 확인

- 사용자의 지시에 따라 로그인된 **Chrome 확장**으로 Google Search Console과 네이버 Search Advisor를 조작한다. 기존 로그인 계정을 유지한다.
- Google은 URL 검사 화면의 대상 주소가 신청하려는 주소와 일치한 뒤 「색인 생성 요청」을 누르고 결과를 확인한다. 이전 URL의 결과 대화상자를 닫은 뒤 다음 주소로 넘어간다. 접수 후에는 마지막 크롤 시점·색인 상태·저장된 페이지가 최신인지 확인한다.
- 네이버는 「요청 → 웹 페이지 수집」에서 정식 주소를 입력하고, 요청 내역의 실제 링크·등록일로 접수를 확인한다. 목록 갱신이 늦거나 이전 행의 접근성 이름이 남으면 실제 링크와 행 본문을 다시 읽고, 접수 여부를 확인하기 전에 재신청하지 않는다. 신청 뒤 실제 검색 결과의 인물 사진·제목·설명도 확인한다.
- Google의 「할당량 초과」 또는 네이버의 「사이트별 일간 최대 요청 수를 초과하였습니다.」가 뜨면 해당 엔진의 당일 신청을 끝낸다. 다른 주소로 우회해 계속 누르지 않는다. Google 접수 건수는 날마다 달랐으므로 고정 건수를 가정하지 않는다. 네이버는 이번에 50주소 접수 뒤 한도를 확인했다.
- Google 접수 확정은 결과 대화상자의 「check_circle 색인 생성 요청됨 - URL이 우선순위 크롤링 대기열에 추가되었습니다」 문구로만 판정한다. 「색인 생성 요청됨 / 다시 요청」 칩이나 직전 주소의 대화상자 잔여 텍스트가 본문에 남아 오탐을 만든다. 접수 직후 같은 주소를 다시 검사하면 칩 상태(요청됨·등록됨)로 실제 반영을 확인할 수 있다.
- Google의 「색인 생성 요청을 제출하는 중에 문제가 발생했습니다」는 할당량 초과와 구분한다. 해당 주소를 반복 요청하지 않고 다음 주소로 넘어간다. 결과 미확인·조작 실패가 이어지면 원인을 확인한 뒤 재개한다.

이 문서에는 현재 도달점·마지막 접수·한도 문구·다음 신청 대상만 갱신한다. 날짜별 이력이나 URL별 조사 파일을 따로 쌓지 않는다. 사이트맵·IndexNow·메타데이터 운영 규칙은 [SEO](../project/operations/ops-02-seo.md)가 쥔다.
