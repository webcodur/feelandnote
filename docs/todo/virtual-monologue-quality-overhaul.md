## 왜 별도 작업인가

기존 독백은 인물별 말투와 구성, 어려운 정보의 독자 안내, 삶과 철학의 연결을 전수 비판한 산출물이 아니다. 현행 실존 인물 생성기 `fill-virtual-monologue-gpt.ts`도 다음 한계가 있다.

- 근거 재료가 `bio + 생몰`뿐이다.
- 기존 글이 가진 근거 없는 동기·내면·영웅 서사를 개선본이 물려받을 수 있다.
- 기존 글의 재사용 가치와 무관하게 한 방식으로 처리한다.
- 생성 직후 독립적인 사실·구조·한국어 검토가 없다.
- 2026-07-29 착수 시점에는 생성 결과를 곧바로 DB에 UPDATE했다.

문법 교정기 `audit-monologue-grammar.ts`는 비문만 국소 치환하는 도구다. 이 작업이 다루는 사실, 인물성, 구조, 난이도, 근거 밖 자기고백은 검수 범위가 아니다.

## 절대 불변 규칙

1. **좋은 글은 다시 생성하지 않는다.** 모든 인물을 바꾸는 것이 목표가 아니다.
2. **생성기는 후보만 만든다.** 별도 승인·조건부 게시기를 거치기 전 DB UPDATE 금지.
3. **기존 글은 개선 모드에만 제공한다.** 신규 모드는 기존 표현과 구조를 보지 않는다.
4. **외부 비판을 당사자의 자기반성으로 바꾸지 않는다.**
5. **공개 행동을 단일한 내적 동기의 결과로 확정하지 않는다.**
6. **출처 없는 현장 장면·군중 반응·구체 수치·인과를 만들지 않는다.**
7. **직접인용은 원문과 출처가 있을 때만 쓴다.**
8. **어려운 말은 먼저 쉬운 말로 바꾼다.** 용어 보존이 필요할 때만 `용어(쉬운 뜻)`으로 안내한다.
9. **괄호 개수를 품질 지표로 삼지 않는다.** 필요 없는 괄호는 설명이 아니라 소음이다.
10. **한국어를 먼저 확정한다.** 영문은 같은 사실과 무게를 바탕으로 별도 작성한다.
11. **실존 인물과 fiction을 섞지 않는다.** fiction은 원전 manifest와 전용 스킬을 따른다.
12. **수치 점수로 승인하지 않는다.** `blocking / major / minor` 결함과 통독 판단으로 결정한다.

## 네 갈래 판정

### 유지

- 핵심 사실이 근거와 맞는다.
- 인물 고유의 중심 갈등과 문장 호흡이 이미 있다.
- 어려운 정보가 초심자를 버리지 않는다.
- blocking·major 결함이 없다.

유지 판정도 근거 대조를 거친다. 단순히 문장이 매끈하다는 이유로 유지하지 않는다.

### 개선

- 검증 가능한 생애와 사상의 중심축이 남아 있다.
- 좋은 문장과 인물 고유 재료를 특정할 수 있다.
- 결함이 일부 문단의 과밀함, 난이도, 순서, 말투처럼 국소적이다.
- 기존 글의 뼈대를 보존해도 근거 밖 자기서사가 원고를 지배하지 않는다.

### 신규

- 판박이 자기소개·업적 나열·교훈형 결말이 글의 뼈대다.
- 근거 없는 동기·깨달음·후회·미해결 고백이 중심 역할을 한다.
- 서로 무관한 개념을 많이 넣어 인물의 삶과 철학이 연결되지 않는다.
- 비슷한 인물 이름으로 바꿔도 대부분 성립한다.
- 국소 수정으로 살리면 사실상 전면 재작성이 된다.

### 보류

- 신원이나 생애 정보가 충돌한다.
- 믿을 만한 직접·기관·전기 자료가 부족하다.
- 논쟁적 사실을 한 출처로만 확인할 수 있다.
- 본인과 동명이인, 공동창업자, 작품 속 인물의 발언이 분리되지 않는다.

자료가 없으면 짧게 쓰는 것이 아니라 작성 자체를 보류한다.

## 작성·검토 순서

1. **구조 감사** — 전수 텍스트의 결측, 링크·한자·형식 잔존, 판박이 오프닝·결말, 반복 구절을 읽기 전용으로 집계한다.
2. **근거 조사** — 이번 배치 인물의 근거 묶음을 만든다.
3. **판정** — 유지·개선·신규·보류를 결정하고 이유를 남긴다.
4. **작성** — GPT-5.6이 개선 또는 신규 후보를 만든다.
5. **1차 독립 검토** — 새 GPT 컨텍스트가 근거 저항성을 검토한다.
6. **수정** — 작성 컨텍스트와 분리된 새 실행이 blocking·major만 고친다.
7. **2차 통독** — 인물 고유성, 쉬운 한국어, 삶과 철학의 연결을 다시 읽는다.
8. **조건부 게시** — 시작 당시 원문 해시가 현재 DB와 같고 후보 상태가 `approved`일 때만 갱신한다.
9. **재실행 검증** — 같은 배치를 다시 실행하면 전원 `SKIP`이어야 한다.
10. **서비스 검수** — 캐시 갱신 후 변경 인물의 실제 한국어 화면을 전원 확인한다.

### 결함 등급

- `blocking`: 사실 오류, 오인용, 동명이인, 근거 없는 내면·인과, 원문과 반대 의미, 작업 지시 누출
- `major`: 인물 교체 가능, 삶과 철학 단절, 영웅화·참회 세탁, 설명문·정책문으로 평준화, 핵심 반론 삭제
- `minor`: 번역투, 무생물 주어, 종결 반복, 불필요한 괄호, 문단 호흡, 국소 중복

blocking이 하나라도 남으면 게시하지 않는다. major는 고친 뒤 원고 전체를 다시 읽는다.

## 후보 배치와 게시 가드

정식 배치는 `docs/celeb-data/virtual-monologue/`에 둔다. 바꾼 인물만 이전 본문을 포함해 복구 가능하게 보존한다.

필수 필드:

- `batchId`, `promptVersion`, `model`, `createdAt`
- `slug`, `nickname`, `profileType`
- `route`, `routeReason`
- `currentText`, `currentHash`
- `dossier`, `candidateText`, `candidateHash`, `candidatePromptVersion`
- `reviews[]`: `evidence | editorial` 렌즈, 모델·프롬프트 버전·시각·판정·강점·심각도별 결함
- `review.blocking`, `review.major`, `review.minor`: 두 독립 검토의 게시용 집계
- `approval`: 승인 시각·승인 주체·재독 판단 메모
- `status`: `draft | reviewed | approved | rejected | hold | published`
- `publishedAt`, `liveVerifiedAt`

게시기는 다음 조건을 모두 확인한다.

- `status=approved`
- evidence·editorial 검토가 각각 존재하고 둘 다 `pass`
- 두 검토와 집계에서 blocking·major 0
- 승인 주체·시각·판단 메모가 모두 기록됨
- DB 현재 본문의 SHA-256이 `currentHash`와 일치
- 후보가 비어 있지 않음
- 한자·em dash·URL·마크다운 링크·작업 지시 없음
- 말투 일관성

## 첫 6명에서 확정한 운영 교훈

- 외부 비판·위험을 화자의 후회·약속·자기비판으로 바꾸지 않는다. 직접 근거가 없으면 검증된 사실을 병치한다.
- evidence는 사실·인용·내면·용어 정확성, editorial은 목소리·구조·쉬운 한국어만 책임진다. editorial이 새 사실을 요구하거나 사실 지원 여부를 판정하지 않는다.
- 낯선 개념의 짧은 괄호 안내는 서비스 필수 장치다. 괄호가 있다는 이유만으로 결함으로 잡지 않는다.
- `keep`도 긍정적으로 입증해야 한다. 젠슨 황의 최초 유지 판정은 근거 검토에서 무너져 개선으로 바뀌었다.
- `논쟁을 숨기지 말라`는 지시만 강하게 주면 모델이 모범적인 자기반성을 창작한다. 사건·결과와 실제 입장을 나란히 두고 해설자의 윤리 결말을 붙이지 않는다.
- 한 인물의 반복 실패로 전체 검수 규격을 계속 바꾸지 않는다. 후보 수정 2회 뒤에도 major가 남으면 기존 서비스 글을 유지하고 보류한다.
- 알렉스 카프는 WEF 장문 대담까지 근거를 확장했지만 회사 정책문 구조가 반복됐다. 비회사 장문 대담의 추가 근거 또는 인간 편집자의 새 중심축 결정이 재개 조건이다.
- 게시 5명은 조건부 DB UPDATE, `celebs` 캐시 갱신 HTTP 200, 게시기 재실행 `SKIP`, 공개 한국어 탭의 승인 문단 완전 일치를 확인했다. 연결 가능한 시각 브라우저가 없어 `liveVerifiedAt`은 아직 채우지 않았고 `liveHtmlVerification`만 기록했다.

## 둘째 6명에서 확인한 운영 교훈

- 링크 혼입처럼 구조상 명백한 결함도 단순 삭제로 끝내지 않는다. 히파티아·손빈은 링크 주변에 근거 밖 감정과 편집자식 사료 해설이 함께 있어 한 번의 비판 수정이 필요했다.
- 근거 묶음의 `researchLimits`는 실제 검토에서 작동했다. 히파티아의 기구 수령, 손빈의 감정 배제, 베버의 평생 문제의식, 밀의 어린 시절과 자유론 사이 직접 인과가 차단됐다.
- 두 차례 수정 뒤에도 major가 남은 페리클레스는 숫자를 채우기 위해 게시하지 않았다. 재개 조건은 배심 수당·시민권법·전쟁 전략만 남기는 인간 편집 구조의 선확정이다.
- relation 티어는 웹 코드에서 독백을 의도적으로 준비되지 않은 항목으로 처리한다. 클로윈디의 빈 값은 공개 결측이 아니며, 익명 계정의 얇은 생애 자료를 800자 자기서사로 부풀리지 않는다.
- 둘째 묶음 게시 4명도 조건부 DB UPDATE, 캐시 갱신 HTTP 200, 재실행 전원 `SKIP`, 공개 한국어 HTML 승인 문단 완전 일치를 확인했다. 누적 게시 검증은 9명이다.

## 마지막 12명에서 확인한 운영 교훈

- 제한 병렬화는 모델 호출만 동시에 실행하고 결과를 한 번에 원자 병합해야 안전하다. 같은 배치 파일을 쓰는 생성·검토 CLI 두 프로세스를 동시에 실행하지 않는다.
- 근거 검토와 편집 검토는 실제로 서로 다른 결함을 잡았다. 공자·광해군·푸틴에서는 외부 비판을 자기반성으로 옮기는 문제를, 반 고흐·프리다·베토벤·큐브릭에서는 `A가 아니라 B`식 교정 문장 반복을 별도로 걸렀다.
- 어려운 정보의 괄호 안내는 개념어뿐 아니라 독자가 맥락 없이는 알기 힘든 기관·제도·작품 형식에도 필요하다. 다만 모든 고유명사에 괄호를 붙이지 않고 이해를 막는 첫 등장에만 둔다.
- 광해군은 정치적 책임을 수동태로 세탁하지 않으면서도 후대 편집자의 모범적 자백을 입히지 않는 사실 귀속 문장이 필요하다. 해당 문장 구조를 인간 편집으로 먼저 확정하는 것이 재개 조건이다.
- 아인슈타인은 자유 낙하 사고실험과 일반 상대성 이론 구상의 직접 근거가 dossier에 부족했다. 근거를 보강하거나 그 인과를 제거하기 전에는 게시하지 않는다.
- 큐브릭은 사실 검토를 통과했지만 교정형 대조 리듬이 두 차례 수정 뒤에도 남았다. 사실이 맞는 글과 인물 목소리가 살아 있는 글은 별도 게이트다.
- 푸틴은 단일 1인칭 필드의 구조적 한계를 드러냈다. 당사자의 전쟁 정당화만 두면 책임 세탁이 되고, 유엔·국제형사재판소 판단을 그의 입으로 말하게 하면 창작된 자기비판이 된다. 비1인칭 편집 맥락을 분리할 UI·데이터 규칙이 생기기 전까지 보류한다.
- 마지막 묶음 게시 8명은 조건부 DB UPDATE, 캐시 갱신 HTTP 200, 재실행 전원 `SKIP`, 공개 한국어 HTML 승인 문단 완전 일치를 확인했다. VM-P1 누적 게시 검증은 17명이다.

## VM-KO-01 25명에서 확인한 운영 교훈

- 최초 후보는 두 검토 동시 통과가 0명이었다. 1차 수정 뒤 10명, 잔여자 2차 수정 뒤 13명이 통과했다. 생성 한 번이나 고정 체크리스트 한 번으로 품질을 판정하지 않는 이유가 실제 수치로 확인됐다.
- 최초 생성기는 dossier 밖의 널리 알려진 세부를 상식처럼 보태거나 `researchLimits`를 인물의 자기해설로 옮겼다. 생성·수정 프롬프트 v3부터 dossier만 사실 원천으로 쓰고, 현재 서비스 글은 문장 재료일 뿐 사실 근거가 아니며, 조사 한계는 화자가 말할 내용이 아니라 금지선이라고 명시했다.
- 모델 수정 2회 뒤 네 명은 검토자가 정확히 지목한 괄호 형식·출처 귀속·편집자식 결말 삭제만 국소 교정했다. 샤를마뉴·앨런 튜링·링컨은 두 검토를 다시 통과했고, 프랭클린은 구조 major가 남아 보류했다. 이 예외는 새 사실·주장·감정·구조를 더하지 않을 때만 한 번 허용한다.
- 최종 결과는 `published 16 / hold 9`다. 보류 9명은 단순 실패 목록이 아니라 반복 결함과 재개 조건을 각 dossier에 기록했고 기존 DB 원고를 보존했다.
- 순차 배치 러너는 생성 → evidence → editorial → 최대 2회 수정·재검토까지만 자동화한다. 승인·인간 국소 교정·보류·DB 게시를 자동화하지 않은 경계가 실제 출고에서 유효했다.
- 게시 16명은 직접 통독, 명시 승인, 원문 SHA-256 조건부 UPDATE, 캐시 HTTP 200, 같은 게시 명령 재실행 `SKIP`, 공개 SSR 문단 완전 일치를 모두 통과했다. 연결 가능한 브라우저가 0개였으므로 HTML 일치와 CSS·탭·스크롤 육안 검수를 같은 것으로 기록하지 않았고 `liveVerifiedAt`은 비워 뒀다.
- 후속 배치에서는 두 안전 가드가 즉시 결함을 잡았다. 뉴턴 dossier의 등록되지 않은 URL은 병합을 차단했고, 노자의 `제 이름`은 정당한 1인칭인데도 검증식이 놓쳤다. 전자는 근거를 줄여 고쳤고 후자는 생성·게시 양쪽 검증식을 함께 고쳤다.
